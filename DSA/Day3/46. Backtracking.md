# Backtracking

## 1. Overview
**Backtracking** is a systematic, recursive **Depth-First Search (DFS)** algorithm for solving combinatorial, enumeration, and constraint-satisfaction problems. It incrementally builds candidate solutions one decision at a time and immediately abandons (**prunes**) a partial candidate the moment it violates any problem constraint, rolling back state changes to explore alternative branches.

### The Core Choose - Explore - Unchoose Pattern
Every backtracking algorithm follows a three-step state transition at each node in the decision tree:
1. **Choose:** Select an available option and mutate the current partial state (`path.append(choice)`).
2. **Explore:** Recurse deeper to make the next decision (`backtrack(next_state)`).
3. **Unchoose (Backtrack):** Revert the state mutation (`path.pop()`) after the recursive call returns so sibling branches start from an unaltered state.

### State-Space Decision Tree with Pruning
```text
                        [ Start: path = [] ]
                       /          |          \
               choose A       choose B       choose C
                 /                |                \
            [path = A]       [path = B]       [path = C]
              /    \              |                 |
         choose B  choose C    choose C         [X] Pruned
           /          \           |          (violates constraint;
      [A, B]        [A, C]     [B, C]         subtree skipped)
      (Valid)       (Valid)    (Valid)
```

### Backtracking vs. Brute-Force DFS vs. Dynamic Programming
* **Brute-Force DFS:** Generates every complete leaf candidate first and validates constraints only at the bottom of the tree.
* **Backtracking:** Validates constraints **at every intermediate node**, cutting off entire invalid subtrees early.
* **Dynamic Programming (DP):** Solves problems with **overlapping subproblems** and **optimal substructure** where only an optimal count or score is needed. When a problem asks to **enumerate all valid configurations** (such as all subsets, permutations, or valid board layouts), backtracking is required.

## 2. Core Backtracking Patterns

| Pattern | Decision at Each Step | Recursive Index | Base Case | Duplicate Handling |
| :--- | :--- | :--- | :--- | :--- |
| **Subsets (Power Set)** | Pick next element from `start .. n - 1` | `i + 1` | Every recursive entry records `path.copy()` | Sort input; skip if `i > start` and `nums[i] == nums[i - 1]` |
| **Combinations (Size $k$)** | Pick next element from `start .. n - 1` | `i + 1` | `len(path) == k` | Sort input; skip adjacent identical values at same depth |
| **Combination Sum (Reuse)** | Pick candidate `candidates[i]` while `rem >= 0` | `i` (reuse allowed) | `remaining == 0` | Sort input; `break` early if `candidates[i] > remaining` |
| **Permutations** | Pick any element not yet marked in `used` | Loop `0 .. n - 1` | `len(path) == n` | Sort input; skip if `i > 0` and `nums[i] == nums[i - 1]` and `not used[i - 1]` |
| **2D Grid / Board Search** | Move to 4-directional neighbor `(nr, nc)` | `(nr, nc)` | `idx == len(word)` or `row == n` | Temporarily mark cell visited (e.g., `'#'`), restore on return |

│   └── i=2 (pick 3): backtrack(start=3, path=[1, 3]) -> record [1, 3]

│   └── pop 1 -> path=[]

### 2. N-Queens Constraint Pruning on a $4 \times 4$ Board
Instead of testing all $4^4 = 256$ placements, tracking occupied columns (`cols`), positive diagonals (`r + c`), and negative diagonals (`r - c`) prunes doomed rows immediately:

```text
Row 0: Place Q at (0, 0)
  Row 1:
    - col 0: [X] same column as (0, 0)
    - col 1: [X] same negative diagonal (1 - 1 == 0 - 0)
    - col 2: Valid -> Place Q at (1, 2)
      Row 2:
        - col 0: [X] same column as (0, 0)
        - col 1: [X] same positive diagonal (2 + 1 == 1 + 2)
        - col 2: [X] same column as (1, 2)
        - col 3: [X] same negative diagonal (2 - 3 == 1 - 2)
        -> Dead end! Backtrack immediately without visiting Row 3.
```

## 4. Time and Space Complexity Analysis
Assume $n$ is the input size, $k$ is the target combination size, $R \times C$ are grid dimensions, and $L$ is target word length:

| Problem | Worst-Case Time Complexity | Auxiliary Space (Excluding Output) | Explanation |
| :--- | :--- | :--- | :--- |
| **Subsets / Subsets II** | **$O(n \cdot 2^n)$** | **$O(n)$** | $2^n$ subsets generated; each subset takes up to $O(n)$ time to copy |
| **Permutations / Permutations II** | **$O(n \cdot n!)$** | **$O(n)$** | $n!$ permutations generated; each leaf takes $O(n)$ time to copy |
| **Combinations** | **$O(k \cdot \binom{n}{k})$** | **$O(k)$** | $\binom{n}{k}$ combinations of length $k$; recursion depth is $k$ |
| **Combination Sum** | **$O(n^{T/M + 1})$** | **$O(T/M)$** | $T$ = target sum, $M$ = smallest candidate value (max tree depth) |
| **N-Queens ($N \times N$ Board)** | **$O(N!)$** | **$O(N)$** | At most $N$ choices in row 0, $N - 1$ in row 1, $N - 2$ in row 2, etc. |
| **Word Search ($R \times C$ Grid)** | **$O(R \cdot C \cdot 3^L)$** | **$O(L)$** | Start from $R \cdot C$ cells; up to $3$ unvisited neighbors per step of length $L$ |

## 5. Practical Python Implementations

### 1. Subsets II (Handling Duplicate Input Elements)
```python
def subsets_with_duplicates(nums: list[int]) -> list[list[int]]:
    """
    Return all unique subsets of `nums` (which may contain duplicates).
    Sorting groups identical values so duplicate branches at the same depth are skipped.
    Time: O(n * 2^n) | Auxiliary Space: O(n)
    """
    nums.sort()
    results: list[list[int]] = []
    path: list[int] = []

    def backtrack(start: int) -> None:
        results.append(path.copy())
        for i in range(start, len(nums)):
            # Skip duplicate elements at the same decision level
            if i > start and nums[i] == nums[i - 1]:
                continue
            path.append(nums[i])
            backtrack(i + 1)
            path.pop()

    backtrack(0)
    return results
```

### 2. Permutations (Using a Boolean `used` Array)
```python
def generate_permutations(nums: list[int]) -> list[list[int]]:
    """
    Return all possible orderings of distinct integers in `nums`.
    Time: O(n * n!) | Auxiliary Space: O(n)
    """
    results: list[list[int]] = []
    path: list[int] = []
    used: list[bool] = [False] * len(nums)

    def backtrack() -> None:
        if len(path) == len(nums):
            results.append(path.copy())
            return

        for i, num in enumerate(nums):
            if used[i]:
                continue
            used[i] = True
            path.append(num)
            backtrack()
            path.pop()
            used[i] = False

    backtrack()
    return results
```

### 3. Combination Sum (With Early Sorted Pruning)
```python
def combination_sum(candidates: list[int], target: int) -> list[list[int]]:
    """
    Return all unique combinations of `candidates` (with unlimited reuse)
    whose elements sum to `target`.
    Time: O(n^(T/M + 1)) | Auxiliary Space: O(T/M)
    """
    candidates.sort()
    results: list[list[int]] = []
    path: list[int] = []

    def backtrack(start: int, remaining: int) -> None:
        if remaining == 0:
            results.append(path.copy())
            return

        for i in range(start, len(candidates)):
            val = candidates[i]
            # Because `candidates` is sorted, all subsequent values also exceed `remaining`
            if val > remaining:
                break
            path.append(val)
            backtrack(i, remaining - val)  # Pass `i` (not `i + 1`) because reuse is allowed
            path.pop()

    backtrack(0, target)
    return results
```

### 4. N-Queens Solver (Using $O(1)$ Diagonal Sets)
```python
def solve_n_queens(n: int) -> list[list[str]]:
    """
    Return all distinct solutions to placing `n` non-attacking queens on an n x n board.
    Uses hash sets for columns, positive diagonals (r + c), and negative diagonals (r - c).
    Time: O(N!) | Auxiliary Space: O(N)
    """
    solutions: list[list[str]] = []
    queen_cols: list[int] = []
    cols: set[int] = set()
    pos_diags: set[int] = set()  # r + c is constant along '/' diagonals
    neg_diags: set[int] = set()  # r - c is constant along '\' diagonals

    def backtrack(row: int) -> None:
        if row == n:
            board = [
                "." * col + "Q" + "." * (n - col - 1)
                for col in queen_cols
            ]
            solutions.append(board)
            return

        for col in range(n):
            if col in cols or (row + col) in pos_diags or (row - col) in neg_diags:
                continue

            # Choose
            cols.add(col)
            pos_diags.add(row + col)
            neg_diags.add(row - col)
            queen_cols.append(col)

            # Explore
            backtrack(row + 1)

            # Unchoose
            queen_cols.pop()
            neg_diags.remove(row - col)
            pos_diags.remove(row + col)
            cols.remove(col)

    backtrack(0)
    return solutions


if __name__ == "__main__":
    print("Subsets of [1, 2, 2]:  ", subsets_with_duplicates([1, 2, 2]))
    print("Permutations [1, 2, 3]:", generate_permutations([1, 2, 3]))
    print("Combination sum = 7:   ", combination_sum([2, 3, 6, 7], target=7))
    print("4-Queens solution count:", len(solve_n_queens(4)))
```

## 6. Common Pitfalls and Best Practices

1. **Appending `path` Directly Instead of `path.copy()` (`results.append(path)`):**
   Because `path` is a single mutable list modified throughout recursion, `results.append(path)` stores multiple references to the same list—resulting in `[[], [], ...]` once backtracking finishes. Always append **`path.copy()`** (or `list(path)`).
2. **Forgetting to Undo State Mutations on Backtrack:**
   Every mutation made before the recursive call (`path.append`, `used[i] = True`, `board[r][c] = "#"`) must be symmetrically undone immediately after the recursive call returns. Missing an undo step corrupts all subsequent sibling branches.
3. **Validating Constraints at Leaf Nodes Instead of Pruning Early:**
   Checking `is_valid(path)` only when `len(path) == n` turns backtracking into brute-force DFS. Always check constraints **before** recursing so invalid partial states are discarded immediately.
4. **Skipping Duplicates Without Sorting First:**
   The duplicate-skipping check `if i > start and nums[i] == nums[i - 1]: continue` relies on identical values being adjacent. Always call **`nums.sort()`** before starting recursion whenever the input may contain duplicates.
5. **Confusing `i + 1` with `i` in Recursive Calls:**
   * Pass **`i + 1`** when each element may be used **at most once** (Subsets, Combinations).
   * Pass **`i`** when an element may be reused **unlimited times** (Combination Sum); passing `i` when `remaining` does not strictly decrease causes infinite recursion (`RecursionError`).

## 7. Quick Reference

| Concept / Rule | Key Detail |
| :--- | :--- |
| **Core Template** | `choose(x)` $\to$ `backtrack(next_state)` $\to$ `unchoose(x)` |
| **Snapshot Rule** | Always record **`path.copy()`** at valid states—never append the mutable `path` reference |
| **Subsets vs. Permutations** | Subsets advance a `start` index (`i + 1`); Permutations scan `0 .. n - 1` with a `used` set/array |
| **Duplicate Avoidance** | Sort input first, then skip `nums[i] == nums[i - 1]` at the same recursion depth (`i > start`) |
| **Early Pruning** | Reject invalid choices before recursing; break early on sorted arrays when `val > remaining` |
| **Complexity Profile** | Exponential / Factorial time ($O(n \cdot 2^n)$ or $O(n \cdot n!)$); **$O(\text{depth})$** auxiliary stack space |
