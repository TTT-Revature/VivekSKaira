# Hash Tables and Hash Functions

## 1. Overview
A **hash table** (also called a **hash map**) is an associative data structure that maps **keys** to **values** for **$O(1)$ average-case** lookup, insertion, and deletion. Instead of searching sequentially ($O(n)$) or traversing tree branches ($O(\log n)$), a hash table uses a **hash function** to transform each key directly into an array index (**bucket**).

* **Core Architecture:**
  $$\text{Key} \xrightarrow{\text{hash}(k)} \text{Integer Hash Code} \xrightarrow{\text{compression } (\bmod\ m)} \text{Bucket Index } [0 \dots m - 1]$$
* **Why Hash Tables Dominate in Practice:**
  * **Constant-Time Average Operations:** Membership checks (`key in d`), reads (`d[key]`), writes (`d[key] = val`), and deletions (`del d[key]`) execute in $\Theta(1)$ expected time.
  * **Backbone of Modern Languages:** Python's built-in **`dict`** and **`set`** are implemented as compact open-addressing hash tables in CPython.

---

## 2. Hash Functions: Design and Properties
A **hash function** $h(k)$ maps an arbitrary-size key $k$ to a fixed-width integer hash code, which is then compressed into a valid table index in $[0, m - 1]$ where $m$ is the number of buckets.

### 1. Properties of a Good Hash Function
1. **Deterministic:** Equal keys must **always** produce the exact same hash value within the same program execution (`k1 == k2` $\implies$ `hash(k1) == hash(k2)`).
2. **Uniform Distribution:** Keys should spread evenly across all $m$ buckets to minimize collisions.
3. **Fast Computation:** Hashing a key of fixed size takes $O(1)$ time (and $O(L)$ for a string/byte sequence of length $L$).
4. **Avalanche Effect:** Changing a single bit or character in the input key (e.g., `"user1"` vs. `"user2"`) should produce a completely different hash code.

### 2. Index Compression Methods
Once an integer hash code $H = \text{hash}(k)$ is computed, it is mapped to a bucket index in $[0, m - 1]$:
* **Division Method (`H % m`):** Uses modulo arithmetic; works best when table size $m$ is a **prime number** not close to a power of $2$, reducing patterns in low-order bits.
* **Bitwise Masking (`H & (m - 1)`):** When $m = 2^p$ is a power of $2$, bitwise AND replaces expensive integer division with a single CPU cycle—used internally by CPython (`hash(key) & mask`).

### 3. Hashability and Security in Python
* **Python's Hashability Contract:** An object is **hashable** only if its hash value never changes during its lifetime and it implements both `__hash__()` and `__eq__()` consistently. Immutable built-ins (`int`, `float`, `str`, `bytes`, `tuple` of hashables) are hashable, while mutable containers (`list`, `dict`, `set`) raise `TypeError: unhashable type`.
* **Salted SipHash Defense:** To prevent **hash-flooding Denial-of-Service (DoS) attacks** (where crafted keys intentionally collide to degrade $O(1)$ lookups into $O(n)$), Python hashes `str` and `bytes` using **SipHash** seeded with a random per-process secret salt at interpreter startup.

---

## 3. Collision Resolution Strategies
Because the space of possible keys is vastly larger than the number of table buckets $m$ (the **Pigeonhole Principle**), two distinct keys can map to the same bucket index—a **hash collision**.

### 1. Separate Chaining (Closed Addressing)
Each bucket $i \in [0, m - 1]$ stores a pointer to an auxiliary bucket chain (typically a linked list or small dynamic array) containing all `(key, value)` pairs that hashed to index $i$.

```text
Buckets          Colliding Entries (Linked Chains)
+-----+
|  0  | ---> [ ("alice", 92) ] ---> [ ("dave", 88) ] ---> None
+-----+
|  1  | ---> None
+-----+
|  2  | ---> [ ("bob", 79) ] ---> None
+-----+
|  3  | ---> [ ("carol", 95) ] ---> [ ("erin", 84) ] ---> None
+-----+
```

### 2. Open Addressing (Closed Hashing)
All `(key, value)` entries are stored **directly inside the table array itself** with no external linked-list nodes. When a collision occurs at initial slot $h_0$, the table follows a deterministic **probe sequence** $h_0, h_1, h_2, \dots$ until it finds either the matching key or an empty slot:

* **Linear Probing:** Checks consecutive slots $h_i = (h(k) + i) \bmod m$. Delivers superior CPU cache locality, but suffers from **primary clustering** (long contiguous runs of occupied slots).
* **Quadratic Probing:** Uses quadratic steps $h_i = (h(k) + c_1 i + c_2 i^2) \bmod m$ to break up contiguous runs, though keys with identical initial hashes still share the same probe path (**secondary clustering**).
* **Double Hashing:** Uses a second independent hash function for step size: $h_i = (h_1(k) + i \cdot h_2(k)) \bmod m$.
* **CPython Perturbation Probing & Tombstones:** CPython's `dict` uses a compact split-array layout with perturbation-based open addressing (folding higher hash bits into the probe step) and marks deleted index slots with a **`DUMMY` tombstone** so probe chains for subsequent keys remain unbroken.

### Separate Chaining vs. Open Addressing

| Dimension | Separate Chaining | Open Addressing |
| :--- | :--- | :--- |
| **Entry Storage** | External chains (linked lists / buckets) per slot | Stored directly inside the contiguous table array |
| **Load Factor ($\alpha = n / m$)** | Can exceed $1.0$ (graceful degradation) | Must stay strictly $< 1.0$ (CPython resizes at $\alpha > 2/3$) |
| **Deletion Complexity** | Simple node unlink; leaves no residue | Requires `DUMMY` tombstones to preserve probe sequences |
| **Memory & Cache Locality** | Extra pointer overhead per node; scattered heap reads | Zero node pointers; high cache locality on short probes |

## 4. Load Factor, Rehashing, and Complexity Analysis
The **load factor** measures how full a hash table is:
$$\alpha = \frac{n}{m} = \frac{\text{Number of Stored Entries}}{\text{Total Number of Buckets}}$$

* **Dynamic Resizing (Rehashing):**
  When $\alpha$ crosses a threshold (e.g., $\alpha > 0.75$ for chaining or $\alpha > \frac{2}{3}$ in Python `dict`), the table allocates a larger bucket array (typically $2\times$ size) and reinserts all active entries. Although a single resize takes $\Theta(n)$ time, geometric growth amortizes insertion cost to **$O(1)$**.

| Operation | Best Case | Average Case (with resizing) | Worst Case (all keys collide) | Auxiliary Space |
| :--- | :--- | :--- | :--- | :--- |
| **Search (`get` / `in`)** | $\Omega(1)$ | **$\Theta(1)$** | $O(n)$ | $O(1)$ |
| **Insert (`set`)** | $\Omega(1)$ | **$\Theta(1)$ amortized** | $O(n)$ | $O(1)$ amortized |
| **Delete (`del` / `pop`)** | $\Omega(1)$ | **$\Theta(1)$** | $O(n)$ | $O(1)$ |
| **Space Complexity** | — | **$\Theta(n)$** | $\Theta(n)$ | $\Theta(n)$ |

## 5. Practical Python Implementations

### 1. Hash Table Using Separate Chaining
```python
from collections.abc import Hashable, Iterator
from typing import Generic, TypeVar

K = TypeVar("K", bound=Hashable)
V = TypeVar("V")


class ChainedHashTable(Generic[K, V]):
    """Hash table resolving collisions via separate chaining with automatic resizing."""

    _MAX_LOAD_FACTOR = 0.75

    def __init__(self, initial_capacity: int = 8) -> None:
        if initial_capacity <= 0:
            raise ValueError("Capacity must be positive")
        self._capacity: int = initial_capacity
        self._buckets: list[list[tuple[K, V]]] = [[] for _ in range(self._capacity)]
        self._size: int = 0

    def _bucket_index(self, key: K) -> int:
        return hash(key) % self._capacity

    def _resize(self, new_capacity: int) -> None:
        old_buckets = self._buckets
        self._capacity = new_capacity
        self._buckets = [[] for _ in range(self._capacity)]
        self._size = 0

        for bucket in old_buckets:
            for key, value in bucket:
                self[key] = value

    def __setitem__(self, key: K, value: V) -> None:
        """Insert or update a key-value pair: O(1) amortized time."""
        if (self._size + 1) / self._capacity > self._MAX_LOAD_FACTOR:
            self._resize(self._capacity * 2)

        idx = self._bucket_index(key)
        bucket = self._buckets[idx]

        for i, (existing_key, _) in enumerate(bucket):
            if existing_key == key:
                bucket[i] = (key, value)
                return

        bucket.append((key, value))
        self._size += 1

    def __getitem__(self, key: K) -> V:
        """Retrieve value associated with `key`: O(1) average time."""
        idx = self._bucket_index(key)
        for existing_key, value in self._buckets[idx]:
            if existing_key == key:
                return value
        raise KeyError(key)

    def __delitem__(self, key: K) -> None:
        """Delete `key` from the table: O(1) average time."""
        idx = self._bucket_index(key)
        bucket = self._buckets[idx]
        for i, (existing_key, _) in enumerate(bucket):
            if existing_key == key:
                bucket.pop(i)
                self._size -= 1
                return
        raise KeyError(key)

    def __contains__(self, key: object) -> bool:
        try:
            self[key]  # type: ignore[index]
            return True
        except (KeyError, TypeError):
            return False

    def __len__(self) -> int:
        return self._size

    def __iter__(self) -> Iterator[K]:
        for bucket in self._buckets:
            for key, _ in bucket:
                yield key
```

### 2. Hash Table Using Open Addressing (Linear Probing + Tombstones)
```python
class _DeletedSentinel:
    """Marker indicating a previously occupied slot whose probe chain must stay intact."""


_TOMBSTONE = _DeletedSentinel()


class OpenAddressingHashTable(Generic[K, V]):
    """Hash table resolving collisions via linear probing and tombstone deletion."""

    _MAX_LOAD_FACTOR = 0.65

    def __init__(self, initial_capacity: int = 8) -> None:
        self._capacity: int = initial_capacity
        self._slots: list[tuple[K, V] | _DeletedSentinel | None] = [None] * self._capacity
        self._size: int = 0

    def _find_slot(self, key: K) -> tuple[bool, int]:
        """
        Return (True, existing_index) if `key` is found,
        or (False, first_available_insert_index) otherwise.
        """
        start = hash(key) % self._capacity
        first_tombstone: int | None = None

        for step in range(self._capacity):
            idx = (start + step) % self._capacity
            entry = self._slots[idx]

            if entry is None:
                return False, first_tombstone if first_tombstone is not None else idx
            if isinstance(entry, _DeletedSentinel):
                if first_tombstone is None:
                    first_tombstone = idx
            elif entry[0] == key:
                return True, idx

        if first_tombstone is not None:
            return False, first_tombstone
        raise RuntimeError("Hash table is full")

    def _resize(self, new_capacity: int) -> None:
        old_slots = self._slots
        self._capacity = new_capacity
        self._slots = [None] * self._capacity
        self._size = 0

        for entry in old_slots:
            if entry is not None and not isinstance(entry, _DeletedSentinel):
                self[entry[0]] = entry[1]

    def __setitem__(self, key: K, value: V) -> None:
        if (self._size + 1) / self._capacity > self._MAX_LOAD_FACTOR:
            self._resize(self._capacity * 2)

        found, idx = self._find_slot(key)
        self._slots[idx] = (key, value)
        if not found:
            self._size += 1

    def __getitem__(self, key: K) -> V:
        found, idx = self._find_slot(key)
        if not found:
            raise KeyError(key)
        entry = self._slots[idx]
        assert isinstance(entry, tuple)
        return entry[1]

    def __delitem__(self, key: K) -> None:
        found, idx = self._find_slot(key)
        if not found:
            raise KeyError(key)
        self._slots[idx] = _TOMBSTONE
        self._size -= 1

    def __len__(self) -> int:
        return self._size


if __name__ == "__main__":
    chained = ChainedHashTable[str, int]()
    chained["alpha"] = 10
    chained["beta"] = 20
    print("Chained lookup 'alpha':", chained["alpha"], "| Count:", len(chained))

    open_table = OpenAddressingHashTable[str, int]()
    open_table["k1"] = 100
    open_table["k2"] = 200
    del open_table["k1"]  # Places tombstone so 'k2' remains reachable on probe path
    print("Open addressing 'k2' after deleting 'k1':", open_table["k2"])
```

## 6. Common Pitfalls and Best Practices

1. **Breaking the `__hash__` and `__eq__` Contract in Custom Classes:**
   If a custom class defines `__eq__` without defining `__hash__`, Python automatically sets `__hash__ = None` (making instances unhashable). If you implement both, ensure that whenever `a == b` is `True`, `hash(a) == hash(b)` is also `True`—or use **`@dataclass(frozen=True)`**, which generates both safely.
2. **Mutating an Object Used as a Dictionary Key:**
   If a key's hash changes after insertion, future lookups hash to a different bucket and fail to locate the entry even though it remains in the table. Never mutate fields used in `__hash__` while an object is stored in a `dict` or `set`.
3. **Setting Deleted Slots to `None` in Open Addressing:**
   Clearing a deleted slot directly to `None` prematurely terminates probe chains for keys inserted later that collided with the deleted key. Always mark deleted slots with a **`TOMBSTONE` (`DUMMY`)** sentinel and purge tombstones during table resizing.
4. **Persisting Python's `hash()` Values Across Runs or Networks:**
   Because Python seeds string and byte hashes with a random salt on every process launch, `hash("session_id")` produces different integers across runs. Use **`hashlib.sha256`** or **`hashlib.blake2b`** whenever deterministic hashes are needed across processes or databases.
5. **Using a `list` Instead of a `set` / `dict` for Repeated Membership Queries:**
   Checking `x in my_list` inside a loop takes $O(n)$ per check ($O(n^2)$ total), whereas converting `my_list` to a `set` reduces each membership check to **$O(1)$ average time**.

## 7. Quick Reference

| Concept / Metric | Key Detail |
| :--- | :--- |
| **Core Purpose** | Maps keys to values via a hash function for **$O(1)$ average** lookup, insert, and delete |
| **Hash Function Requirements** | Deterministic, uniform distribution, fast ($O(1)$), avalanche effect |
| **Python Built-Ins** | `dict` (key-value map) and `set` (keys-only hash table) |
| **CPython Internals** | Compact open-addressing table with perturbation probing, `DUMMY` tombstones, and $\alpha = 2/3$ resize threshold |
| **Separate Chaining** | Buckets store linked lists/chains; tolerates $\alpha > 1.0$; simple deletion |
| **Open Addressing** | All entries live in the main array; probes via linear, quadratic, or double hashing; requires tombstones |
| **Time / Space Complexity** | Average: **$\Theta(1)$** time \| Worst (all collide): **$O(n)$** time \| Space: **$\Theta(n)$** |
