# Memoization and Tabulation

## 1. Overview
**Memoization** and **Tabulation** are the two implementation strategies used in **Dynamic Programming (DP)** to eliminate redundant computation when solving problems with **overlapping subproblems** and **optimal substructure**. Both techniques store intermediate subproblem results so each unique state is solved only once, reducing exponential recursive runtimes down to polynomial time.

* **Memoization (Top-Down DP):** Starts from the original target problem and recursively breaks it down into smaller subproblems. Before computing a subproblem, it checks a cache (typically a hash map or array); on a cache hit, it returns the stored result immediately, and on a miss, it computes, caches, and returns the result.
* **Tabulation (Bottom-Up DP):** Starts from the smallest base cases and iteratively fills a table (`dp` array or matrix) in topological dependency order until reaching the target state—completely avoiding recursion and call-stack overhead.

### Top-Down vs. Bottom-Up Execution Architecture
```text
TOP-DOWN MEMOIZATION (Demand-Driven)          BOTTOM-UP TABULATION (Dependency-Driven)

         [ Target: solve(n) ]                            [ Base Cases: dp[0], dp[1] ]
                  |                                                   |
         Check Cache(n) ---> [ HIT ] -> Return                        v
                  |                                      Loop i = 2 .. n (Topological Order)
               [ MISS ]                                               |
                  |                                                   v
         Recurse: solve(n-1), solve(n-2)                 Compute dp[i] from earlier cells
                  |                                                   |
                  v                                                   v
         Store Result in Cache                           [ Target Result: dp[n] ]
```

## 2. Memoization vs. Tabulation Comparison

| Dimension | Memoization (Top-Down) | Tabulation (Bottom-Up) |
| :--- | :--- | :--- |
| **Direction of Execution** | Root problem $\to$ Base cases (recursive) | Base cases $\to$ Root problem (iterative) |
| **Storage Structure** | Hash map (`dict`, `@functools.cache`) or sentinel-initialized array | 1D or multi-dimensional array (`list`) |
| **Subproblems Evaluated** | **Lazy:** Computes only subproblems reachable from the target state | **Eager:** Computes every state in the table range `0 .. n` |
| **Call-Stack Overhead** | High; incurs function-call frames and risks `RecursionError` ($n \ge 1000$) | **None;** runs in a flat loop with $O(1)$ stack frames |
| **CPU Cache Locality** | Lower (pointer chasing in hash maps and recursive stack jumps) | **Higher** (sequential memory writes in contiguous arrays) |
| **Dependency Ordering** | Handled automatically by the recursion tree | Must be determined manually by the programmer |
| **Space Optimization** | Difficult (must retain cached states for arbitrary lookups) | **Straightforward** (can collapse rows/states into $O(1)$ or $O(n)$ rolling variables) |

### When to Choose Which Strategy
* **Choose Memoization when:**
  * Only a sparse subset of states in the state space is actually reachable (for example, large jumps or irregular state transitions).
  * The recursive recurrence is natural, while the exact topological iteration order for a table is complex (such as tree DP or DAG DP).
  * Input depth is bounded safely below Python's recursion limit (`sys.getrecursionlimit()`, default `1000`).
* **Choose Tabulation when:**
  * Nearly all subproblems in `0 .. n` must be visited anyway (dense state space).
  * Input sizes are large ($n \ge 1000$), where recursion would trigger `RecursionError`.
  * Maximum execution speed and minimal memory footprint (rolling-variable space optimization) are required.

## 3. Step-by-Step Visual Traces

### 1. Top-Down Memoization Trace (`fib(5)`)
We trace `fib(5)` using a dictionary `memo = {0: 0, 1: 1}`:

```text
Call Stack & Cache Trace:
1. fib(5) -> miss -> calls fib(4) + fib(3)
2.   fib(4) -> miss -> calls fib(3) + fib(2)
3.     fib(3) -> miss -> calls fib(2) + fib(1)
4.       fib(2) -> miss -> calls fib(1) + fib(0)
5.         fib(1) -> [HIT] returns 1
6.         fib(0) -> [HIT] returns 0
7.       store memo[2] = 1, returns 1
8.       fib(1) -> [HIT] returns 1
9.     store memo[3] = 2, returns 2
10.    fib(2) -> [HIT] returns 1          (entire fib(2) subtree skipped!)
11.  store memo[4] = 3, returns 3
12.  fib(3) -> [HIT] returns 2            (entire fib(3) subtree skipped!)
13. store memo[5] = 5, returns 5

Final Cache: {0: 0, 1: 1, 2: 1, 3: 2, 4: 3, 5: 5}
```

### 2. Bottom-Up Tabulation Trace (`fib(5)`)
Instead of recursing downward, tabulation populates `dp[0 .. 5]` left-to-right:

```text
Index i:        0      1      2      3      4      5
------------------------------------------------------
Base Cases:   [ 0,     1,     _,     _,     _,     _ ]
Step i = 2:   [ 0,     1,     1,     _,     _,     _ ]   dp[2] = dp[1] + dp[0] = 1 + 0
Step i = 3:   [ 0,     1,     1,     2,     _,     _ ]   dp[3] = dp[2] + dp[1] = 1 + 1
Step i = 4:   [ 0,     1,     1,     2,     3,     _ ]   dp[4] = dp[3] + dp[2] = 2 + 1
Step i = 5:   [ 0,     1,     1,     2,     3,     5 ]   dp[5] = dp[4] + dp[3] = 3 + 2

Rolling Variable Compression (O(1) Space):
  prev2 = 0, prev1 = 1
  i = 2 -> curr = 1  (prev2 = 1, prev1 = 1)
  i = 3 -> curr = 2  (prev2 = 1, prev1 = 2)
  i = 4 -> curr = 3  (prev2 = 2, prev1 = 3)
  i = 5 -> curr = 5  (prev2 = 3, prev1 = 5) -> Answer: 5
```

### 3. Converting Memoization to Tabulation (4-Step Checklist)
1. **Identify State Parameters:** Count the changing arguments in the recursive function (e.g., `(i, w)` $\implies$ 2D table `dp[i][w]`).
2. **Allocate Table Dimensions:** Size each dimension to cover all valid parameter bounds (including base-case index `0` or `n`).
3. **Seed Base Cases:** Copy the recursive base-case return values directly into the boundary cells of the table.
4. **Reverse the Loop Direction:** If the recursion calls `f(i - 1)` from `f(i)`, iterate `i` **upward** (`1 -> n`). If the recursion calls `f(i + 1)` from `f(i)`, iterate `i` **downward** (`n - 1 -> 0`).

## 4. Time and Space Complexity Analysis

For any Dynamic Programming algorithm (both memoized and tabulated), the total time complexity is governed by:

$$\text{Total Time} = (\text{Number of Unique States}) \times (\text{Transition Work per State})$$

| Problem | Naive Recursion | Memoization (Top-Down) | Tabulation (Bottom-Up) | Space-Optimized Tabulation |
| :--- | :--- | :--- | :--- | :--- |
| **Fibonacci ($n$)** | $O(2^n)$ | $\Theta(n)$ time \| $\Theta(n)$ space | $\Theta(n)$ time \| $\Theta(n)$ space | **$\Theta(n)$ time \| $O(1)$ space** |
| **Climbing Stairs ($n$)** | $O(2^n)$ | $\Theta(n)$ time \| $\Theta(n)$ space | $\Theta(n)$ time \| $\Theta(n)$ space | **$\Theta(n)$ time \| $O(1)$ space** |
| **Coin Change (Amount $A$, $C$ coins)** | $O(C^A)$ | $\Theta(A \cdot C)$ time \| $\Theta(A)$ space | **$\Theta(A \cdot C)$ time \| $\Theta(A)$ space** | Cannot reduce below $\Theta(A)$ |
| **Longest Common Subsequence ($m, n$)** | $O(2^{m+n})$ | $\Theta(m \cdot n)$ time \| $\Theta(m \cdot n)$ space | $\Theta(m \cdot n)$ time \| $\Theta(m \cdot n)$ space | **$\Theta(m \cdot n)$ time \| $\Theta(\min(m, n))$ space** |
| **0/1 Knapsack ($N$ items, Cap $W$)** | $O(2^N)$ | $\Theta(N \cdot W)$ time \| $\Theta(N \cdot W)$ space | $\Theta(N \cdot W)$ time \| $\Theta(N \cdot W)$ space | **$\Theta(N \cdot W)$ time \| $\Theta(W)$ space** |

## 5. Practical Python Implementations

### 1. Manual Dictionary Memoization vs. `@functools.cache` (`Fibonacci`)
```python
from functools import cache


def fib_manual_memo(n: int, memo: dict[int, int] | None = None) -> int:
    """
    Top-down DP using an explicit dictionary cache.
    Time: Theta(n) | Auxiliary Space: Theta(n) (dictionary + recursion stack)
    """
    if n < 0:
        raise ValueError("n must be non-negative")
    if memo is None:
        memo = {0: 0, 1: 1}
    if n in memo:
        return memo[n]

    memo[n] = fib_manual_memo(n - 1, memo) + fib_manual_memo(n - 2, memo)
    return memo[n]


@cache
def fib_decorator_memo(n: int) -> int:
    """
    Top-down DP using Python's built-in C-backed @functools.cache decorator.
    Time: Theta(n) | Auxiliary Space: Theta(n)
    """
    if n <= 1:
        return n
    return fib_decorator_memo(n - 1) + fib_decorator_memo(n - 2)


def fib_tabulated(n: int) -> int:
    """
    Bottom-up DP building the full 1D table iteratively (immune to RecursionError).
    Time: Theta(n) | Auxiliary Space: Theta(n)
    """
    if n < 0:
        raise ValueError("n must be non-negative")
    if n <= 1:
        return n

    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]


def fib_space_optimized(n: int) -> int:
    """
    Space-optimized bottom-up DP using two rolling variables.
    Time: Theta(n) | Auxiliary Space: O(1)
    """
    if n < 0:
        raise ValueError("n must be non-negative")
    if n <= 1:
        return n

    prev2, prev1 = 0, 1
    for _ in range(2, n + 1):
        prev2, prev1 = prev1, prev2 + prev1
    return prev1
```

### 2. Side-by-Side 2-Parameter Comparison: Longest Common Subsequence (`LCS`)
Comparing how the exact same recurrence translates between **Top-Down Memoization** and **Bottom-Up Tabulation**:

```python
def lcs_memoized(text1: str, text2: str) -> int:
    """
    Top-down memoization over index pair (i, j) representing suffixes text1[i:] and text2[j:].
    Time: Theta(m * n) | Auxiliary Space: Theta(m * n)
    """
    m, n = len(text1), len(text2)

    @cache
    def solve(i: int, j: int) -> int:
        if i == m or j == n:
            return 0
        if text1[i] == text2[j]:
            return 1 + solve(i + 1, j + 1)
        return max(solve(i + 1, j), solve(i, j + 1))

    return solve(0, 0)


def lcs_tabulated(text1: str, text2: str) -> int:
    """
    Bottom-up tabulation filling dp[m .. 0][n .. 0] in reverse index order
    to match the suffix recurrence of `lcs_memoized`.
    Time: Theta(m * n) | Auxiliary Space: Theta(m * n)
    """
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(m - 1, -1, -1):
        for j in range(n - 1, -1, -1):
            if text1[i] == text2[j]:
                dp[i][j] = 1 + dp[i + 1][j + 1]
            else:
                dp[i][j] = max(dp[i + 1][j], dp[i][j + 1])

    return dp[0][0]


if __name__ == "__main__":
    print("fib(10) manual memo:    ", fib_manual_memo(10))
    print("fib(10) @cache memo:    ", fib_decorator_memo(10))
    print("fib(10) tabulated:      ", fib_tabulated(10))
    print("fib(10) space-optimized:", fib_space_optimized(10))

    print("LCS memoized ('abcde', 'ace'): ", lcs_memoized("abcde", "ace"))
    print("LCS tabulated ('abcde', 'ace'):", lcs_tabulated("abcde", "ace"))
```

## 6. Common Pitfalls and Best Practices

1. **Hitting Python's Recursion Limit in Top-Down Memoization (`RecursionError`):**
   CPython limits call-stack depth to `1000` frames by default. Calling `fib_decorator_memo(2000)` on a cold cache raises `RecursionError`. For inputs where recursion depth can exceed a few hundred steps, use iterative **Tabulation** instead.
2. **Passing Unhashable Arguments (`list`, `dict`, `set`) to `@functools.cache`:**
   `@cache` and `@lru_cache` store arguments as dictionary keys, raising `TypeError: unhashable type` if given a `list`. Always parameterize memoized helpers by hashable **integer indices** (`i`, `j`) or immutable **`tuple`** values.
3. **Stale Cache Bugs When Using Global `@cache` Over Mutating External Variables:**
   If a module-level `@cache` function reads an external variable or input list (e.g., `nums[i]`) that changes between function calls, subsequent calls return stale cached answers from earlier inputs. Define the `@cache` helper **nested inside** the outer function (as in `lcs_memoized`) or call **`fn.cache_clear()`** between runs.
4. **Using `None` as a Missing-Entry Sentinel When `None` Is a Valid Return Value:**
   If a memoized function can legitimately return `None` or `0`, checking `if memo[state]:` or `if memo[state] is not None:` causes cache misses on valid cached results. Check membership explicitly with **`if state in memo:`** or use a dedicated sentinel object (`_UNSET = object()`).
5. **Wrong Loop Direction When Translating Recursion to Tabulation:**
   In Tabulation, every cell read on the right-hand side of the assignment must already be finalized. If `dp[i]` reads `dp[i + 1]`, iterating `i` from `0` to `n - 1` reads uninitialized zeros—iterate `i` **downward** (`range(n - 1, -1, -1)`) instead.

## 7. Quick Reference

| Concept / Rule | Key Detail |
| :--- | :--- |
| **Memoization** | Top-down recursive DP + cache (`@functools.cache` or `dict`); solves only reachable states |
| **Tabulation** | Bottom-up iterative DP + `dp` table; solves all states in topological order; no stack limit |
| **Time Complexity Formula** | $\text{Unique States} \times \text{Work per State}$ (identical asymptotic time for both methods) |
| **Python Caching Decorators** | `@functools.cache` (unbounded) or `@functools.lru_cache(maxsize=None)` |
| **Space Optimization** | Available primarily in **Tabulation** by keeping only the last $1$–$2$ states or rows |
| **Conversion Rule** | Function parameters $\to$ table dimensions; base cases $\to$ boundary cells; recursion $\to$ loop |
