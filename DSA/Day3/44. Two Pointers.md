# Two Pointers

## 1. Overview
The **Two Pointers** technique is an algorithmic pattern that uses two index variables (or node references) to traverse a linear data structure—such as an array, string, or linked list—in a coordinated manner. By maintaining monotonic invariants between the two pointers, it eliminates redundant inner-loop scans and reduces naive **$O(n^2)$** brute-force solutions to **$\Theta(n)$ single-pass** runtimes using **$O(1)$ auxiliary space**.

### Three Core Pointer Geometries
```text
1. Opposite-Direction (Converging):
   [ x0,  x1,  x2,  x3,  x4,  x5 ]
     ^                        ^
    left --->            <--- right

2. Same-Direction (Fast & Slow / Read-Write):
   [ x0,  x1,  x2,  x3,  x4,  x5 ]
     ^         ^
    slow ---> fast --->

3. Parallel Two-Sequence:
   Sequence A: [ a0,  a1,  a2,  a3 ]   (pointer i --->)
   Sequence B: [ b0,  b1,  b2,  b3 ]   (pointer j --->)
```

* **When Two Pointers Applies:**
  * Searching for pairs or triplets satisfying a target sum or constraint in a **sorted** sequence.
  * Symmetry and boundary checks (palindromes, reversing arrays in-place, trapping rain water).
  * In-place array compaction and partitioning (removing duplicates, moving zeroes, Dutch National Flag).
  * Linked list structural queries (cycle detection, finding the middle node, finding the $k$-th node from the end).
  * Merging or comparing two sorted sequences.

## 2. The Three Two-Pointer Patterns

### 1. Opposite-Direction (Converging) Pointers
Two pointers start at opposite boundaries (`left = 0`, `right = n - 1`) and move inward until they meet (`while left < right:`).
* **Decision Rule:** At each step, evaluate the pair `(arr[left], arr[right])`. Because the sequence is sorted (or bounded by height/distance), one pointer's extreme value can be safely eliminated in $O(1)$ time:
  * If `current_sum < target`, increment `left` to increase the sum.
  * If `current_sum > target`, decrement `right` to decrease the sum.
* **Classic Problems:** Two Sum II (Sorted Input), 3Sum, Valid Palindrome, Container With Most Water, Trapping Rain Water.

### 2. Same-Direction (Fast & Slow / Read-Write) Pointers
Both pointers start at the beginning of the sequence and advance forward in the same direction, separated by either a condition or a fixed speed ratio:
* **Read / Write Compaction (`read` and `write`):** `read` scans every element from `0` to `n - 1`, while `write` tracks the boundary of the valid compacted prefix. Whenever `arr[read]` satisfies the retention condition, it is copied to `arr[write]` and `write` advances.
* **Tortoise and Hare (`slow` and `fast`):** `slow` advances $1$ step per iteration while `fast` advances $2$ steps per iteration:
  * When `fast` reaches the end of a linked list, `slow` sits at the **exact midpoint**.
  * If the linked list contains a cycle, `fast` is mathematically guaranteed to lap and meet `slow` inside the cycle in $O(n)$ time.

### 3. Parallel (Two-Sequence) Pointers
Two independent pointers (`i = 0`, `j = 0`) traverse two separate sequences simultaneously (`while i < len(seq_a) and j < len(seq_b):`).
* **Decision Rule:** Compare `seq_a[i]` and `seq_b[j]`, advance whichever pointer belongs to the smaller (or matched) element, and handle any unconsumed tail once one sequence finishes.
* **Classic Problems:** Merging two sorted arrays/lists, sorted array intersection, verifying whether string $S$ is a subsequence of string $T$.

## 3. Step-by-Step Visual Traces

### 1. Converging Pointers: Sorted Two Sum (`nums = [2, 3, 6, 8, 11]`, `target = 14`)
```text
Initial: [ 2,  3,  6,  8, 11 ]   target = 14
           ^L              ^R

Step 1: nums[0] + nums[4] = 2 + 11 = 13 < 14  -> sum too small, advance L
        [ 2,  3,  6,  8, 11 ]
              ^L          ^R

Step 2: nums[1] + nums[4] = 3 + 11 = 14 == 14 -> MATCH! Return (1, 4)
```
Every step eliminates an entire row or column of the $n \times n$ pair matrix, guaranteeing at most $n - 1$ iterations.

### 2. Read / Write Pointers: Move Zeroes In-Place (`nums = [0, 1, 0, 3, 12]`)
`write` marks the next slot for a non-zero element; `read` scans left to right:

```text
Initial: [ 0,  1,  0,  3, 12 ]   write = 0

read = 0: nums[0] == 0 -> skip
read = 1: nums[1] == 1 != 0 -> swap(nums[0], nums[1]), write = 1
          [ 1,  0,  0,  3, 12 ]
                ^w  ^r

read = 2: nums[2] == 0 -> skip
read = 3: nums[3] == 3 != 0 -> swap(nums[1], nums[3]), write = 2
          [ 1,  3,  0,  0, 12 ]
                    ^w      ^r

read = 4: nums[4] == 12 != 0 -> swap(nums[2], nums[4]), write = 3
          [ 1,  3, 12,  0,  0 ]
                        ^w

Final Result: [ 1, 3, 12, 0, 0 ]
```

## 4. Time and Space Complexity Analysis
Assume $n$ is the length of the primary input sequence (and $m$ is the length of the second sequence in parallel scans):

| Problem / Pattern | Brute-Force Time | Two-Pointer Time | Two-Pointer Auxiliary Space | Precondition |
| :--- | :--- | :--- | :--- | :--- |
| **Two Sum (Sorted Array)** | $O(n^2)$ | **$\Theta(n)$** | **$O(1)$** | Input sorted in ascending order |
| **3Sum (Unique Triplets)** | $O(n^3)$ | **$\Theta(n^2)$** | $O(1)$ (excluding sort/output) | Sort input first ($\Theta(n \log n)$) |
| **Container With Most Water** | $O(n^2)$ | **$\Theta(n)$** | **$O(1)$** | Non-negative height array |
| **Move Zeroes / Remove Duplicates** | $O(n^2)$ (shifts) | **$\Theta(n)$** | **$O(1)$** | Sorted required for duplicate removal |
| **Linked List Cycle / Midpoint** | $O(n)$ time, $O(n)$ space | **$\Theta(n)$** | **$O(1)$** | Valid singly linked list |
| **Merge Two Sorted Arrays** | $O((n + m) \log(n + m))$ | **$\Theta(n + m)$** | $\Theta(n + m)$ (output array) | Both inputs sorted |
| **Is Subsequence (`S` in `T`)** | $O(n \cdot m)$ | **$O(n + m)$** | **$O(1)$** | Relative order preserved |

## 5. Practical Python Implementations

### 1. Opposite-Direction Pointers (Sorted Two Sum & Container With Most Water)
```python
def two_sum_sorted(nums: list[int], target: int) -> tuple[int, int] | None:
    """
    Find zero-based indices (left, right) in a sorted list whose values sum to `target`.
    Time: Theta(n) | Auxiliary Space: O(1)
    """
    left = 0
    right = len(nums) - 1

    while left < right:
        current_sum = nums[left] + nums[right]
        if current_sum == target:
            return left, right
        if current_sum < target:
            left += 1
        else:
            right -= 1

    return None


def max_water_area(heights: list[int]) -> int:
    """
    Compute the maximum water area formed by two vertical lines and the x-axis.
    Always advance the shorter wall, as moving the taller wall can never increase area.
    Time: Theta(n) | Auxiliary Space: O(1)
    """
    left = 0
    right = len(heights) - 1
    best_area = 0

    while left < right:
        width = right - left
        if heights[left] < heights[right]:
            best_area = max(best_area, heights[left] * width)
            left += 1
        else:
            best_area = max(best_area, heights[right] * width)
            right -= 1

    return best_area
```

### 2. Same-Direction Pointers (In-Place Compaction & Floyd's Cycle Detection)
```python
from dataclasses import dataclass


def move_zeroes_in_place(nums: list[int]) -> list[int]:
    """
    Move all zeroes to the end of `nums` in-place while preserving non-zero order.
    Time: Theta(n) | Auxiliary Space: O(1)
    """
    write = 0
    for read in range(len(nums)):
        if nums[read] != 0:
            if write != read:
                nums[write], nums[read] = nums[read], nums[write]
            write += 1
    return nums


@dataclass
class ListNode:
    val: int
    next: "ListNode | None" = None


def detect_cycle_start(head: ListNode | None) -> ListNode | None:
    """
    Floyd's Tortoise and Hare algorithm:
    1. Detect whether a cycle exists using 1x (`slow`) and 2x (`fast`) pointers.
    2. Reset one pointer to `head` and advance both 1x to locate the cycle entry node.
    Time: Theta(n) | Auxiliary Space: O(1)
    """
    slow = head
    fast = head

    while fast is not None and fast.next is not None:
        assert slow is not None
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            entry = head
            while entry is not slow:
                assert entry is not None and slow is not None
                entry = entry.next
                slow = slow.next
            return entry

    return None
```

### 3. Parallel Two-Sequence Pointers (`is_subsequence`)
```python
def is_subsequence(sub: str, text: str) -> bool:
    """
    Return True if all characters of `sub` appear in `text` in relative order.
    Time: O(len(text)) | Auxiliary Space: O(1)
    """
    sub_idx = 0
    text_idx = 0

    while sub_idx < len(sub) and text_idx < len(text):
        if sub[sub_idx] == text[text_idx]:
            sub_idx += 1
        text_idx += 1

    return sub_idx == len(sub)

    n1.next, n2.next, n3.next, n4.next = n2, n3, n4, n2
```

## 6. Common Pitfalls and Best Practices

1. **Applying Converging Pointers to an Unsorted Array:**
   Moving `left += 1` or `right -= 1` based on sum comparisons only works when the array is **sorted**. If the input is unsorted and you need original indices, use a **Hash Map** ($\Theta(n)$ time, $\Theta(n)$ space) instead of sorting (which alters indices).
2. **Confusing `while left < right:` with `while left <= right:`:**
   * Use **`while left < right:`** whenever the two pointers must refer to **two distinct elements** (such as pair sums, swapping ends, or container area). Using `<=` compares an element with itself when `left == right`.
   * Use **`while left <= right:`** in Binary Search or problems where a single middle element (`left == right`) must still be processed (such as squaring a sorted array into an output buffer).
3. **Forgetting to Advance Pointers Inside Every Branch:**
   In complex `if / elif / else` blocks (such as skipping duplicates in 3Sum), forgetting `left += 1` or `right -= 1` in one branch causes an infinite loop. Verify that `right - left` strictly decreases on every iteration.
4. **Null-Pointer Dereferencing in Linked-List Fast/Slow Pointers:**
   Always check **`while fast is not None and fast.next is not None:`** before accessing `fast.next.next`, because `fast` jumps two nodes at a time and can land on `None` on even-length lists.
5. **Confusing Two Pointers with Sliding Window:**
   While related, **Two Pointers** evaluates discrete pairs or partitions elements, whereas **Sliding Window** maintains a dynamic aggregate state (such as window sum or character frequency) over the entire contiguous subarray `arr[left : right + 1]`.

## 7. Quick Reference

| Variant | Initialization | Loop Condition | Typical Movement | Classic Use Cases |
| :--- | :--- | :--- | :--- | :--- |
| **Converging** | `left = 0`, `right = n - 1` | `while left < right:` | `left += 1` or `right -= 1` | Sorted Two Sum, 3Sum, Palindrome, Max Water |
| **Read / Write** | `write = 0`, `read = 0` | `for read in range(n):` | `write += 1` on valid item | Move Zeroes, Remove Duplicates, In-Place Filter |
| **Fast & Slow** | `slow = head`, `fast = head` | `while fast and fast.next:` | `slow = slow.next`, `fast = fast.next.next` | Cycle Detection, Linked List Midpoint |
| **Parallel** | `i = 0`, `j = 0` | `while i < n and j < m:` | `i += 1` and/or `j += 1` | Merge Sorted Lists, Subsequence Check, Intersection |
