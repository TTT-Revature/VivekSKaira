# Collision Handling

## 1. Overview
A **hash collision** occurs when two or more distinct keys map to the same bucket index in a hash table:

```text
key_1 = "alice"  --->  hash("alice") % 8  = 3  --+
                                                 +-->  COLLISION at Bucket 3
key_2 = "bob"    --->  hash("bob")   % 8  = 3  --+
```

### Why Collisions Are Mathematically Inevitable
1. **Pigeonhole Principle:** The universe of possible keys (strings, tuples, integers) is vastly larger than any fixed table capacity $m$, so multiple keys must share the same bucket index.
2. **Birthday Paradox:** Even with a perfectly uniform hash function over $m$ buckets, the probability of a collision exceeds $50\%$ after inserting roughly $\sqrt{m}$ keys (for example, in a table of $m = 365$ slots, a collision is more likely than not after just $23$ insertions).

Because collisions cannot be eliminated completely, every hash table relies on a **collision resolution strategy** to preserve **$O(1)$ average-case** lookup, insertion, and deletion.

---

## 2. Separate Chaining (Closed Addressing)
In **Separate Chaining**, the hash table is an array of $m$ bucket pointers. Every bucket $i \in [0, m - 1]$ references an independent secondary container (typically a singly linked list or dynamic array) holding all `(key, value)` pairs whose keys hashed to index $i$.

### Visual Memory Layout (`m = 5`)
```text
Bucket Array      Auxiliary Chains
+-------+
|   0   | ----->  [ ("k1", 10) ] ---> [ ("k6", 60) ] ---> None
+-------+
|   1   | ----->  None
+-------+
|   2   | ----->  [ ("k2", 20) ] ---> None
+-------+
|   3   | ----->  [ ("k3", 30) ] ---> [ ("k8", 80) ] ---> [ ("k9", 90) ] ---> None
+-------+
|   4   | ----->  [ ("k4", 40) ] ---> None
+-------+
```

### Operational Mechanics
* **Lookup (`get`):** Compute `idx = hash(key) % m`, then scan the chain at `buckets[idx]` comparing keys until a match is found or the chain ends.
* **Insertion (`put`):** Compute `idx = hash(key) % m`. Scan `buckets[idx]`; if `key` already exists, overwrite its value; otherwise append `(key, value)` to the chain.
* **Deletion (`delete`):** Locate `key` in `buckets[idx]` and unlink/remove the node directly—no tombstone markers are needed.
* **Balanced-Tree Fallback (Treeification):** Production implementations (such as Java's `HashMap`) convert a bucket's linked list into a self-balancing **Red-Black Tree** once chain length exceeds a threshold (e.g., $8$ nodes), bounding worst-case bucket lookup from $O(n)$ down to **$O(\log n)$**.

## 3. Open Addressing (Closed Hashing)
In **Open Addressing**, all `(key, value)` entries live **directly inside the main table array** with zero external linked-list pointers. When a key's home bucket $h_0$ is already occupied, the table computes a deterministic **probe sequence** $h_0, h_1, h_2, \dots, h_{m-1}$ until it finds the target key or an empty slot.

### 1. Linear Probing
Checks consecutive slots sequentially using a constant step size (typically $1$):

$$h_i(k) = (h(k) + i) \bmod m \quad \text{for } i = 0, 1, 2, \dots, m - 1$$

* **Advantage:** Best-in-class CPU cache locality because consecutive slots sit in the same cache line.
* **Drawback — Primary Clustering:** Occupied slots coalesce into long contiguous blocks. Any key hashing anywhere inside a cluster appends to the tail of that cluster, increasing average probe length as $\alpha$ approaches $1$.

### 2. Quadratic Probing
Increases the step offset quadratically to jump over contiguous blocks:

$$h_i(k) = (h(k) + c_1 i + c_2 i^2) \bmod m \quad \text{for } i = 0, 1, 2, \dots, m - 1$$

* **Advantage:** Eliminates primary clustering by scattering probes across distant slots.
* **Drawback — Secondary Clustering:** Two keys with the exact same initial hash $h(k_1) = h(k_2)$ still follow the exact same probe sequence.
* **Table Size Constraint:** To guarantee the probe sequence visits at least half the table without cycling prematurely, $m$ is typically chosen as a prime number (with $c_1 = 0, c_2 = 1$) or a power of $2$ (with $c_1 = c_2 = \frac{1}{2}$).

### 3. Double Hashing
Uses a **second independent hash function** $h_2(k)$ to compute a key-dependent step size:

$$h_i(k) = (h_1(k) + i \cdot h_2(k)) \bmod m \quad \text{for } i = 0, 1, 2, \dots, m - 1$$

* **Advantage:** Eliminates both primary and secondary clustering because keys with identical $h_1(k)$ values take different step sizes $h_2(k)$.
* **Full-Table Coverage Rule:** $h_2(k)$ must never evaluate to $0$ and must be **coprime** to table size $m$ ($\gcd(h_2(k), m) = 1$). When $m = 2^p$, ensuring $h_2(k)$ is always **odd** guarantees every slot in $[0, m - 1]$ is visited before repeating.

### 4. CPython Perturbation Probing
CPython's `dict` avoids pure linear clustering without computing a second hash function by folding higher-order bits of the hash code into each probe step:

```text
i = hash_code & mask
perturb = hash_code

while slot[i] is occupied and key does not match:
    perturb >>= 5
    i = (i * 5 + perturb + 1) & mask
```

Once `perturb` shifts down to `0`, the recurrence `i = (i * 5 + 1) & mask` is mathematically guaranteed to visit every slot in a power-of-two table exactly once.

### 5. Lazy Deletion and Tombstones
In Open Addressing, **never clear a deleted slot directly to `None`**, because doing so breaks the probe chain for keys inserted later that collided with the deleted key. Instead, mark deleted slots with a **`TOMBSTONE` (`DUMMY`)** sentinel:

```text
Scenario: m = 5, Linear Probing, h("A") = 1, h("B") = 1

Step 1: Insert "A" -> slot 1 empty -> store "A" at index 1
Step 2: Insert "B" -> slot 1 occupied -> probe slot 2 -> store "B" at index 2
Step 3: Delete "A" -> replace index 1 with TOMBSTONE (not None!)

Index:   0          1              2          3        4
       +------+--------------+----------+--------+--------+
Slots: | None |  TOMBSTONE   |   "B"    |  None  |  None  |
       +------+--------------+----------+--------+--------+
                     |            ^
                     +-- lookup ->+  (lookup("B") sees TOMBSTONE and keeps probing)
```

* **Lookup Rule:** Continue probing past `TOMBSTONE` slots; stop only when `key` is found or a true `None` (never-used) slot is reached.
* **Insertion Rule:** Record the first `TOMBSTONE` seen along the probe path; if `key` is not found before hitting `None`, reuse that `TOMBSTONE` slot.
* **Rehashing Cleanup:** When the table resizes, all `TOMBSTONE` markers are discarded and only active entries are reinserted.

## 4. Comparison of Collision Handling Techniques

| Metric / Property | Separate Chaining | Linear Probing | Quadratic Probing | Double Hashing |
| :--- | :--- | :--- | :--- | :--- |
| **Storage Location** | External chains per bucket | Inside main array | Inside main array | Inside main array |
| **Load Factor ($\alpha = n/m$)** | Can exceed $1.0$ | Must stay $\lt 1.0$ ($\le 0.7$) | Must stay $\lt 1.0$ ($\le 0.7$) | Must stay $\lt 1.0$ ($\le 0.75$) |
| **Primary Clustering** | None | **High** | None | None |
| **Secondary Clustering** | None | None | **Moderate** | None |
| **Cache Locality** | Low (pointer chasing) | **Highest** (sequential) | Moderate | Low (strided jumps) |
| **Deletion Mechanism** | Direct node removal | `TOMBSTONE` sentinel | `TOMBSTONE` sentinel | `TOMBSTONE` sentinel |
| **Expected Probe Count ($\alpha = 0.5$)** | $1 + \frac{\alpha}{2} = 1.25$ | $\frac{1}{2}\left(1 + \frac{1}{1-\alpha}\right) = 1.5$ | $\approx 1.44$ | $\frac{1}{\alpha}\ln\left(\frac{1}{1-\alpha}\right) \approx 1.39$ |

## 5. Python Implementations

### 1. Double Hashing Open-Addressing Table (with Tombstones and Resizing)
```python
from collections.abc import Hashable
from typing import Generic, TypeVar

K = TypeVar("K", bound=Hashable)
V = TypeVar("V")


class _Tombstone:
    """Sentinel indicating a deleted slot whose probe chain must remain intact."""


_TOMBSTONE = _Tombstone()


class DoubleHashingTable(Generic[K, V]):
    """
    Open-addressing hash table using double hashing over a power-of-two capacity.
    Because step size h2(key) is always odd and capacity is 2^p, gcd(h2, capacity) == 1,
    guaranteeing full-table probe coverage.
    """

    _MAX_LOAD_FACTOR = 0.70

    def __init__(self, initial_capacity: int = 8) -> None:
        if initial_capacity < 2 or (initial_capacity & (initial_capacity - 1)) != 0:
            raise ValueError("initial_capacity must be a power of 2 >= 2")
        self._capacity: int = initial_capacity
        self._slots: list[tuple[K, V] | _Tombstone | None] = [None] * self._capacity
        self._size: int = 0

    def _h1(self, key: K) -> int:
        """Primary hash index in [0, capacity - 1]."""
        return hash(key) & (self._capacity - 1)

    def _h2(self, key: K) -> int:
        """Secondary odd step size in [1, capacity - 1] (always coprime to 2^p)."""
        return (((hash(key) >> 5) | 1) & (self._capacity - 1)) or 1

    def _find_slot(self, key: K) -> tuple[bool, int]:
        """
        Return (True, existing_index) if key is present,
        or (False, target_insert_index) otherwise.
        """
        idx = self._h1(key)
        step = self._h2(key)
        first_tombstone: int | None = None

        for _ in range(self._capacity):
            entry = self._slots[idx]
            if entry is None:
                return False, first_tombstone if first_tombstone is not None else idx
            if entry is _TOMBSTONE:
                if first_tombstone is None:
                    first_tombstone = idx
            elif entry[0] == key:
                return True, idx

            idx = (idx + step) & (self._capacity - 1)

        if first_tombstone is not None:
            return False, first_tombstone
        raise RuntimeError("Hash table capacity exhausted")

    def _resize(self, new_capacity: int) -> None:
        old_slots = self._slots
        self._capacity = new_capacity
        self._slots = [None] * self._capacity
        self._size = 0

        for entry in old_slots:
            if isinstance(entry, tuple):
                self[entry[0]] = entry[1]

    def __setitem__(self, key: K, value: V) -> None:
        if (self._size + 1) / self._capacity > self._MAX_LOAD_FACTOR:
            self._resize(self._capacity * 2)

        found, idx = self._find_slot(key)
        self._slots[idx] = (key, value)
        if not found:
            self._size += 1

    def __getitem__(self, key: K) -> V:
        found, idx = self._find_slot(key)
        if not found:
            raise KeyError(key)
        entry = self._slots[idx]
        assert isinstance(entry, tuple)
        return entry[1]

    def __delitem__(self, key: K) -> None:
        found, idx = self._find_slot(key)
        if not found:
            raise KeyError(key)
        self._slots[idx] = _TOMBSTONE
        self._size -= 1

    def __len__(self) -> int:
        return self._size
```

### 2. Separate Chaining Table with Collision Diagnostics
```python
class SeparateChainingTable(Generic[K, V]):
    """Hash table resolving collisions via per-bucket chains with load diagnostics."""

    _MAX_LOAD_FACTOR = 0.75

    def __init__(self, initial_capacity: int = 8) -> None:
        self._capacity: int = initial_capacity
        self._buckets: list[list[tuple[K, V]]] = [[] for _ in range(self._capacity)]
        self._size: int = 0

    def _index(self, key: K) -> int:
        return hash(key) % self._capacity

    def _resize(self, new_capacity: int) -> None:
        old_buckets = self._buckets
        self._capacity = new_capacity
        self._buckets = [[] for _ in range(self._capacity)]
        self._size = 0

        for chain in old_buckets:
            for key, value in chain:
                self[key] = value

    def __setitem__(self, key: K, value: V) -> None:
        if (self._size + 1) / self._capacity > self._MAX_LOAD_FACTOR:
            self._resize(self._capacity * 2)

        chain = self._buckets[self._index(key)]
        for i, (existing_key, _) in enumerate(chain):
            if existing_key == key:
                chain[i] = (key, value)
                return

        chain.append((key, value))
        self._size += 1

    def __getitem__(self, key: K) -> V:
        for existing_key, value in self._buckets[self._index(key)]:
            if existing_key == key:
                return value
        raise KeyError(key)

    def __delitem__(self, key: K) -> None:
        chain = self._buckets[self._index(key)]
        for i, (existing_key, _) in enumerate(chain):
            if existing_key == key:
                chain.pop(i)
                self._size -= 1
                return
        raise KeyError(key)

    def max_chain_length(self) -> int:
        """Return the longest bucket chain length (1 means zero collisions in that bucket)."""
        return max((len(chain) for chain in self._buckets), default=0)


if __name__ == "__main__":
    dh_table = DoubleHashingTable[str, int](initial_capacity=8)
    for idx, name in enumerate(["alice", "bob", "carol", "dave", "erin"], start=1):
        dh_table[name] = idx * 10

    del dh_table["bob"]  # Marks slot with TOMBSTONE without breaking probe paths
    print("Double hashing lookup 'erin':", dh_table["erin"], "| Active entries:", len(dh_table))

    sc_table = SeparateChainingTable[str, int](initial_capacity=8)
    for idx, name in enumerate(["alice", "bob", "carol", "dave", "erin"], start=1):
        sc_table[name] = idx * 10
    print("Separate chaining max bucket depth:", sc_table.max_chain_length())
```

## 6. Common Pitfalls and Best Practices

1. **Clearing Deleted Open-Addressing Slots to `None`:**
   Setting `slots[idx] = None` on deletion prematurely terminates probe chains for keys inserted after the deleted key, causing false `KeyError` lookups. Always use a **`TOMBSTONE`** sentinel and purge tombstones during resizing.
2. **Counting Tombstones as Active Entries Without Triggering Resize:**
   If an open-addressing table undergoes heavy insert-delete cycles, slots fill up with `TOMBSTONE` markers even when `_size` is low. Track `occupied_or_tombstone` count (or trigger a rehash when tombstones exceed a fraction of capacity) so `_find_slot` never degrades into a full-array scan.
3. **Choosing an Even Step Size $h_2(k)$ with a Power-of-Two Table Size:**
   If $m = 16$ and $h_2(k) = 4$, double hashing only probes $4$ slots ($0, 4, 8, 12$) and enters an infinite loop even when $12$ slots are empty. Always ensure $\gcd(h_2(k), m) = 1$ (e.g., force $h_2(k)$ to be odd when $m = 2^p$).
4. **Letting Load Factor Exceed $0.75$ in Open Addressing:**
   Unlike separate chaining (which tolerates $\alpha \gt 1$), open addressing slows down sharply once $\alpha \gt 0.75$ because average probe length grows as $\frac{1}{1 - \alpha}$. Always resize before the table becomes dense.
5. **Assuming Collisions Indicate a Broken Hash Function:**
   Collisions are guaranteed by the Pigeonhole Principle and Birthday Paradox. Focus on keeping the hash function uniform and enforcing timely resizing rather than trying to write a "collision-free" hash function for arbitrary inputs.

## 7. Quick Reference

| Concept | Key Takeaway |
| :--- | :--- |
| **Root Cause** | Pigeonhole Principle ($|U| \gg m$) and Birthday Paradox ($\approx \sqrt{m}$ keys for $50\%$ collision chance) |
| **Separate Chaining** | Stores colliding items in per-bucket lists/trees; simple deletion; tolerates $\alpha \gt 1.0$ |
| **Linear Probing** | Step $+1 \bmod m$; best CPU cache locality; suffers from **primary clustering** |
| **Quadratic Probing** | Step $+c_1 i + c_2 i^2 \bmod m$; avoids primary clustering; suffers from **secondary clustering** |
| **Double Hashing** | Step $+i \cdot h_2(k) \bmod m$ with $\gcd(h_2(k), m) = 1$; avoids both clustering forms |
| **Tombstone (`DUMMY`)** | Placeholder for deleted slots in open addressing so existing probe sequences stay intact |
| **Complexity** | Average: **$\Theta(1)$** lookup/insert/delete \| Worst (degenerate collisions): **$O(n)$** |
