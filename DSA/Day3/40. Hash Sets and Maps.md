# Hash Sets and Maps

## 1. Overview
**Hash Sets** and **Hash Maps** are fundamental associative data structures built on top of hash tables. Both use a hash function to map keys directly to memory slots for **$O(1)$ average-case** operations, differing in whether they store standalone keys or key-value associations:

* **Hash Set (`set`, `frozenset` in Python):** Implements the mathematical **Set Abstract Data Type (ADT)**. Stores an unordered collection of **unique, hashable elements** with no associated values. Used for fast membership testing, deduplication, and set algebra.
* **Hash Map (`dict`, `collections.defaultdict`, `collections.Counter` in Python):** Implements the **Map / Dictionary ADT**. Stores **unique, hashable keys** mapped to **arbitrary values** (`key -> value`). Used for frequency counting, caching, indexing, and complement lookups.

### Structural Comparison (`set` vs. `dict` in CPython)
```text
Hash Set (set): Single Array of (hash, key_ptr) Slots (Unordered)
+-------+-------------------------------+
| Index | Stored Slot                   |
+-------+-------------------------------+
|   0   | None                          |
|   1   | (hash("bob"),   "bob")        |
|   2   | DUMMY (tombstone)             |
|   3   | (hash("alice"), "alice")      |
+-------+-------------------------------+

Hash Map (dict): Compact Sparse Indices + Dense Insertion-Ordered Entries
dk_indices (Sparse Hash Table)         dk_entries (Dense Insertion-Ordered Array)
+-------+---------------+              +-------+---------------------------------------+
| Slot  | Entry Index   |              | Index | Record: (hash, key_ptr, value_ptr)    |
+-------+---------------+              +-------+---------------------------------------+
|   0   | EMPTY (-1)    |              |   0   | (hash("alice"), "alice", 95)          |
|   1   | 1  -----------+------------> |   1   | (hash("bob"),   "bob",   88)          |
|   2   | DUMMY (-2)    |              +-------+---------------------------------------+
|   3   | 0  -----------+------------> (points to index 0 in dk_entries)
+-------+---------------+
```

* **Insertion Order Guarantee:** Because `dict` appends new `(hash, key, value)` records sequentially into `dk_entries`, Python dictionaries preserve **insertion order** (guaranteed by the language specification since Python 3.7).
* **Arbitrary Order in `set`:** Python's `set` stores entries directly in its hash table slots without a separate dense order array, so iteration order depends on hash codes and insertion/deletion history.

## 2. Hash Set vs. Hash Map vs. List

| Feature / Dimension | Hash Set (`set`) | Hash Map (`dict`) | Dynamic Array (`list`) |
| :--- | :--- | :--- | :--- |
| **Stored Data** | Unique keys only (`{k1, k2}`) | Unique keys mapped to values (`{k1: v1, k2: v2}`) | Indexed sequence of elements (`[x0, x1]`) |
| **Duplicate Elements** | **Not allowed** (duplicates ignored) | **Keys unique**; values may repeat | Allowed |
| **Element / Key Constraint** | Must be **hashable** (immutable) | Keys must be **hashable**; values can be any object | Any object (hashable or mutable) |
| **Lookup / Membership (`in`)** | **$\Theta(1)$** average, $O(n)$ worst | **$\Theta(1)$** average, $O(n)$ worst | **$O(n)$** linear scan |
| **Insertion / Deletion** | **$\Theta(1)$** average | **$\Theta(1)$** average | $O(1)$ at tail; $O(n)$ at front/middle |
| **Ordering** | Unordered | Insertion-ordered | Index-ordered |
| **Primary Use Cases** | Membership checks, deduplication, set intersection/union | Counting, grouping, memoization, fast key-value lookup | Ordered sequences, random index access |

## 3. Time and Space Complexity Analysis

### Core Operations
Assume $n$ is the number of elements in the set or map, and $m$ is the size of a second set in binary set operations:

| Operation | Hash Set (`set`) | Hash Map (`dict`) | Notes |
| :--- | :--- | :--- | :--- |
| **Search / Membership (`x in s`, `k in d`)** | $\Theta(1)$ avg \| $O(n)$ worst | $\Theta(1)$ avg \| $O(n)$ worst | $O(n)$ occurs only under pathological hash collisions |
| **Access by Key (`d[k]`, `d.get(k)`)** | N/A | $\Theta(1)$ avg \| $O(n)$ worst | Raises `KeyError` on `d[k]` if missing |
| **Insert / Update (`s.add(x)`, `d[k] = v`)** | $\Theta(1)$ amortized | $\Theta(1)$ amortized | Triggers $2\times$ resize when load factor $\alpha \gt 2/3$ |
| **Delete (`s.remove(x)`, `del d[k]`)** | $\Theta(1)$ avg \| $O(n)$ worst | $\Theta(1)$ avg \| $O(n)$ worst | Marks slot with `DUMMY` tombstone; does not shrink table |
| **Iteration (`for x in s`, `for k, v in d.items()`)** | $\Theta(n + \text{capacity})$ | $\Theta(n)$ | `dict` iterates densely over `dk_entries` |
| **Space Complexity** | $\Theta(n)$ | $\Theta(n)$ | Higher per-element memory overhead than `list` or `tuple` |

### Algebraic Set Operations Complexity
For two hash sets $S$ of size $n$ and $T$ of size $m$:

| Operation | Python Syntax | Average Time Complexity | Mechanism |
| :--- | :--- | :--- | :--- |
| **Union** | `S \| T` or `S.union(T)` | $\Theta(n + m)$ | Copies all elements from $S$ and $T$ into a new set |
| **Intersection** | `S & T` or `S.intersection(T)` | $\Theta(\min(n, m))$ | Iterates over the **smaller** set and probes the larger set in $O(1)$ |
| **Difference** | `S - T` or `S.difference(T)` | $\Theta(n)$ | Iterates over $S$ and keeps items absent from $T$ |
| **Symmetric Difference** | `S ^ T` or `S.symmetric_difference(T)` | $\Theta(n + m)$ | Keeps items present in $S$ or $T$ but not both |
| **Subset Check** | `S <= T` or `S.issubset(T)` | $O(n)$ (immediate $O(1)$ if $n \gt m$) | Verifies every element of $S$ exists in $T$ |

## 4. Essential Algorithmic Patterns in Python

### 1. Hash Set Patterns: Deduplication and $O(n)$ Sequence Detection
```python
from collections.abc import Iterable
from typing import TypeVar

T = TypeVar("T")


def deduplicate_preserve_order(items: Iterable[T]) -> list[T]:
    """
    Remove duplicates while preserving first-seen order.
    Time: Theta(n) average | Auxiliary Space: O(n)
    """
    seen: set[T] = set()
    unique_items: list[T] = []
    for item in items:
        if item not in seen:
            seen.add(item)
            unique_items.append(item)
    return unique_items


def longest_consecutive_sequence(nums: list[int]) -> int:
    """
    Find the length of the longest consecutive integer sequence in O(n) time.
    Only starts counting from numbers `x` where `x - 1` is NOT in the set.
    Time: Theta(n) average | Auxiliary Space: O(n)
    """
    num_set = set(nums)
    best_length = 0

    for num in num_set:
        # Start a streak only at the true beginning of a sequence
        if (num - 1) not in num_set:
            current = num
            streak = 1
            while (current + 1) in num_set:
                current += 1
                streak += 1
            best_length = max(best_length, streak)

    return best_length
```

### 2. Hash Map Patterns: Complement Lookup, Frequency Counting, and Grouping
```python
from collections import Counter, defaultdict


def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    """
    Return indices (i, j) such that nums[i] + nums[j] == target in a single pass.
    Time: Theta(n) average | Auxiliary Space: O(n)
    """
    seen_index: dict[int, int] = {}
    for idx, value in enumerate(nums):
        complement = target - value
        if complement in seen_index:
            return seen_index[complement], idx
        seen_index[value] = idx
    return None


def are_anagrams(first: str, second: str) -> bool:
    """
    Check whether two strings contain identical character frequencies.
    Time: Theta(n) | Auxiliary Space: O(k) where k is unique character count
    """
    if len(first) != len(second):
        return False
    return Counter(first) == Counter(second)


def group_anagrams(words: list[str]) -> list[list[str]]:
    """
    Group words that share the same sorted character signature.
    Time: O(N * K log K) for N words of max length K | Auxiliary Space: O(N * K)
    """
    groups: defaultdict[str, list[str]] = defaultdict(list)
    for word in words:
        signature = "".join(sorted(word))
        groups[signature].append(word)
    return list(groups.values())


if __name__ == "__main__":
    print("Deduplicated:", deduplicate_preserve_order([3, 1, 3, 2, 1, 4]))
    print("Longest streak:", longest_consecutive_sequence([100, 4, 200, 1, 3, 2]))
    print("Two Sum indices:", two_sum([2, 7, 11, 15], target=9))
    print("Grouped anagrams:", group_anagrams(["eat", "tea", "tan", "ate", "nat", "bat"]))
```

## 5. Immutable Variants: `frozenset` and Read-Only Mappings
* **`frozenset`:** An immutable, **hashable** version of `set`. Because its contents cannot change after creation, a `frozenset` can itself be inserted into another `set` or used as a `dict` key (for example, representing an undirected graph edge `frozenset({u, v})` or a combination of feature flags).
* **`types.MappingProxyType`:** Wraps an existing `dict` in a live, read-only view (`proxy[k]` works in $O(1)$, while `proxy[k] = v` raises `TypeError`), useful for exposing configuration dictionaries safely without copying data.

## 6. Common Pitfalls and Best Practices

1. **Inserting Unhashable Objects into a `set` or as `dict` Keys:**
   Mutable containers (`list`, `set`, `dict`) cannot be hashed and raise `TypeError: unhashable type`. Convert lists to `tuple` (e.g., `tuple(coords)`) and sets to `frozenset` before using them as keys.
2. **Mutating a `set` or `dict` While Iterating Over It:**
   Adding or removing keys inside a `for k in d:` or `for x in s:` loop shifts internal table state and raises `RuntimeError: dictionary/set changed size during iteration`. Iterate over a snapshot (`for k in list(d):`) or build a new collection via comprehension.
3. **Writing `{}` Expecting an Empty Set:**
   In Python syntax, `{}` creates an empty **`dict`**, not an empty `set`. Always initialize an empty hash set with **`set()`**.
4. **Using `s.remove(x)` Without Checking Membership:**
   `s.remove(x)` raises `KeyError` if `x` is absent, whereas **`s.discard(x)`** removes `x` if present and silently does nothing if missing. Similarly, use **`d.get(key, default)`** or **`collections.defaultdict`** instead of catching `KeyError` on missing dictionary lookups.
5. **Assuming Deleting Keys Frees Underlying Hash Table Memory:**
   Deleting entries replaces slots with `DUMMY` markers without shrinking the allocated bucket array. If a dictionary grows to millions of entries and then has most keys deleted, recreate it (`d = dict(d)`) if reclaiming memory is required.

## 7. Quick Reference

| Concept / Idiom | Detail |
| :--- | :--- |
| **Hash Set (`set`)** | Stores unique hashable elements; $O(1)$ avg `in`, `add`, `discard`; supports `\|`, `&`, `-`, `^` |
| **Hash Map (`dict`)** | Stores unique hashable keys mapped to values; $O(1)$ avg lookup/insert/delete; preserves insertion order |
| **Specialized Maps** | `collections.Counter` (frequency counts), `collections.defaultdict` (auto-initialized missing keys) |
| **Nested / Composite Keys** | Use `tuple` for ordered composite keys and `frozenset` for unordered set keys |
| **Empty Constructors** | Empty map: `{}` or `dict()` \| Empty set: `set()` (never `{}`) |
| **Core Complexity** | Lookup, Insert, Delete: **$\Theta(1)$ average**, **$O(n)$ worst** \| Space: **$\Theta(n)$** |
