# Divide and Conquer

## 1. Overview
**Divide and Conquer** is an algorithmic paradigm that solves a problem by recursively breaking it down into smaller, **independent (disjoint)** subproblems of the same type until they reach a simple base case, solving those base cases directly, and then combining their solutions into the final answer.

### The Three Phases of Divide and Conquer
1. **Divide:** Partition the input of size $n$ into $a$ smaller disjoint subproblems, each typically of size $n / b$.
2. **Conquer:** Solve each subproblem recursively. When a subproblem becomes sufficiently small (base case, such as $n \le 1$), solve it directly in $O(1)$ time.
3. **Combine:** Merge the subproblem solutions into the solution for the original problem in $f(n)$ time.

### Execution Flow Diagram
```text
                        [ Original Problem (Size n) ]
                                      |
                        1. DIVIDE (into a subproblems)
                        /             |             \
                       v              v              v
              [ Subproblem ]   [ Subproblem ]   [ Subproblem ]   (Size n / b)
                 /      \         /      \         /      \
                v        v       v        v       v        v
             [Base]    [Base] [Base]    [Base] [Base]    [Base]  2. CONQUER (Direct)
                \        /       \        /       \        /
                 v      v         v      v         v      v
              [ Sub-Result ]   [ Sub-Result ]   [ Sub-Result ]   3. COMBINE (Cost f(n))
                        \             |             /
                         v            v            v
                        [  Final Optimal Solution   ]
```

### Divide and Conquer vs. Related Paradigms

| Dimension | Divide and Conquer | Decrease and Conquer | Dynamic Programming (DP) |
| :--- | :--- | :--- | :--- |
| **Subproblem Count** | Splits into **$a \ge 2$** subproblems per step | Reduces to **$1$** smaller subproblem per step | Splits into multiple subproblems |
| **Subproblem Overlap** | **Disjoint** (independent subproblems) | Single chain of subproblems | **Overlapping** (same subproblems repeat) |
| **Caching / Memoization** | Not needed (each subproblem solved once) | Not needed | **Required** (table or memo cache) |
| **Classic Examples** | Merge Sort, Quick Sort, Strassen's Matrix Multiplication | Binary Search, Quickselect, Euclidean GCD | Fibonacci, Edit Distance, 0/1 Knapsack |

## 2. Recurrence Relations and the Master Theorem

The runtime $T(n)$ of a standard Divide and Conquer algorithm is expressed by the recurrence relation:

$$T(n) = a \cdot T\left(\frac{n}{b}\right) + f(n)$$

* **$a \ge 1$:** Number of recursive subproblems spawned at each step.
* **$b \gt 1$:** Factor by which the input size shrinks in each subproblem.
* **$f(n)$:** Cost of dividing the input and combining the subproblem results.

### Solving via the Master Theorem
Compare the divide/combine work $f(n)$ against the critical polynomial $n^{\log_b a}$ (which represents the number of leaves at the bottom of the recursion tree):

| Case | Condition | Asymptotic Runtime $T(n)$ | Intuition & Canonical Example |
| :--- | :--- | :--- | :--- |
| **Case 1 (Leaf-Heavy)** | $f(n) = O\left(n^{\log_b a - \epsilon}\right)$ for some $\epsilon \gt 0$ | **$\Theta\left(n^{\log_b a}\right)$** | Work at the leaves dominates total cost.<br>Example: Strassen's ($a = 7, b = 2, f(n) = \Theta(n^2) \implies \Theta(n^{\log_2 7})$) |
| **Case 2 (Balanced)** | $f(n) = \Theta\left(n^{\log_b a} \log^k n\right)$ for $k \ge 0$ | **$\Theta\left(n^{\log_b a} \log^{k+1} n\right)$** | Every level of the recursion tree does equal work.<br>Example: Merge Sort ($a = 2, b = 2, f(n) = \Theta(n) \implies \Theta(n \log n)$) |
| **Case 3 (Root-Heavy)** | $f(n) = \Omega\left(n^{\log_b a + \epsilon}\right)$ for $\epsilon \gt 0$ and $a f(n/b) \le c f(n)$ ($c \lt 1$) | **$\Theta(f(n))$** | Root divide/combine step dominates all recursive calls.<br>Example: $T(n) = 2T(n/2) + \Theta(n^2) \implies \Theta(n^2)$ |

## 3. Step-by-Step Visual Traces

### 1. Merge Sort and Inversion Counting (`arr = [5, 2, 4, 1]`)
An **inversion** is a pair of indices $(i, j)$ such that $i \lt j$ and $\text{arr}[i] \gt \text{arr}[j]$. During the **Combine** phase, whenever an element from the right sorted half is placed before remaining elements in the left sorted half, all remaining left elements form inversions with it:

```text
DIVIDE PHASE:
                  [ 5,  2,  4,  1 ]
                   /             \
             [ 5,  2 ]         [ 4,  1 ]
              /     \           /     \
            [5]     [2]       [4]     [1]    (Base cases: size 1, 0 inversions)

COMBINE PHASE:
            [5]  +  [2]  --->  [ 2,  5 ]     (2 < 5: 1 inversion: (5, 2))
            [4]  +  [1]  --->  [ 1,  4 ]     (1 < 4: 1 inversion: (4, 1))

        [ 2,  5 ]  +  [ 1,  4 ]
          - Pick 1 from right: 1 < 2 -> 2 inversions: (2, 1), (5, 1)
          - Pick 2 from left:  0 inversions
          - Pick 4 from right: 4 < 5 -> 1 inversion:  (5, 4)
          - Pick 5 from left:  0 inversions
                         |
                         v
                  [ 1,  2,  4,  5 ]          Total Inversions = 1 + 1 + 3 = 5
```

### 2. Binary Exponentiation (`2^10`)
Instead of multiplying $2$ ten times in $O(n)$ steps, Divide and Conquer halves the exponent $n$ at each step using $x^n = (x^{n/2})^2$:

```text
power(2, 10)
  └── power(2, 5)          -> compute half, then square: 32 * 32 = 1024
        └── power(2, 2)    -> compute half, square, multiply by 2: (4 * 4) * 2 = 32
              └── power(2, 1) -> compute half, then square: 2 * 2 = 4
                    └── power(2, 0) -> Base case returns 1

Total Multiplications: 4 (instead of 10) -> O(log n) time
```

## 5. Practical Python Implementations

### 1. Count Inversions via Merge Sort (Index-Bounded, Zero Slice Copies)
```python
def count_inversions(nums: list[int]) -> tuple[list[int], int]:
    """
    Return a sorted copy of `nums` and the total number of inversions (i < j and nums[i] > nums[j]).
    Uses a single preallocated auxiliary buffer to avoid O(n log n) slice allocations.
    Time: Theta(n log n) | Auxiliary Space: Theta(n)
    """
    arr = nums.copy()
    buffer = [0] * len(arr)

    def sort_and_count(low: int, high: int) -> int:
        if high - low <= 1:
            return 0

        mid = low + (high - low) // 2
        inversions = sort_and_count(low, mid) + sort_and_count(mid, high)

        # Combine sorted halves [low, mid) and [mid, high)
        left, right, write = low, mid, low
        while left < mid and right < high:
            if arr[left] <= arr[right]:
                buffer[write] = arr[left]
                left += 1
            else:
                buffer[write] = arr[right]
                # Every remaining element in arr[left:mid] is strictly greater than arr[right]
                inversions += mid - left
                right += 1
            write += 1

        while left < mid:
            buffer[write] = arr[left]
            left += 1
            write += 1

        while right < high:
            buffer[write] = arr[right]
            right += 1
            write += 1

        arr[low:high] = buffer[low:high]
        return inversions

    total_inversions = sort_and_count(0, len(arr))
    return arr, total_inversions
```

### 2. Randomized Quickselect ($k$-th Smallest Element in $\Theta(n)$ Average Time)
Unlike Quicksort, Quickselect recurses into **only one partition** (the half containing target index `k`), reducing $T(n) = T(n/2) + \Theta(n)$ to **$\Theta(n)$ expected time**:

```python
import random


def quickselect_kth_smallest(nums: list[int], k: int) -> int:
    """
    Return the k-th smallest element (1-indexed: k = 1 returns minimum) without sorting the full array.
    Uses randomized Lomuto partitioning over an in-place copy.
    Time: Theta(n) average, O(n^2) worst | Auxiliary Space: O(n) for copy (O(1) extra workspace)
    """
    if k < 1 or k > len(nums):
        raise ValueError("k must satisfy 1 <= k <= len(nums)")

    arr = nums.copy()
    target_idx = k - 1
    low, high = 0, len(arr) - 1

    while low <= high:
        pivot_idx = random.randint(low, high)
        arr[pivot_idx], arr[high] = arr[high], arr[pivot_idx]
        pivot_val = arr[high]

        store_idx = low
        for scan in range(low, high):
            if arr[scan] < pivot_val:
                arr[store_idx], arr[scan] = arr[scan], arr[store_idx]
                store_idx += 1

        arr[store_idx], arr[high] = arr[high], arr[store_idx]

        if store_idx == target_idx:
            return arr[store_idx]
        if store_idx < target_idx:
            low = store_idx + 1
        else:
            high = store_idx - 1

    raise RuntimeError("Unreachable state in quickselect")
```

### 3. Fast Modular Exponentiation (`mod_pow`)
```python
def mod_pow_recursive(base: int, exponent: int, modulus: int) -> int:
    """
    Compute (base ** exponent) mod modulus using recursive Divide and Conquer.
    Time: Theta(log exponent) | Auxiliary Space: Theta(log exponent) call stack
    """
    if modulus == 1:
        return 0
    if exponent == 0:
        return 1

    half = mod_pow_recursive(base, exponent // 2, modulus)
    squared = (half * half) % modulus
    if exponent % 2 == 0:
        return squared
    return (squared * (base % modulus)) % modulus
```

## 6. Common Pitfalls and Best Practices

1. **Passing List Slices (`arr[:mid]`, `arr[mid:]`) in Python Recursion:**
   Slicing a Python list allocates a new list and copies $O(n)$ references on every call, increasing memory overhead and hidden constant factors. Always pass **index boundaries `(low, high)`** into recursive helper functions instead of slicing.
2. **Applying Divide and Conquer When Subproblems Overlap:**
   If recursive subproblems share identical states (such as `fib(n - 1)` and `fib(n - 2)`), pure Divide and Conquer recomputes the same subtrees exponentially many times ($O(2^n)$). Whenever subproblems overlap, switch to **Dynamic Programming** (memoization or bottom-up tabulation).
3. **Incorrect Base Cases or Non-Shrinking Midpoints (`RecursionError`):**
   If a partition range `[low, high)` does not strictly shrink on every branch (for example, calling `recurse(low, mid)` when `mid == high`), recursion never terminates. Verify base cases (`high - low <= 1` or `low >= high`) and compute midpoints safely with **`mid = low + (high - low) // 2`**.
4. **Using Deterministic Pivots on Pre-Sorted Inputs:**
   Picking `arr[0]` or `arr[-1]` as the pivot in Quicksort or Quickselect produces completely unbalanced $0 : (n - 1)$ splits on sorted or reverse-sorted inputs, degrading runtime from $\Theta(n \log n)$ to **$O(n^2)$** and risking stack overflow. Always randomize pivot selection (`random.randint(low, high)`).
5. **Ignoring Recursion Overhead for Tiny Subarrays:**
   For subarrays smaller than ~16–32 elements, recursive function calls cost more than iterative loops. High-performance hybrid sorts (such as Python's **Timsort** and C++'s **Introsort**) switch to **Insertion Sort** once subproblem size drops below a small threshold.

## 7. Quick Reference

| Concept / Rule | Key Detail |
| :--- | :--- |
| **Three Core Steps** | **Divide** into disjoint subproblems $\to$ **Conquer** recursively $\to$ **Combine** results |
| **Master Recurrence** | $T(n) = a T(n/b) + f(n)$; compare $f(n)$ with $n^{\log_b a}$ |
| **Balanced Work ($f(n) = \Theta(n^{\log_b a})$)** | Multiply by $\log n$: $T(n) = \Theta(n^{\log_b a} \log n)$ (e.g., Merge Sort: $\Theta(n \log n)$) |
| **Single-Branch Reduction** | Recursing into only 1 half ($a = 1$) gives $\Theta(\log n)$ if $f(n) = O(1)$ (Binary Search) or $\Theta(n)$ if $f(n) = \Theta(n)$ (Quickselect) |
| **Python Memory Rule** | Pass index bounds `(low, high)` rather than slicing `arr[:mid]` to avoid $O(n)$ per-call copies |
| **When Not to Use** | When subproblems **overlap** (use Dynamic Programming) or when a single greedy choice suffices |
