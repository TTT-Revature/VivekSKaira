# Insertion Sort

## 1. Overview
**Insertion Sort** is a comparison-based, **in-place** sorting algorithm that builds the final sorted array one element at a time—much like sorting a hand of playing cards. On each iteration, it takes the next unsorted element (`key`) and inserts it into its proper position within the already-sorted prefix to its left.

* **Core Characteristics:**
  * **In-Place ($O(1)$ Auxiliary Space):** Rearranges elements directly inside the input array using only a single temporary `key` variable and index pointers.
  * **Stable:** Preserves the relative order of equal elements because shifting stops as soon as an element $\le \text{key}$ is encountered.
  * **Adaptive:** Runs in linear **$\Omega(n)$** time when the input is already sorted or nearly sorted.
  * **Online:** Can sort a stream of elements as they arrive one by one without needing the entire dataset upfront.
  * **Hybrid-Sort Building Block:** Real-world production algorithms such as **Timsort** (Python's `list.sort()` / `sorted()`) and **Introsort** (C++ `std::sort`) switch to Insertion Sort for small subarrays (typically $n \le 16\text{ to }64$) because its low constant overhead and sequential memory access outperform recursive divide-and-conquer on small partitions.

## 2. How It Works: Step-by-Step and Visual Trace

### Step-by-Step Algorithm
Given a zero-indexed array `arr` of length $n$:

1. Treat `arr[0]` as a trivially sorted prefix of length $1$.
2. For each index `i` from `1` to `n - 1`:
   * Store `key = arr[i]` and initialize `j = i - 1`.
   * While `j >= 0` and `arr[j] > key`:
     * Shift `arr[j]` one slot to the right: `arr[j + 1] = arr[j]`.
     * Decrement `j` by `1`.
   * Place `key` into its vacated slot: `arr[j + 1] = key`.

### Visual Trace (`[12, 11, 13, 5, 6]`)
```text
Initial Array: [ 12 | 11, 13, 5, 6 ]   (sorted prefix: [12])

Pass 1 (i = 1, key = 11):
  12 > 11 -> shift 12 right -> insert 11 at index 0
  -> [ 11, 12 | 13, 5, 6 ]

Pass 2 (i = 2, key = 13):
  12 <= 13 -> 0 shifts needed -> 13 stays at index 2
  -> [ 11, 12, 13 | 5, 6 ]

Pass 3 (i = 3, key = 5):
  13 > 5, 12 > 5, 11 > 5 -> shift all three right -> insert 5 at index 0
  -> [ 5, 11, 12, 13 | 6 ]

Pass 4 (i = 4, key = 6):
  13 > 6, 12 > 6, 11 > 6 -> shift 13, 12, 11 right; 5 <= 6 stops scan -> insert 6 at index 1
  -> [ 5, 6, 11, 12, 13 ]

Sorted Result: [ 5, 6, 11, 12, 13 ]
```

## 3. Time and Space Complexity Analysis
Assume $n$ is the number of elements in the input array:

| Case | Input Condition | Comparisons | Element Shifts | Time Complexity | Auxiliary Space |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Best Case** | Already sorted in ascending order | $n - 1$ | $0$ | **$\Omega(n)$** | $O(1)$ |
| **Average Case** | Randomly ordered elements | $\approx \frac{n^2}{4}$ | $\approx \frac{n^2}{4}$ | **$\Theta(n^2)$** | $O(1)$ |
| **Worst Case** | Reverse-sorted in descending order | $\frac{n(n - 1)}{2}$ | $\frac{n(n - 1)}{2}$ | **$O(n^2)$** | $O(1)$ |

### Relationship to Inversions
An **inversion** is a pair of indices $(p, q)$ such that $p < q$ and $\text{arr}[p] > \text{arr}[q]$.
* Every element shift in Insertion Sort removes **exactly one inversion**.
* If an array contains $I$ inversions, Insertion Sort performs exactly $I$ shifts and at most $I + (n - 1)$ comparisons, giving an exact runtime of **$\Theta(n + I)$**:
  * **Already sorted ($I = 0$):** $\Theta(n + 0) = \Theta(n)$.
  * **$k$-sorted / nearly sorted ($I = O(n)$):** $\Theta(n + n) = \Theta(n)$.
  * **Reverse sorted ($I = \frac{n(n - 1)}{2}$):** $\Theta(n^2)$.

## 4. Python Implementations

### 1. Standard Shift-Based Insertion Sort
```python
from typing import TypeVar

T = TypeVar("T", int, float, str)


def insertion_sort(items: list[T]) -> list[T]:
    """
    Sort `items` in-place in ascending order using standard shift-based Insertion Sort.
    Time: Omega(n) best | Theta(n^2) average | O(n^2) worst
    Auxiliary Space: O(1) | Stable: Yes
    """
    for i in range(1, len(items)):
        key = items[i]
        j = i - 1

        # Shift elements strictly greater than `key` one position to the right
        while j >= 0 and items[j] > key:
            items[j + 1] = items[j]
            j -= 1

        items[j + 1] = key

    return items
```

### 2. Binary Insertion Sort (Reducing Comparisons via Binary Search)
Because the prefix `items[0 : i]` is already sorted on iteration `i`, we can find the exact insertion index in **$O(\log i)$ comparisons** using `bisect.bisect_right` (preserving stability). Note that shifting elements right still takes $O(i)$ time, so worst-case time remains **$O(n^2)$**, though comparisons drop from $O(n^2)$ to **$O(n \log n)$**—useful when element comparisons are expensive (such as comparing long strings or custom objects):

```python
import bisect


def binary_insertion_sort(items: list[T]) -> list[T]:
    """
    Insertion Sort using binary search to locate insertion indices.
    Comparisons: O(n log n) | Shifts & Total Worst-Case Time: O(n^2)
    Auxiliary Space: O(1) | Stable: Yes
    """
    for i in range(1, len(items)):
        key = items[i]
        # bisect_right places `key` after any existing equal elements (preserves stability)
        insert_pos = bisect.bisect_right(items, key, 0, i)

        # Shift slice [insert_pos : i] right by one slot
        items[insert_pos + 1 : i + 1] = items[insert_pos:i]
        items[insert_pos] = key

    return items


if __name__ == "__main__":
    data_a = [12, 11, 13, 5, 6]
    data_b = [12, 11, 13, 5, 6]

    print("Standard Insertion Sort:", insertion_sort(data_a))
    print("Binary Insertion Sort:  ", binary_insertion_sort(data_b))
```

## 5. Comparison of Quadratic Sorting Algorithms

| Metric / Property | Insertion Sort | Bubble Sort (Optimized) | Selection Sort |
| :--- | :--- | :--- | :--- |
| **Best-Case Time** | **$\Omega(n)$** | $\Omega(n)$ | $\Omega(n^2)$ |
| **Average-Case Time** | **$\Theta(n^2)$** (~$\frac{n^2}{4}$ comparisons) | $\Theta(n^2)$ (~$\frac{n^2}{2}$ comparisons) | $\Theta(n^2)$ ($\frac{n(n-1)}{2}$ comparisons) |
| **Worst-Case Time** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| **Write Operations (Worst)** | $\frac{n(n - 1)}{2}$ single-assignment shifts | $\frac{n(n - 1)}{2}$ full swaps ($3\times$ assignments) | **$O(n)$** (at most $n - 1$ swaps) |
| **Auxiliary Space** | $O(1)$ | $O(1)$ | $O(1)$ |
| **Stable?** | **Yes** (with strict `>`) | **Yes** (with strict `>`) | **No** (standard swap version) |
| **Adaptive?** | **Yes** ($\Theta(n + I)$ runtime) | **Yes** (exits when 0 swaps occur) | **No** |
| **Online?** | **Yes** | No | No |
| **Practical Winner** | **Fastest on small or nearly-sorted arrays** | Rarely used in practice | Preferred only when writes are ultra-costly |

## 6. Common Pitfalls and Best Practices

1. **Using Full Swaps (`items[j], items[j + 1] = items[j + 1], items[j]`) Instead of Shifting:**
   Swapping adjacent pairs on every inner step performs **three** array writes per step instead of **one** shift write, making the constant factor roughly $2\times\text{–}3\times$ slower. Save `key = items[i]` once, shift elements right with `items[j + 1] = items[j]`, and write `key` once after the loop.
2. **Breaking Stability with `items[j] >= key`:**
   Using `>=` instead of strict `>` shifts equal elements past `key`, reversing the original order of duplicate keys. Always stop shifting when `items[j] <= key`.
3. **Off-by-One Loop Bounds (`j > 0` Instead of `j >= 0`):**
   Writing `while j > 0:` prevents elements from ever shifting into index `0`, leaving the minimum element stranded at index `1`. Always use `while j >= 0 and items[j] > key:`.
4. **Assuming Binary Insertion Sort Is $O(n \log n)$ Total Time:**
   Binary search reduces **comparisons** to $O(n \log n)$, but shifting elements in a contiguous array still requires $O(n^2)$ data movements in the worst case—so total time complexity remains **$O(n^2)$**.
5. **Forgetting Insertion Sort for Small Subarrays in Custom Divide-and-Conquer Sorts:**
   When implementing Merge Sort or Quick Sort from scratch, falling back to Insertion Sort once subarray length drops below `16`–`32` eliminates deep recursion overhead and significantly improves real-world wall-clock speed.
