# Arrays: Operations, Complexity, and Problem Solving

## 1. Overview
An **array** is a fundamental linear data structure that stores a collection of elements in a **contiguous block of memory**, allowing constant-time access to any element via its zero-based integer index ($0$ to $n - 1$).

* **How Contiguous Indexing Works ($O(1)$ Random Access):**
  Because elements occupy consecutive memory slots of fixed byte width, the memory address of element $i$ is calculated directly via arithmetic without traversing earlier elements:
  $$\text{Address}(\text{arr}[i]) = \text{Base\_Address} + (i \times \text{Element\_Size})$$
* **Why Arrays Are Essential in DSA:**
  * **Instant Random Access:** Reading or updating `arr[i]` takes $O(1)$ time regardless of array length.
  * **CPU Cache Locality:** Consecutive memory layout maximizes CPU L1/L2 cache line hits, making array iteration significantly faster in practice than pointer-based structures like linked lists.
  * **Foundational Building Block:** Strings, hash tables, binary heaps, stacks, queues, and matrices are all implemented on top of arrays.

## 2. Static Arrays vs. Dynamic Arrays (Python `list`)
Arrays exist in two primary forms depending on whether their memory capacity is fixed at creation or resized automatically:

| Feature | Static Array | Dynamic Array (Python `list`) |
| :--- | :--- | :--- |
| **Capacity** | Fixed at allocation time (`N` slots) | Grows and shrinks automatically as elements are added/removed |
| **Memory Layout** | Raw values stored contiguously (`array.array`, C arrays, NumPy `ndarray`) | Contiguous array of **object references (pointers)** to Python objects on the heap |
| **Append at End** | $O(1)$ only while unused capacity remains; fails when full | **$O(1)$ amortized** ($O(n)$ worst-case when resizing triggers) |
| **Memory Overhead** | Minimal (exact payload bytes only) | Extra over-allocated pointer slots + per-object Python header overhead |

### How Dynamic Array Resizing Achieves $O(1)$ Amortized Append
When a Python `list` fills its allocated capacity and `append()` is called:
1. CPython allocates a larger contiguous buffer (growing proportionally by ~12.5% plus a small constant).
2. Existing element pointers are copied into the new buffer ($O(n)$ work) and the old buffer is freed.
3. Because the capacity increases geometrically, expensive resizes happen exponentially less frequently as $n$ grows. Across $n$ consecutive appends, total copy operations sum to $O(n)$, yielding **$\frac{O(n)}{n} = O(1)$ amortized time per append**.

## 3. Core Array Operations and Complexity

| Operation | Python Example | Average / Amortized Time | Worst-Case Time | Auxiliary Space | Reason |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Index Access (Read)** | `val = arr[i]` | $\Theta(1)$ | $\Theta(1)$ | $O(1)$ | Direct offset address calculation |
| **Index Update (Write)** | `arr[i] = val` | $\Theta(1)$ | $\Theta(1)$ | $O(1)$ | Overwrites pointer at known offset |
| **Append at End** | `arr.append(x)` | $\Theta(1)$ (amortized) | $\Theta(n)$ | $O(1)$ amortized | Writes into pre-allocated tail slot; $O(n)$ only on resize |
| **Remove from End** | `arr.pop()` | $\Theta(1)$ | $\Theta(1)$ | $O(1)$ | Decrements length without shifting other elements |
| **Insert at Index `i`** | `arr.insert(i, x)` | $\Theta(n)$ | $\Theta(n)$ | $O(1)$ | Shifts all elements at indices $\ge i$ one slot right |
| **Delete at Index `i`** | `arr.pop(i)` / `del arr[i]` | $\Theta(n)$ | $\Theta(n)$ | $O(1)$ | Shifts all elements at indices $> i$ one slot left |
| **Search (Unsorted)** | `x in arr` / `arr.index(x)` | $\Theta(n)$ | $\Theta(n)$ | $O(1)$ | Sequential linear scan from index `0` |
| **Search (Sorted)** | `bisect.bisect_left(arr, x)` | $\Theta(\log n)$ | $\Theta(\log n)$ | $O(1)$ | Binary search halves search range each step |
| **Slicing (`k` items)** | `sub = arr[a:b]` | $\Theta(k)$ | $\Theta(n)$ | $O(k)$ | Allocates new list and copies $k = b - a$ references |
| **Sorting** | `arr.sort()` / `sorted(arr)` | $\Theta(n \log n)$ | $\Theta(n \log n)$ | $O(n)$ | Timsort (hybrid Merge + Insertion Sort) |

## 4. Core Array Problem-Solving Patterns
Brute-force array solutions often rely on nested loops ($O(n^2)$). Most optimal array algorithms reduce time complexity to **$O(n)$** or **$O(n \log n)$** using four recurring patterns:

### 1. Two Pointers
Maintains two integer indices moving through the array in a coordinated way so every element is visited at most once ($O(n)$ time, $O(1)$ auxiliary space):
* **Opposite-End Pointers (`left = 0`, `right = n - 1`):** Converge inward toward the middle. Ideal for sorted pair sums, palindrome checks, container area maximization, and in-place array reversal.
* **Same-Direction (Slow / Fast) Pointers (`slow = 0`, `fast = 0`):** `fast` scans ahead to inspect elements while `slow` tracks the boundary of valid/processed elements. Ideal for in-place deduplication and partitioning without allocating a second array.

### 2. Sliding Window
Maintains a contiguous subarray `[left, right]` and updates window state incrementally as `right` expands and `left` shrinks—avoiding redundant re-summation ($O(n)$ time, $O(1)$ or $O(k)$ auxiliary space):
* **Fixed-Size Window:** Window length stays constant at $k$ (e.g., maximum sum of any $k$ consecutive elements).
* **Variable-Size Window:** `right` expands until a condition is met or violated, then `left` advances to restore validity (e.g., smallest subarray with sum $\ge \text{target}$).

### 3. Prefix Sums (Cumulative Sums)
Precomputes an array `prefix` of size $n + 1$ where `prefix[i]` stores the sum of `arr[0 : i]`:
* **Build Time:** $O(n)$ time, $O(n)$ auxiliary space.
* **Range Query:** Computes the sum of any subarray `arr[left : right + 1]` in **$O(1)$ time**:
  $$\text{SubarraySum}(\text{left}, \text{right}) = \text{prefix}[\text{right} + 1] - \text{prefix}[\text{left}]$$

### 4. Kadane's Algorithm (Dynamic Subarray Optimization)
Tracks the best subarray ending at the current index in a single left-to-right pass ($O(n)$ time, $O(1)$ auxiliary space):
* At each element `x`, decide whether extending the previous subarray (`current_sum + x`) is better than starting fresh at `x` (`max(x, current_sum + x)`).

## 5. Practical Python Implementations

```python
def remove_duplicates_sorted_in_place(nums: list[int]) -> int:
    """
    Pattern: Slow/Fast Two Pointers
    Remove duplicates from a sorted array in-place and return the count of unique elements.
    Time: O(n) | Auxiliary Space: O(1)
    """
    if not nums:
        return 0

    write_idx = 1
    for read_idx in range(1, len(nums)):
        if nums[read_idx] != nums[read_idx - 1]:
            nums[write_idx] = nums[read_idx]
            write_idx += 1

    return write_idx


def min_subarray_len_at_least(target: int, nums: list[int]) -> int:
    """
    Pattern: Variable-Size Sliding Window (for positive integers)
    Return the minimal length of a contiguous subarray whose sum >= target, or 0 if none.
    Time: O(n) (each index enters and leaves the window at most once) | Auxiliary Space: O(1)
    """
    left = 0
    window_sum = 0
    min_length = float("inf")

    for right, value in enumerate(nums):
        window_sum += value
        while window_sum >= target:
            min_length = min(min_length, right - left + 1)
            window_sum -= nums[left]
            left += 1

    return 0 if min_length == float("inf") else int(min_length)


class PrefixSumRangeQuery:
    """
    Pattern: Prefix Sums
    Precomputes cumulative sums in O(n) to answer arbitrary range sum queries in O(1).
    """

    def __init__(self, nums: list[int]) -> None:
        self.prefix = [0] * (len(nums) + 1)
        for i, value in enumerate(nums):
            self.prefix[i + 1] = self.prefix[i] + value

    def range_sum(self, left: int, right: int) -> int:
        """Return sum of nums[left..right] inclusive in O(1) time."""
        if not (0 <= left <= right < len(self.prefix) - 1):
            raise IndexError("Invalid query range")
        return self.prefix[right + 1] - self.prefix[left]


def max_subarray_sum(nums: list[int]) -> int:
    """
    Pattern: Kadane's Algorithm
    Find the largest sum of any non-empty contiguous subarray.
    Time: O(n) | Auxiliary Space: O(1)
    """
    if not nums:
        raise ValueError("Input array must not be empty")

    current_sum = best_sum = nums[0]
    for value in nums[1:]:
        current_sum = max(value, current_sum + value)
        best_sum = max(best_sum, current_sum)
    return best_sum


if __name__ == "__main__":
    # 1. Two Pointers In-Place Deduplication
    sorted_arr = [1, 1, 2, 2, 2, 3, 4, 4]
    k = remove_duplicates_sorted_in_place(sorted_arr)
    print(f"Unique count: {k} | Deduplicated prefix: {sorted_arr[:k]}")

    # 2. Variable Sliding Window
    print("Min subarray length (sum >= 7):", min_subarray_len_at_least(7, [2, 3, 1, 2, 4, 3]))

    # 3. Prefix Sum Queries
    ps = PrefixSumRangeQuery([3, 1, 4, 1, 5, 9])
    print("Range sum [1..4]:", ps.range_sum(1, 4))  # 1 + 4 + 1 + 5 = 11

    # 4. Kadane's Algorithm
    print("Max subarray sum:", max_subarray_sum([-2, 1, -3, 4, -1, 2, 1, -5, 4]))  # 6
```

## 6. Common Pitfalls and Best Practices

1. **Using `arr.pop(0)` or `arr.insert(0, x)` Inside Loops:**
   Inserting or deleting at the front of a Python `list` shifts every subsequent element in memory ($O(n)$ per call), turning an $O(n)$ loop into $O(n^2)$. Use **`collections.deque`** when queue operations at both ends are needed, or collect items in reverse and call `arr.reverse()` once at the end.
2. **Shallow Row Reference Trap in 2D Arrays (`[[0] * cols] * rows`):**
   Multiplying a list of lists duplicates references to the **exact same inner list object**, so mutating `grid[0][1] = 9` silently mutates every row. Always initialize 2D arrays with a list comprehension: **`[[0] * cols for _ in range(rows)]`**.
3. **Mutating a List While Iterating Forward Over It:**
   Removing items (`arr.remove()` or `arr.pop()`) during a forward `for` loop shifts unseen elements leftward into already-visited indices, causing elements to be skipped. Either build a new list with a comprehension or iterate in reverse (`for i in range(len(arr) - 1, -1, -1):`).
4. **Creating Unnecessary Array Slices Inside Loops or Recursion:**
   Writing `helper(arr[1:])` copies $n - 1$ elements on every call ($O(n)$ time and space per step). Pass index boundaries (`helper(arr, left, right)`) instead to keep slicing overhead at $O(1)$.
5. **Off-by-One Boundary Errors:**
   Double-check loop termination conditions (`left < right` vs. `left <= right`), inclusive vs. exclusive right indices, and empty-array edge cases (`len(arr) == 0` or `len(arr) == 1`) before finalizing any index math.

## 7. Quick Reference

| Problem Cue / Requirement | Recommended Pattern / Tool | Time Complexity | Auxiliary Space |
| :--- | :--- | :--- | :--- |
| Find pair/triplet in a **sorted** array | **Opposite-End Two Pointers** | $O(n)$ (or $O(n^2)$ for 3Sum) | $O(1)$ |
| Remove duplicates / filter elements **in-place** | **Slow/Fast Two Pointers** | $O(n)$ | $O(1)$ |
| Longest/shortest **contiguous subarray** meeting a condition | **Sliding Window** | $O(n)$ | $O(1)$ to $O(k)$ |
| Frequent **range sum queries** on an immutable array | **Prefix Sums** | $O(n)$ build, $O(1)$ query | $O(n)$ |
| Maximum/minimum sum of a **contiguous subarray** | **Kadane's Algorithm** | $O(n)$ | $O(1)$ |
| Find target or insertion boundary in a **sorted** array | **Binary Search (`bisect`)** | $O(\log n)$ | $O(1)$ |
| Fast $O(1)$ additions/removals at **both ends** | `collections.deque` (instead of `list`) | $O(1)$ | $O(n)$ |
