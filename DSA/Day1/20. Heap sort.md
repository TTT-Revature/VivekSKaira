# Heap Sort

## 1. Overview
**Heap Sort** is a comparison-based, **in-place** sorting algorithm that uses a **Binary Heap** data structure to sort elements in **$\Theta(n \log n)$** time across all input cases while using strictly **$O(1)$ auxiliary memory**.

* **Core Characteristics:**
  * **Guaranteed $\Theta(n \log n)$ Worst-Case Time:** Combines the worst-case time guarantee of Merge Sort with the in-place memory efficiency of Quick Sort.
  * **Strictly In-Place ($O(1)$ Auxiliary Space):** Uses an implicit binary heap stored directly inside the input array and an iterative `sift_down` routine—requiring zero extra buffers and zero recursion stack frames.
  * **Unstable:** Swapping the root element with the end of the heap moves equal elements across arbitrary distances, breaking relative order.
  * **Non-Adaptive & Cache-Unfriendly:** Performs $\Theta(n \log n)$ operations even on already-sorted arrays, and jumping between parent (`i`) and child (`2i + 1`) indices causes more CPU cache misses than sequential scans in Quick Sort or Merge Sort.
  * **Industry Role (Introsort):** Standard libraries (such as C++ `std::sort`) use **Introsort**, which starts with Quick Sort for speed and switches to **Heap Sort** if recursion depth exceeds $2 \log_2 n$—preventing Quick Sort's $O(n^2)$ worst case while preserving $O(1)$ auxiliary space.

## 2. Implicit Binary Heap Representation
A **Binary Heap** is a **Complete Binary Tree** (all levels completely filled except possibly the last, which is filled left-to-right) stored without node pointers inside a standard zero-indexed array:

* **Zero-Based Index Formulas (for node at index `i`):**
  * **Parent Index:** `(i - 1) // 2` (for `i > 0`)
  * **Left Child Index:** `2 * i + 1`
  * **Right Child Index:** `2 * i + 2`
  * **Last Non-Leaf (Internal) Node:** `(n // 2) - 1` (all indices from `n // 2` to `n - 1` are leaf nodes)
* **Max-Heap Invariant (for Ascending Sort):**
  Every parent node must be greater than or equal to its children (`arr[parent] >= arr[left]` and `arr[parent] >= arr[right]`), guaranteeing that **`arr[0]` always holds the largest element** in the active heap.

```text
Tree View (Max-Heap):              Array View (Zero-Indexed):
         10 (0)                    Index:   0    1    2    3    4
        /      \                   Array: [ 10,   5,   3,   4,   1 ]
     5 (1)     3 (2)                        ^    ^    ^
    /    \                                  |    |    +-- right child of 0 (2*0 + 2)
 4 (3)  1 (4)                               |    +------- left child of 0  (2*0 + 1)
                                            +------------ root (global maximum)
```

## 3. How It Works: Two-Phase Algorithm and Visual Trace

Heap Sort executes in two distinct phases:

### Phase 1: Build a Max-Heap ($\Theta(n)$)
Transform the arbitrary input array into a valid Max-Heap **bottom-up** (Floyd's algorithm). Starting from the last non-leaf node `i = (n // 2) - 1` down to `0`, call `sift_down(arr, i, n)` to sink smaller values down until the Max-Heap property holds for the entire array.

### Phase 2: Repeatedly Extract the Maximum ($\Theta(n \log n)$)
For `end` from `n - 1` down to `1`:
1. Swap the root `arr[0]` (the largest remaining element) with `arr[end]`, locking `arr[end]` in its final sorted position.
2. Shrink the active heap size to `end`.
3. Call `sift_down(arr, 0, end)` to restore the Max-Heap invariant at the root in $O(\log n)$ time.

### Visual Trace (`[4, 10, 3, 5, 1]`)
```text
Initial Unsorted Array: [ 4, 10, 3, 5, 1 ]   (n = 5, last non-leaf = 5 // 2 - 1 = 1)

--- Phase 1: Build Max-Heap ---
i = 1 (val 10): children are 5, 1 -> 10 >= 5, 1 (no swap) -> [ 4, 10, 3, 5, 1 ]
i = 0 (val 4) : largest child is 10 (idx 1) -> swap(4, 10)  -> [ 10, 4, 3, 5, 1 ]
                continue sifting 4 at idx 1: largest child is 5 (idx 3) -> swap(4, 5)
Max-Heap Built: [ 10, 5, 3, 4, 1 ]

--- Phase 2: Extract Max & Shrink Heap ---
end = 4: swap(arr[0], arr[4]) -> [ 1, 5, 3, 4 | 10 ] -> sift_down(0, 4) -> [ 5, 4, 3, 1 | 10 ]
end = 3: swap(arr[0], arr[3]) -> [ 1, 4, 3 | 5, 10 ] -> sift_down(0, 3) -> [ 4, 1, 3 | 5, 10 ]
end = 2: swap(arr[0], arr[2]) -> [ 3, 1 | 4, 5, 10 ] -> sift_down(0, 2) -> [ 3, 1 | 4, 5, 10 ]
end = 1: swap(arr[0], arr[1]) -> [ 1 | 3, 4, 5, 10 ] -> sift_down(0, 1) -> [ 1 | 3, 4, 5, 10 ]

Final Sorted Array: [ 1, 3, 4, 5, 10 ]
```

## 4. Time and Space Complexity Analysis
Assume $n$ is the number of elements in the input array:

| Case | Time Complexity | Auxiliary Space | In-Place? | Stable? |
| :--- | :--- | :--- | :--- | :--- |
| **Best Case** | $\Theta(n \log n)$ (or $\Omega(n)$ if all elements are identical) | **$O(1)$** | **Yes** | **No** |
| **Average Case** | $\Theta(n \log n)$ | **$O(1)$** | **Yes** | **No** |
| **Worst Case** | $\Theta(n \log n)$ | **$O(1)$** | **Yes** | **No** |

### Why Bottom-Up Heap Construction Takes $\Theta(n)$ (Not $O(n \log n)$)
* At height $h$ above the leaves (where leaves have $h = 0$ and the root has $h = \lfloor \log_2 n \rfloor$), there are at most $\lceil \frac{n}{2^{h+1}} \rceil$ nodes, and `sift_down` moves each node at most $h$ levels downward.
* Summing work across all heights yields a convergent geometric series:
  $$T_{\text{build}}(n) = \sum_{h=0}^{\lfloor \log_2 n \rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil \cdot O(h) = O\left(n \sum_{h=0}^{\infty} \frac{h}{2^{h+1}}\right) = O(n \cdot 1) = \Theta(n)$$
* **Phase 2** then performs $n - 1$ extractions, each taking $O(\log n)$ time for `sift_down`, resulting in $\Theta(n) + \Theta(n \log n) = \Theta(n \log n)$ total runtime.

## 5. Python Implementations

### 1. In-Place Max-Heap Sort ($O(1)$ Auxiliary Space)
Using an iterative `while` loop for `_sift_down` guarantees strict **$O(1)$ auxiliary space** with zero recursion overhead:

```python
from typing import TypeVar

T = TypeVar("T", int, float, str)


def _sift_down(items: list[T], root: int, heap_size: int) -> None:
    """
    Restore the Max-Heap property for the subtree rooted at `root`
    within bounds [0, heap_size).
    Time: O(log n) | Auxiliary Space: O(1)
    """
    current = root
    while True:
        largest = current
        left = 2 * current + 1
        right = 2 * current + 2

        if left < heap_size and items[left] > items[largest]:
            largest = left
        if right < heap_size and items[right] > items[largest]:
            largest = right

        if largest == current:
            break

        items[current], items[largest] = items[largest], items[current]
        current = largest


def heap_sort(items: list[T]) -> list[T]:
    """
    Sort `items` in-place in ascending order using Heap Sort.
    Time: Theta(n log n) | Auxiliary Space: O(1) | Stable: No
    """
    n = len(items)
    if n <= 1:
        return items

    # Phase 1: Build Max-Heap bottom-up in Theta(n) time
    for start in range((n // 2) - 1, -1, -1):
        _sift_down(items, start, n)

    # Phase 2: Extract max to end of array and restore heap in Theta(n log n) time
    for end in range(n - 1, 0, -1):
        items[0], items[end] = items[end], items[0]
        _sift_down(items, 0, end)

    return items
```

### 2. Using Python's Standard Library `heapq` (Out-of-Place Min-Heap)
Python's built-in **`heapq`** module implements a **min-heap** (`heapify` in $\Theta(n)$, `heappop` in $O(\log n)$). Because `heapq` lacks a max-heap `heapify` without negating keys, sorting via `heapq` typically allocates an $O(n)$ output list:

```python
import heapq


def heapq_sort_out_of_place(items: list[T]) -> list[T]:
    """
    Sort `items` using Python's C-optimized min-heap (`heapq`).
    Time: Theta(n log n) | Auxiliary Space: O(n) (allocates copy + output list)
    """
    min_heap = items.copy()
    heapq.heapify(min_heap)  # Theta(n)
    return [heapq.heappop(min_heap) for _ in range(len(min_heap))]


if __name__ == "__main__":
    data = [12, 11, 13, 5, 6, 7]
    print("In-place Heap Sort:     ", heap_sort(data.copy()))
    print("Standard library heapq: ", heapq_sort_out_of_place(data))
```

## 6. Comparison of $O(n \log n)$ Comparison Sorts

| Metric / Property | Heap Sort | Merge Sort | Quick Sort (Randomized) |
| :--- | :--- | :--- | :--- |
| **Best-Case Time** | $\Theta(n \log n)$ | $\Theta(n \log n)$ | $\Omega(n \log n)$ |
| **Average-Case Time** | $\Theta(n \log n)$ | $\Theta(n \log n)$ | $\Theta(n \log n)$ |
| **Worst-Case Time** | **$\Theta(n \log n)$** | **$\Theta(n \log n)$** | **$O(n^2)$** |
| **Auxiliary Space** | **$O(1)$** (strictly in-place) | $O(n)$ (merge buffer on arrays) | $O(\log n)$ average stack frames |
| **Stable?** | **No** | **Yes** | **No** |
| **Cache Locality** | Poor (non-sequential parent/child jumps) | Moderate | **Excellent** (sequential scans) |
| **Best Use Cases** | Memory-constrained systems needing guaranteed $O(n \log n)$ worst case; Introsort fallback; top-$k$ selection | Stable sorting, linked lists, external disk sorting | Fast general-purpose in-memory array sorting |

## 7. Common Pitfalls and Best Practices

1. **Passing Full Array Length `n` Instead of Shrinking `end` During Phase 2:**
   When calling `_sift_down(items, 0, end)` after swapping `items[0]` with `items[end]`, the active heap boundary must be `end` (not `n`). Passing `n` pulls already-sorted maximum elements from the right suffix back up into the heap.
2. **Off-by-One Child Index Formulas in Zero-Based Arrays:**
   In 1-based textbook pseudocode, children are `2*i` and `2*i + 1`. In 0-based Python lists, children are **`2*i + 1`** and **`2*i + 2`**, and the last internal node is **`(n // 2) - 1`**. Mixing 1-based and 0-based formulas leaves `items[0]` unheapified or causes `IndexError`.
3. **Building the Heap Top-Down Instead of Bottom-Up:**
   Inserting elements one by one using `sift_up` takes **$\Theta(n \log n)$** time because half the nodes sit at the bottom level and travel $\log_2 n$ steps upward. Always build the heap **bottom-up** from `(n // 2) - 1` down to `0` using `sift_down` to achieve **$\Theta(n)$** construction.
4. **Implementing `sift_down` Recursively:**
   A recursive `sift_down` consumes **$O(\log n)$ call stack frames**, forfeiting Heap Sort's signature **$O(1)$ auxiliary space** advantage. Always write `sift_down` as an iterative `while` loop.
5. **Sorting the Entire Array When Only Top-$k$ Elements Are Needed:**
   If you only need the $k$ smallest or largest items rather than a fully sorted array, do not run full Heap Sort ($O(n \log n)$); use **`heapq.nsmallest(k, items)`** or **`heapq.nlargest(k, items)`**, which run in **$O(n \log k)$** time.
