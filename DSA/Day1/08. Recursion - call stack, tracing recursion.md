# Recursion: Call Stack and Tracing Recursion

## 1. Overview
**Recursion** is a problem-solving technique in which a function solves a problem by calling itself on one or more smaller subproblems until it reaches a trivial case that can be solved directly.

* **The Two Mandatory Parts of Every Recursive Function:**
  1. **Base Case(s):** One or more terminating conditions where the function returns a result immediately **without** making another recursive call. Without a reachable base case, recursion runs indefinitely until memory is exhausted (`RecursionError`).
  2. **Recursive Case (Progress Toward Base Case):** Breaks the current problem into a strictly smaller or simpler instance and calls itself, ensuring every step moves closer to the base case.
* **Why Recursion Matters in DSA:**
  * Naturally models hierarchical and self-similar structures (trees, nested directories, JSON/ASTs, graphs).
  * Forms the backbone of **Divide and Conquer** (Merge Sort, Quick Sort, Binary Search), **Backtracking** (permutations, N-Queens), and **Top-Down Dynamic Programming** (memoization).

---

## 2. How the Call Stack Executes Recursion
Computers do not execute recursive calls magically—they rely on the **Call Stack**, a **LIFO (Last-In, First-Out)** memory structure managed by the runtime.

* **What Is a Stack Frame (Activation Record)?**
  Every time a function is invoked (whether recursive or regular), Python allocates a new **stack frame** on top of the call stack containing:
  * The function's **local variables and parameters** for that specific invocation.
  * The **return address** (the exact instruction in the caller where execution must resume once this call finishes).
* **Two Phases of Recursive Execution:**
  1. **Winding (Push) Phase:** Each recursive call pauses the current frame at the call site and pushes a brand-new frame onto the top of the stack until the **base case** is reached.
  2. **Unwinding (Pop) Phase:** Once the base case returns a value, its frame is popped off the stack, control returns to the caller's suspended line, and intermediate results combine step-by-step back down to the initial caller.

### Visual Call Stack Lifecycle (`factorial(3)`)
```text
Winding Phase (Pushing Frames)         Unwinding Phase (Popping Frames)
------------------------------         --------------------------------
| factorial(0) -> returns 1  |  <-- Base case reached! Pop & return 1
| factorial(1) [waiting: 1 *]|      -> 1 * 1 = 1 (popped)
| factorial(2) [waiting: 2 *]|      -> 2 * 1 = 2 (popped)
| factorial(3) [waiting: 3 *]|      -> 3 * 2 = 6 (popped -> final result: 6)
+----------------------------+
```

## 3. Tracing Recursion Step-by-Step

### 1. Linear Recursion (Single Recursive Branch)
In **linear recursion**, each function call makes at most **one** recursive call. Code placed **before** the recursive call executes during the **winding phase**; code placed **after** the recursive call executes during the **unwinding phase**:

```python
def trace_countdown_and_up(n: int) -> None:
    """Demonstrate winding (pre-call) vs. unwinding (post-call) execution order."""
    if n == 0:
        print("Base case reached: n = 0")
        return

    # 1. Executed during WINDING phase (top-down: 3 -> 2 -> 1)
    print(f"Winding   (push frame): n = {n}")

    trace_countdown_and_up(n - 1)

    # 2. Executed during UNWINDING phase (bottom-up: 1 -> 2 -> 3)
    print(f"Unwinding (pop frame) : n = {n}")


if __name__ == "__main__":
    trace_countdown_and_up(3)
```

**Exact Trace Output:**
```text
Winding   (push frame): n = 3
Winding   (push frame): n = 2
Winding   (push frame): n = 1
Base case reached: n = 0
Unwinding (pop frame) : n = 1
Unwinding (pop frame) : n = 2
Unwinding (pop frame) : n = 3
```

### 2. Tree Recursion (Multiple Recursive Branches)
In **tree recursion**, a function makes **two or more** recursive calls per invocation (such as Fibonacci or binary tree traversals). Tracing tree recursion requires drawing a **Recursion Tree** and following **Depth-First Left-to-Right** execution:

```python
def fib_traced(n: int, depth: int = 0) -> int:
    """Trace the recursion tree of naive Fibonacci(n)."""
    indent = "  " * depth
    print(f"{indent}-> fib({n})")

    if n <= 1:
        print(f"{indent}<- fib({n}) returns {n} (base case)")
        return n

    left = fib_traced(n - 1, depth + 1)
    right = fib_traced(n - 2, depth + 1)
    result = left + right

    print(f"{indent}<- fib({n}) returns {result}")
    return result


if __name__ == "__main__":
    print(f"Final result: {fib_traced(3)}")
```

**Recursion Tree for `fib(3)`:**
```text
          fib(3) = 2
         /          \
   fib(2) = 1      fib(1) = 1
    /      \
fib(1)=1  fib(0)=0
```
* **Execution Order (DFS):** `fib(3)` $\rightarrow$ `fib(2)` $\rightarrow$ `fib(1)` (returns `1`) $\rightarrow$ `fib(0)` (returns `0`) $\rightarrow$ `fib(2)` returns `1` $\rightarrow$ `fib(1)` (returns `1`) $\rightarrow$ `fib(3)` returns `2`.
* **Maximum Call Stack Depth:** Equal to the **height of the recursion tree** ($n = 3$ frames), **not** the total number of nodes in the tree ($5$ calls), because finished left-branch frames are popped before right-branch frames are pushed.

## 4. Complexity Analysis of Recursive Functions

| Recursion Pattern | Example | Total Function Calls (Time) | Max Stack Depth (Auxiliary Space) |
| :--- | :--- | :--- | :--- |
| **Linear ($n \to n - 1$)** | `factorial(n)`, linked-list traversal | $\Theta(n)$ | $\Theta(n)$ |
| **Halving ($n \to n / 2$, 1 branch)** | Recursive `binary_search(arr, target)` | $\Theta(\log n)$ | $\Theta(\log n)$ |
| **Divide & Conquer ($n \to n / 2$, 2 branches + $O(n)$ merge)** | `merge_sort(arr)` | $\Theta(n \log n)$ | $\Theta(n)$ ($O(n)$ merge buffers + $O(\log n)$ stack) |
| **Binary Tree Recursion ($n \to n - 1, n - 2$)** | Naive `fib(n)` | $\Theta(2^n)$ (precisely $\Theta(\phi^n)$) | $\Theta(n)$ (longest root-to-leaf path) |
| **N-ary Backtracking** | Permutations of $n$ items | $\Theta(n \cdot n!)$ | $\Theta(n)$ |

## 5. Python's Recursion Limit and Iteration Conversion
Unlike languages such as Scheme or Scala, **Python does not perform Tail-Call Optimization (TCO)**. Every recursive call adds a real frame to the CPython call stack.

* **Default Stack Limit (`sys.getrecursionlimit()`):**
  Python caps recursion depth (typically **1,000 frames**) to prevent a C-level stack overflow crash, raising **`RecursionError: maximum recursion depth exceeded`** if exceeded.
* **Converting Deep Recursion to Iteration:**
  Any linear or tail-recursive function can be rewritten as a `while` loop with $O(1)$ auxiliary space, and any tree/graph recursion can be converted to an iterative loop using an explicit `list` stack:

```python
import sys


def factorial_recursive(n: int) -> int:
    """Time: O(n) | Auxiliary Space: O(n) stack frames (fails if n >= ~1000)."""
    if n < 0:
        raise ValueError("n must be non-negative")
    if n <= 1:
        return 1
    return n * factorial_recursive(n - 1)


def factorial_iterative(n: int) -> int:
    """Time: O(n) | Auxiliary Space: O(1) (works for arbitrarily large n)."""
    if n < 0:
        raise ValueError("n must be non-negative")
    result = 1
    for factor in range(2, n + 1):
        result *= factor
    return result


if __name__ == "__main__":
    print(f"Python recursion limit: {sys.getrecursionlimit()}")
    print(f"Recursive 5! = {factorial_recursive(5)}")
    print(f"Iterative 5! = {factorial_iterative(5)}")
```

## 6. Common Pitfalls and Best Practices

1. **Missing or Unreachable Base Case:**
   Forgetting the base case—or making a recursive call that does not move strictly closer to it (such as calling `fn(n)` instead of `fn(n - 1)`, or passing negative numbers to `if n == 0:`)—causes infinite recursion and `RecursionError`.
2. **Forgetting `return` on the Recursive Call:**
   Writing `factorial(n - 1)` instead of `return n * factorial(n - 1)` computes the inner value during unwinding and then discards it, returning `None` to the caller (which often triggers `TypeError: unsupported operand type(s) for *: 'int' and 'NoneType'`).
3. **Confusing Total Recursive Calls with Maximum Stack Depth:**
   In tree recursion (`fib(n)`), total calls grow exponentially ($O(2^n)$), but **auxiliary stack space** is proportional only to the **maximum depth of the tree** ($O(n)$), because stack frames from completed branches are popped and reused.
4. **Recomputing Overlapping Subproblems Without Memoization:**
   In naive tree recursion (`fib(n)`), identical subproblems like `fib(2)` are recomputed exponentially many times. Cache results with **`@functools.cache`** (or a dictionary) to reduce time complexity from $O(2^n)$ to $O(n)$.
5. **Using Mutable Default Arguments Across Recursive Calls:**
   Defining `def collect(node, path=[]):` shares the same list object across every call and invocation. Always initialize mutable accumulators inside the function body or pass `path: list[int] | None = None`.

## 7. Quick Reference

| Concept | Key Definition / Rule |
| :--- | :--- |
| **Base Case** | Terminating condition that returns directly without further recursive calls |
| **Recursive Case** | Reduces problem size toward the base case and invokes the same function |
| **Call Stack** | LIFO runtime stack holding active stack frames (parameters, locals, return address) |
| **Winding Phase** | Pre-recursive execution as stack frames are pushed down to the base case |
| **Unwinding Phase** | Post-recursive execution as base-case results return and frames pop off the stack |
| **Auxiliary Stack Space** | Determined by the **maximum recursion depth** (height of recursion tree), not total calls |
| **Python Stack Limit** | ~1,000 frames (`sys.getrecursionlimit()`); no Tail-Call Optimization (TCO) |
