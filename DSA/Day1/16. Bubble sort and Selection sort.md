# Bubble Sort and Selection Sort

## 1. Overview
**Bubble Sort** and **Selection Sort** are foundational comparison-based, **in-place** sorting algorithms with quadratic **$O(n^2)$** average and worst-case time complexity. While outperformed by $O(n \log n)$ algorithms (such as Merge Sort, Quick Sort, and Timsort) on large datasets, both are essential for understanding sorting invariants, algorithmic stability, adaptivity, and swap minimization.

* **Core Classification Terms:**
  * **In-Place ($O(1)$ Auxiliary Space):** Both algorithms rearrange elements directly inside the input array without allocating extra containers proportional to $n$.
  * **Stable vs. Unstable:** A sorting algorithm is **stable** if elements with equal keys preserve their original relative order after sorting.
  * **Adaptive vs. Non-Adaptive:** An **adaptive** sorting algorithm detects existing order in the input and reduces its runtime accordingly (for example, terminating early on an already-sorted array).

---

## 2. Bubble Sort

### 1. Concept and Mechanism
**Bubble Sort** repeatedly scans the unsorted prefix of an array from left to right, comparing **adjacent elements** (`arr[j]` and `arr[j + 1]`) and swapping them whenever they are out of order (`arr[j] > arr[j + 1]`).

* After pass $1$, the largest element has "bubbled" up to its final position at index $n - 1$.
* After pass $k$, the $k$ largest elements are locked in their final positions at the right end of the array, so each subsequent pass inspects one fewer element.
* **Early-Exit Optimization (`swapped` flag):** If an entire pass completes with **zero swaps**, the array is already sorted and the algorithm terminates immediately.

### 2. Step-by-Step Visual Trace (`[5, 1, 4, 2]`)
```text
Initial Array: [ 5, 1, 4, 2 ]

Pass 1 (i = 0, compare indices 0..2):
  [ 5, 1, 4, 2 ] -> 5 > 1 (swap) -> [ 1, 5, 4, 2 ]
  [ 1, 5, 4, 2 ] -> 5 > 4 (swap) -> [ 1, 4, 5, 2 ]
  [ 1, 4, 5, 2 ] -> 5 > 2 (swap) -> [ 1, 4, 2 | 5 ]  (5 is locked)

Pass 2 (i = 1, compare indices 0..1):
  [ 1, 4, 2 | 5 ] -> 1 <= 4 (ok) -> [ 1, 4, 2 | 5 ]
  [ 1, 4, 2 | 5 ] -> 4 > 2 (swap)-> [ 1, 2 | 4, 5 ]  (4 is locked)

Pass 3 (i = 2, compare index 0):
  [ 1, 2 | 4, 5 ] -> 1 <= 2 (ok) -> swapped = False -> Terminate early!

Sorted Result: [ 1, 2, 4, 5 ]
```

### 3. Key Properties of Bubble Sort
* **Stable:** Yes. Swaps occur strictly when `arr[j] > arr[j + 1]` (never on `>=`), so equal elements never cross over each other.
* **Adaptive:** Yes (with the `swapped` flag). Runs in **$\Omega(n)$** time ($n - 1$ comparisons, $0$ swaps) on an already-sorted array.
* **Write-Heavy:** Performs up to $\frac{n(n - 1)}{2} = O(n^2)$ swaps on reverse-sorted input.

## 3. Selection Sort

### 1. Concept and Mechanism
**Selection Sort** partitions the array into a **sorted prefix** (indices `0` to `i - 1`) and an **unsorted suffix** (indices `i` to `n - 1`). On each pass `i`:

1. Scan the entire unsorted suffix `arr[i : n]` to find the index `min_idx` of the **minimum element**.
2. Swap `arr[i]` with `arr[min_idx]` (if `min_idx != i`), extending the sorted prefix by one element.

### 2. Step-by-Step Visual Trace (`[29, 10, 14, 37, 13]`)
```text
Initial Array: [ 29, 10, 14, 37, 13 ]

Pass 1 (i = 0): min in [29, 10, 14, 37, 13] is 10 (idx 1) -> swap(arr[0], arr[1])
  -> [ 10 | 29, 14, 37, 13 ]

Pass 2 (i = 1): min in [29, 14, 37, 13] is 13 (idx 4)     -> swap(arr[1], arr[4])
  -> [ 10, 13 | 14, 37, 29 ]

Pass 3 (i = 2): min in [14, 37, 29] is 14 (idx 2)         -> already in place
  -> [ 10, 13, 14 | 37, 29 ]

Pass 4 (i = 3): min in [37, 29] is 29 (idx 4)             -> swap(arr[3], arr[4])
  -> [ 10, 13, 14, 29 | 37 ]

Sorted Result: [ 10, 13, 14, 29, 37 ]
```

### 3. Key Properties of Selection Sort
* **Minimizes Memory Writes ($O(n)$ Swaps):** Performs **at most $n - 1$ swaps** total—making it useful when write operations to memory (such as Flash or EEPROM storage) are significantly more expensive than reads.
* **Non-Adaptive:** Always performs $\sum_{i=0}^{n-2} (n - 1 - i) = \frac{n(n - 1)}{2}$ comparisons ($\Theta(n^2)$) even if the input is already sorted, because finding the minimum requires inspecting every remaining unsorted element.
* **Unstable (Standard Swap Implementation):** Swapping non-adjacent elements can jump an earlier duplicate past an equal element. For example, sorting `[5a, 5b, 2]` swaps `5a` with `2`, producing `[2, 5b, 5a]` where `5b` now precedes `5a`.

## 4. Python Implementations

```python
from typing import TypeVar

T = TypeVar("T", int, float, str)


def bubble_sort(items: list[T]) -> list[T]:
    """
    Sort `items` in-place in ascending order using optimized Bubble Sort.
    Time: Omega(n) best | Theta(n^2) average | O(n^2) worst
    Auxiliary Space: O(1) | Stable: Yes
    """
    n = len(items)
    for i in range(n - 1):
        swapped = False
        # Last `i` elements are already in their final sorted positions
        for j in range(n - 1 - i):
            if items[j] > items[j + 1]:
                items[j], items[j + 1] = items[j + 1], items[j]
                swapped = True
        if not swapped:
            break
    return items


def selection_sort(items: list[T]) -> list[T]:
    """
    Sort `items` in-place in ascending order using Selection Sort.
    Time: Theta(n^2) best, average, and worst
    Auxiliary Space: O(1) | Stable: No
    """
    n = len(items)
    for i in range(n - 1):
        min_idx = i
        for j in range(i + 1, n):
            if items[j] < items[min_idx]:
                min_idx = j
        if min_idx != i:
            items[i], items[min_idx] = items[min_idx], items[i]
    return items


if __name__ == "__main__":
    sample_a = [64, 34, 25, 12, 22, 11, 90]
    sample_b = [64, 34, 25, 12, 22, 11, 90]

    print("Bubble Sort result:   ", bubble_sort(sample_a))
    print("Selection Sort result:", selection_sort(sample_b))
```

## 5. Side-by-Side Comparison: Bubble Sort vs. Selection Sort

| Metric / Property | Bubble Sort (Optimized) | Selection Sort |
| :--- | :--- | :--- |
| **Best-Case Time** | **$\Omega(n)$** (already sorted, 0 swaps) | $\Omega(n^2)$ |
| **Average-Case Time** | $\Theta(n^2)$ | $\Theta(n^2)$ |
| **Worst-Case Time** | $O(n^2)$ (reverse sorted) | $O(n^2)$ |
| **Total Comparisons (Worst)** | $\frac{n(n - 1)}{2}$ | $\frac{n(n - 1)}{2}$ |
| **Total Swaps (Worst)** | **$O(n^2)$** ($\frac{n(n - 1)}{2}$ swaps) | **$O(n)$** (at most $n - 1$ swaps) |
| **Auxiliary Space** | $O(1)$ (in-place) | $O(1)$ (in-place) |
| **Stable?** | **Yes** (swaps only adjacent elements on `>`) | **No** (long-distance swaps reorder equal keys) |
| **Adaptive?** | **Yes** (exits early when `swapped` is `False`) | **No** (blind to existing order) |
| **Practical Niche** | Detecting or finishing nearly-sorted tiny arrays | Situations where memory writes/swaps are costly |

## 6. Common Pitfalls and Best Practices

1. **Omitting the `swapped` Early-Exit Flag in Bubble Sort:**
   Without tracking `swapped`, Bubble Sort continues executing redundant passes over an already-sorted array, degrading its best-case time complexity from $\Omega(n)$ to $\Theta(n^2)$.
2. **Using `>=` Instead of `>` in Bubble Sort Comparisons:**
   Swapping when `items[j] >= items[j + 1]` swaps equal elements, destroying Bubble Sort's stability and performing unnecessary writes. Always use strict inequality (`>`).
3. **Off-by-One Inner Loop Bounds (`IndexError`):**
   In Bubble Sort, the inner loop accesses `items[j + 1]`, so `j` must stop at `n - 2 - i` (`range(n - 1 - i)`). In Selection Sort, `j` scans up to the final element (`range(i + 1, n)`).
4. **Assuming Selection Sort Is Stable:**
   Standard in-place Selection Sort is **unstable**. If stability is required with $O(n)$ writes, either pair elements with their original indices `(value, original_index)` as tie-breakers or shift elements right instead of swapping (which increases writes to $O(n^2)$).
5. **Using $O(n^2)$ Sorts in Production Python Applications:**
   Both algorithms scale poorly beyond a few thousand elements ($n = 100{,}000 \implies \sim 5 \times 10^9$ comparisons). In production Python, always use built-in **`list.sort()`** or **`sorted()`**, which use C-implemented **Timsort** ($O(n \log n)$ worst case, $\Omega(n)$ best case, and stable).

## 7. Quick Reference

| Algorithm | Core Idea | Time (Best / Avg / Worst) | Swaps (Worst) | Space | Stable |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Bubble Sort** | Repeatedly swap adjacent out-of-order pairs so maxima bubble right | $\Omega(n)$ / $\Theta(n^2)$ / $O(n^2)$ | $O(n^2)$ | $O(1)$ | Yes |
| **Selection Sort** | Repeatedly select minimum from unsorted suffix and swap to front | $\Omega(n^2)$ / $\Theta(n^2)$ / $O(n^2)$ | **$O(n)$** | $O(1)$ | No |
