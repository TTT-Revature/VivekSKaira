# Linear Search

## 1. Overview
**Linear search** (also known as **sequential search**) is the simplest searching algorithm in computer science. It locates a target value within a collection by examining elements **one by one in sequential order** from the beginning until either a match is found or the entire collection has been inspected.

* **Core Characteristics:**
  * **No Ordering Prerequisite:** Works identically on **unsorted** and **sorted** collections.
  * **Structure-Agnostic:** Operates on any iterable or sequential data structure—including arrays (`list`), linked lists, files, and generator streams—because it does not require $O(1)$ random index access.
  * **Constant Auxiliary Memory:** Uses only a loop index or iterator pointer, requiring **$O(1)$ auxiliary space**.
* **Visual Trace (`target = 23` in `[14, 8, 42, 23, 19]`):**
  ```text
  Index:    0      1      2      3      4
         +------+------+------+------+------+
  Array: |  14  |   8  |  42  |  23  |  19  |
         +------+------+------+------+------+
            ^      ^      ^      ^
            |      |      |      |
  Step 1: 14 != 23 (continue)    |
  Step 2:        8 != 23 (continue)
  Step 3:               42 != 23 (continue)
  Step 4:                      23 == 23 -> Match found! Return index 3
  ```

---

## 2. Step-by-Step Algorithm
Given a sequence `arr` of length $n$ and a `target` value:

1. Initialize an index pointer `i = 0`.
2. While `i` is less than $n$:
   * Compare `arr[i]` with `target`.
   * If `arr[i] == target`, stop immediately and return `i`.
   * Otherwise, increment `i` by `1`.
3. If the loop terminates without finding a match, return `-1` (a standard sentinel indicating the target is absent).

---

## 3. Time and Space Complexity Analysis
Assume $n$ is the number of elements in the input collection:

| Case | Condition | Comparisons | Time Complexity | Auxiliary Space |
| :--- | :--- | :--- | :--- | :--- |
| **Best Case** | `target` is the very first element (`arr[0]`) | $1$ | $\Omega(1)$ | $O(1)$ |
| **Average Case** | `target` is equally likely to be at any index $0 \dots n - 1$ | $\frac{n + 1}{2}$ | $\Theta(n)$ | $O(1)$ |
| **Worst Case** | `target` is at the last index (`arr[n - 1]`) or is not present | $n$ | $O(n)$ | $O(1)$ |

### Average-Case Derivation
If the target is present in the array and has an equal probability $\frac{1}{n}$ of appearing at each position $1, 2, \dots, n$, the expected number of comparisons is:
$$E[\text{Comparisons}] = \frac{1 + 2 + 3 + \dots + n}{n} = \frac{n(n + 1)}{2n} = \frac{n + 1}{2} \implies \Theta(n)$$

*(Note: A recursive formulation of linear search still runs in $O(n)$ time, but consumes **$O(n)$ auxiliary space** due to $n$ stacked call frames—making the iterative version strictly superior.)*

## 4. Practical Python Implementations

### 1. Standard Iterative Linear Search (First Match & All Matches)
```python
from collections.abc import Iterable, Sequence
from typing import Callable, TypeVar

T = TypeVar("T")


def linear_search(items: Sequence[T], target: T) -> int:
    """
    Return the index of the first occurrence of `target` in `items`, or -1 if absent.
    Time: O(n) worst/average, O(1) best | Auxiliary Space: O(1)
    """
    for index, value in enumerate(items):
        if value == target:
            return index
    return -1


def linear_search_all(items: Sequence[T], target: T) -> list[int]:
    """
    Return a list of all indices where `target` occurs in `items`.
    Time: Theta(n) (always scans entire sequence) | Auxiliary Space: O(k) for k matches
    """
    return [index for index, value in enumerate(items) if value == target]
```

### 2. Predicate-Based Linear Search (Searching Records or Objects)
When searching structured records (such as dictionaries or dataclass instances) by a specific attribute rather than full object equality, pass a **predicate function** (`Callable[[T], bool]`):

```python
def find_first_matching(items: Iterable[T], predicate: Callable[[T], bool]) -> T | None:
    """
    Return the first element in `items` satisfying `predicate`, or None if no match exists.
    Works on any iterable (lists, linked lists, generators) with short-circuit evaluation.
    Time: O(n) | Auxiliary Space: O(1)
    """
    return next((item for item in items if predicate(item)), None)
```

### 3. Sentinel Linear Search Optimization
In low-level implementations, each iteration performs **two** comparisons: a bounds check (`i < n`) and a value check (`arr[i] == target`). **Sentinel linear search** places a copy of `target` at the end of a mutable list so the loop is guaranteed to terminate without checking `i < n` on every step, reducing total comparisons from $2n + 1$ to $n + 2$:

```python
def sentinel_linear_search(items: list[T], target: T) -> int:
    """
    Perform linear search using a temporary sentinel at the end of `items`
    to eliminate per-iteration index bounds checks.
    Time: O(n) | Auxiliary Space: O(1)
    """
    n = len(items)
    if n == 0:
        return -1

    last_element = items[-1]
    items[-1] = target  # Place sentinel at final slot

    index = 0
    while items[index] != target:
        index += 1

    items[-1] = last_element  # Restore original final element

    if index < n - 1 or last_element == target:
        return index
    return -1


if __name__ == "__main__":
    numbers = [14, 8, 42, 23, 19, 42]

    print("First index of 23:  ", linear_search(numbers, 23))       # 3
    print("First index of 99:  ", linear_search(numbers, 99))       # -1
    print("All indices of 42:  ", linear_search_all(numbers, 42))   # [2, 5]
    print("Sentinel search 19: ", sentinel_linear_search(numbers, 19))  # 4

    users = [
        {"id": 101, "role": "trainee"},
        {"id": 102, "role": "mentor"},
        {"id": 103, "role": "admin"},
    ]
    admin_user = find_first_matching(users, lambda u: u["role"] == "admin")
    print("Matched record:     ", admin_user)
```

### 4. Built-In Python Linear Search Tools
Python's standard sequence operations execute linear search directly in C:
* **`target in seq`:** Returns `True` or `False` in $O(n)$ worst-case time, short-circuiting on the first match.
* **`seq.index(target)`:** Returns the first matching index in $O(n)$ time, or raises `ValueError` if `target` is absent.

## 5. Linear Search vs. Binary Search

| Dimension | Linear Search | Binary Search |
| :--- | :--- | :--- |
| **Input Order Requirement** | **None** (works on unsorted or sorted data) | Must be **sorted** beforehand |
| **Data Structure Support** | Arrays, linked lists, streams, any iterable | Requires **$O(1)$ random access** (arrays/lists) |
| **Best-Case Time** | $\Omega(1)$ | $\Omega(1)$ |
| **Average / Worst-Case Time** | $\Theta(n)$ / $O(n)$ | $\Theta(\log n)$ / $O(\log n)$ |
| **Auxiliary Space** | $O(1)$ | $O(1)$ iterative / $O(\log n)$ recursive |
| **Preprocessing Overhead** | **$O(1)$** (zero setup) | $O(n \log n)$ if sorting is needed first |
| **When to Prefer** | Small inputs, unsorted data, single/infrequent queries, or linked lists | Large sorted datasets queried repeatedly |

## 6. Common Pitfalls and Best Practices

1. **Sorting Unsorted Data Just to Run a Single Search:**
   Sorting an unsorted list takes $O(n \log n)$ time before Binary Search can even begin. If you only need to search an unsorted dataset **once** (or fewer than $\log_2 n$ times), running a single **$O(n)$ Linear Search** is asymptotically and practically faster.
2. **Scanning Twice with `if x in arr: return arr.index(x)`:**
   Checking `x in arr` followed by `arr.index(x)` performs two separate $O(n)$ scans when `x` is near the end of the list. Use a single `enumerate` pass (or wrap `arr.index(x)` in a `try ... except ValueError:` block) to scan the list at most once.
3. **Indexing a Linked List Inside a `for i in range(n)` Loop:**
   Calling `linked_list.get(i)` inside a loop traverses from the head on every iteration, turning an $O(n)$ linear search into **$O(n^2)$**. Always traverse linked lists using node pointers (`curr = curr.next`) or a Python iterator.
4. **Exact Equality (`==`) on Floating-Point Numbers:**
   Binary floating-point rounding (such as `0.1 + 0.2 == 0.30000000000000004`) can cause `value == target` to fail unexpectedly. When searching for floats, compare with **`math.isclose(value, target)`**.
5. **Running Linear Search Inside an Outer Loop ($O(n \cdot m)$):**
   Searching a list of size $m$ inside a loop of $n$ items produces $O(n \cdot m)$ time. When performing many membership or key lookups on static data, convert the target collection into a **`set`** or **`dict`** in $O(m)$ preprocessing time to reduce each lookup to **$O(1)$ average time**.

## 7. Quick Reference

| Concept | Summary |
| :--- | :--- |
| **Mechanism** | Checks elements sequentially from index `0` to `n - 1` until a match is found |
| **Preconditions** | None — works on unsorted collections and non-indexable iterables |
| **Time Complexity** | Best: $\Omega(1)$ \| Average: $\Theta(n)$ \| Worst: $O(n)$ |
| **Auxiliary Space** | $O(1)$ iterative ($O(n)$ if written recursively) |
| **Python Idioms** | `enumerate(seq)`, `target in seq`, `next((x for x in seq if pred(x)), None)` |
| **Optimization Threshold** | Switch from repeated linear scans to a `set`/`dict` ($O(1)$ lookup) or sort + binary search ($O(\log n)$) when performing multiple queries on large datasets |
