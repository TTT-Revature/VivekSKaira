# Binary Search

## 1. Overview
**Binary search** is an efficient **divide-and-conquer** searching algorithm that locates a target value within a sorted collection by repeatedly halving the active search interval.

* **Two Mandatory Preconditions:**
  1. **Monotonic Order:** The collection must be sorted (non-decreasing or non-increasing) or satisfy a monotonic boolean condition so that inspecting the middle element safely eliminates half of the remaining candidates.
  2. **$O(1)$ Random Access:** The underlying structure must support constant-time index lookup (such as an array or Python `list`), making binary search unsuitable for standard linked lists.
* **Why Binary Search Scales:**
  Each comparison eliminates **50% of the remaining search space**. Even for $n = 1{,}000{,}000{,}000$ ($10^9$) elements, binary search requires at most $\lceil \log_2(10^9) \rceil = 30$ comparisons.

---

## 2. How It Works: Step-by-Step and Visual Trace
Maintain two inclusive boundary pointers, `low = 0` and `high = n - 1`:

1. While `low <= high`:
   * Compute the midpoint index: `mid = low + (high - low) // 2`.
   * If `arr[mid] == target`, return `mid`.
   * If `arr[mid] < target`, the target cannot be in `[low, mid]`; set `low = mid + 1`.
   * If `arr[mid] > target`, the target cannot be in `[mid, high]`; set `high = mid - 1`.
2. If `low > high`, the search space is empty; return `-1`.

### Visual Trace (`target = 23` in `[2, 5, 8, 12, 16, 23, 38, 56, 72]`)
```text
Index:    0    1    2    3    4    5    6    7    8
Array: [  2,   5,   8,  12,  16,  23,  38,  56,  72 ]

Step 1: low=0, high=8 -> mid=4 (arr[4]=16 < 23) -> discard left half, low = 5
                            [  23,  38,  56,  72 ]
Step 2: low=5, high=8 -> mid=6 (arr[6]=38 > 23) -> discard right half, high = 5
                            [  23 ]
Step 3: low=5, high=5 -> mid=5 (arr[5]=23 == 23) -> Match found! Return index 5
```

## 3. Time and Space Complexity Analysis
Assume $n$ is the number of elements in the input array:

| Case | Condition | Comparisons | Time Complexity | Iterative Auxiliary Space | Recursive Auxiliary Space |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Best Case** | `target` is at the initial midpoint | $1$ | $\Omega(1)$ | $O(1)$ | $O(1)$ |
| **Average Case** | `target` is uniformly distributed across indices | $\approx \log_2 n - 1$ | $\Theta(\log n)$ | $O(1)$ | $O(\log n)$ |
| **Worst Case** | `target` is at a leaf of the decision tree or absent | $\lfloor \log_2 n \rfloor + 1$ | $O(\log n)$ | $O(1)$ | $O(\log n)$ |

* **Recurrence Relation:**
  $$T(n) = T\left(\frac{n}{2}\right) + \Theta(1) \implies T(n) = \Theta(\log n)$$
* **Iterative vs. Recursive Space:**
  The iterative implementation uses only three integer variables (`low`, `high`, `mid`) for **$O(1)$ auxiliary space**, whereas the recursive implementation pushes $\log_2 n$ frames onto the call stack (**$O(\log n)$ auxiliary space**). Always prefer the iterative form in production code.

## 4. Core Implementations in Python

### 1. Standard Iterative and Recursive Binary Search
```python
from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T", int, float, str)


def binary_search_iterative(items: Sequence[T], target: T) -> int:
    """
    Return an index of `target` in sorted `items`, or -1 if absent.
    Time: O(log n) | Auxiliary Space: O(1)
    """
    low, high = 0, len(items) - 1

    while low <= high:
        mid = low + (high - low) // 2
        if items[mid] == target:
            return mid
        if items[mid] < target:
            low = mid + 1
        else:
            high = mid - 1

    return -1


def binary_search_recursive(
    items: Sequence[T], target: T, low: int = 0, high: int | None = None
) -> int:
    """
    Recursive binary search over inclusive bounds [low, high].
    Time: O(log n) | Auxiliary Space: O(log n) call stack frames
    """
    if high is None:
        high = len(items) - 1
    if low > high:
        return -1

    mid = low + (high - low) // 2
    if items[mid] == target:
        return mid
    if items[mid] < target:
        return binary_search_recursive(items, target, mid + 1, high)
    return binary_search_recursive(items, target, low, mid - 1)
```

### 2. Boundary Search Variations (Handling Duplicates)
When an array contains duplicate elements, standard binary search returns an arbitrary matching index. **Lower bound** and **upper bound** templates locate exact insertion points and duplicate ranges in $O(\log n)$ time:

* **`lower_bound(items, target)`:** First index `i` in `[0, len(items)]` where `items[i] >= target`.
* **`upper_bound(items, target)`:** First index `i` in `[0, len(items)]` where `items[i] > target`.

```python
def lower_bound(items: Sequence[T], target: T) -> int:
    """
    Return the smallest index `i` such that items[i] >= target (or len(items) if all < target).
    Time: O(log n) | Auxiliary Space: O(1)
    """
    low, high = 0, len(items)  # Half-open interval [low, high)
    while low < high:
        mid = low + (high - low) // 2
        if items[mid] < target:
            low = mid + 1
        else:
            high = mid
    return low


def upper_bound(items: Sequence[T], target: T) -> int:
    """
    Return the smallest index `i` such that items[i] > target (or len(items) if all <= target).
    Time: O(log n) | Auxiliary Space: O(1)
    """
    low, high = 0, len(items)  # Half-open interval [low, high)
    while low < high:
        mid = low + (high - low) // 2
        if items[mid] <= target:
            low = mid + 1
        else:
            high = mid
    return low


def find_first_and_last(items: Sequence[T], target: T) -> tuple[int, int]:
    """
    Return (first_index, last_index) of `target` in sorted `items`, or (-1, -1) if absent.
    Time: O(log n) | Auxiliary Space: O(1)
    """
    first = lower_bound(items, target)
    if first == len(items) or items[first] != target:
        return (-1, -1)
    last = upper_bound(items, target) - 1
    return (first, last)
```

## 5. Binary Search on Answer (Monotonic Predicate Pattern)
Binary search is not restricted to arrays—it applies to **any numeric range `[low, high]`** governed by a monotonic boolean predicate `is_feasible(x)` that transitions from `False` to `True` (or `True` to `False`):

```text
Candidate x:    1      2      3      4      5      6      7
is_feasible(x): False  False  False  True   True   True   True
                                     ^
                                     +-- Minimum feasible answer (found in O(log(high - low)))
```

```python
def integer_sqrt(n: int) -> int:
    """
    Compute floor(sqrt(n)) without floating-point math using binary search on [0, n].
    Time: O(log n) | Auxiliary Space: O(1)
    """
    if n < 0:
        raise ValueError("n must be non-negative")
    if n < 2:
        return n

    low, high = 1, n // 2
    answer = 1

    while low <= high:
        mid = low + (high - low) // 2
        square = mid * mid
        if square == n:
            return mid
        if square < n:
            answer = mid
            low = mid + 1
        else:
            high = mid - 1

    return answer
```

## 6. Python Standard Library: `bisect` Module
Python's built-in **`bisect`** module implements C-optimized `lower_bound` and `upper_bound` operations in $O(\log n)$ time:

| Function | Equivalent Operation | Behavior on Duplicates |
| :--- | :--- | :--- |
| **`bisect.bisect_left(arr, x)`** | `lower_bound(arr, x)` | Returns the **leftmost** insertion index (before existing `x` entries) |
| **`bisect.bisect_right(arr, x)`** | `upper_bound(arr, x)` | Returns the **rightmost** insertion index (after existing `x` entries) |
| **`bisect.insort_left(arr, x)`** | `arr.insert(bisect_left(arr, x), x)` | Finds position in $O(\log n)$, but insertion shifts list elements in **$O(n)$** |

```python
import bisect

if __name__ == "__main__":
    data = [2, 5, 8, 12, 16, 23, 38, 56, 72]
    print("Iterative search 23:", binary_search_iterative(data, 23))  # 5
    print("Recursive search 56:", binary_search_recursive(data, 56))  # 7

    dups = [1, 3, 3, 3, 5, 7, 7, 9]
    print("First and last of 3:", find_first_and_last(dups, 3))       # (1, 3)
    print("Count of 3:         ", bisect.bisect_right(dups, 3) - bisect.bisect_left(dups, 3))  # 3
    print("Integer sqrt(50):   ", integer_sqrt(50))                   # 7
```

## 7. Common Pitfalls and Best Practices

1. **Infinite Loops from Stagnant Midpoint Updates:**
   In a half-open loop (`while low < high:`), writing `low = mid` instead of `low = mid + 1` causes an infinite loop whenever `high == low + 1` because `mid = low + (high - low) // 2` rounds down to `low`. When keeping `low = mid` (for finding a maximum feasible value), compute an upper-biased midpoint: **`mid = low + (high - low + 1) // 2`**.
2. **Integer Overflow in Fixed-Width Languages:**
   Although Python integers have arbitrary precision and never overflow, writing `(low + high) // 2` in C++, Java, or Rust overflows signed 32-bit integers when `low + high > 2^31 - 1`. Always write **`low + (high - low) // 2`** as a cross-language best practice.
3. **Applying Binary Search to Linked Lists:**
   Finding the middle node of a singly or doubly linked list requires $O(n)$ pointer traversal. Running binary search on a linked list still takes **$O(n)$ time** ($n/2 + n/4 + n/8 + \dots = n$) and performs worse than linear search due to poor CPU cache locality.
4. **Assuming `bisect_left` Confirms Element Presence:**
   `bisect.bisect_left(arr, x)` returns the **insertion index** even when `x` is not in `arr` (and can return `len(arr)` if `x` is greater than all elements). Always verify `idx < len(arr) and arr[idx] == x` before treating `idx` as a match.
5. **Mixing Inclusive (`[low, high]`) and Half-Open (`[low, high)`) Invariants:**
   Choose one loop invariant and keep all three pieces consistent:
   * **Inclusive:** `high = len(arr) - 1`, `while low <= high:`, updates `low = mid + 1` and `high = mid - 1`.
   * **Half-Open:** `high = len(arr)`, `while low < high:`, updates `low = mid + 1` and `high = mid`.

## 8. Quick Reference

| Aspect | Detail / Complexity |
| :--- | :--- |
| **Algorithm Paradigm** | Divide and Conquer (halves search space on every step) |
| **Prerequisites** | Sorted / monotonic data + $O(1)$ random index access |
| **Time Complexity** | Best: $\Omega(1)$ \| Average: $\Theta(\log n)$ \| Worst: $O(\log n)$ |
| **Auxiliary Space** | Iterative: **$O(1)$** \| Recursive: $O(\log n)$ |
| **Lower Bound (`bisect_left`)** | First index `i` where `arr[i] >= target` |
| **Upper Bound (`bisect_right`)** | First index `i` where `arr[i] > target` |
| **Occurrence Count** | `upper_bound(arr, target) - lower_bound(arr, target)` in $O(\log n)$ |
| **Binary Search on Answer** | Finds minimum/maximum feasible value over any monotonic predicate `[False...True]` |
