# Merge Sort

## 1. Overview
**Merge Sort** is a comparison-based, **divide-and-conquer** sorting algorithm that guarantees **$\Theta(n \log n)$** time complexity across best, average, and worst-case inputs. It works by recursively splitting an input sequence into two halves until single-element sublists are reached, and then merging pairs of sorted sublists back together in linear time.

* **Core Characteristics:**
  * **Guaranteed $\Theta(n \log n)$ Performance:** Unlike Quick Sort (which degrades to $O(n^2)$ on adversarial pivot choices), Merge Sort always divides the array evenly in half, ensuring predictable $\Theta(n \log n)$ runtime regardless of input distribution.
  * **Stable:** Preserves the relative order of equal keys when ties during merging favor the left subarray (`left[i] <= right[j]`).
  * **Out-of-Place on Arrays ($O(n)$ Auxiliary Space):** Standard array-based Merge Sort requires a temporary auxiliary buffer of size $n$ to merge sorted halves cleanly.
  * **Optimal for Linked Lists and External Sorting:** Because merging accesses elements strictly sequentially without requiring $O(1)$ random indexing, Merge Sort sorts linked lists in **$O(n \log n)$ time and $O(1)$ auxiliary space**, and powers external disk-based sorting for datasets larger than RAM.

---

## 2. How It Works: Divide, Conquer, and Combine

### 1. The Three Divide-and-Conquer Phases
1. **Divide:** Compute the midpoint `mid = (low + high) // 2` to split the current subarray `arr[low : high + 1]` into two halves: `arr[low : mid + 1]` and `arr[mid + 1 : high + 1]`.
2. **Conquer:** Recursively apply Merge Sort to both halves until reaching the **base case** (`low >= high`, a subarray of length $0$ or $1$, which is trivially sorted).
3. **Combine (Merge):** Use two pointers (`i` at the start of the left sorted half, `j` at the start of the right sorted half) to repeatedly copy the smaller element into a temporary buffer in $\Theta(n)$ time.

### 2. Step-by-Step Visual Trace (`[38, 27, 43, 3, 9, 82, 10]`)
```text
Unsorted Input:         [ 38, 27, 43, 3, 9, 82, 10 ]
                             /                  \
Divide Level 1:      [ 38, 27, 43, 3 ]      [ 9, 82, 10 ]
                        /        \             /       \
Divide Level 2:    [ 38, 27 ]  [ 43, 3 ]   [ 9, 82 ]  [ 10 ]
                     /    \      /    \      /    \      |
Divide Level 3:   [38]   [27] [43]   [3]   [9]   [82]  [10]   <-- Base cases (size 1)
                    \     /     \     /      \     /     |
Merge Level 3:     [ 27, 38 ]  [ 3, 43 ]    [ 9, 82 ]  [ 10 ]
                        \         /             \       /
Merge Level 2:       [ 3, 27, 38, 43 ]       [ 9, 10, 82 ]
                             \                  /
Merge Level 1:          [ 3, 9, 10, 27, 38, 43, 82 ]          <-- Final Sorted Array
```

## 3. Time and Space Complexity Analysis
Assume $n$ is the number of elements in the input sequence:

| Case | Input Condition | Time Complexity | Array Auxiliary Space | Linked List Auxiliary Space | Stable? |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Best Case** | Already sorted in ascending order | $\Theta(n \log n)$ | $O(n)$ | $O(1)$ (bottom-up) | Yes |
| **Average Case** | Randomly ordered elements | $\Theta(n \log n)$ | $O(n)$ | $O(1)$ (bottom-up) | Yes |
| **Worst Case** | Reverse-sorted or alternating halves | $\Theta(n \log n)$ | $O(n)$ | $O(1)$ (bottom-up) | Yes |

### Recurrence Relation and Recursion Tree Derivation
Splitting an array of size $n$ into two subproblems of size $\frac{n}{2}$ plus a linear $\Theta(n)$ merge yields:
$$T(n) = 2T\left(\frac{n}{2}\right) + \Theta(n)$$

By **Master Theorem Case 2** ($a = 2, b = 2, f(n) = \Theta(n) = \Theta(n^{\log_2 2})$):
* **Recursion Tree Height:** Halving $n$ repeatedly reaches size $1$ in **$\log_2 n$ levels**.
* **Work per Level:** At level $k$, there are $2^k$ subarrays each of size $\frac{n}{2^k}$, requiring $2^k \times \Theta\left(\frac{n}{2^k}\right) = \Theta(n)$ merge operations.
* **Total Work:**
  $$T(n) = \Theta(n) \times \log_2 n = \Theta(n \log n)$$

*(Note: Although top-down recursive Merge Sort also uses $O(\log n)$ call stack frames, $O(n) + O(\log n) = O(n)$ total auxiliary space.)*

## 4. Python Implementations

### 1. Top-Down Recursive Merge Sort (Single Reusable Auxiliary Buffer)
Allocating a single temporary buffer `aux` of size $n$ upfront avoids creating $O(n \log n)$ slice copies across recursive calls while keeping auxiliary memory strictly **$O(n)$**:

```python
from typing import TypeVar

T = TypeVar("T", int, float, str)


def merge_sort(items: list[T]) -> list[T]:
    """
    Sort `items` in-place in ascending order using Top-Down Merge Sort
    with a single pre-allocated auxiliary buffer.
    Time: Theta(n log n) all cases | Auxiliary Space: O(n) | Stable: Yes
    """
    n = len(items)
    if n <= 1:
        return items

    aux: list[T] = items.copy()

    def _merge(low: int, mid: int, high: int) -> None:
        # Copy active segment [low..high] into auxiliary buffer
        aux[low : high + 1] = items[low : high + 1]

        left = low
        right = mid + 1
        dest = low

        while left <= mid and right <= high:
            # Use '<=' (not '<') so equal elements from the left half stay first (stability)
            if aux[left] <= aux[right]:
                items[dest] = aux[left]
                left += 1
            else:
                items[dest] = aux[right]
                right += 1
            dest += 1

        # Copy any remaining elements from the left half
        # (Remaining right-half elements are already in their final positions in `items`)
        while left <= mid:
            items[dest] = aux[left]
            left += 1
            dest += 1

    def _sort_range(low: int, high: int) -> None:
        if low >= high:
            return
        mid = low + (high - low) // 2
        _sort_range(low, mid)
        _sort_range(mid + 1, high)
        # Micro-optimization: skip merge if already ordered across boundary
        if items[mid] <= items[mid + 1]:
            return
        _merge(low, mid, high)

    _sort_range(0, n - 1)
    return items
```

### 2. Bottom-Up Iterative Merge Sort (Zero Recursion Stack)
**Bottom-Up Merge Sort** eliminates recursion completely by treating the array as $n$ sorted subarrays of width `1` and iteratively merging adjacent pairs of width `1, 2, 4, 8, ...` until width $\ge n$:

```python
def merge_sort_bottom_up(items: list[T]) -> list[T]:
    """
    Sort `items` iteratively using Bottom-Up Merge Sort (no recursion stack).
    Time: Theta(n log n) | Auxiliary Space: O(n) | Stable: Yes
    """
    n = len(items)
    if n <= 1:
        return items

    aux: list[T] = items.copy()
    width = 1

    while width < n:
        for low in range(0, n, 2 * width):
            mid = min(low + width - 1, n - 1)
            high = min(low + 2 * width - 1, n - 1)
            if mid >= high:
                continue

            aux[low : high + 1] = items[low : high + 1]
            left, right, dest = low, mid + 1, low

            while left <= mid and right <= high:
                if aux[left] <= aux[right]:
                    items[dest] = aux[left]
                    left += 1
                else:
                    items[dest] = aux[right]
                    right += 1
                dest += 1

            while left <= mid:
                items[dest] = aux[left]
                left += 1
                dest += 1

        width *= 2

    return items


if __name__ == "__main__":
    sample_a = [38, 27, 43, 3, 9, 82, 10]
    sample_b = [38, 27, 43, 3, 9, 82, 10]

    print("Top-Down Merge Sort: ", merge_sort(sample_a))
    print("Bottom-Up Merge Sort:", merge_sort_bottom_up(sample_b))
```

## 5. Applications Beyond Standard Arrays

### 1. Sorting Linked Lists ($O(n \log n)$ Time, $O(1)$ Auxiliary Space)
Merge Sort is the industry-standard algorithm for sorting linked lists (used in Java/Python linked-structure utilities) because:
* Finding the middle node takes $O(n)$ via fast/slow pointers—which matches the $O(n)$ merge cost at each level without changing the $\Theta(n \log n)$ recurrence.
* Merging two sorted linked lists simply rewires existing `next` pointers in **$O(1)$ auxiliary space** without allocating a temporary array.

### 2. External Sorting ($k$-Way Merge)
When sorting a massive log file or database table (e.g., 500 GB) that cannot fit in RAM (e.g., 16 GB):
1. Read 16 GB chunks into RAM, sort each chunk with an in-memory sort, and write sorted runs back to disk.
2. Open all sorted runs simultaneously and use a **Min-Heap (`heapq`)** of size $k$ to perform a **$k$-way merge**, streaming the smallest current record across all chunks to the final output file in $O(N \log k)$ time.

### 3. Counting Inversions in $O(n \log n)$
During the merge step, whenever `aux[right] < aux[left]`, all remaining elements in the left half (`mid - left + 1` elements) are strictly greater than `aux[right]`. Summing `mid - left + 1` on each right-element selection counts all array inversions in **$\Theta(n \log n)$** instead of $O(n^2)$.

## 6. Common Pitfalls and Best Practices

1. **Destroying Stability by Using `<` Instead of `<=` During Merge:**
   Writing `if aux[left] < aux[right]:` picks the **right** element first when `aux[left] == aux[right]`, reversing the relative order of duplicate keys. Always use **`if aux[left] <= aux[right]:`** so equal elements from the left half are placed first.
2. **Allocating New Slices (`merge_sort(arr[:mid])`) on Every Recursive Call:**
   While concise for teaching, passing `arr[:mid]` and `arr[mid:]` allocates new list objects at every node of the recursion tree, increasing garbage collection overhead. Reusing a single pre-allocated `aux` array keeps heap allocations minimal.
3. **Forgetting to Drain Remaining Elements After the Main `while` Loop:**
   The main comparison loop stops as soon as **either** `left > mid` or `right > high`. Failing to copy the leftover elements from the non-exhausted half drops data from the final output.
4. **Assuming Merge Sort Is Adaptive by Default:**
   Standard Merge Sort still splits and merges an already-sorted array in $\Theta(n \log n)$ time. Adding the boundary check `if items[mid] <= items[mid + 1]: return` lets already-sorted inputs finish in **$\Omega(n)$** comparisons without affecting worst-case complexity.
5. **Using Merge Sort Alone on Tiny Subarrays:**
   For small partitions ($n \le 16\text{–}32$), Insertion Sort outperforms Merge Sort due to zero recursion overhead and better cache locality—which is why Python's **Timsort** combines Merge Sort with Insertion Sort on small runs.
