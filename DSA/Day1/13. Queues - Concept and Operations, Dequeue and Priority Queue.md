# Queues: Concept, Operations, Deque, and Priority Queue

## 1. Overview
A **queue** is a linear abstract data type (ADT) that enforces a strict **FIFO (First-In, First-Out)** access order: the earliest element added to the queue is always the first element removed.

* **Two-End Access:**
  Unlike a stack (which operates at a single top end), a standard queue separates insertion and removal across two distinct ends:
  * **Rear (Back / Tail):** Where new elements enter the queue (**enqueue**).
  * **Front (Head):** Where existing elements leave the queue (**dequeue**).
* **Visual Representation:**
  ```text
       dequeue() -> 10                                  enqueue(40)
            ^                                                |
            |                                                v
       +---------+---------+---------+                  +---------+
  front|   10    |   20    |   30    | rear   --->      |   40    |
       +---------+---------+---------+                  +---------+
  ```
* **Core Applications in Computer Science:**
  * **Breadth-First Search (BFS):** Explores graphs and trees level-by-level in shortest-path order.
  * **Task & CPU Scheduling:** Manages ready processes in round-robin and first-come-first-served schedulers.
  * **Asynchronous Buffering & Message Queues:** Decouples producers and consumers across network sockets, I/O streams, and event loops.
  * **Rate Limiting & Sliding Windows:** Tracks timestamped requests within a rolling time window.

---

## 2. Core Queue Operations and Complexities
Assume $n$ is the number of elements currently stored in the queue:

| Operation | Description | Time Complexity | Auxiliary Space | Boundary Condition |
| :--- | :--- | :--- | :--- | :--- |
| **`enqueue(item)`** | Inserts `item` at the rear of the queue | $\Theta(1)$ | $O(1)$ | Raises **Queue Overflow** if fixed capacity is full |
| **`dequeue()`** | Removes and returns the element at the front | $\Theta(1)$ | $O(1)$ | Raises **Queue Underflow** if the queue is empty |
| **`front()` / `peek()`** | Returns the front element without removing it | $\Theta(1)$ | $O(1)$ | Raises **Queue Underflow** if the queue is empty |
| **`is_empty()`** | Returns `True` if `size == 0`, else `False` | $\Theta(1)$ | $O(1)$ | None |
| **`size()` / `__len__()`** | Returns the total count of elements in the queue | $\Theta(1)$ | $O(1)$ | None |

## 3. Standard Queue Implementations in Python

### Why Python `list` Should Not Be Used as a Queue
Using `list.append(x)` to enqueue at the rear takes $O(1)$ amortized time, but calling `list.pop(0)` to dequeue from the front requires shifting all remaining $n - 1$ elements left by one slot (**$\Theta(n)$ time**). Over $n$ operations, a `list`-backed queue degrades to **$\Theta(n^2)$**.

### 1. Standard Library Queue (`collections.deque`)
**`collections.deque`** (double-ended queue) is implemented in C as a doubly-linked list of fixed-size blocks, providing **strict worst-case $\Theta(1)$** `append()` (enqueue) and `popleft()` (dequeue):

```python
from collections import deque
from typing import Generic, TypeVar

T = TypeVar("T")


class QueueUnderflowError(Exception):
    """Raised when attempting to dequeue or peek from an empty queue."""


class FIFOQueue(Generic[T]):
    """FIFO queue backed by collections.deque with strict O(1) operations."""

    def __init__(self) -> None:
        self._items: deque[T] = deque()

    def enqueue(self, item: T) -> None:
        """Add an element to the rear of the queue: O(1)."""
        self._items.append(item)

    def dequeue(self) -> T:
        """Remove and return the front element: O(1)."""
        if not self._items:
            raise QueueUnderflowError("Cannot dequeue from an empty queue")
        return self._items.popleft()

    def front(self) -> T:
        """Inspect the front element without removing it: O(1)."""
        if not self._items:
            raise QueueUnderflowError("Cannot peek into an empty queue")
        return self._items[0]

    def is_empty(self) -> bool:
        return len(self._items) == 0

    def __len__(self) -> int:
        return len(self._items)
```

### 2. Circular Array Queue (Ring Buffer)
When implementing a bounded queue over a fixed-size array of capacity $C$, advancing `front` and `rear` linearly eventually leaves unused slots at the front. A **circular queue** wraps indices around the array using modulo arithmetic (`(index + 1) % capacity`), achieving **$\Theta(1)$** enqueue and dequeue without shifting elements:

```python
from typing import Generic, TypeVar

T = TypeVar("T")


class QueueOverflowError(Exception):
    """Raised when attempting to enqueue into a full bounded queue."""


class CircularQueue(Generic[T]):
    """Fixed-capacity FIFO ring buffer using modulo index wrap-around."""

    def __init__(self, capacity: int) -> None:
        if capacity <= 0:
            raise ValueError("Capacity must be a positive integer")
        self._capacity: int = capacity
        self._buffer: list[T | None] = [None] * capacity
        self._front: int = 0
        self._size: int = 0

    def enqueue(self, item: T) -> None:
        """Insert item at the logical rear index: O(1) time, O(1) space."""
        if self._size == self._capacity:
            raise QueueOverflowError("CircularQueue is full")
        rear = (self._front + self._size) % self._capacity
        self._buffer[rear] = item
        self._size += 1

    def dequeue(self) -> T:
        """Remove and return item at the front index: O(1) time, O(1) space."""
        if self._size == 0:
            raise QueueUnderflowError("CircularQueue is empty")
        value = self._buffer[self._front]
        self._buffer[self._front] = None  # Release reference for garbage collection
        self._front = (self._front + 1) % self._capacity
        self._size -= 1
        assert value is not None
        return value

    def front(self) -> T:
        if self._size == 0:
            raise QueueUnderflowError("CircularQueue is empty")
        value = self._buffer[self._front]
        assert value is not None
        return value

    def is_full(self) -> bool:
        return self._size == self._capacity

    def is_empty(self) -> bool:
        return self._size == 0

    def __len__(self) -> int:
        return self._size
```

## 4. Double-Ended Queue (Deque)
A **deque** (pronounced *"deck"*) generalizes both a stack and a queue by supporting **$\Theta(1)$ insertion and deletion at both ends** (`front` and `rear`).

### Core Deque Operations (`collections.deque`)

| Operation | `collections.deque` Method | Time Complexity | Auxiliary Space |
| :--- | :--- | :--- | :--- |
| **Insert at Rear** | `dq.append(x)` | $\Theta(1)$ | $O(1)$ |
| **Insert at Front** | `dq.appendleft(x)` | $\Theta(1)$ | $O(1)$ |
| **Remove from Rear** | `dq.pop()` | $\Theta(1)$ | $O(1)$ |
| **Remove from Front** | `dq.popleft()` | $\Theta(1)$ | $O(1)$ |
| **Peek Front / Rear** | `dq[0]` / `dq[-1]` | $\Theta(1)$ | $O(1)$ |
| **Rotate `k` Steps** | `dq.rotate(k)` | $\Theta(k)$ | $O(1)$ |
| **Random Index Access** | `dq[i]` | $O(n)$ | $O(1)$ |

*(Tip: Initializing `deque(maxlen=k)` automatically evicts the opposite end in $O(1)$ time whenever a new item exceeds capacity $k$—ideal for rolling history buffers.)*

### Classic Deque Pattern: Monotonic Deque (Sliding Window Maximum)
A **monotonic deque** stores indices whose corresponding values are maintained in strictly decreasing (or increasing) order, answering sliding-window extrema queries in **$O(n)$ total time**:

```python
from collections import deque


def sliding_window_maximum(nums: list[int], k: int) -> list[int]:
    """
    Return the maximum value in every contiguous subarray of size k.
    Time: O(n) (each index enters and leaves the deque at most once) | Auxiliary Space: O(k)
    """
    if not nums or k <= 0:
        return []

    window_indices: deque[int] = deque()  # Values at stored indices are monotonically decreasing
    result: list[int] = []

    for idx, value in enumerate(nums):
        # 1. Evict indices that have fallen outside the current [idx - k + 1, idx] window
        while window_indices and window_indices[0] <= idx - k:
            window_indices.popleft()

        # 2. Pop smaller values from the rear since they can never be the window maximum
        while window_indices and nums[window_indices[-1]] <= value:
            window_indices.pop()

        window_indices.append(idx)

        # 3. Record window maximum once the first k elements have been processed
        if idx >= k - 1:
            result.append(nums[window_indices[0]])

    return result
```

## 5. Priority Queue
A **priority queue** is an abstract data type where every element is associated with a **priority key**. Instead of FIFO arrival order, **`dequeue` always removes and returns the element with the highest priority** (by convention in Python, the **smallest** key in a min-priority queue).

### Data Structure Comparison for Priority Queues

| Underlying Structure | `enqueue` (Insert) | `dequeue` (Extract Min/Max) | `peek` (Find Min/Max) | Build from $n$ Items |
| :--- | :--- | :--- | :--- | :--- |
| **Unsorted Array / List** | $\Theta(1)$ | $\Theta(n)$ | $\Theta(n)$ | $\Theta(n)$ |
| **Sorted Array / List** | $\Theta(n)$ (shifting) | $\Theta(1)$ (from end) | $\Theta(1)$ | $\Theta(n \log n)$ |
| **Binary Heap (`heapq`)** | **$O(\log n)$** | **$O(\log n)$** | **$\Theta(1)$** | **$\Theta(n)$** (`heapify`) |

### Python `heapq` Implementation (Min-Heap & Max-Heap Patterns)
Python's built-in **`heapq`** module implements a **binary min-heap** directly on top of a standard `list`:
* **Min-Priority Queue:** Push `(priority, tie_breaker, item)` tuples so the smallest `priority` always sits at `heap[0]`.
* **Max-Priority Queue:** Negate numeric priorities (`-priority`) when pushing and negate again when popping.

```python
import heapq
from itertools import count
from typing import Generic, TypeVar

T = TypeVar("T")


class MinPriorityQueue(Generic[T]):
    """
    Binary-heap priority queue with deterministic FIFO tie-breaking.
    The monotonically increasing `_counter` ensures items with equal priority
    are never compared directly (preventing TypeError on unorderable payloads).
    """

    def __init__(self) -> None:
        self._heap: list[tuple[int, int, T]] = []
        self._counter = count()

    def push(self, priority: int, item: T) -> None:
        """Insert item with given integer priority: O(log n) time."""
        heapq.heappush(self._heap, (priority, next(self._counter), item))

    def pop(self) -> tuple[int, T]:
        """Remove and return (priority, item) with lowest priority value: O(log n) time."""
        if not self._heap:
            raise QueueUnderflowError("Cannot pop from an empty PriorityQueue")
        priority, _, item = heapq.heappop(self._heap)
        return priority, item

    def peek(self) -> tuple[int, T]:
        """Return (priority, item) with lowest priority value without removing: O(1) time."""
        if not self._heap:
            raise QueueUnderflowError("Cannot peek into an empty PriorityQueue")
        priority, _, item = self._heap[0]
        return priority, item

    def __len__(self) -> int:
        return len(self._heap)


if __name__ == "__main__":
    # 1. Circular Queue Demo
    cq = CircularQueue[str](capacity=3)
    cq.enqueue("A")
    cq.enqueue("B")
    cq.enqueue("C")
    print("Circular dequeue:", cq.dequeue())  # A
    cq.enqueue("D")                           # Wraps around to index 0
    print("Circular front after wrap:", cq.front())  # B

    # 2. Monotonic Deque Sliding Window Maximum
    print("Sliding max:", sliding_window_maximum([1, 3, -1, -3, 5, 3, 6, 7], k=3))

    # 3. Priority Queue with Tie-Breaking
    pq = MinPriorityQueue[dict[str, str]]()
    pq.push(priority=2, item={"task": "send-email"})
    pq.push(priority=1, item={"task": "failover-db"})
    pq.push(priority=1, item={"task": "alert-oncall"})
    print("Highest priority task:", pq.pop())  # (1, {'task': 'failover-db'})
```

## 6. Common Pitfalls and Best Practices

1. **Using `list.pop(0)` for FIFO Queues:**
   Removing from index `0` of a Python `list` shifts all remaining elements ($O(n)$ per dequeue). Always use **`collections.deque.popleft()`** for $O(1)$ FIFO removal.
2. **Omitting a Tie-Breaker in `heapq` Tuples:**
   If you push `(priority, task_object)` into `heapq` and two tasks share the exact same `priority`, Python compares `task_object_1 < task_object_2`—raising **`TypeError: '<' not supported between instances of ...`** if the payload is a `dict` or custom class without `__lt__`. Always insert a unique sequence counter: **`(priority, next(counter), item)`**.
3. **Treating `heapq` as a Sorted List:**
   A binary heap guarantees only that `heap[0]` is the minimum element and each parent satisfies `heap[i] <= heap[2*i + 1]` and `heap[i] <= heap[2*i + 2]`. Iterating over `heap` directly does **not** yield elements in sorted order; repeatedly call `heapq.heappop(heap)` (or `heapq.nsmallest(k, iterable)`).
4. **Using `queue.Queue` / `queue.PriorityQueue` in Single-Threaded Algorithms:**
   Classes in the `queue` standard library module acquire mutex locks on every operation, adding substantial overhead in single-threaded code. Use `collections.deque` and `heapq` for single-threaded DSA, and reserve `queue.Queue` / `queue.PriorityQueue` for multi-threaded producer-consumer synchronization.
5. **Forgetting to Clear References in Fixed-Capacity Circular Buffers:**
   When dequeuing from a Python list-backed ring buffer, failing to set `self._buffer[self._front] = None` keeps a live reference to the dequeued object in the underlying array, preventing garbage collection until that slot is overwritten.

## 7. Quick Reference

| Queue Variant | Ordering Discipline | Primary Python Tool | Enqueue Time | Dequeue Time | Peek Time |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Standard Queue** | **FIFO** (First-In, First-Out) | `collections.deque` (`append` / `popleft`) | $\Theta(1)$ | $\Theta(1)$ | $\Theta(1)$ |
| **Circular Queue** | **FIFO** in fixed-size ring buffer | Fixed `list` + `% capacity` indexing | $\Theta(1)$ | $\Theta(1)$ | $\Theta(1)$ |
| **Deque** | **Double-ended** (both front and rear) | `collections.deque` (`appendleft` / `pop`) | $\Theta(1)$ (both ends) | $\Theta(1)$ (both ends) | $\Theta(1)$ (both ends) |
| **Priority Queue** | **Priority-ordered** (min or max key first) | `heapq` (`heappush` / `heappop`) | $O(\log n)$ | $O(\log n)$ | $\Theta(1)$ |
