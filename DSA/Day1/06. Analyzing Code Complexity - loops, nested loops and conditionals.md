# Analyzing Code Complexity: Loops, Nested Loops, and Conditionals

## 1. Overview
Deriving the time complexity of real source code requires systematically counting how many times basic operations execute as a function of input size $n$. Control-flow constructs—**sequential statements**, **conditionals (`if`/`elif`/`else`)**, **single loops**, and **nested loops**—follow clear algebraic rules that reduce any function to its dominant Big-O bound.

* **Core Strategy (Inside-Out Evaluation):**
  1. Identify the **input size variable(s)** (e.g., $n = \text{len(arr)}$).
  2. Assign $O(1)$ to elementary operations (arithmetic, comparisons, scalar assignments, indexing `arr[i]`).
  3. Evaluate control-flow blocks from the **innermost statement outward**, applying addition for sequential blocks and multiplication for nested repetition.
  4. Drop constant multipliers and lower-order terms to obtain the tightest asymptotic bound.

## 2. Sequential Blocks and Conditionals (`if` / `elif` / `else`)

### 1. Sequential Statements (Addition Rule)
When statement block $A$ runs in $O(f(n))$ and statement block $B$ runs in $O(g(n))$ one after another, total complexity is the **sum**—which simplifies to the **maximum** of the two growth rates:
$$T(n) = O(f(n)) + O(g(n)) = O(\max(f(n), g(n)))$$

### 2. Conditional Branches (Worst-Case Maximum Rule)
In an `if / elif / else` structure, only **one** branch executes on any single pass:
* **Worst-Case Complexity:** Governed by the **slowest possible branch** (plus the cost of evaluating the condition itself):
  $$T_{\text{worst}}(n) = T(\text{condition}) + \max\big(T(\text{if-branch}),\; T(\text{else-branch})\big)$$
* **Best-Case Complexity:** Governed by the **fastest reachable branch**.

```python
def process_records(records: list[int], sort_output: bool) -> list[int]:
    """
    Condition evaluation: O(1)
    - If branch:   sorted(records) -> O(n log n)
    - Else branch: records.copy()  -> O(n)
    Worst-case time:  O(max(n log n, n)) = O(n log n)
    Best-case time:   O(n) (when sort_output is False)
    """
    if sort_output:
        return sorted(records)
    return records.copy()
```

### 3. Conditionals Inside a Loop (Amortized / Guarded Expensive Work)
When an `if` condition inside an $O(n)$ loop triggers an expensive $O(n)$ operation **only once** (or a constant number of times) rather than on every iteration, do **not** blindly multiply $n \times n$:

```python
def find_and_reverse_first_negative(nums: list[int]) -> list[int]:
    """
    Loop runs at most n times: O(n).
    The expensive slice reversal nums[::-1] (O(n)) runs AT MOST ONCE because of `return`.
    Total time: O(n) + O(n) = O(n), NOT O(n^2).
    """
    for idx, value in enumerate(nums):
        if value < 0:
            return nums[:idx] + nums[idx:][::-1]
    return nums.copy()
```

## 3. Analyzing Single Loops
A single loop's complexity equals **(number of iterations) $\times$ (cost per iteration)**:

| Loop Pattern | Example Code | Iteration Count | Time Complexity |
| :--- | :--- | :--- | :--- |
| **Linear Step ($\pm c$)** | `for i in range(0, n, 2):` | $\lceil n / 2 \rceil$ | $\Theta(n)$ |
| **Multiplicative / Divisive Step** | `i = 1; while i < n: i *= 2` | $\lfloor \log_2 n \rfloor + 1$ | $\Theta(\log n)$ |
| **Sub-Linear Bound ($\sqrt{n}$)** | `i = 1; while i * i <= n: i += 1` | $\lfloor \sqrt{n} \rfloor$ | $\Theta(\sqrt{n})$ |
| **Constant Bound** | `for i in range(min(n, 100)):` | At most $100$ | $\Theta(1)$ |
| **Early Exit (`break` / `return`)** | `for x in arr: if x == target: break` | Best: $1$; Worst: $n$ | Best: $\Theta(1)$, Worst: $\Theta(n)$ |

### Example: Square-Root Loop ($O(\sqrt{n})$)
```python
def is_prime(n: int) -> bool:
    """Loop condition i * i <= n terminates after at most sqrt(n) steps: O(sqrt(n))."""
    if n < 2:
        return False
    divisor = 2
    while divisor * divisor <= n:
        if n % divisor == 0:
            return False
        divisor += 1
    return True
```

## 4. Analyzing Nested Loops
Nested loops are evaluated by summing the inner loop's work across every iteration of the outer loop:
$$\text{Total Operations} = \sum_{i} \big(\text{Operations in inner loop for outer index } i\big)$$

### 1. Independent Nested Loops (Rectangular Grid)
When the inner loop bound does not depend on the outer loop index:
```python
def matrix_sum(matrix: list[list[int]]) -> int:
    """Outer runs R times, inner runs C times -> Theta(R * C) (or Theta(n^2) if R = C = n)."""
    total = 0
    for row in matrix:          # R iterations
        for value in row:       # C iterations per row
            total += value      # O(1)
    return total
```

### 2. Dependent Nested Loops (Triangular Series)
When the inner loop starts or ends at outer index $i$ (e.g., `for j in range(i + 1, n):`), sum the arithmetic series:
$$\sum_{i=0}^{n-1} (n - 1 - i) = (n - 1) + (n - 2) + \dots + 1 + 0 = \frac{n(n - 1)}{2} = \Theta(n^2)$$

### 3. Mixed Linear and Logarithmic Nested Loops
When one loop steps linearly ($n$) and the other scales multiplicatively/divisively ($\log n$):
```python
def harmonic_steps(n: int) -> int:
    """
    Outer loop runs n times.
    Inner loop doubles j from 1 to n -> log2(n) iterations per outer step.
    Total operations: n * log2(n) -> Theta(n log n).
    """
    ops = 0
    for _ in range(n):          # n iterations
        j = 1
        while j < n:            # log2(n) iterations
            ops += 1
            j *= 2
    return ops
```

### 4. Geometric Shrinking Inner Loop (Harmonic Series $\rightarrow O(n \log n)$)
When the inner loop steps by $i$ on each outer iteration $i = 1, 2, \dots, n$ (such as the Sieve of Eratosthenes divisor loop), sum the harmonic series:
$$\sum_{i=1}^{n} \frac{n}{i} = n \left(1 + \frac{1}{2} + \frac{1}{3} + \dots + \frac{1}{n}\right) \approx n \ln n = \Theta(n \log n)$$

### 5. Halving Inner Loop Governed by Outer Variable ($O(n)$)
If the outer loop halves $i$ (`n`, `n/2`, `n/4`, ...) and the inner loop runs $i$ times:
$$n + \frac{n}{2} + \frac{n}{4} + \frac{n}{8} + \dots + 1 < 2n = \Theta(n)$$
*(A geometric series whose work halves at every level is bounded by $2\times$ the top level—it is linear $O(n)$, not $O(n \log n)$.)*

## 5. Accounting for Hidden Loops in Python Built-Ins
A loop body that looks like a single line of Python may conceal an $O(n)$ or $O(k)$ internal loop:

| Python Operation | Actual Time Complexity | Hidden Cost Inside a Loop of Size $n$ |
| :--- | :--- | :--- |
| `x in my_list` / `my_list.index(x)` | $O(n)$ | Turns $O(n)$ loop into **$O(n^2)$** |
| `my_list.pop(0)` / `my_list.insert(0, x)` | $O(n)$ | Shifts all remaining pointers $\rightarrow$ **$O(n^2)$** |
| `arr[start:end]` (slicing $k$ elements) | $O(k)$ | Copies $k$ references $\rightarrow$ up to **$O(n^2)$** |
| `result += char` (string concatenation in loop) | $O(k)$ per append | Allocates new string repeatedly $\rightarrow$ **$O(n^2)$** |
| `min(arr)` / `max(arr)` / `sum(arr)` | $O(n)$ | Calling inside a loop $\rightarrow$ **$O(n^2)$** |
| `x in my_set` / `my_dict[k]` | $O(1)$ average | Keeps $O(n)$ loop at **$O(n)$** |

## 6. Worked Walkthrough: Tracing and Verifying Complex Control Flow
The example below demonstrates how to analyze a function combining sequential loops, nested loops, and conditional branches—and verifies operation counts empirically:

```python
def analyze_workflow(data: list[int], threshold: int) -> tuple[int, int]:
    """
    Step-by-step complexity analysis for input list of length n:
      1. Validation guard:          O(1)
      2. First loop (linear scan):  n iterations * O(1)          = O(n)
      3. Conditional block:
         - If branch (count > threshold):
             Triangular nested loop -> n*(n-1)/2 iterations      = O(n^2)
         - Else branch:
             Logarithmic halving loop -> log2(n) iterations      = O(log n)

    Combined Worst-Case Time: O(1) + O(n) + max(O(n^2), O(log n)) = Theta(n^2)
    Combined Best-Case Time:  O(1) + O(n) + O(log n)              = Theta(n)
    """
    if not data:
        return 0, 0

    ops = 0
    above_count = 0

    # Block 1: Single linear loop -> Theta(n)
    for val in data:
        ops += 1
        if val > threshold:
            above_count += 1

    # Block 2: Conditional with asymmetric branches
    if above_count > threshold:
        # Branch A: Dependent nested loop -> Theta(n^2)
        n = len(data)
        for i in range(n):
            for j in range(i + 1, n):
                ops += 1
    else:
        # Branch B: Logarithmic loop -> Theta(log n)
        step = len(data)
        while step > 1:
            ops += 1
            step //= 2

    return above_count, ops


if __name__ == "__main__":
    sample = list(range(100))
    # Triggers Branch B (above_count = 19 <= 80) -> O(n)
    _, best_ops = analyze_workflow(sample, threshold=80)
    # Triggers Branch A (above_count = 89 > 10)  -> O(n^2)
    _, worst_ops = analyze_workflow(sample, threshold=10)

    print(f"n = 100 | Fast branch ops (Theta(n)): {best_ops} | Slow branch ops (Theta(n^2)): {worst_ops}")
```

## 7. Common Pitfalls and Best Practices

1. **Multiplying Sequential Loops Instead of Adding Them:**
   Two consecutive loops (`for x in arr:` followed by `for y in arr:`) execute $n + n = 2n$ steps, which is **$O(n)$**, not $O(n^2)$. Only **nested** loops multiply.
2. **Assuming Every Two-Level Nested Loop Is $O(n^2)$:**
   Always inspect the loop bounds and step updates:
   * Inner loop runs constant $k$ times (`for j in range(5):`) $\rightarrow$ **$O(n)$**.
   * Inner loop doubles/halves (`j *= 2`) $\rightarrow$ **$O(n \log n)$**.
   * Inner loop advances a shared two-pointer index (`while j < n and ...: j += 1` without resetting `j`) $\rightarrow$ **$O(n)$ amortized** across the entire outer loop.
3. **Treating Two Distinct Input Sizes as the Same $n$:**
   If an outer loop iterates over `users` (size $U$) and an inner loop iterates over `roles` (size $R$), write **$O(U \cdot R)$**, not $O(n^2)$.
4. **Overlooking Conditional `break` or `return` Statements:**
   A loop with an early `return` or `break` separates **best-case** complexity (exits on iteration 1 $\rightarrow O(1)$) from **worst-case** complexity (never triggers early exit $\rightarrow O(n)$).
5. **Forgetting Python Built-In Hidden Loops:**
   Always check whether methods called inside a loop (`in` on a `list`, `pop(0)`, string `+=`, slicing `arr[:]`) perform linear scans or memory copies under the hood.

## 8. Quick Reference

| Control-Flow Construct | Combination Rule | Resulting Complexity Example |
| :--- | :--- | :--- |
| **Sequential Blocks** (`A` then `B`) | Add: $O(f(n) + g(n)) = O(\max(f, g))$ | $O(n)$ loop + $O(n \log n)$ sort $\rightarrow O(n \log n)$ |
| **Conditional (`if` / `else`)** | Worst-case max: $O(\max(T_{\text{if}}, T_{\text{else}}))$ | `if` $O(n^2)$ vs. `else` $O(n)$ $\rightarrow O(n^2)$ worst case |
| **Single Loop ($\pm c$ step)** | Iterations $\times$ body cost | `for i in range(n):` with $O(1)$ body $\rightarrow O(n)$ |
| **Single Loop ($\times c$ or $/ c$ step)** | $\log_c(n) \times$ body cost | `while i < n: i *= 2` $\rightarrow O(\log n)$ |
| **Independent Nested Loops** | Multiply: $O(\text{outer} \times \text{inner})$ | $n$ outer $\times$ $n$ inner $\rightarrow O(n^2)$ |
| **Dependent Triangular Loop** | Arithmetic sum: $\sum_{i=0}^{n-1} i = \frac{n(n-1)}{2}$ | `for i in range(n): for j in range(i):` $\rightarrow O(n^2)$ |
| **Linear $\times$ Logarithmic Loop** | Multiply: $n \times \log n$ | `for i in range(n):` with `j *= 2` inner $\rightarrow O(n \log n)$ |
| **Two-Pointer Inner `while` Loop** | Inner pointer never resets; moves $\le n$ times total | `for r in range(n): while cond: l += 1` $\rightarrow O(n)$ |
