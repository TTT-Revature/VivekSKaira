# Variables and Naming Conventions

## 1. What is a Variable?
In Python, a **variable** is a named reference (label) that points to an object stored in memory. Rather than acting as a fixed memory box with a locked type, a variable acts as a tag attached to a value.

* **No Explicit Declaration:** Variables are created the moment a value is assigned to them using the assignment operator (`=`).
* **Dynamic Typing:** A variable's type is inferred automatically at runtime and can change if reassigned to a different type of value.

```python
status = "Active"   # Points to a string object
status = 200        # Now points to an integer object
```

---

## 2. Variable Assignment Patterns

### Standard Assignment
```python
intern_name = "Vivek"
training_weeks = 12
```

### Multiple Assignment
Assign different values to multiple variables in a single line:
```python
role, track, batch = "Junior Trainer", "FDE", 2026
```

### Chained Assignment
Assign the same value to multiple variables simultaneously:
```python
x = y = z = 0
```

### Swapping Values
Python allows swapping two variable values directly without needing a temporary variable:
```python
a = 10
b = 20
a, b = b, a  # a is now 20, b is now 10
```

## 3. Variable Naming Rules (Syntax Requirements)
Python enforces strict rules for variable names (identifiers). Violating these raises a `SyntaxError`:

1. Must start with a letter (`a-z`, `A-Z`) or an underscore (`_`).
2. Cannot start with a digit (`0-9`).
3. Can only contain alphanumeric characters and underscores (`A-z`, `0-9`, `_`).
4. Spaces and special characters (`@`, `$`, `%`, `-`) are not allowed.
5. Variable names are **case-sensitive** (`count`, `Count`, and `COUNT` are three separate variables).
6. Cannot be a Python reserved keyword (`if`, `else`, `for`, `while`, `class`, `def`, `return`, `True`, `None`, etc.).

```python
# Valid variable names
user_age = 23
_internal_flag = True
score2 = 95

# Invalid variable names (will raise SyntaxError)
2nd_score = 90      # Starts with a digit
user-name = "John"  # Contains a hyphen
class = "Python"    # Uses a reserved keyword
```

## 4. Naming Conventions (PEP 8 Standards)
While Python only enforces the syntax rules above, the **PEP 8** style guide defines standard naming conventions so code remains consistent and readable across teams:

| Naming Style | Convention | Usage | Example |
| :--- | :--- | :--- | :--- |
| **`snake_case`** | All lowercase with underscores separating words | Standard variables, functions, and methods | `first_name`, `total_marks` |
| **`UPPER_SNAKE_CASE`** | All uppercase with underscores separating words | Constants (values not meant to change) | `MAX_RETRIES = 3`, `PI = 3.14` |
| **`PascalCase`** | Capitalize the first letter of each word | Class names (not standard variables) | `TrainingModule`, `UserAccount` |

### Special Underscore Conventions
* **Single Leading Underscore (`_var`):** Indicates a variable is intended for internal or private use within a module or class.
* **Single Trailing Underscore (`var_`):** Used to avoid naming conflicts with Python keywords or built-ins (e.g., `class_`, `type_`).
* **Double Leading and Trailing Underscores (`__var__`):** Reserved for Python's built-in special ("dunder") attributes such as `__name__` and `__doc__`. Avoid creating custom variables with this pattern.

---

## 5. Best Practices
* **Be Descriptive:** Choose clear names that describe what the data represents (`student_count` instead of `sc`).
* **Avoid Built-in Shadowing:** Never name variables after built-in Python functions or types such as `list`, `str`, `int`, `id`, `sum`, or `input`, as doing so overrides their built-in behavior in that scope.
