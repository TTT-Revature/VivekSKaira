# Mutable and Immutable Objects

## 1. Overview
In Python, every piece of data is an object stored in memory with a unique identity, a type, and a value. Based on whether their value can be changed after creation, objects are classified into two categories:

* **Mutable Objects:** Their internal state or content can be modified **in place** after creation without changing their memory address.
* **Immutable Objects:** Their internal state **cannot** be altered after creation. Any operation that appears to modify an immutable object actually creates a brand-new object in memory.

You can check an object's unique memory identifier using the built-in `id()` function.

---

## 2. Immutable Objects
Once an immutable object is created, its value is fixed. Reassigning a variable holding an immutable value simply points the variable name to a new memory location.

### Common Immutable Types
* Numeric types: `int`, `float`, `complex`
* Text and binary: `str`, `bytes`
* Boolean and None: `bool`, `NoneType`
* Collections: `tuple`, `frozenset`

### Example
```python
x = 10
print(id(x))  # e.g., 140712345678912

x = x + 5     # Creates a new integer object (15)
print(id(x))  # Different memory ID (e.g., 140712345679072)

text = "Hello"
# text[0] = "J"  # Raises TypeError: 'str' object does not support item assignment
text = text + " World"  # Creates a new string object
```

---

## 3. Mutable Objects
Mutable objects allow you to add, remove, or update their elements directly in memory while preserving the exact same object identity (`id`).

### Common Mutable Types
* Collections: `list`, `dict`, `set`
* Binary: `bytearray`
* Custom user-defined class instances (by default)

### Example
```python
scores = [80, 85, 90]
print(id(scores))  # e.g., 2345678901248

scores.append(95)  # Modifies the existing list in place
print(scores)      # [80, 85, 90, 95]
print(id(scores))  # Same memory ID (2345678901248)
```

---

## 4. Comparison Summary

| Feature | Mutable Objects | Immutable Objects |
| :--- | :--- | :--- |
| **In-place modification** | Allowed | Not allowed |
| **Memory address (`id`) on update** | Remains the same | Changes (new object created) |
| **Built-in examples** | `list`, `dict`, `set`, `bytearray` | `int`, `float`, `str`, `tuple`, `bool`, `frozenset` |
| **Use as dictionary keys** | No (unhashable) | Yes (hashable, if all elements are immutable) |
| **Thread safety** | Requires synchronization | Inherently thread-safe |

---

## 5. Key Nuances to Remember

### 1. Reassignment vs. Mutation
Assigning a completely new value with `=` changes the reference even for mutable types; methods like `.append()` or index updates mutate in place.
```python
items = [1, 2]
print(id(items))  # ID A

items.append(3)   # Mutation -> still ID A
items = [1, 2, 3] # Reassignment -> new ID B
```

### 2. Shared References (Aliasing)
When two variables point to the same mutable object, modifying it through one variable affects the other:
```python
list_a = [1, 2, 3]
list_b = list_a      # Both variables reference the exact same list
list_b.append(4)

print(list_a)        # [1, 2, 3, 4]
```
