# Introduction to Type Hints

## 1. What are Type Hints?
**Type hints** (introduced in Python 3.5 via **PEP 484**) are optional annotations used to specify the expected data types of variables, function parameters, and return values.

* **No Runtime Enforcement:** Python remains a **dynamically typed** language. Type hints are ignored by the Python interpreter during execution and do not raise errors if mismatched types are passed at runtime.
* **Static Analysis:** They are primarily used by IDEs (VS Code, PyCharm) and external static type checkers (such as `mypy` or `pyright`) to catch type-related bugs before code runs.

---

## 2. Why Use Type Hints?
* **Improved Readability:** Code becomes self-documenting—developers immediately know what inputs a function expects and what it returns.
* **Better IDE Autocomplete:** Editors use type annotations to provide accurate method suggestions and inline warnings.
* **Early Bug Detection:** Static type checkers flag incompatible types before deployment without executing the program.

---

## 3. Basic Type Hint Syntax

### Variable Annotations
Use a colon (`:`) followed by the expected type:
```python
intern_name: str = "Vivek"
training_weeks: int = 12
passing_score: float = 75.0
is_certified: bool = False

# Declaring a variable's type before assigning a value
final_grade: str
```

### Function Annotations
Annotate parameters with `: <type>` and the return value with `-> <type>`:
```python
def calculate_total(price: float, quantity: int) -> float:
    return price * quantity

# Use -> None when a function does not return a value
def log_message(message: str) -> None:
    print(f"[LOG]: {message}")
```

---

## 4. Annotating Collections and Multiple Types

### Built-in Collections (Python 3.9+)
Specify the inner element types inside square brackets `[]`:
```python
modules: list[str] = ["Python", "SQL", "Git"]
scores: dict[str, int] = {"Python": 92, "SQL": 88}
coordinates: tuple[float, float] = (28.61, 77.20)
unique_ids: set[int] = {101, 102, 103}
```
*(Note: In Python versions prior to 3.9, import capitalized equivalents from the `typing` module: `from typing import List, Dict, Tuple, Set`.)*

### Union and Optional Types
When a variable or parameter can accept more than one type—or `None`:
```python
from typing import Any, Optional, Union

# Union (Python 3.10+ pipe syntax vs. older typing.Union)
user_id: int | str = "EMP-402"
legacy_id: Union[int, str] = 402

# Optional (indicates a value can be the specified type or None)
middle_name: str | None = None
legacy_middle: Optional[str] = None

# Any (disables type checking for that variable)
dynamic_payload: Any = {"status": 200}
```

## 5. Runtime Behavior vs. Static Checking

### At Runtime (Python Interpreter)
Python stores annotations in a special `__annotations__` dictionary but does not enforce them:
```python
def add_numbers(a: int, b: int) -> int:
    return a + b

# Runs without error at runtime despite passing strings
print(add_numbers("Hello, ", "World"))  # Output: Hello, World

# Inspect stored annotations
print(add_numbers.__annotations__)
# {'a': <class 'int'>, 'b': <class 'int'>, 'return': <class 'int'>}
```

### Static Type Checking (`mypy`)
Running a static checker from the terminal catches the mismatch without running the script:
```bash
pip install mypy
mypy script.py
# error: Argument 1 to "add_numbers" has incompatible type "str"; expected "int"
```

## 6. Quick Reference

| Annotation | Meaning | Example |
| :--- | :--- | :--- |
| `x: int` | Integer value | `count: int = 5` |
| `x: str` | String value | `role: str = "FDE"` |
| `list[T]` | List containing elements of type `T` | `names: list[str] = ["A", "B"]` |
| `dict[K, V]` | Dictionary with key type `K` and value type `V` | `ages: dict[str, int] = {"Sam": 24}` |
| `T1 \| T2` | Value can be either `T1` or `T2` | `code: int \| str = 200` |
| `T \| None` | Value can be `T` or `None` | `token: str \| None = None` |
| `-> None` | Function returns nothing | `def reset() -> None:` |
