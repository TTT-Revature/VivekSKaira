# Absolute and Relative Imports in Python

## 1. Overview
When organizing a Python project into packages and subpackages, modules frequently need to share functions, classes, and constants. Python provides two explicit mechanisms for importing modules within a package hierarchy:

* **Absolute Imports:** Specify the full import path starting from the **top-level package root** located on `sys.path`.
* **Relative Imports:** Specify the target module's location **relative to the current module's package** (`__package__`) using leading dots (`.`, `..`).

*(Note: Python 3 requires all relative imports to be **explicit** with leading dots. Python 2's implicit relative imports—such as writing `import helper` inside a package to import a sibling file—are no longer supported.)*

---

## 2. Reference Package Structure
All examples in this guide use the following multi-level project structure, assuming `project_root/` is the current working directory (or `src/` is installed in editable mode):

```text
project_root/
├── main.py
└── fde_platform/
    ├── __init__.py
    ├── config.py
    ├── core/
    │   ├── __init__.py

    ├── services/
    │   ├── __init__.py

    │   └── reporting.py
    └── utils/
        ├── __init__.py

```

## 3. Absolute Imports
An **absolute import** traces the complete path from the project's top-level root package down to the desired module or object, regardless of where the importing file sits in the directory tree.

### How Python Resolves Absolute Imports
1. Python searches **`sys.modules`** first to check if the module is already loaded and cached.
2. If not cached, Python searches the directories listed in **`sys.path`** in order:
   * The directory of the entry-point script (or current working directory when using `python -m`).
   * Directories listed in the `PYTHONPATH` environment variable.
   * Standard library directories.
   * Third-party `site-packages` directories in the active virtual environment.

### Examples
```python
# File: fde_platform/services/grading.py

# 1. Importing a top-level package module
from fde_platform import config

# 2. Importing specific classes/exceptions from a sibling subpackage
from fde_platform.core.models import Trainee
from fde_platform.core.exceptions import GradingError

# 3. Importing a helper function from another subpackage
from fde_platform.utils.formatters import format_percentage


def compute_final_grade(trainee: Trainee, raw_score: float) -> str:
    if raw_score < 0 or raw_score > config.MAX_SCORE:
        raise GradingError(f"Invalid score {raw_score} for {trainee.name}")
    return format_percentage(raw_score, config.MAX_SCORE)
```

### Advantages of Absolute Imports
* **Self-Documenting:** Immediately tells any reader the exact location of the imported symbol inside the repository.
* **Resilient to File Moves:** Moving `grading.py` into another subpackage does not break its own outgoing absolute imports.
* **PEP 8 Recommended Default:** Recommended by PEP 8 for clarity and predictable error messages.

## 4. Relative Imports
A **relative import** locates a module relative to the **current module's position** inside its package using leading dots in a `from ... import ...` statement.

### Leading-Dot Notation Rules
* **Single dot (`.`):** Current package directory (same folder as the current file).
* **Double dot (`..`):** Parent package directory (one level up).
* **Triple dot (`...`):** Grandparent package directory (two levels up; each additional dot moves one package level higher).

### Examples
```python
# File: fde_platform/services/reporting.py

# 1. Single dot (.): import from a sibling module in the same package (fde_platform.services)
from . import grading
from .grading import compute_final_grade

# 2. Double dot (..): import from the parent package (fde_platform)
from .. import config

# 3. Double dot + subpackage (..subpkg): import from sibling subpackages
from ..core.models import Trainee
from ..utils.formatters import format_percentage


def build_summary(trainee: Trainee, score: float) -> str:
    grade = compute_final_grade(trainee, score)
    pct = format_percentage(score, config.MAX_SCORE)
    return f"{trainee.name}: {grade} ({pct})"
```

### Relative Imports Inside `__init__.py`
Inside a package's `__init__.py`, a single dot (`.`) refers to that package itself—making relative imports ideal for re-exporting public symbols cleanly:

```python
# File: fde_platform/core/__init__.py
from .models import Trainee
from .exceptions import GradingError

__all__ = ["Trainee", "GradingError"]
```

## 5. Side-by-Side Comparison

| Dimension | Absolute Import | Relative Import |
| :--- | :--- | :--- |
| **Syntax** | `from pkg.sub import item` or `import pkg.sub` | `from . import mod` or `from ..sub import item` |
| **Resolution Anchor** | Top-level directories on `sys.path` | Current module's `__package__` attribute |
| **Plain `import` Allowed?** | Yes (`import fde_platform.config`) | **No** (`import .config` is a `SyntaxError`) |
| **Readability** | Explicit full path; clear from anywhere | Concise for closely related internal modules |
| **Renaming Top-Level Package** | Requires updating every import across the codebase | Internal package imports continue working unchanged |
| **Moving Current File** | Outgoing imports remain valid | Relative dot paths (`..`) must be recalculated |
| **Direct Script Execution** | Works if project root is on `sys.path` | Fails unless executed as a module (`python -m`) |

## 6. Executing Package Modules (`python -m`)
A common source of import errors occurs when running a submodule directly from the terminal.

### Why Direct File Execution Breaks Relative Imports
When you run:
```bash
# Running a submodule file directly as a script:
python fde_platform/services/reporting.py
```
Python treats `reporting.py` as a standalone top-level script rather than part of `fde_platform.services`:
* `__name__` is set to `"__main__"`.
* `__package__` is set to `None`.
* `sys.path[0]` becomes `project_root/fde_platform/services/` instead of `project_root/`.

Because `__package__` is `None`, Python has no package anchor to resolve `.` or `..`, raising:
```text
ImportError: attempted relative import with no known parent package
```

### The Standard Solution: Run with `-m` from Project Root
Execute modules inside a package using Python's **`-m` (module) flag** (without the `.py` extension) from `project_root/`:

```bash
# Executes fde_platform/services/reporting.py with __package__ == "fde_platform.services"
python -m fde_platform.services.reporting
```
With `-m`, Python adds the current working directory (`project_root/`) to `sys.path[0]` and sets `__package__` properly, allowing **both absolute and relative imports** to resolve cleanly.

## 7. Common Pitfalls and Best Practices

### 1. Using `import .module` Syntax (SyntaxError)
Relative imports **must** always use the `from ... import ...` form:
```python
# PITFALL: SyntaxError: invalid syntax
# import .grading

# CORRECT:
from . import grading
```

### 2. Traversing Above the Top-Level Package
Using more leading dots than the depth of the package hierarchy attempts to escape the top-level package and raises an error:
```python
# Inside fde_platform/services/reporting.py (only 2 levels deep inside fde_platform):
# PITFALL: ImportError: attempted relative import beyond top-level package
# from ...outside_module import something
```

### 3. Avoid `sys.path.append(...)` Hacks in Production Code
Manually mutating `sys.path` inside source files (`sys.path.append("../..")`) makes imports fragile, breaks static analysis tools (`mypy`, IDE navigation), and depends on the caller's working directory. Instead:
* Run modules with **`python -m package.module`** from the project root, or
* Configure a `pyproject.toml` and install the package in editable mode (`pip install -e .`).

### 4. Practical Guidelines for Choosing Between Both Styles
* **Use Absolute Imports by default** across application layers, entry points (`main.py`), and `tests/`.
* **Use Relative Imports selectively** inside cohesive subpackages (such as `from .models import User` inside `auth/`) and in `__init__.py` facade files where subpackages are tightly coupled and might be renamed as a unit.
* **Keep relative imports shallow:** Avoid chains deeper than two dots (`..`); if you need `...` or `....`, switch to an absolute import for readability.

## 8. Quick Reference

| Syntax | Import Type | Target Resolved (from `fde_platform/services/reporting.py`) |
| :--- | :--- | :--- |
| `from fde_platform.config import MAX_SCORE` | Absolute | `fde_platform/config.py` -> `MAX_SCORE` |
| `import fde_platform.utils.formatters as fmt` | Absolute | `fde_platform/utils/formatters.py` aliased as `fmt` |
| `from . import grading` | Relative (current pkg) | `fde_platform/services/grading.py` |
| `from .grading import compute_final_grade` | Relative (current pkg) | `fde_platform/services/grading.py` -> `compute_final_grade` |
| `from .. import config` | Relative (parent pkg) | `fde_platform/config.py` |
| `from ..core.models import Trainee` | Relative (sibling subpkg) | `fde_platform/core/models.py` -> `Trainee` |
| `python -m fde_platform.services.reporting` | CLI execution | Runs submodule with `__package__` intact |
