# Attributes, Methods, `__init__` and `self`

## 1. Overview
In Python's object-oriented model, every object combines **state** (data stored inside the object) with **behavior** (functions that operate on that data). Four foundational mechanisms make this work:

* **`self`:** The explicit reference to the specific object instance currently executing a method.
* **`__init__`:** The special initializer method that sets up an object's starting state right after creation.
* **Attributes:** Variables bound to an instance (`self.attr`) or a class (`ClassName.attr`) that store data.
* **Methods:** Functions defined inside a class body that define how instances or the class itself behave.

---

## 2. Understanding `self`
In Python, **`self`** is the conventional name for the first parameter of every instance method. It holds a reference to the exact instance on which the method was called, allowing different objects of the same class to maintain separate data.

### How Python Passes `self` Automatically
When you call a method on an object (`account.deposit(500)`), Python automatically translates that call into a function call on the class, passing the object itself as the first positional argument:

```python
class Wallet:
    def add_funds(self, amount: float) -> None:
        self.balance += amount

w = Wallet()
w.balance = 100.0

# Both statements are identical under the hood:
w.add_funds(50.0)           # Bound method call (Python passes 'w' as 'self')
Wallet.add_funds(w, 50.0)   # Unbound call on the class (explicitly passing 'w')

print(w.balance)            # 150.0
```

### Key Rules About `self`
1. **Convention, Not a Keyword:** `self` is not a reserved keyword in Python, though PEP 8 strictly mandates naming the first parameter `self` for readability across all Python codebases.
2. **Required in Definition, Omitted in Call:** You must declare `self` in the method signature (`def reset(self):`), but you never pass it manually when calling `obj.reset()`.
3. **Why Omitting `self` Fails:** Defining `def reset():` inside a class and calling `obj.reset()` raises `TypeError: Wallet.reset() takes 0 positional arguments but 1 was given`.

## 3. The `__init__` Initializer Method
**`__init__`** (pronounced "dunder init") is a special **dunder (double-underscore) method** invoked automatically whenever a new instance is created from a class. Its purpose is to initialize the instance's attributes with valid starting values.

### `__new__` vs. `__init__`
Object instantiation happens in two sequential steps:
1. **`__new__(cls, ...)`:** Allocates memory and creates the raw, uninitialized object instance, then returns it.
2. **`__init__(self, ...)`:** Receives that newly created instance as `self` and populates its initial attributes. Because `__init__` only configures an existing object, it **must always return `None`**.

```python
class DeploymentJob:
    """Represents a cloud deployment task with validated initial parameters."""

    def __init__(
        self,
        service_name: str,
        environment: str = "staging",
        retries: int = 3,
    ) -> None:
        if retries < 0:
            raise ValueError("retries cannot be negative")

        # Instance attributes initialized on 'self'
        self.service_name = service_name
        self.environment = environment
        self.retries = retries
        self.status = "PENDING"  # Default state not passed as a parameter

job1 = DeploymentJob("auth-api")
job2 = DeploymentJob("billing-worker", environment="production", retries=5)

print(job1.service_name, job1.environment, job1.status)  # auth-api staging PENDING
print(job2.service_name, job2.environment, job2.retries) # billing-worker production 5
```

## 4. Attributes: Instance vs. Class Attributes
Attributes are variables attached to objects or classes. Where an attribute is assigned determines its lifetime and whether it is isolated per object or shared globally across all instances.

### 1. Instance Attributes
* Defined inside `__init__` (or other instance methods) using **`self.attribute_name = value`**.
* Stored in each instance's private namespace dictionary (**`obj.__dict__`**).
* Modifying an instance attribute affects **only that single object**.

### 2. Class Attributes
* Defined directly inside the `class` block outside any method.
* Stored in the class's namespace dictionary (**`ClassName.__dict__`**).
* Shared across the class and every instance created from it.

### Attribute Lookup Order and Shadowing
When evaluating `obj.attr`, Python follows a strict lookup chain:
1. Check **`obj.__dict__`** (instance namespace).
2. If not found, check **`ClassName.__dict__`** (class namespace).
3. If still not found, walk parent classes in Method Resolution Order (**MRO**), raising `AttributeError` if absent everywhere.

Assigning **`obj.class_attr = new_value`** does **not** overwrite the class attribute—instead, it creates a new instance attribute inside `obj.__dict__` that **shadows** the class attribute for that specific object:

```python
class ServerNode:
    # Class attributes (shared defaults and tracking)
    default_region = "ap-south-1"
    active_nodes = 0

    def __init__(self, hostname: str, cpu_cores: int) -> None:
        # Instance attributes (unique per object)
        self.hostname = hostname
        self.cpu_cores = cpu_cores
        ServerNode.active_nodes += 1

node_a = ServerNode("web-01", 4)
node_b = ServerNode("db-01", 16)

print(ServerNode.active_nodes)  # 2
print(node_a.default_region)    # 'ap-south-1' (found on ServerNode)

# Shadowing 'default_region' on node_a only
node_a.default_region = "us-east-1"

print(node_a.default_region)    # 'us-east-1' (resolved from node_a.__dict__)
print(node_b.default_region)    # 'ap-south-1' (resolved from ServerNode.__dict__)
print(vars(node_a))             # {'hostname': 'web-01', 'cpu_cores': 4, 'default_region': 'us-east-1'}
print(vars(node_b))             # {'hostname': 'db-01', 'cpu_cores': 16}
```

### Instance vs. Class Attributes Summary

| Dimension | Instance Attribute | Class Attribute |
| :--- | :--- | :--- |
| **Syntax** | `self.name = "Alice"` | `org = "Revature"` (in class body) |
| **Storage Location** | `instance.__dict__` | `ClassName.__dict__` |
| **Scope** | Isolated to a single object | Shared across all instances of the class |
| **Access Pattern** | `instance.name` | `ClassName.org` (recommended) or `instance.org` |
| **Typical Use Case** | Entity fields (`id`, `email`, `balance`) | Constants, shared configuration, instance counters |

## 5. Methods: Instance, Class, and Static Methods
Methods are functions defined inside a class that encapsulate behavior. Python supports three method types based on how they interact with `self` and the class (`cls`).

### 1. Instance Methods
* Take **`self`** as their first parameter.
* Read and update instance attributes (`self.attr`) and can inspect class attributes (`type(self).class_attr`).

### 2. Class Methods (`@classmethod`)
* Decorated with **`@classmethod`** and take **`cls`** (the class itself) as their first parameter.
* Operate on class-level state and serve as **alternative constructors** (factory methods) that build instances from different input formats.

### 3. Static Methods (`@staticmethod`)
* Decorated with **`@staticmethod`** and take **neither `self` nor `cls`**.
* Function as self-contained utility or validation helpers logically grouped within the class namespace.

```python
class ExamAttempt:
    passing_threshold = 70.0  # Class attribute

    def __init__(self, candidate: str, score: float) -> None:
        self.candidate = candidate
        self.score = score

    # 1. Instance method: reads instance state ('self.score') and class state
    def has_passed(self) -> bool:
        return self.score >= self.passing_threshold

    # 2. Class method: updates class-level configuration
    @classmethod
    def set_passing_threshold(cls, new_threshold: float) -> None:
        if not (0.0 <= new_threshold <= 100.0):
            raise ValueError("Threshold must be between 0 and 100.")
        cls.passing_threshold = new_threshold

    # 2b. Class method: alternative constructor from dictionary payload
    @classmethod
    def from_dict(cls, payload: dict[str, str | float]) -> "ExamAttempt":
        return cls(
            candidate=str(payload["candidate"]),
            score=float(payload["score"]),
        )

    # 3. Static method: pure helper with no dependency on 'self' or 'cls'
    @staticmethod
    def calculate_percentage(obtained: float, maximum: float) -> float:
        if maximum <= 0:
            raise ValueError("Maximum marks must be positive.")
        return round((obtained / maximum) * 100, 2)

pct = ExamAttempt.calculate_percentage(42, 50)            # 84.0
attempt = ExamAttempt.from_dict({"candidate": "Vivek", "score": pct})
print(attempt.has_passed())                               # True

ExamAttempt.set_passing_threshold(85.0)
print(attempt.has_passed())                               # False
```

### Method Types Comparison

| Method Type | Decorator | Implicit First Arg | Can Access `self`? | Can Access `cls`? | Primary Purpose |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Instance Method** | None | `self` | Yes | Yes (`type(self)`) | Read or mutate object-specific state |
| **Class Method** | `@classmethod` | `cls` | No | Yes | Mutate class state; provide factory constructors |
| **Static Method** | `@staticmethod` | None | No | No | Group stateless helper/validation logic inside the class |

## 6. Common Pitfalls and Best Practices

### 1. Returning a Value from `__init__`
`__init__` is an initializer, not a factory. Returning anything other than `None` immediately raises `TypeError`:

```python
class Broken:
    def __init__(self, x: int):
        self.x = x
        return self  # TypeError: __init__() should return None, not 'Broken'
```

### 2. Mutable Default Arguments in `__init__`
Default parameter values are evaluated once at function definition time. Using `tags: list[str] = []` causes every instance created without an explicit `tags` argument to share the **exact same list** in memory:

```python
# PITFALL: Shared mutable list across instances
class TagBucketBroken:
    def __init__(self, tags: list[str] = []) -> None:
        self.tags = tags

# CORRECT: Default to None and allocate a fresh list inside __init__
class TagBucketSafe:
    def __init__(self, tags: list[str] | None = None) -> None:
        self.tags = list(tags) if tags is not None else []
```

### 3. In-Place Mutation vs. Rebinding of Class Attributes
* **Rebinding (`obj.count += 1`):** Creates a new instance attribute `obj.count` that shadows `ClassName.count`.
* **In-place mutation (`obj.shared_list.append("x")`):** Modifies the underlying mutable class attribute in place, affecting **all** instances. Always store per-instance mutable collections inside `__init__`.

### 4. Declare All Instance Attributes in `__init__`
Initialize every instance attribute inside `__init__` (using `None` if a value is not yet available) rather than adding new `self.attr` assignments later in arbitrary methods. This prevents unexpected `AttributeError` failures and keeps `vars(obj)` consistent.

## 7. Quick Reference

| Element | Syntax | Key Behavior |
| :--- | :--- | :--- |
| `self` | `def method(self, arg):` | Refers to the calling instance; passed automatically by Python |
| `__init__` | `def __init__(self, ...):` | Initializes attributes on a newly created object; must return `None` |
| Instance attribute | `self.attr = val` | Stored in `obj.__dict__`; unique to each instance |
| Class attribute | `attr = val` (class body) | Stored in `Class.__dict__`; shared across all instances |
| Attribute lookup | `obj.attr` | Searches `obj.__dict__` first, then `Class.__dict__`, then parent MRO |
| Instance method | `def fn(self, ...):` | Operates on instance data via `self` |
| Class method | `@classmethod def fn(cls, ...):` | Operates on class state via `cls`; ideal for alternative constructors |
| Static method | `@staticmethod def fn(...):` | Utility function inside class namespace without `self` or `cls` |
