# Instance, Class, and Static Methods in Python

## 1. Overview
In Python, methods defined inside a class fall into three categories depending on **what state they receive automatically** when called:

* **Instance Methods (default):** Receive the specific object instance (**`self`**) as the first argument. Used to read or modify instance-specific state.
* **Class Methods (`@classmethod`):** Receive the class object (**`cls`**) as the first argument. Used to access or modify class-level state and build alternative constructors (factory methods).
* **Static Methods (`@staticmethod`):** Receive **neither `self` nor `cls`**. Behave like regular functions placed inside the class namespace for logical grouping and domain cohesion.

---

## 2. Instance Methods
Instance methods are the standard methods in any Python class. They require at least one parameter—conventionally named **`self`**—which Python binds automatically to the instance on which the method is invoked.

### Capabilities and Behavior
* Can read and mutate **instance attributes** (`self.attr`).
* Can read and mutate **class attributes** (via `type(self).attr` or `ClassName.attr`).
* Can call other instance, class, or static methods on `self`.
* Calling `instance.method(arg)` is syntactic shorthand for calling `ClassName.method(instance, arg)`.

```python
class TrainingSession:
    platform = "Revature LMS"

    def __init__(self, topic: str, duration_mins: int) -> None:
        self.topic = topic
        self.duration_mins = duration_mins
        self.completed = False

    def mark_completed(self) -> None:
        """Instance method: mutates instance-specific state via 'self'."""
        self.completed = True

    def summary(self) -> str:
        """Instance method: reads both instance ('self') and class attributes."""
        status = "Done" if self.completed else "Pending"
        return f"[{self.platform}] {self.topic} ({self.duration_mins}m) - {status}"

session = TrainingSession("Python OOP", 60)

# Both calls below execute the exact same logic:
session.mark_completed()
# TrainingSession.mark_completed(session)

print(session.summary())  # [Revature LMS] Python OOP (60m) - Done
```

## 3. Class Methods (`@classmethod`)
Decorating a method with **`@classmethod`** tells Python to pass the **class itself (`cls`)** as the first argument instead of an instance—whether the method is invoked on the class (`Employee.from_csv(...)`) or on an instance (`emp.from_csv(...)`).

### Capabilities and Primary Use Cases
1. **Alternative Constructors (Factory Methods):** Python classes support only a single `__init__` method. `@classmethod` lets you define clean factory constructors (such as `from_string()`, `from_dict()`, or `from_json()`) that parse external formats and return `cls(...)`.
2. **Managing Shared Class State:** Safely reads or updates class attributes across the class hierarchy.
3. **Inheritance and Polymorphism Support:** Because `cls` dynamically refers to whichever class or subclass called the method, factory methods automatically instantiate the **subclass** rather than hardcoding the parent class.

```python
class Employee:
    organization = "Revature"
    total_created = 0

    def __init__(self, name: str, department: str) -> None:
        self.name = name
        self.department = department
        Employee.total_created += 1

    @classmethod
    def from_csv_row(cls, row: str) -> "Employee":
        """Alternative constructor: instantiates 'cls' dynamically (subclass-friendly)."""
        name, department = [item.strip() for item in row.split(",")]
        return cls(name, department)

    @classmethod
    def update_organization(cls, new_org: str) -> None:
        """Modifies class-level state via 'cls'."""
        cls.organization = new_org

class Trainer(Employee):
    def describe(self) -> str:
        return f"Trainer {self.name} | Dept: {self.department} | Org: {self.organization}"

# Calling from_csv_row on Trainer passes cls=Trainer, returning a Trainer object
trainer = Trainer.from_csv_row("Vivek Singh Kaira, Forward Deployed Engineering")
print(type(trainer) is Trainer)  # True
print(trainer.describe())        # Trainer Vivek Singh Kaira | Dept: Forward Deployed Engineering | Org: Revature
```

## 4. Static Methods (`@staticmethod`)
Decorating a method with **`@staticmethod`** disables automatic binding completely—Python passes neither `self` nor `cls`. Internally, a static method is a plain function stored inside the class's namespace.

### Capabilities and When to Use
* **No Access to State:** Cannot read or modify instance attributes (`self`) or class attributes (`cls`) unless explicitly passed as regular parameters.
* **Callable Both Ways:** Can be invoked via `ClassName.helper(...)` without creating an instance, or via `instance.helper(...)`.
* **Best Used For:** Pure validation helpers, formatting routines, or domain calculations that belong conceptually to the class but do not depend on object or class state.

```python
import re

class EmailValidator:
    def __init__(self, allowed_domains: set[str]) -> None:
        self.allowed_domains = allowed_domains

    def is_permitted(self, email: str) -> bool:
        """Instance method: depends on 'self.allowed_domains'."""
        if not self.has_valid_syntax(email):
            return False
        domain = email.split("@")[-1].lower()
        return domain in self.allowed_domains

    @staticmethod
    def has_valid_syntax(email: str) -> bool:
        """Static method: pure validation check needing neither 'self' nor 'cls'."""
        pattern = r"^[\w.+-]+@[\w-]+\.[\w.-]+$"
        return bool(re.match(pattern, email.strip()))

# Called directly on the class without instantiation
print(EmailValidator.has_valid_syntax("vivek@revature.com"))  # True

# Also accessible through an instance
validator = EmailValidator({"revature.com", "amity.edu"})
print(validator.is_permitted("vivek@revature.com"))           # True
print(validator.is_permitted("user@unknown.org"))             # False
```

## 5. Side-by-Side Comparison

| Feature | Instance Method | Class Method | Static Method |
| :--- | :--- | :--- | :--- |
| **Decorator** | None (default) | `@classmethod` | `@staticmethod` |
| **Implicit First Argument** | `self` (the instance) | `cls` (the class) | None |
| **Called On** | Instance (`obj.fn()`) | Class (`Cls.fn()`) or Instance (`obj.fn()`) | Class (`Cls.fn()`) or Instance (`obj.fn()`) |
| **Reads / Mutates `self`?** | Yes | No | No |
| **Reads / Mutates `cls`?** | Yes (via `type(self)`) | Yes (directly via `cls`) | No (unless hardcoded by class name) |
| **Polymorphic Across Subclasses?** | Yes (`self` is subclass instance) | Yes (`cls` is subclass type) | No (unaware of calling class) |
| **Primary Use Cases** | Core object behavior and state mutation | Alternative constructors (`from_*`), class configuration | Stateless domain utilities and input validators |

## 6. How Python Binds Methods Under the Hood
In Python, regular functions implement the **descriptor protocol** (`__get__`), which controls what happens when an attribute is looked up on a class versus an instance:

1. **Regular Function (Instance Method):**
   * Accessed on the class (`Demo.inst_m`): returns the raw **`function`** object.
   * Accessed on an instance (`d.inst_m`): invokes `__get__`, returning a **`bound method`** object that automatically prepends `d` as `self`.
2. **`@classmethod` Descriptor:**
   * Accessed on either the class (`Demo.cls_m`) or an instance (`d.cls_m`): returns a **`bound method`** bound to the class (`Demo`), automatically prepending `Demo` as `cls`.
3. **`@staticmethod` Descriptor:**
   * Accessed on either the class (`Demo.stat_m`) or an instance (`d.stat_m`): suppresses binding and returns the underlying **`function`** object unchanged.

```python
class Demo:
    def inst_m(self) -> None:
        pass

    @classmethod
    def cls_m(cls) -> None:
        pass

    @staticmethod
    def stat_m() -> None:
        pass

d = Demo()
print(type(Demo.inst_m), type(d.inst_m))  # <class 'function'> <class 'method'>
print(type(Demo.cls_m), type(d.cls_m))    # <class 'method'> <class 'method'>
print(type(Demo.stat_m), type(d.stat_m))  # <class 'function'> <class 'function'>
```

## 7. Common Pitfalls and Best Practices

### 1. Hardcoding the Class Name Inside a `@classmethod` Factory
Always instantiate **`cls(...)`** inside a `@classmethod` rather than hardcoding `ParentClass(...)`. Hardcoding the parent class name breaks inheritance by returning a parent instance instead of a subclass instance:

```python
class Config:
    def __init__(self, data: dict) -> None:
        self.data = data

    # PITFALL: Always returns Config even when called as AppConfig.from_defaults()
    # @classmethod
    # def from_defaults(cls):
    #     return Config({"debug": False})

    # CORRECT: Uses 'cls' so subclasses return instances of themselves
    @classmethod
    def from_defaults(cls) -> "Config":
        return cls({"debug": False})
```

### 2. Using `@staticmethod` When `@classmethod` Is Appropriate
If a utility method references the class name inside its body (e.g., `if count > MyClass.MAX_ITEMS:` or `return MyClass(...)`), make it a **`@classmethod`** using `cls` so subclasses inherit and override class attributes cleanly.

### 3. Omitting `self` or `cls` in Method Signatures
* Defining `def run():` without `@staticmethod` and calling `obj.run()` raises `TypeError: run() takes 0 positional arguments but 1 was given`.
* Defining `@classmethod def create():` without `cls` and calling `Cls.create()` raises the same `TypeError` because Python still attempts to pass `cls` as the first argument.

### 4. Decision Checklist: Choosing the Right Method Type
* **Does the method need access to specific instance attributes (`self.x`)?** -> Use an **instance method**.
* **Does the method create new instances of the class or access/modify class-level state (`cls.x`)?** -> Use a **`@classmethod`**.
* **Is the logic closely tied to the class's domain, yet needs neither `self` nor `cls`?** -> Use a **`@staticmethod`** (or a module-level function if it applies across multiple unrelated classes).

---

## 8. Quick Reference

| Syntax | Bound Parameter | Invocation Pattern | Key Takeaway |
| :--- | :--- | :--- | :--- |
| `def fn(self, ...):` | `self` (instance) | `obj.fn(...)` | Default method type; operates on per-object state |
| `@classmethod` + `def fn(cls, ...):` | `cls` (class) | `Cls.fn(...)` or `obj.fn(...)` | Ideal for factory constructors and subclass-aware class logic |
| `@staticmethod` + `def fn(...):` | None | `Cls.fn(...)` or `obj.fn(...)` | Plain function namespaced inside a class; zero implicit arguments |
