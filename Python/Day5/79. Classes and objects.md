# Classes and Objects in Python

## 1. Overview
**Object-Oriented Programming (OOP)** is a programming paradigm that structures software around **objects**—self-contained units that bundle data (state) and functions (behavior) together. In Python, every value (integers, strings, lists, functions, and modules) is an object derived from a class.

* **Class:** A blueprint or user-defined type (created with the `class` keyword) that defines the structure, attributes, and methods shared by all objects of that kind.
* **Object (Instance):** A concrete realization created (**instantiated**) from a class. Each instance maintains its own independent state in memory while sharing the class's behavior.
* **Naming Convention (PEP 8):** Use **`PascalCase`** (CapWords) for class names (e.g., `BankAccount`, `TraineeProfile`) and **`snake_case`** for instance variables, attributes, and methods.

## 2. Defining a Class and Creating Objects

### The `__init__` Initializer and `self`
When you call a class like a function (`Trainee("Vivek", "FDE")`), Python creates a new instance in memory and automatically invokes its **`__init__`** method to initialize the object's starting attributes.

* **`self`:** Represents the specific instance being initialized or operated on. Python passes `self` automatically as the first argument to every instance method—you include `self` in the method definition, but omit it when calling the method.
* **`__init__` vs. Constructor:** Technically, `__new__` creates and returns the raw instance, while `__init__` initializes it and must always return `None`.

```python
class Trainee:
    """Represents a trainee enrolled in a technical training track."""

    def __init__(self, name: str, track: str, score: float = 0.0) -> None:
        # Instance attributes bound to 'self'
        self.name = name
        self.track = track
        self.score = score

    def update_score(self, points: float) -> None:
        """Instance method that modifies the instance's state."""
        self.score += points

    def summary(self) -> str:
        """Instance method that reads the instance's state."""
        return f"{self.name} ({self.track}) - Score: {self.score:.1f}"

# Instantiating two independent objects from the Trainee class
t1 = Trainee("Vivek", "FDE", 90.0)
t2 = Trainee("Rashi", "Data Science")

t1.update_score(5.5)
print(t1.summary())  # Vivek (FDE) - Score: 95.5
print(t2.summary())  # Rashi (Data Science) - Score: 0.0
```

## 3. Instance Attributes vs. Class Attributes
Attributes store data on classes and objects. Where an attribute is defined determines whether it is unique to each object or shared across all instances.

| Feature | Instance Attribute | Class Attribute |
| :--- | :--- | :--- |
| **Where Defined** | Inside `__init__` (or other methods) via `self.attr = val` | Directly inside the `class` body outside any method |
| **Ownership & Storage** | Unique to each object; stored in `instance.__dict__` | Shared by the class and all instances; stored in `ClassName.__dict__` |
| **How Accessed** | `instance.attr` | `ClassName.attr` (preferred) or `instance.attr` |
| **Best Used For** | Object-specific state (`name`, `balance`, `id`) | Constants, shared defaults, or class-wide counters (`organization`, `tax_rate`) |

### Attribute Lookup Order and Shadowing
When reading `obj.attr`, Python searches **`obj.__dict__` first**, and only falls back to **`ClassName.__dict__`** (and parent classes) if the attribute is not found on the instance. Assigning `obj.class_attr = new_val` creates a new **instance attribute** that shadows the class attribute on that specific object without changing it for other instances.

```python
class Employee:
    # Class attributes shared across all instances
    company = "Revature"
    employee_count = 0

    def __init__(self, name: str, role: str) -> None:
        # Instance attributes unique to each object
        self.name = name
        self.role = role
        Employee.employee_count += 1

emp1 = Employee("Vivek", "Junior Trainer Intern")
emp2 = Employee("Lakshya", "AI Engineer")

print(Employee.employee_count)  # 2
print(emp1.company)             # 'Revature' (resolved from class)

# Assigning via 'emp1' creates an instance attribute shadowing Employee.company
emp1.company = "Client Site"
print(emp1.company)             # 'Client Site' (from emp1.__dict__)
print(emp2.company)             # 'Revature' (unchanged on class and emp2)
print(Employee.company)         # 'Revature'
```

## 4. Types of Methods (`self`, `@classmethod`, `@staticmethod`)
A class can define three distinct kinds of methods depending on what state they need to access:

### 1. Instance Methods (Default)
* Receive the instance **`self`** as the first parameter.
* Can read and modify both **instance attributes** (`self.x`) and **class attributes** (`self.__class__.y`).

### 2. Class Methods (`@classmethod`)
* Receive the class **`cls`** as the first parameter.
* Can read and modify **class attributes**, but cannot access instance-specific attributes.
* Commonly used as **alternative constructors** (factory methods) to instantiate objects from alternative input formats (strings, dictionaries, JSON).

### 3. Static Methods (`@staticmethod`)
* Receive neither `self` nor `cls`.
* Behave like regular functions placed inside the class namespace for logical organization and validation helpers.

```python
class Course:
    platform = "Revature LMS"

    def __init__(self, code: str, title: str, credits: int) -> None:
        self.code = code
        self.title = title
        self.credits = credits

    # 1. Instance method: operates on a specific Course object
    def describe(self) -> str:
        return f"[{self.code}] {self.title} ({self.credits} credits) on {self.platform}"

    # 2. Class method: alternative constructor parsing a delimited string
    @classmethod
    def from_string(cls, raw: str) -> "Course":
        code, title, credits_str = [part.strip() for part in raw.split("|")]
        return cls(code, title, int(credits_str))

    # 3. Static method: self-contained utility check
    @staticmethod
    def is_valid_code(code: str) -> bool:
        return len(code) == 6 and code[:2].isalpha() and code[2:].isdigit()

c1 = Course.from_string("PY1010 | Core Python | 4")
print(c1.describe())                      # [PY1010] Core Python (4 credits) on Revature LMS
print(Course.is_valid_code("PY1010"))     # True
```

### Method Comparison Table

| Method Type | Decorator | First Parameter | Accesses Instance State (`self`)? | Accesses Class State (`cls`)? |
| :--- | :--- | :--- | :--- | :--- |
| **Instance Method** | None | `self` | Yes | Yes (via `type(self)` or `self.__class__`) |
| **Class Method** | `@classmethod` | `cls` | No | Yes |
| **Static Method** | `@staticmethod` | None | No | No |

## 5. Essential Object Representations (`__str__` vs. `__repr__`)
By default, printing a custom object outputs its class name and memory address (e.g., `<__main__.Course object at 0x...>`). Implementing **`__repr__`** and **`__str__`** gives objects clear string representations:

* **`__repr__(self)`:** Unambiguous, developer-oriented representation (ideally valid Python syntax that could recreate the object). Used by `repr()`, interactive consoles, debuggers, and when objects appear inside lists or dictionaries.
* **`__str__(self)`:** Readable, end-user-oriented representation used by `print(obj)` and `str(obj)`. If `__str__` is not defined, Python automatically falls back to `__repr__`.

```python
class Point:
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    def __repr__(self) -> str:
        return f"Point(x={self.x!r}, y={self.y!r})"

    def __str__(self) -> str:
        return f"({self.x}, {self.y})"

p = Point(3.0, 4.5)
print(str(p))    # (3.0, 4.5)           -> calls __str__
print(repr(p))   # Point(x=3.0, y=4.5)  -> calls __repr__
print([p])       # [Point(x=3.0, y=4.5)] -> containers always use __repr__
```

## 6. Inspecting and Managing Objects Dynamically
Python provides built-in functions for runtime type checking and dynamic attribute access:

```python
class ServerConfig:
    def __init__(self, host: str, port: int) -> None:
        self.host = host
        self.port = port

cfg = ServerConfig("127.0.0.1", 8000)

# Type and relationship checks
print(type(cfg) is ServerConfig)      # True
print(isinstance(cfg, ServerConfig))  # True
print(isinstance(cfg, object))        # True (all classes inherit from 'object')

# Inspecting the instance namespace dictionary
print(vars(cfg))                      # {'host': '127.0.0.1', 'port': 8000}

# Dynamic attribute access
print(hasattr(cfg, "port"))           # True
print(getattr(cfg, "timeout", 30))    # 30 (default returned if attribute is absent)
setattr(cfg, "debug", True)           # Adds cfg.debug = True dynamically
delattr(cfg, "debug")                 # Removes cfg.debug
```

## 7. Common Pitfalls and Best Practices

### 1. Mutable Default Arguments in `__init__`
Default parameter values are evaluated **once** when `def __init__` is defined—not each time an object is instantiated. Never use a mutable object (`[]`, `{}`, `set()`) as a default argument:

```python
# PITFALL: All instances share the exact same 'skills' list!
class BrokenTrainee:
    def __init__(self, name: str, skills: list[str] = []) -> None:
        self.name = name
        self.skills = skills

# CORRECT: Use None as default and create a fresh list inside __init__
class SafeTrainee:
    def __init__(self, name: str, skills: list[str] | None = None) -> None:
        self.name = name
        self.skills = list(skills) if skills is not None else []
```

### 2. Mutable Class Attributes Shared Unintentionally
Defining a mutable collection (like `items = []`) at the class level shares that single list across every instance. Define per-object collections inside `__init__` using `self.items = []`.

### 3. Forgetting `self` in Method Definitions
Omitting `self` from an instance method definition (`def reset():`) causes `TypeError: reset() takes 0 positional arguments but 1 was given` when called as `obj.reset()`, because Python always passes the instance as the first positional argument.

### 4. Initializing All Instance Attributes Inside `__init__`
Declare every expected instance attribute inside `__init__` (even if initialized to `None`) rather than creating attributes conditionally in other methods. This keeps the object's schema predictable and prevents `AttributeError`.

## 8. Quick Reference

| Concept / Construct | Syntax | Description |
| :--- | :--- | :--- |
| Class definition | `class ClassName:` | Defines a blueprint for creating objects |
| Object instantiation | `obj = ClassName(arg1, arg2)` | Creates a new instance and runs `__init__` |
| Initializer method | `def __init__(self, ...):` | Sets up initial instance attributes on `self` |
| Instance attribute | `self.attr = value` | Data unique to each object (`obj.__dict__`) |
| Class attribute | `attr = value` (in class body) | Data shared across all instances (`ClassName.__dict__`) |
| Instance method | `def method(self, ...):` | Operates on a specific instance via `self` |
| Class method | `@classmethod def fn(cls, ...):` | Operates on the class via `cls`; used for factory constructors |
| Static method | `@staticmethod def fn(...):` | Utility function inside class scope without `self` or `cls` |
| String representations | `__repr__(self)` / `__str__(self)` | Developer representation (`repr()`) vs. user display (`print()`) |
| Type & attribute checks | `isinstance()`, `getattr()`, `vars()` | Inspects object types and dynamic attributes at runtime |
