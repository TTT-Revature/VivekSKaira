# Shallow/Deep Copy and Garbage Collection

## 1. Overview
Because Python variables store **references to objects in memory** rather than raw copies of data, managing object lifecycles requires understanding two complementary mechanisms:

* **Object Copying (`copy` module):** Controls whether duplicating a data structure shares nested references (**shallow copy**) or recursively clones every nested object (**deep copy**).
* **Garbage Collection (Memory Management):** Automatically reclaims memory occupied by objects that are no longer reachable by the program—handled in CPython through **reference counting** (primary) combined with a **generational cyclic garbage collector** (`gc` module).

---

## 2. Shallow Copy vs. Deep Copy
Standard assignment (`b = a`) creates an **alias** pointing to the exact same object in memory. To create an independent duplicate, Python's **`copy`** module provides two distinct strategies.

### 1. Shallow Copy (`copy.copy()`)
* Allocates a **new outer container** object (`id(shallow) != id(original)`).
* Populates the new container with **references to the same inner elements** (`shallow[0] is original[0]`).
* **Common Ways to Create a Shallow Copy:** `copy.copy(obj)`, `obj.copy()`, slicing `lst[:]`, or type constructors (`list(lst)`, `dict(d)`, `set(s)`).

### 2. Deep Copy (`copy.deepcopy()`)
* Allocates a **new outer container** AND **recursively duplicates every nested mutable object** at every depth (`deep[0] is not original[0]`).
* Maintains an internal **`memo` dictionary** (`{original_id: copied_obj}`) during traversal so shared internal references remain shared within the copy and self-referential (cyclic) structures do not cause infinite recursion.

```python
import copy

original = [
    {"module": "Python Basics", "completed": True},
    {"module": "Python OOP", "completed": False},
]

# 1. Shallow copy: outer list is new, inner dicts are still shared references
shallow = copy.copy(original)
shallow.append({"module": "Databases", "completed": False})  # Affects only 'shallow'
shallow[1]["completed"] = True                               # Mutates shared inner dict!

print("Original after shallow edit:", original)
# [{'module': 'Python Basics', 'completed': True}, {'module': 'Python OOP', 'completed': True}]

# 2. Deep copy: completely isolated at every nesting level
deep = copy.deepcopy(original)
deep[0]["completed"] = False

print("Original after deep edit   :", original[0]["completed"])  # True (unchanged)
print("Deep copy value            :", deep[0]["completed"])      # False
```

### Comparison: Assignment vs. Shallow Copy vs. Deep Copy

| Operation | Syntax | Outer Object New? | Nested Objects New? | Performance & Memory Cost |
| :--- | :--- | :--- | :--- | :--- |
| **Assignment (Alias)** | `b = a` | No | No | Instant ($O(1)$); zero extra memory |
| **Shallow Copy** | `copy.copy(a)`, `a.copy()`, `a[:]` | Yes | No (references copied) | Fast ($O(n)$ top-level pointers) |
| **Deep Copy** | `copy.deepcopy(a)` | Yes | Yes (recursively cloned) | Slower ($O(N)$ across all nested nodes) |

## 3. Customizing Copy Behavior (`__copy__` and `__deepcopy__`)

### 1. Copying Immutable Objects
For pure immutable objects (`int`, `str`, `bytes`, or a `tuple` containing only immutable items), both `copy.copy()` and `copy.deepcopy()` return the **original object unchanged** (`id` stays identical) because immutable values cannot be mutated anyway.

### 2. Defining `__copy__` and `__deepcopy__` on Custom Classes
Custom classes can control how they are copied by implementing **`__copy__(self)`** and **`__deepcopy__(self, memo)`**:

```python
import copy

class TrainingBatch:
    def __init__(self, batch_id: str, trainees: list[str], db_connection: object) -> None:
        self.batch_id = batch_id
        self.trainees = trainees
        self.db_connection = db_connection  # External resource that should not be deep-copied

    def __copy__(self) -> "TrainingBatch":
        return TrainingBatch(self.batch_id, self.trainees, self.db_connection)

    def __deepcopy__(self, memo: dict[int, object]) -> "TrainingBatch":
        # Deep-copy the trainees list, but share the non-copyable db_connection reference
        cloned_trainees = copy.deepcopy(self.trainees, memo)
        new_batch = TrainingBatch(self.batch_id, cloned_trainees, self.db_connection)
        memo[id(self)] = new_batch
        return new_batch

conn = object()
b1 = TrainingBatch("FDE-01", ["Vivek", "Rashi"], conn)
b2 = copy.deepcopy(b1)

print(b1.trainees is b2.trainees)            # False (deep-copied)
print(b1.db_connection is b2.db_connection)  # True  (preserved intentionally)
```

## 4. Memory Management and Reference Counting
CPython manages memory automatically using **reference counting** as its primary mechanism. Every Python object internally stores a reference counter (`ob_refcnt`) tracking how many active references point to it.

### What Changes the Reference Count?
* **Increments (`+1`):** Assigning to a variable (`y = x`), adding to a container (`items.append(x)`), passing as a function argument, or binding as an object attribute (`self.data = x`).
* **Decrements (`-1`):** Executing `del x`, reassigning `x = None`, a local variable going out of scope when a function returns, or removing/destroying a container holding `x`.

As soon as an object's reference count drops to **`0`**, CPython **immediately and deterministically deallocates** its memory.

```python
import sys

payload = [1, 2, 3]
# Note: sys.getrefcount() adds 1 temporary reference for its own parameter
print("Initial count :", sys.getrefcount(payload))  # 2 (payload + getrefcount arg)

alias = payload
print("After alias   :", sys.getrefcount(payload))  # 3

container = [payload]
print("In container  :", sys.getrefcount(payload))  # 4

del alias
container.clear()
print("After cleanup :", sys.getrefcount(payload))  # 2
```

### The Limitation of Reference Counting: Reference Cycles
Reference counting alone **cannot reclaim circular references** (reference cycles), where two or more container objects reference each other—or an object references itself—even after all external variables are deleted:

```python
class Node:
    def __init__(self, name: str) -> None:
        self.name = name
        self.partner: "Node | None" = None

node_a = Node("A")
node_b = Node("B")

# Create a circular reference: A -> B and B -> A
node_a.partner = node_b
node_b.partner = node_a

# Deleting external names drops each refcount from 2 to 1—NOT 0!
del node_a
del node_b
# Both Node objects are now unreachable, yet refcount == 1 keeps them alive until cyclic GC runs
```

## 5. Generational Cyclic Garbage Collection (`gc` Module)
To detect and free unreachable reference cycles, CPython runs a **generational cyclic garbage collector** (exposed via the built-in **`gc`** module) alongside reference counting.

### How Generational GC Works
1. **Tracked Objects:** Only container objects capable of holding references to other objects (`list`, `dict`, `set`, `tuple`, custom class instances, functions) are tracked by the cyclic collector. Atomic primitives (`int`, `float`, `str`, `bytes`) cannot form cycles and are managed purely by reference counting.
2. **Three Generations (`0`, `1`, `2`):** Based on the *generational hypothesis* (most objects become unreachable shortly after creation):
   * **Generation 0:** Newly allocated container objects. Collected most frequently.
   * **Generation 1:** Objects that survived a Generation 0 collection.
   * **Generation 2:** Long-lived objects that survived Generation 1 collections. Collected least frequently.
3. **Cycle Detection:** When allocations exceed a generation's threshold, the collector isolates unreachable cyclic subgraphs (whose internal references account for 100% of their remaining refcounts), breaks the references, and frees their memory.

### Controlling and Inspecting the Garbage Collector
```python
import gc

# Inspect current object counts per generation and configured thresholds
print("GC enabled    :", gc.isenabled())       # True
print("Gen thresholds:", gc.get_threshold())   # e.g., (700, 10, 10) or generational thresholds
print("Current counts:", gc.get_count())       # (gen0, gen1, gen2)

# Create an unreachable self-referencing cycle
cyclic_list: list[object] = []
cyclic_list.append(cyclic_list)
del cyclic_list

# Force an immediate full collection across all generations
unreachable_collected = gc.collect()
print("Unreachable cyclic objects reclaimed:", unreachable_collected)
```

## 6. Weak References (`weakref` Module)
Sometimes you need to cache objects or maintain parent-child back-references **without preventing the garbage collector from reclaiming them** when no strong references remain. The **`weakref`** module creates references that **do not increment `ob_refcnt`**:

```python
import weakref

class CachedDocument:
    def __init__(self, title: str) -> None:
        self.title = title

doc = CachedDocument("Architecture_Notes.md")
weak_doc = weakref.ref(doc)

print(weak_doc())     # <__main__.CachedDocument object at ...> (returns object while alive)

del doc               # Strong reference removed -> refcount hits 0 -> immediately freed
print(weak_doc())     # None (weak reference automatically resolves to None)
```
*(Tip: Use `weakref.WeakValueDictionary()` for in-memory caches so cached entries are evicted automatically once callers drop their strong references.)*

## 7. Common Pitfalls and Best Practices

1. **`del x` Does Not Delete an Object Directly:**
   `del x` only removes the variable name `x` from the current namespace and decrements the underlying object's reference count by 1. The object is freed only when *all* strong references to it are gone.
2. **Unintentional Memory Retention via Global Lists and Caches:**
   Even with automatic garbage collection, appending objects to module-level lists, unbounded dictionaries, or decorators without limits (`@lru_cache(maxsize=None)`) keeps strong references alive for the entire process lifetime.
3. **Deep-Copying Non-Copyable Resources Raises `TypeError`:**
   Calling `copy.deepcopy()` on objects holding open file handles, network sockets, database connections, thread locks, or running generators fails with `TypeError: cannot pickle '...' object`. Exclude them via `__deepcopy__`.
4. **Avoid Disabling Cyclic GC Unless Benchmarking Proves Necessity:**
   Calling `gc.disable()` removes cyclic collection overhead in short-lived batch jobs, but any circular references created while disabled will leak memory until `gc.enable()` and `gc.collect()` are called.

## 8. Quick Reference

| Function / Method | Module | Purpose |
| :--- | :--- | :--- |
| `copy.copy(obj)` | `copy` | Creates a shallow copy (new outer container, shared nested references) |
| `copy.deepcopy(obj)` | `copy` | Recursively duplicates an object and all nested mutable objects |
| `__copy__` / `__deepcopy__` | Data model | Customizes shallow and deep copy behavior on user-defined classes |
| `sys.getrefcount(obj)` | `sys` | Returns current reference count of `obj` (includes +1 for call argument) |
| `gc.collect(generation=2)` | `gc` | Runs cyclic garbage collection immediately and returns count of freed objects |
| `gc.get_count()` / `gc.get_threshold()` | `gc` | Inspects current allocation counts and collection thresholds across generations |
| `gc.disable()` / `gc.enable()` | `gc` | Disables or re-enables automatic cyclic garbage collection (refcounting stays active) |
| `weakref.ref(obj)` | `weakref` | Creates a non-owning reference that does not keep `obj` alive in memory |
