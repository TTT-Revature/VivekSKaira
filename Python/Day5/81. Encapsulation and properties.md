# Encapsulation and Properties in Python

## 1. Overview
**Encapsulation** is one of the core principles of Object-Oriented Programming (OOP). It combines an object's **data (attributes)** and **behavior (methods)** into a single unit (a class) while controlling how external code reads or modifies internal state.

* **Purpose of Encapsulation:**
  * Protects internal object invariants from invalid or accidental modification.
  * Hides internal implementation details behind a clean, stable public interface.
  * Allows internal representation to change later without breaking code that uses the class.
* **Python's Philosophy:** Unlike Java or C++, Python does not enforce strict `private` or `protected` access restrictions at the compiler level. Instead, it combines **naming conventions** (`_single_underscore` and `__double_underscore`) with the **`@property` decorator** to provide clean, Pythonic attribute control.

---

## 2. Visibility Conventions and Name Mangling
Python communicates intended attribute and method visibility through leading underscores:

### 1. Public (`attribute`)
* Accessible from anywhere inside or outside the class.
* All attributes and methods in Python are public by default.

### 2. Protected (`_attribute`)
* Prefixed with a **single leading underscore**.
* Signals to other developers that the member is an **internal implementation detail** intended only for use within the class and its subclasses.
* Python does not block access at runtime, though `from module import *` skips top-level names starting with `_`.

### 3. Private (`__attribute`) and Name Mangling
* Prefixed with **two leading underscores** (and at most one trailing underscore, distinguishing it from dunder methods like `__init__`).
* At compile time, Python rewrites `__attribute` into **`_ClassName__attribute`**—a mechanism called **name mangling**.
* Name mangling is designed to **prevent accidental attribute name collisions in subclasses**, not to provide security against intentional inspection.

```python
class UserAccount:
    def __init__(self, username: str, role: str, password_hash: str) -> None:
        self.username = username              # Public attribute
        self._role = role                     # Protected attribute (internal convention)
        self.__password_hash = password_hash  # Private attribute (name-mangled)

    def verify_password(self, candidate_hash: str) -> bool:
        return self.__password_hash == candidate_hash

account = UserAccount("vivek_kaira", "FDE_Intern", "sha256:9f86d08")

# 1. Public access
print(account.username)                    # vivek_kaira

# 2. Protected access (works syntactically, discouraged outside class/subclasses)
print(account._role)                       # FDE_Intern

# 3. Private access directly raises AttributeError
# print(account.__password_hash)           # AttributeError: 'UserAccount' object has no attribute '__password_hash'

# 4. Name-mangled attribute stored in __dict__
print(account._UserAccount__password_hash) # sha256:9f86d08
```

### Visibility Conventions Comparison

| Convention | Syntax | Runtime Behavior | Intended Usage |
| :--- | :--- | :--- | :--- |
| **Public** | `attr` | Unrestricted access everywhere | Part of the class's documented public API |
| **Protected** | `_attr` | Unrestricted access; signals internal use by convention | Internal helpers and backing fields for properties/subclasses |
| **Private** | `__attr` | Name-mangled to `_ClassName__attr` | Avoiding attribute name clashes in inheritance hierarchies |

## 3. Properties (`@property`, Setter, and Deleter)
In languages without properties, developers write explicit `get_balance()` and `set_balance()` methods from the start. In Python, you expose clean attribute access (`account.balance`) and use the **`@property`** decorator (a built-in **descriptor**) to attach getter, setter, and deleter logic whenever validation or computation is needed.

### Defining Getter, Setter, and Deleter
* **`@property`:** Turns a method into a **getter**, executed automatically when `obj.attr` is read.
* **`@<name>.setter`:** Defines a **setter**, executed automatically when `obj.attr = value` is assigned.
* **`@<name>.deleter`:** Defines a **deleter**, executed automatically when `del obj.attr` is run.

```python
class BankAccount:
    """Demonstrates encapsulation using a backing attribute and @property."""

    def __init__(self, owner: str, initial_balance: float = 0.0) -> None:
        self.owner = owner
        # Invokes the @balance.setter during initialization so validation runs immediately
        self.balance = initial_balance

    @property
    def balance(self) -> float:
        """Getter: returns the current account balance."""
        return self._balance

    @balance.setter
    def balance(self, value: float) -> None:
        """Setter: validates that balance is numeric and non-negative."""
        if not isinstance(value, (int, float)):
            raise TypeError("Balance must be a numeric value.")
        if value < 0:
            raise ValueError(f"Balance cannot be negative; received {value}.")
        self._balance = float(value)

    @balance.deleter
    def balance(self) -> None:
        """Deleter: resets the balance safely instead of removing the attribute."""
        print(f"Resetting balance for {self.owner} to 0.0")
        self._balance = 0.0

acc = BankAccount("Vivek", 5000.0)
print(acc.balance)     # 5000.0  -> calls @property getter

acc.balance = 7500.0   # Calls @balance.setter
print(acc.balance)     # 7500.0

# acc.balance = -100.0 # Raises ValueError: Balance cannot be negative; received -100.0.

del acc.balance        # Calls @balance.deleter
print(acc.balance)     # 0.0
```

## 4. Key Use Cases for Properties

### 1. Read-Only Attributes
Omitting `@<name>.setter` makes a property **read-only**. Any attempt to assign to it raises `AttributeError`:

```python
class Circle:
    def __init__(self, radius: float) -> None:
        if radius <= 0:
            raise ValueError("Radius must be positive.")
        self._radius = radius

    @property
    def radius(self) -> float:
        return self._radius  # No setter defined -> read-only

c = Circle(5.0)
print(c.radius)  # 5.0
# c.radius = 10  # AttributeError: property 'radius' of 'Circle' object has no setter
```

### 2. Computed (Derived) Attributes
Properties let you calculate values dynamically from other attributes so derived state never goes stale or out of sync:

```python
class Rectangle:
    def __init__(self, width: float, height: float) -> None:
        self.width = width
        self.height = height

    @property
    def area(self) -> float:
        """Dynamically computed whenever accessed; always reflects current dimensions."""
        return self.width * self.height

    @property
    def perimeter(self) -> float:
        return 2 * (self.width + self.height)

rect = Rectangle(4.0, 5.0)
print(rect.area)       # 20.0
rect.width = 10.0
print(rect.area)       # 50.0 (automatically updated)
```

### 3. Backward-Compatible Refactoring
You can start with a simple public attribute (`self.celsius = 25.0`) and later convert `celsius` into a validated `@property` backed by `self._celsius`—**without changing how external callers read or write `obj.celsius`**.

## 5. Alternative Syntax: The Built-In `property()` Function
`@property` is syntactic sugar for Python's built-in **`property(fget=None, fset=None, fdel=None, doc=None)`** descriptor class. You may occasionally encounter the functional form in older codebases:

```python
class SensorReading:
    def __init__(self, value: float) -> None:
        self._value = value

    def _get_value(self) -> float:
        return self._value

    def _set_value(self, new_val: float) -> None:
        if not (0.0 <= new_val <= 100.0):
            raise ValueError("Reading out of [0, 100] range.")
        self._value = new_val

    value = property(fget=_get_value, fset=_set_value, doc="Validated sensor reading.")

reading = SensorReading(42.5)
print(reading.value)  # 42.5
```

## 6. Common Pitfalls and Best Practices

### 1. Infinite `RecursionError` Inside Getters and Setters
Always store the underlying data in a **protected backing attribute** (`self._age`) rather than assigning to `self.age` inside the property's own getter or setter:

```python
# PITFALL: Assigning 'self.age = value' inside '@age.setter' calls the setter infinitely!
class BrokenPerson:
    @property
    def age(self) -> int:
        return self.age         # RecursionError!

    @age.setter
    def age(self, value: int) -> None:
        self.age = value        # RecursionError!

# CORRECT: Use a single-underscore backing attribute 'self._age'
class SafePerson:
    def __init__(self, age: int) -> None:
        self.age = age          # Triggers setter once, storing into self._age

    @property
    def age(self) -> int:
        return self._age

    @age.setter
    def age(self, value: int) -> None:
        if value < 0:
            raise ValueError("Age cannot be negative.")
        self._age = value
```

### 2. Calling a Property with Parentheses
Because `@property` turns a method into an attribute accessor, calling `rect.area()` with parentheses raises `TypeError: 'float' object is not callable`. Access it as `rect.area`.

### 3. Keep `@property` Methods Fast and Side-Effect-Free
Callers expect attribute reads (`user.profile`) to be instantaneous and free of major side effects. Avoid performing network requests, database queries, or heavy file I/O inside a `@property`—use a regular method such as `user.fetch_profile()` instead.

### 4. Prefer Single Underscore (`_attr`) Over Double Underscore (`__attr`)
Use `_attr` by default for internal attributes and property backing fields. Reserve `__attr` name mangling for base classes intended to be subclassed where accidental attribute name collisions are a genuine risk.

## 7. Quick Reference

| Construct / Pattern | Syntax | Behavior / Purpose |
| :--- | :--- | :--- |
| Public attribute | `self.name = val` | Unrestricted public interface |
| Protected attribute | `self._name = val` | Convention for internal state and property backing storage |
| Private attribute | `self.__name = val` | Name-mangled to `_ClassName__name` to prevent subclass collisions |
| Property getter | `@property` | Runs method automatically when reading `obj.prop` |
| Property setter | `@prop.setter` | Runs method automatically when assigning `obj.prop = val` |
| Property deleter | `@prop.deleter` | Runs method automatically when executing `del obj.prop` |
| Read-only property | `@property` without `.setter` | Allows reading `obj.prop`; raises `AttributeError` on assignment |
| Functional descriptor | `prop = property(fget, fset, fdel)` | Non-decorator equivalent of `@property` |
