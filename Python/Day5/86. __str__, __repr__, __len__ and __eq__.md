# Special (Dunder) Methods: `__str__`, `__repr__`, `__len__`, and `__eq__`

## 1. Overview
In Python, **special methods**—commonly called **dunder (double-underscore) methods** or **magic methods**—are hooks in the **Python Data Model** that allow user-defined classes to integrate seamlessly with built-in functions, operators, and language syntax.

* **Implicit Invocation:** You rarely call dunder methods directly (avoid `obj.__len__()`). Instead, Python invokes them automatically when you use standard syntax (`len(obj)`, `print(obj)`, `obj1 == obj2`).
* **Core Methods Covered:**
  * **`__repr__`:** Unambiguous, developer-facing string representation (`repr(obj)`).
  * **`__str__`:** Readable, user-facing string representation (`str(obj)`, `print(obj)`).
  * **`__len__`:** Item count or size of a container object (`len(obj)`), also governing default truthiness (`bool(obj)`).
  * **`__eq__`:** Value-based equality comparison (`obj1 == obj2`).

## 2. `__repr__` vs. `__str__` (String Representations)
By default, custom objects inherit `object.__repr__` and `object.__str__`, which output unhelpful memory addresses such as `<__main__.Course object at 0x000001A2B3C4>`. Implementing `__repr__` and `__str__` gives objects meaningful text representations for debugging and display.

### 1. `__repr__(self) -> str`
* **Audience:** Developers, logs, debuggers, and interactive REPL sessions.
* **Goal:** Return an **unambiguous** string—ideally valid Python syntax that could recreate the object (`ClassName(field=value)`).
* **Where Used:** Called by `repr(obj)`, interactive prompts, `f"{obj!r}"`, and whenever an object is printed **inside a container** (`list`, `tuple`, `dict`, `set`).

### 2. `__str__(self) -> str`
* **Audience:** End users and readable console/report output.
* **Goal:** Return a clean, **human-readable** summary of the object.
* **Where Used:** Called by `str(obj)`, `print(obj)`, and standard f-strings (`f"{obj}"`).

### Fallback Rule
If a class defines **`__repr__`** without **`__str__`**, Python automatically uses `__repr__` for both `repr(obj)` and `str(obj)`. However, defining only `__str__` leaves `repr(obj)` and container printing showing the raw memory address. **Always implement `__repr__` first.**

```python
class Trainee:
    def __init__(self, trainee_id: int, name: str, track: str) -> None:
        self.trainee_id = trainee_id
        self.name = name
        self.track = track

    def __repr__(self) -> str:
        # Unambiguous developer representation
        return (
            f"Trainee(trainee_id={self.trainee_id!r}, "
            f"name={self.name!r}, track={self.track!r})"
        )

    def __str__(self) -> str:
        # Clean end-user display format
        return f"#{self.trainee_id} - {self.name} ({self.track})"

t = Trainee(101, "Vivek", "FDE")

print(str(t))    # #101 - Vivek (FDE)
print(t)         # #101 - Vivek (FDE)  (print() calls str())
print(repr(t))   # Trainee(trainee_id=101, name='Vivek', track='FDE')
print([t])       # [Trainee(trainee_id=101, name='Vivek', track='FDE')]
```

### Comparison: `__repr__` vs. `__str__`

| Feature | `__repr__` | `__str__` |
| :--- | :--- | :--- |
| **Primary Audience** | Developers and debugging tools | End users and UI/CLI output |
| **Triggered By** | `repr(obj)`, REPL evaluation, `f"{obj!r}"`, `[obj]` | `str(obj)`, `print(obj)`, `f"{obj}"` |
| **Design Style** | Explicit, unambiguous (`ClassName(a=1, b=2)`) | Readable, formatted prose or summary |
| **Fallback Behavior** | Falls back to `<module.Class object at 0x...>` | Falls back to `__repr__` if `__str__` is missing |

## 3. `__len__` (Size and Implicit Truthiness)
Implementing **`__len__(self) -> int`** allows an object to work with Python's built-in **`len()`** function.

### Contract and Rules
1. **Return Type:** Must return a **non-negative integer (`int >= 0`)**. Returning a `float`, `str`, or `None` raises `TypeError`; returning a negative integer raises `ValueError`.
2. **Implicit Boolean Evaluation (`bool(obj)`):** When a class does not define `__bool__`, Python automatically determines truthiness by calling `__len__`:
   * `len(obj) > 0` -> evaluates to `True`
   * `len(obj) == 0` -> evaluates to `False`

```python
class TaskQueue:
    def __init__(self, tasks: list[str] | None = None) -> None:
        self._tasks = list(tasks) if tasks is not None else []

    def add(self, task: str) -> None:
        self._tasks.append(task)

    def __len__(self) -> int:
        return len(self._tasks)

queue = TaskQueue()
print(len(queue))    # 0
print(bool(queue))   # False (uses __len__ automatically)

queue.add("Run unit tests")
queue.add("Push notes to GitHub")
print(len(queue))    # 2
if queue:            # Evaluates to True because len(queue) > 0
    print(f"Queue has {len(queue)} pending task(s).")
```

## 4. `__eq__` (Value Equality)
By default, custom objects inherit `object.__eq__`, which checks **object identity (`self is other`)**—meaning two distinct instances with identical attributes evaluate to `False` under `==`. Implementing **`__eq__(self, other: object) -> bool`** defines **value-based equality**.

### How `==`, `!=`, and `NotImplemented` Work
* **Automatic `!=` Delegation:** In Python 3, implementing `__eq__` automatically makes **`!=`** return the logical negation (`not (a == b)`), so you rarely need to implement `__ne__` separately.
* **Returning `NotImplemented`:** When `other` is not a compatible type, return the built-in singleton **`NotImplemented`** (not `False` and not `raise TypeError`). Returning `NotImplemented` tells Python to try the right-hand operand's `other.__eq__(self)` method before falling back to `False`.

```python
class Version:
    def __init__(self, major: int, minor: int, patch: int) -> None:
        self.major = major
        self.minor = minor
        self.patch = patch

    def __repr__(self) -> str:
        return f"Version({self.major}, {self.minor}, {self.patch})"

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Version):
            return NotImplemented
        return (self.major, self.minor, self.patch) == (
            other.major,
            other.minor,
            other.patch,
        )

v1 = Version(3, 12, 1)
v2 = Version(3, 12, 1)
v3 = Version(3, 13, 0)

print(v1 is v2)          # False (two distinct objects in memory)
print(v1 == v2)          # True  (equal values via __eq__)
print(v1 != v3)          # True  (automatically derived from __eq__)
print(v1 == "3.12.1")    # False (Version.__eq__ returns NotImplemented -> str.__eq__ -> False)
```

### Important Side Effect: `__eq__` Disables `__hash__`
In Python, any object used in a `set` or as a `dict` key must satisfy: **`a == b` implies `hash(a) == hash(b)`**. Because custom `__eq__` changes equality rules, Python automatically sets **`__hash__ = None`** on any class that defines `__eq__` without `__hash__`, making its instances **unhashable** (`TypeError: unhashable type`).
* If your object is **mutable**, keep it unhashable (do not implement `__hash__`).
* If your object is **immutable**, implement `__hash__` over the exact same attributes compared in `__eq__` (e.g., `return hash((self.major, self.minor, self.patch))`).

## 5. Complete Combined Example
Below is a cohesive container class combining all four dunder methods:

```python
class ModuleSyllabus:
    """Represents a training module containing an ordered list of topics."""

    def __init__(self, code: str, title: str, topics: list[str] | None = None) -> None:
        self.code = code
        self.title = title
        self.topics = list(topics) if topics is not None else []

    def __repr__(self) -> str:
        return (
            f"ModuleSyllabus(code={self.code!r}, title={self.title!r}, "
            f"topics={self.topics!r})"
        )

    def __str__(self) -> str:
        return f"{self.code}: {self.title} ({len(self)} topics)"

    def __len__(self) -> int:
        return len(self.topics)

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, ModuleSyllabus):
            return NotImplemented
        return (self.code, self.title, self.topics) == (
            other.code,
            other.title,
            other.topics,
        )

m1 = ModuleSyllabus("PY-OOP", "Object-Oriented Python", ["Classes", "Inheritance", "Dunder Methods"])
m2 = ModuleSyllabus("PY-OOP", "Object-Oriented Python", ["Classes", "Inheritance", "Dunder Methods"])

print(str(m1))    # PY-OOP: Object-Oriented Python (3 topics)
print(repr(m1))   # ModuleSyllabus(code='PY-OOP', title='Object-Oriented Python', topics=['Classes', 'Inheritance', 'Dunder Methods'])
print(len(m1))    # 3
print(m1 == m2)   # True
```

## 6. Common Pitfalls and Best Practices

1. **Never Call Dunder Methods Directly:**
   Write `len(cart)`, `str(user)`, and `a == b` instead of `cart.__len__()`, `user.__str__()`, or `a.__eq__(b)`. Built-in functions perform extra validation (such as verifying that `__len__` returns a non-negative `int` and handling `NotImplemented` symmetry for `==`).
2. **Do Not Raise `TypeError` or Return `False` for Mismatched Types in `__eq__`:**
   Always return **`NotImplemented`** when `isinstance(other, ExpectedClass)` is `False`. Raising `TypeError` breaks expressions like `obj in mixed_list`, and returning `False` prematurely prevents `other.__eq__(self)` from running.
3. **Keep `__str__`, `__repr__`, `__len__`, and `__eq__` Fast and Pure:**
   These methods are invoked implicitly during logging, debugging, container checks, and comparisons. Never perform network calls, database queries, or state mutations inside them.
4. **Prevent Infinite Recursion in `__repr__` / `__str__` on Self-Referential Objects:**
   If an object can hold references to itself (e.g., a tree or graph node), formatting child references recursively without cycle protection causes `RecursionError`.

## 7. Quick Reference

| Dunder Method | Signature | Triggered By | Return Contract & Key Notes |
| :--- | :--- | :--- | :--- |
| `__repr__` | `def __repr__(self) -> str:` | `repr(x)`, REPL, `[x]`, `f"{x!r}"` | Returns `str`; unambiguous developer format; fallback for `__str__` |
| `__str__` | `def __str__(self) -> str:` | `str(x)`, `print(x)`, `f"{x}"` | Returns `str`; readable end-user display format |
| `__len__` | `def __len__(self) -> int:` | `len(x)`, `bool(x)` (if no `__bool__`) | Returns `int >= 0`; `0` makes object falsy in `if x:` |
| `__eq__` | `def __eq__(self, other: object) -> bool:` | `x == y`, `x != y` | Returns `bool` or `NotImplemented`; disables `__hash__` unless defined |
