# Objects, References, and Mutation in Python

## 1. Overview
In Python, **everything is an object** stored in memory, and variables are **names (references)** bound to those objects—not fixed memory boxes that hold raw values directly. Understanding how references and mutability interact prevents subtle bugs involving shared state, unexpected side effects, and copying.

Every Python object has three fundamental characteristics:
1. **Identity (`id(obj)`):** A unique integer identifier assigned when the object is created (in CPython, its memory address). Identity never changes during an object's lifetime.
2. **Type (`type(obj)`):** Determines the operations the object supports and whether its value can change.
3. **Value:** The actual data stored inside the object.

---

## 2. Variables as References (`id()`, `is`, and `==`)
Assigning one variable to another (`b = a`) does **not** copy the underlying object. Instead, it binds the new name `b` to the **exact same object** referenced by `a` (increasing its reference count).

### Identity (`is`) vs. Equality (`==`)
* **`a is b` (Identity):** Evaluates to `True` only if `a` and `b` point to the **exact same object** in memory (`id(a) == id(b)`).
* **`a == b` (Equality):** Evaluates to `True` if the objects have **equal values** (delegates to `__eq__`).

```python
list_a = [10, 20, 30]
list_b = list_a          # Alias: binds list_b to the exact same list object
list_c = [10, 20, 30]    # Creates a brand-new list object with identical contents

print(id(list_a) == id(list_b))  # True
print(id(list_a) == id(list_c))  # False

print(list_a is list_b)          # True  (same object in memory)
print(list_a is list_c)          # False (two distinct objects)
print(list_a == list_c)          # True  (equal values)
```

*(Note: Always use **`is` / `is not`** when checking for singletons such as `None`, `True`, or `False`—for example, `if result is None:`. Never use `is` to compare numbers or strings, because CPython interns small integers and certain strings unpredictably.)*

---

## 3. Mutability vs. Immutability
An object's **mutability** determines whether its internal value can be altered after creation without changing its identity (`id()`).

### 1. Immutable Objects
Once created, an immutable object's state **cannot be changed**. Any operation that appears to modify it actually allocates a **new object** and rebinds the variable name to that new object.
* **Built-in Immutable Types:** `int`, `float`, `bool`, `str`, `tuple`, `frozenset`, `bytes`.

```python
text = "Revature"
original_id = id(text)

# Creates a new string object and rebinds 'text'
text = text + " FDE"
print(text)                       # Revature FDE
print(id(text) == original_id)    # False (new object created)
```

### 2. Mutable Objects
A mutable object allows its internal contents to be modified **in place** while keeping the exact same `id()`.
* **Built-in Mutable Types:** `list`, `dict`, `set`, `bytearray`, and most custom class instances.

```python
skills = ["Python", "SQL"]
original_id = id(skills)

# Mutates the existing list in place
skills.append("Git")
print(skills)                     # ['Python', 'SQL', 'Git']
print(id(skills) == original_id)  # True (same object modified in place)
```

### Type Classification Table

| Category | Built-In Types | In-Place Modification Allowed? | Effect of "Update" Operation |
| :--- | :--- | :--- | :--- |
| **Immutable** | `int`, `float`, `bool`, `str`, `tuple`, `frozenset`, `bytes` | No | Creates a new object and rebinds the variable (`id()` changes) |
| **Mutable** | `list`, `dict`, `set`, `bytearray`, standard class instances | Yes | Modifies object contents in place (`id()` remains unchanged) |

### Subtlety: Immutable Containers Holding Mutable Elements
A `tuple` is immutable because its sequence of object references cannot be reassigned (`t[0] = ...` raises `TypeError`). However, if a `tuple` contains a mutable object such as a `list`, that inner list can still be mutated in place:

```python
record = ("Vivek", ["Python", "SQL"])
# record[0] = "Rashi"        # TypeError: 'tuple' object does not support item assignment
record[1].append("PyTorch")  # Valid: mutates the inner list referenced at index 1
print(record)                # ('Vivek', ['Python', 'SQL', 'PyTorch'])
```

## 4. Aliasing and In-Place Mutation vs. Rebinding
**Aliasing** occurs when two or more variable names refer to the same mutable object. Mutating the object through one alias is immediately visible through every other alias.

```python
default_scores = [80, 85, 90]
trainee_scores = default_scores  # Alias created

# In-place mutation affects both names
trainee_scores.append(95)
print("default_scores:", default_scores)  # [80, 85, 90, 95]
print("trainee_scores:", trainee_scores)  # [80, 85, 90, 95]
```

### `+=` on Lists vs. `+` Rebinding
For lists, augmented assignment (`+=`) calls `__iadd__`, which **mutates the list in place** (like `.extend()`). In contrast, `a = a + [x]` creates a **new list** and rebinds `a`, leaving other aliases untouched:

```python
a = [1, 2]
b = a
a += [3]           # In-place mutation: both 'a' and 'b' see [1, 2, 3]
print(a, b, a is b)  # [1, 2, 3] [1, 2, 3] True

a = a + [4]        # Rebinding: 'a' points to a new list; 'b' stays [1, 2, 3]
print(a, b, a is b)  # [1, 2, 3, 4] [1, 2, 3] False
```

## 5. Shallow Copy vs. Deep Copy (`copy` Module)
To avoid unintended aliasing on mutable data structures, create an explicit copy. Python distinguishes between **shallow copies** and **deep copies**:

### 1. Shallow Copy (`copy.copy()`, `.copy()`, Slicing `[:]`)
* Creates a **new outer container** object.
* Populates it with **references to the exact same inner elements** (does not recursively copy nested objects).
* Sufficient when all elements inside the container are immutable (e.g., `list[int]`, `list[str]`).

### 2. Deep Copy (`copy.deepcopy()`)
* Creates a **new outer container** AND **recursively duplicates every nested object** at all levels.
* Guarantees complete isolation between the original structure and the copy.

```python
import copy

original = [[1, 2], [3, 4]]

# 1. Shallow copy: outer list is new, inner lists are still shared references
shallow = copy.copy(original)  # Equivalent to original.copy() or original[:]
shallow[0].append(99)

print("Original after shallow mutation:", original)  # [[1, 2, 99], [3, 4]]
print("Shallow copy                   :", shallow)   # [[1, 2, 99], [3, 4]]

# 2. Deep copy: outer and inner lists are completely independent
deep = copy.deepcopy(original)
deep[1].append(777)

print("Original after deep mutation   :", original)  # [[1, 2, 99], [3, 4]]
print("Deep copy                      :", deep)      # [[1, 2, 99], [3, 4, 777]]
```

| Copy Strategy | Syntax | Outer Container Copied? | Nested Mutable Objects Copied? |
| :--- | :--- | :--- | :--- |
| **Assignment (Alias)** | `b = a` | No (same reference) | No |
| **Shallow Copy** | `a.copy()`, `a[:]`, `list(a)`, `copy.copy(a)` | Yes | No (inner references shared) |
| **Deep Copy** | `copy.deepcopy(a)` | Yes | Yes (recursively duplicated) |

## 6. Function Argument Passing (Call-by-Sharing)
Python passes arguments by **object reference** (commonly called **pass-by-assignment** or **call-by-sharing**):

1. Inside a function, each parameter is a local variable bound to the **caller's passed object**.
2. **Rebinding** the parameter (`param = new_val`) only changes the local variable inside the function; the caller's variable is unaffected.
3. **Mutating** a mutable argument in place (`param.append(...)` or `param["k"] = v`) modifies the shared object directly, so the caller observes the change.

```python
def update_state(count: int, tags: list[str]) -> None:
    count += 10                  # Rebinds local 'count' (int is immutable); caller unchanged
    tags.append("verified")      # Mutates caller's list in place
    tags = ["replaced_locally"]  # Rebinds local 'tags' only; caller's list stays mutated

num = 5
labels = ["draft"]

update_state(num, labels)
print("num   :", num)     # 5
print("labels:", labels)  # ['draft', 'verified']
```

## 7. Common Pitfalls and Best Practices

### 1. Mutable Default Function Arguments
Default argument expressions are evaluated **once** when the `def` statement executes, creating a single shared object across every call that omits that argument:

```python
# PITFALL: Every call without 'log' appends to the exact same list!
def record_event_broken(event: str, log: list[str] = []) -> list[str]:
    log.append(event)
    return log

# CORRECT: Use None sentinel and allocate a fresh list per call
def record_event_safe(event: str, log: list[str] | None = None) -> list[str]:
    if log is None:
        log = []
    log.append(event)
    return log
```

### 2. Creating Nested Lists with Multiplication (`*`)
Repeating a mutable list with `*` duplicates the **reference** to the same inner list rather than creating independent rows:

```python
# PITFALL: All 3 rows reference the exact same inner list object!
broken_grid = [[0] * 3] * 3
broken_grid[0][0] = 9
print(broken_grid)  # [[9, 0, 0], [9, 0, 0], [9, 0, 0]]

# CORRECT: Use a list comprehension so each row is a distinct list object
safe_grid = [[0] * 3 for _ in range(3)]
safe_grid[0][0] = 9
print(safe_grid)    # [[9, 0, 0], [0, 0, 0], [0, 0, 0]]
```

### 3. Mutating a Collection While Iterating Over It
Adding or removing items from a `list`, `dict`, or `set` while looping directly over it skips elements or raises `RuntimeError: dictionary changed size during iteration`:

```python
numbers = [1, 2, 3, 4, 5, 6]

# CORRECT: Build a filtered list or iterate over a shallow copy (numbers[:])
even_numbers = [n for n in numbers if n % 2 == 0]
print(even_numbers)  # [2, 4, 6]
```

## 8. Quick Reference

| Function / Operator | Syntax | Description |
| :--- | :--- | :--- |
| `id()` | `id(obj)` | Returns the unique integer identity of an object |
| `type()` | `type(obj)` | Returns the class/type of an object |
| `is` / `is not` | `x is None`, `a is b` | Tests whether two names reference the exact same object in memory |
| `==` / `!=` | `a == b` | Tests value equality via `__eq__` |
| `copy.copy()` | `copy.copy(obj)` | Creates a shallow copy (new outer container, shared inner references) |
| `copy.deepcopy()` | `copy.deepcopy(obj)` | Creates a deep copy (recursively copies all nested objects) |
