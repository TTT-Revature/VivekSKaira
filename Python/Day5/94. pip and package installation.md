# `pip` and Package Installation in Python

## 1. Overview
**`pip`** (recursive acronym for *Pip Installs Packages*) is Python's standard package manager. It downloads, resolves dependencies for, builds, and installs third-party libraries into your active environment's **`site-packages`** directory—primarily from the **Python Package Index (PyPI)** (`https://pypi.org`).

* **Recommended Invocation (`python -m pip`):** Always invoke `pip` as a module via the target interpreter (`python -m pip ...` on Windows, `python3 -m pip ...` on macOS/Linux). This guarantees packages are installed into the exact Python interpreter or active virtual environment you intend to use.
* **Bootstrapping and Updating `pip`:**
  ```bash
  # Restore pip from the standard library if missing
  python -m ensurepip --default-pip

  # Upgrade pip itself to the latest release
  python -m pip install --upgrade pip
  ```

## 2. Core `pip` Commands

### 1. Installing and Upgrading Packages
```bash
# Install the latest stable version of a package from PyPI
python -m pip install requests

# Install multiple packages in a single command
python -m pip install pandas numpy scikit-learn

# Upgrade an already installed package to the latest compatible version
python -m pip install --upgrade requests
# Short flag equivalent:
python -m pip install -U requests
```

### 2. Inspecting Installed Packages
```bash
# List all installed packages and their versions in the active environment
python -m pip list

# List only packages that have newer versions available on PyPI
python -m pip list --outdated

# Display metadata (version, summary, license, location, dependencies) for a package
python -m pip show requests

# Verify that all installed packages have compatible dependency versions
python -m pip check
```

### 3. Uninstalling Packages
```bash
# Remove a package (prompts for confirmation)
python -m pip uninstall requests

# Remove a package without interactive confirmation (useful in scripts/CI)
python -m pip uninstall -y requests
```
*(Note: `pip uninstall` removes only the specified package—not transitive dependencies that were installed alongside it.)*

## 3. Version Specifiers (PEP 440)
When installing packages, you can constrain acceptable versions using **PEP 440 version specifiers**. Always wrap comparison operators (`<`, `>`) in quotes so the shell does not interpret them as file redirection operators.

| Operator | Example | Meaning |
| :--- | :--- | :--- |
| `==` | `"requests==2.32.3"` | Exact version match |
| `!=` | `"requests!=2.31.0"` | Exclude a specific broken/incompatible version |
| `>=` / `<=` | `"numpy>=1.26.0"` | Minimum or maximum inclusive version bound |
| `>` / `<` | `"django>=4.2,<5.0"` | Combined range (at least `4.2`, strictly below `5.0`) |
| `~=` | `"fastapi~=0.115.0"` | **Compatible release:** matches `>=0.115.0` and `<0.116.0` (allows patch updates only) |

### Controlling Pre-Releases
By default, `pip` ignores alpha, beta, and release-candidate versions unless explicitly requested:
```bash
# Include pre-release versions (e.g., 2.0.0rc1) when resolving
python -m pip install --pre some-package
```

## 4. Managing Dependencies (`requirements.txt` and `pyproject.toml`)

### 1. `requirements.txt` (Environment Pinning)
For applications and reproducible training environments, **`requirements.txt`** records exact pinned versions so another developer or CI pipeline can recreate the identical environment:

```bash
# Export all currently installed packages and exact versions
python -m pip freeze > requirements.txt

# Install every package listed in requirements.txt
python -m pip install -r requirements.txt
```

Example `requirements.txt`:
```text
certifi==2024.8.30
charset-normalizer==3.4.0
idna==3.10
requests==2.32.3
urllib3==2.2.3
```

### 2. `pyproject.toml` (Standard Project Metadata — PEP 621)
Modern Python packages declare their abstract dependencies and optional dependency groups in **`pyproject.toml`** rather than legacy `setup.py` files:

```toml
[project]
name = "fde-analytics"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = [
    "requests>=2.31.0",
    "pandas>=2.2.0",
]

[project.optional-dependencies]
dev = [
    "pytest>=8.0.0",
    "ruff>=0.6.0",
]
```

```bash
# Install the local project along with its optional 'dev' dependencies
python -m pip install ".[dev]"
```

### 3. Constraints Files (`-c`)
A **constraints file** restricts allowed versions of packages *without* forcing them to be installed unless required by another package:
```bash
python -m pip install -r requirements.txt -c constraints.txt
```

## 5. Distribution Formats and Installation Sources

### 1. Wheels (`.whl`) vs. Source Distributions (`sdist`, `.tar.gz`)
Packages on PyPI are published in two primary archive formats:

| Format | Extension | Contents & Installation Behavior |
| :--- | :--- | :--- |
| **Wheel (Built Distribution)** | `.whl` | Pre-built binary/bytecode archive ready to unpack directly into `site-packages`. Fast; requires no compiler. |
| **Source Distribution (`sdist`)** | `.tar.gz` / `.zip` | Raw source code plus `pyproject.toml`/`setup.py`. `pip` must build a wheel locally (may require a C/C++ compiler). |

```bash
# Fail fast rather than compiling from source if a pre-built wheel is unavailable
python -m pip install --only-binary :all: numpy
```

### 2. Local Projects and Editable Installs (`-e`)
When developing your own package locally:
* **Standard Local Install (`pip install .`):** Copies the package into `site-packages`. Edits to your source files do not take effect until you reinstall.
* **Editable / Development Install (`pip install -e .`):** Links `site-packages` directly to your local source directory (`src/`). Any changes you save in your editor are immediately reflected upon re-importing:
  ```bash
  # Install current directory in editable mode (PEP 660)
  python -m pip install -e .
  ```

### 3. Alternative Indexes, Git Repositories, and Offline Directories
```bash
# Install directly from a Git repository (branch, tag, or commit hash)
python -m pip install "git+[https://github.com/psf/requests.git@v2.32.3](https://github.com/psf/requests.git@v2.32.3)"

# Install from a private internal package repository
python -m pip install --index-url [https://packages.company.internal/simple/](https://packages.company.internal/simple/) internal-sdk

# Search a private index alongside PyPI
python -m pip install --extra-index-url [https://packages.company.internal/simple/](https://packages.company.internal/simple/) internal-sdk

# Download wheels ahead of time and install completely offline
python -m pip download -r requirements.txt -d ./wheelhouse
python -m pip install --no-index --find-links=./wheelhouse -r requirements.txt
```

## 6. How `pip install` Works Under the Hood
When you execute `python -m pip install <package>`, `pip` runs four sequential phases:

1. **Identify Base Requirements:** Parses command-line specifiers, `-r` files, and constraints.
2. **Resolve Dependencies:** Queries index metadata and runs `pip`'s backtracking dependency resolver to find a version set that satisfies every direct and transitive constraint simultaneously.
3. **Build Wheels:** Downloads pre-built `.whl` files (reusing cached artifacts when available) or builds wheels from `sdist` archives inside an isolated temporary build environment.
4. **Install into `site-packages`:** Uninstalls older versions being replaced and extracts the new wheel contents and console entry points into the active environment.

### Managing the Local `pip` Cache
`pip` caches downloaded archives and locally built wheels on disk to speed up future installs:
```bash
python -m pip cache dir     # Print cache directory path
python -m pip cache info    # Display cache size and wheel count
python -m pip cache purge   # Clear all cached files to reclaim disk space
```

## 7. Common Pitfalls and Best Practices

1. **Encountering `error: externally-managed-environment` (PEP 668):**
   Modern Linux distributions (Ubuntu 23.04+, Debian 12+, Fedora) and Homebrew Python installations mark the system Python with an `EXTERNALLY-MANAGED` file to prevent `pip` from corrupting OS-managed Python tools.
   * **Fix:** Create and activate a virtual environment (`python3 -m venv .venv && source .venv/bin/activate`) before running `pip install`. Avoid passing `--break-system-packages` except inside isolated single-purpose Docker containers.
2. **Running Bare `pip` Instead of `python -m pip`:**
   If multiple Python versions are installed, bare `pip` may belong to a different interpreter than `python`. Always use `python -m pip` to eliminate ambiguity.
3. **Ignoring Security Risks with `--extra-index-url`:**
   When using `--extra-index-url`, `pip` checks *both* PyPI and your private index and picks whichever has the higher version number—exposing builds to **dependency confusion** attacks if an attacker publishes a higher-versioned package with the same name on public PyPI. Use `--index-url` pointing solely to a unified private proxy repository instead.
4. **Leaving Production Dependencies Unpinned:**
   Writing `requests` without a version pin in `requirements.txt` allows future builds to pull breaking major releases automatically. Pin exact versions (`==`) for deployed applications, and use compatible ranges (`>=`, `<`) only when publishing reusable libraries.

## 8. Quick Reference

| Command | Description |
| :--- | :--- |
| `python -m pip install <pkg>` | Installs `<pkg>` and its dependencies into the active environment |
| `python -m pip install "<pkg>==1.2.0"` | Installs an exact pinned version of `<pkg>` |
| `python -m pip install -U <pkg>` | Upgrades `<pkg>` to the latest version matching constraints |
| `python -m pip install -e .` | Installs local project in editable (development) mode |
| `python -m pip install -r requirements.txt` | Installs all dependencies listed in a requirements file |
| `python -m pip freeze > requirements.txt` | Exports installed packages and exact versions to `requirements.txt` |
| `python -m pip list` / `pip show <pkg>` | Lists installed packages or inspects metadata for a specific package |
| `python -m pip check` | Verifies installed packages have no broken dependency conflicts |
| `python -m pip uninstall -y <pkg>` | Uninstalls `<pkg>` without interactive prompt |
