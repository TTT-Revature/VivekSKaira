# Python Standard Library Overview

## 1. Overview
Python ships with an extensive collection of built-in modules and packages known as the **Python Standard Library**, reflecting Python's **"batteries included"** philosophy. It provides tested, cross-platform solutions for file I/O, data structures, text processing, networking, concurrency, serialization, and testing—ready to `import` immediately without installing third-party packages via `pip`.

* **Zero External Installation:** Bundled with every standard CPython installation.
* **Cross-Platform Abstraction:** Provides uniform APIs (`pathlib`, `os`, `subprocess`, `socket`) that hide operating-system differences across Linux, macOS, and Windows.
* **High Performance:** Performance-critical modules (`math`, `json`, `re`, `sqlite3`, `itertools`, `collections`) are implemented largely in C underneath clean Python interfaces.

---

## 2. How the Standard Library Is Organized
Standard library components fall into three implementation layers:

1. **Built-In Functions and Types (`builtins`):** Always available in every scope without an explicit `import` statement (e.g., `len()`, `print()`, `range()`, `enumerate()`, `zip()`, `list`, `dict`, `Exception`).
2. **Built-In C Extension Modules:** Compiled directly into the Python interpreter executable (`sys`, `time`, `itertools`, `gc`). Inspecting `sys.__file__` raises `AttributeError` because there is no standalone `.py` file on disk.
3. **Library Modules and Packages (`Lib/`):** Pure Python `.py` files and packages—optionally backed by C accelerators—stored inside Python's installation directory (`sys.base_prefix`).

## 3. Core Categories and Essential Modules

### 1. Operating System, Paths, and Processes
| Module | Primary Purpose | Key Functions / Classes |
| :--- | :--- | :--- |
| **`pathlib`** | Object-oriented filesystem path manipulation | `Path`, `.read_text()`, `.write_text()`, `.glob()`, `.mkdir()` |
| **`os`** | OS environment variables, process info, low-level file ops | `os.environ`, `os.getenv()`, `os.getcwd()`, `os.walk()` |
| **`sys`** | Python runtime parameters, CLI args, module search paths | `sys.argv`, `sys.path`, `sys.exit()`, `sys.version`, `sys.modules` |
| **`shutil`** | High-level file copying, moving, and directory tree removal | `shutil.copy2()`, `shutil.move()`, `shutil.rmtree()`, `shutil.make_archive()` |
| **`subprocess`** | Spawning and communicating with external OS commands | `subprocess.run()`, `subprocess.PIPE`, `CompletedProcess` |

| Module | Primary Purpose | Key Functions / Classes |
| :--- | :--- | :--- |
| **`collections`** | Specialized high-performance container datatypes | `Counter`, `defaultdict`, `deque`, `namedtuple`, `ChainMap` |
| **`itertools`** | Memory-efficient lazy iterator building blocks | `chain()`, `islice()`, `groupby()`, `product()`, `combinations()` |

| **`heapq`** | Binary min-heap priority queue operations on lists | `heappush()`, `heappop()`, `nlargest()`, `nsmallest()` |
| **`bisect`** | Binary search and sorted list insertion | `bisect_left()`, `bisect_right()`, `insort()` |
| **`dataclasses`** | Boilerplate-free data-holding classes | `@dataclass`, `field()`, `asdict()`, `replace()` |

## 4. Practical Example: Composing Standard Library Modules
Many backend scripts and data-processing utilities can be built cleanly using only standard library modules—keeping dependencies at zero:

```python
from collections import Counter
from datetime import datetime, timezone
import json
from pathlib import Path
import secrets


def summarize_events(raw_records: list[dict[str, str]], output_path: Path) -> dict[str, object]:
    """Aggregate event counts, attach UTC metadata and a run ID, and write JSON output."""
    status_counts = Counter(record["status"] for record in raw_records)

    report = {
        "run_id": secrets.token_hex(8),
        "generated_at_utc": datetime.now(timezone.utc).isoformat(),
        "total_events": len(raw_records),
        "breakdown": dict(status_counts),
    }

    output_path.parent.mkdir(parents=True, exist_ok=True)
    output_path.write_text(json.dumps(report, indent=2), encoding="utf-8")
    return report


if __name__ == "__main__":
    sample_logs = [
        {"service": "auth", "status": "OK"},
        {"service": "billing", "status": "ERROR"},
        {"service": "auth", "status": "OK"},
    ]
    summary = summarize_events(sample_logs, Path("build/event_summary.json"))
    print(summary["breakdown"])  # {'OK': 2, 'ERROR': 1}
```

## 5. Inspecting Standard Library Modules at Runtime
Python exposes metadata about its standard library directly at runtime:

```python
import json
import sys

# 1. Check whether a module name belongs to the Python Standard Library (Python 3.10+)
print("json in stdlib    :", "json" in sys.stdlib_module_names)      # True
print("requests in stdlib:", "requests" in sys.stdlib_module_names)  # False

# 2. Locate the physical source file of a standard library module
print("json location     :", json.__file__)

# 3. Inspect public attributes and built-in documentation interactively
print([name for name in dir(json) if not name.startswith("_")])
# ['JSONDecodeError', 'JSONDecoder', 'JSONEncoder', 'dump', 'dumps', 'load', 'loads']
```

## 6. Common Pitfalls and Best Practices

1. **Shadowing Standard Library Module Names:**
   Naming a local script `random.py`, `json.py`, `email.py`, `logging.py`, or `typing.py` places your file ahead of the standard library on `sys.path`. Importing that name—or any standard library module that depends on it—loads your local script instead and raises confusing `AttributeError` or `ImportError` failures.
2. **Using `random` Instead of `secrets` for Security-Sensitive Values:**
   The `random` module uses a deterministic Mersenne Twister generator suitable only for simulations and sampling. Always use **`secrets`** (`secrets.token_urlsafe()`, `secrets.token_hex()`) for passwords, API keys, session IDs, and OTPs.
3. **Using `float` Instead of `decimal.Decimal` for Financial Calculations:**
   Binary floating-point representation causes rounding artifacts (`0.1 + 0.2 == 0.30000000000000004`). Use **`decimal.Decimal`** initialized from strings (`Decimal("19.99")`) for currency and accounting logic.
4. **Unserializing Untrusted Data with `pickle`:**
   `pickle.loads()` can execute arbitrary code during deserialization. Never load `pickle` payloads from untrusted network sources or user uploads; prefer **`json`** for data interchange.
5. **Passing `shell=True` with Unsanitized Strings to `subprocess.run()`:**
   Avoid `subprocess.run(f"ls {user_input}", shell=True)`, which enables shell injection vulnerabilities. Pass arguments as a list with `shell=False` (the default): `subprocess.run(["ls", user_input], check=True)`.

## 7. Quick Reference

| Need | Standard Library Module | Avoid / Legacy Alternative |
| :--- | :--- | :--- |
| Filesystem paths | `pathlib.Path` | Manual `os.path.join()` string manipulation |
| CLI argument parsing | `argparse` | Manual `sys.argv` index slicing |
| Cryptographic tokens | `secrets` | `random` |
| Exact decimal / money math | `decimal.Decimal` | Binary `float` |
| Safe external commands | `subprocess.run([...])` | `os.system(...)` |
| Frequency counting | `collections.Counter` | Manual `dict` counting loops |
| Function memoization | `functools.lru_cache` / `@cache` | Custom global cache dictionaries |
| Diagnostic output | `logging` | Scattered `print()` statements in production code |
