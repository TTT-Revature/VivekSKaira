# Operator Precedence

## 1. Overview
When an expression contains multiple operators, **operator precedence** determines the order in which operations are evaluated. Operators with higher precedence are evaluated before operators with lower precedence.

When two operators share the **same precedence level**, **associativity** determines the direction of evaluation (either left-to-right or right-to-left).

---

## 2. Precedence Hierarchy (Highest to Lowest)
The table below lists Python's operators ordered from highest precedence (evaluated first) to lowest precedence (evaluated last):

| Priority | Operator(s) | Description | Associativity |
| :--- | :--- | :--- | :--- |
| 1 (Highest) | `()` | Parentheses (grouping) | Left-to-right |
| 2 | `x[i]`, `x[a:b]`, `f()`, `x.attr` | Indexing, slicing, function call, attribute access | Left-to-right |
| 3 | `**` | Exponentiation | **Right-to-left** |
| 4 | `+x`, `-x`, `~x` | Unary plus, unary minus, bitwise NOT | Right-to-left |
| 5 | `*`, `@`, `/`, `//`, `%` | Multiplication, matrix mult., division, floor div., modulus | Left-to-right |
| 6 | `+`, `-` | Addition and subtraction | Left-to-right |
| 7 | `<<`, `>>` | Bitwise left and right shifts | Left-to-right |
| 8 | `&` | Bitwise AND | Left-to-right |
| 9 | `^` | Bitwise XOR | Left-to-right |
| 10 | `\|` | Bitwise OR | Left-to-right |
| 11 | `==`, `!=`, `<`, `<=`, `>`, `>=`, `is`, `is not`, `in`, `not in` | Comparisons, identity, and membership tests | Chained (Left-to-right) |
| 12 | `not` | Logical NOT | Right-to-left |
| 13 | `and` | Logical AND | Left-to-right |
| 14 | `or` | Logical OR | Left-to-right |
| 15 | `if ... else` | Conditional (ternary) expression | Right-to-left |
| 16 | `lambda` | Lambda expression | N/A |
| 17 (Lowest) | `:=` | Assignment expression (walrus operator) | Right-to-left |

*(Note: Standard assignment statements such as `=`, `+=`, and `-=` are always evaluated after the right-hand expression has been completely resolved.)*

---

## 3. Associativity Rules

### Left-to-Right Associativity
Most operators at the same precedence level evaluate from left to right:
```python
# Division and multiplication share the same precedence -> evaluated left-to-right
result = 20 / 5 * 2
# Step 1: 20 / 5 -> 4.0
# Step 2: 4.0 * 2 -> 8.0
print(result)  # 8.0
```

### Right-to-Left Associativity
Exponentiation (`**`) is the most common right-to-left associative operator:
```python
# Evaluated from right to left: 2 ** (3 ** 2)
power = 2 ** 3 ** 2
# Step 1: 3 ** 2 -> 9
# Step 2: 2 ** 9 -> 512
print(power)  # 512
```

### Unary Minus vs. Exponentiation
Because `**` has higher precedence than unary minus (`-x`), the exponent applies before the negative sign:
```python
print(-3 ** 2)    # -9  (evaluated as -(3 ** 2))
print((-3) ** 2)  # 9   (parentheses force negative base first)
```

---

## 4. Logical and Comparison Precedence
Arithmetic operators execute first, followed by comparison/membership operators, and finally logical operators (`not`, then `and`, then `or`):

```python
a = 10
b = 5
c = 20

# Evaluated as: (a + b > 12) and (not (c == 10))
outcome = a + b > 12 and not c == 10
# Step 1: 10 + 5 -> 15
# Step 2: 15 > 12 -> True, and c == 10 -> False
# Step 3: not False -> True
# Step 4: True and True -> True
print(outcome)  # True
```

### Chained Comparisons
Comparison operators at priority level 11 do not associate strictly left-to-right like arithmetic; instead, Python chains them implicitly with `and`:
```python
x = 15
# Evaluated as: (10 < x) and (x < 20)
print(10 < x < 20)  # True
```

---

## 5. Best Practices
* **Use Parentheses for Clarity:** Even when parentheses are not strictly required by Python's precedence table, use them to make complex arithmetic or boolean conditions immediately obvious to anyone reading your code.
  ```python
  # Clear and unambiguous
  is_eligible = (age >= 18 and has_id) or is_admin
  ```
* **Break Up Complex Expressions:** If an expression requires multiple nested parentheses, split intermediate results into well-named variables instead.
