# Generator Functions and `yield`

## 1. Overview
A **generator function** is any Python function defined with `def` that contains at least one **`yield`** statement. Instead of computing all results up front and returning them in a collection, a generator function produces values **lazily—one at a time—on demand**.

* **Automatic Iterator Protocol:** Calling a generator function does not execute its body immediately; instead, it returns a **generator object**, which automatically implements both `__iter__()` and `__next__()`.
* **Execution Suspension and Resumption:** Each time `yield` is reached, the generator pauses execution, returns the yielded value to the caller, and preserves its entire local state (local variables, instruction pointer, and active `try`/`with` blocks) in memory until the next `next()` call resumes it.
* **Constant Memory Footprint:** Generates items sequentially rather than storing an entire sequence in RAM, making generators ideal for large files, data pipelines, and infinite streams.

---

## 2. How Generator Functions Execute
A generator object transitions through four distinct states during its lifetime (`GEN_CREATED`, `GEN_RUNNING`, `GEN_SUSPENDED`, `GEN_CLOSED`):

1. **Creation (`GEN_CREATED`):** Calling `gen = countdown(3)` creates and returns the generator object without running a single line inside the function body.
2. **First `next(gen)` Call:** Execution starts from the top of the function and runs until it hits the first `yield` statement, returning that value and pausing (`GEN_SUSPENDED`).
3. **Subsequent `next(gen)` Calls:** Execution resumes immediately *after* the previous `yield` line, preserving all local variable values, until the next `yield` is encountered.
4. **Termination (`GEN_CLOSED`):** When the function reaches its end or executes a `return` statement, Python raises **`StopIteration`** and permanently closes the generator.

```python
import inspect
from collections.abc import Generator

def countdown(start: int) -> Generator[int, None, None]:
    print("Generator started")
    while start > 0:
        yield start
        start -= 1
    print("Generator finished")

gen = countdown(3)
print("State after creation:", inspect.getgeneratorstate(gen))  # GEN_CREATED

print("First value :", next(gen))  # Prints 'Generator started', returns 3
print("State after yield   :", inspect.getgeneratorstate(gen))  # GEN_SUSPENDED

print("Second value:", next(gen))  # Returns 2
print("Third value :", next(gen))  # Returns 1

# Calling next(gen) once more prints 'Generator finished' and raises StopIteration
try:
    next(gen)
except StopIteration:
    print("State at end        :", inspect.getgeneratorstate(gen))  # GEN_CLOSED
```

## 3. `yield` vs. `return`

| Feature | `return` | `yield` |
| :--- | :--- | :--- |
| **Function Type** | Standard function | Generator function |
| **Effect on Execution** | Terminates the function permanently and destroys its local stack frame | Pauses the function and saves all local variables and execution state |
| **Number of Outputs** | Produces at most one return value per call | Can produce zero, one, or arbitrarily many values across multiple `next()` calls |
| **Memory Behavior** | Must build and return an entire list/collection at once for multiple items | Produces one item at a time with $O(1)$ auxiliary memory |
| **Using `return` in a Generator** | N/A | Terminates the generator immediately and raises `StopIteration(value)` |

### Returning a Final Summary Value from a Generator
In Python 3.3+, a generator function can include `return expr`. Executing `return expr` ends iteration by raising `StopIteration` with `expr` stored in **`StopIteration.value`**:

```python
from collections.abc import Generator

def process_batches(items: list[str]) -> Generator[str, None, int]:
    count = 0
    for item in items:
        yield item.strip().upper()
        count += 1
    return count  # Attached to StopIteration.value

gen = process_batches(["python", "sql", "git"])
print(next(gen))  # 'PYTHON'
print(next(gen))  # 'SQL'
print(next(gen))  # 'GIT'

try:
    next(gen)
except StopIteration as exc:
    print(f"Total items processed: {exc.value}")  # Total items processed: 3
```

## 4. Practical Use Cases: Memory Efficiency and Streaming

### 1. Memory Comparison: Eager List vs. Lazy Generator
```python
import sys

def eager_squares(n: int) -> list[int]:
    return [i * i for i in range(n)]

def lazy_squares(n: int):
    for i in range(n):
        yield i * i

n = 1_000_000
eager_result = eager_squares(n)
lazy_result = lazy_squares(n)

print("List size in memory     :", sys.getsizeof(eager_result), "bytes")  # ~8,448,728 bytes
print("Generator size in memory:", sys.getsizeof(lazy_result), "bytes")   # ~200 bytes
```

### 2. Representing Infinite Sequences
Because generators compute elements only when requested, they can model infinite mathematical or ID sequences without running out of memory:

```python
from collections.abc import Iterator

def fibonacci_stream() -> Iterator[int]:
    a, b = 0, 1
    while True:
        yield a
        a, b = b, a + b

fib = fibonacci_stream()
first_eight = [next(fib) for _ in range(8)]
print(first_eight)  # [0, 1, 1, 2, 3, 5, 8, 13]
```

### 3. Composable Data Processing Pipelines
Multiple generators can be chained together so each record flows through every transformation stage one item at a time without creating intermediate lists:

```python
from collections.abc import Iterable, Iterator

def read_non_empty(lines: Iterable[str]) -> Iterator[str]:
    for line in lines:
        cleaned = line.strip()
        if cleaned:
            yield cleaned

def filter_errors(lines: Iterable[str]) -> Iterator[str]:
    for line in lines:
        if line.startswith("ERROR:"):
            yield line.removeprefix("ERROR:").strip()

raw_logs = [
    "INFO: Service started\n",
    "   \n",
    "ERROR: Database connection timed out\n",
    "INFO: Retrying connection\n",
    "ERROR: Authentication failed\n",
]

# No data is processed until the final loop pulls from the pipeline
pipeline = filter_errors(read_non_empty(raw_logs))
for message in pipeline:
    print("Alert ->", message)
```

## 5. Delegating to Sub-Generators (`yield from`)
Introduced in PEP 380, **`yield from iterable`** delegates iteration directly to another iterable or sub-generator, eliminating manual `for item in sub_iterable: yield item` loops and forwarding `.send()`, `.throw()`, and return values transparently.

```python
from collections.abc import Iterable, Iterator

def flatten(nested: Iterable) -> Iterator:
    """Recursively yields elements from arbitrarily nested lists or tuples."""
    for item in nested:
        if isinstance(item, (list, tuple)):
            yield from flatten(item)
        else:
            yield item

data = [1, [2, 3, [4, 5]], (6, [7, 8])]
print(list(flatten(data)))  # [1, 2, 3, 4, 5, 6, 7, 8]
```

### Capturing a Sub-Generator's `return` Value with `yield from`
When delegating to a sub-generator that executes `return result`, `yield from` captures `StopIteration.value` directly:

```python
def sub_worker():
    yield "Step A"
    yield "Step B"
    return 2

def coordinator():
    steps_completed = yield from sub_worker()
    yield f"Done ({steps_completed} steps)"

print(list(coordinator()))
# Output: ['Step A', 'Step B', 'Done (2 steps)']
```

## 6. Generator Control Methods (`.send()`, `.throw()`, `.close()`)
Beyond `next()`, generator objects expose three methods for two-way communication and lifecycle control:

### 1. `.send(value)` — Two-Way Data Passing
`yield` is an expression that evaluates to whatever value is passed into `gen.send(value)` when resuming the generator. A newly created generator must first be **primed** with `next(gen)` (or `gen.send(None)`) so execution reaches the first `yield`.

```python
def running_average():
    total = 0.0
    count = 0
    average = None
    while True:
        new_value = yield average  # Yields current average, receives next input
        if new_value is None:
            break
        total += new_value
        count += 1
        average = total / count

avg_gen = running_average()
next(avg_gen)               # Prime the generator (advances to first yield)

print(avg_gen.send(10))     # 10.0
print(avg_gen.send(20))     # 15.0
print(avg_gen.send(30))     # 20.0
```

### 2. `.throw(exc_type, exc_val)` and `.close()`
* **`.throw(exc)`:** Injects an exception at the exact `yield` point where the generator is currently suspended.
* **`.close()`:** Injects **`GeneratorExit`** at the suspended `yield` point so `try ... finally` or `with` cleanup blocks inside the generator run cleanly before closing it.

```python
def managed_stream():
    try:
        while True:
            yield "Streaming record..."
    finally:
        print("Cleanup executed on close.")

stream = managed_stream()
print(next(stream))  # 'Streaming record...'
stream.close()       # Prints: 'Cleanup executed on close.'
```

## 7. Generator Functions vs. Generator Expressions

| Feature | Generator Function (`def` + `yield`) | Generator Expression (`(expr for x in seq)`) |
| :--- | :--- | :--- |
| **Syntax** | Multi-line `def` block containing `yield` | Compact parenthesized comprehension syntax |
| **Complexity** | Supports loops, branching, `try`/`with` blocks, and stateful logic | Best for single-expression filtering and mapping |
| **Reusability** | Can be called repeatedly to create fresh generators | Single-use object once created |
| **Readability** | Clearer for multi-step pipelines or nested loops | Concise when passed directly into `sum()`, `any()`, `max()`, etc. |

```python
# Generator expression passed directly to sum() (outer parentheses omitted)
total_even_squares = sum(x * x for x in range(10) if x % 2 == 0)
print(total_even_squares)  # 120
```

## 8. Common Pitfalls and Edge Cases

1. **Calling a Generator Function Without Iterating:**
   Calling `my_gen()` does **not** run the function body—any setup or validation code before the first `yield` will not execute until `next()` or a `for` loop starts pulling items.
2. **Single-Pass Exhaustion:**
   Like all iterators, a generator can only be traversed once. Calling `list(gen)` a second time returns `[]`. Re-invoke the generator function if you need another pass.
3. **No `len()` or Indexing Support:**
   Generators compute values dynamically and do not know their length in advance. Calling `len(gen)` or `gen[0]` raises `TypeError: object of type 'generator' has no len()` / `'generator' object is not subscriptable`.
4. **Calling `.send(value)` Before Priming:**
   Calling `gen.send(42)` on a freshly created generator (`GEN_CREATED`) raises `TypeError: can't send non-None value to a just-started generator`. Always call `next(gen)` first.

## 9. Quick Reference

| Keyword / Method / Type | Purpose | Key Behavior |
| :--- | :--- | :--- |
| `yield expr` | Pauses generator and outputs `expr` | Preserves local variables and execution state until next `next()` |
| `yield from iterable` | Delegates iteration to a sub-iterable/generator | Yields all items from `iterable` and captures its `return` value |
| `next(gen[, default])` | Advances generator to the next `yield` | Raises `StopIteration` (or returns `default`) when finished |
| `gen.send(value)` | Resumes generator and passes `value` into `yield` | Generator must be primed with `next(gen)` before sending non-`None` |
| `gen.throw(exc)` | Raises `exc` at the suspended `yield` line | Allows generator `try/except` blocks to handle caller-injected errors |
| `gen.close()` | Terminates generator cleanly via `GeneratorExit` | Triggers `finally` and `with` cleanup blocks inside the generator |
| `collections.abc.Generator` | Type annotation for generator functions | Parameterized as `Generator[YieldType, SendType, ReturnType]` |
