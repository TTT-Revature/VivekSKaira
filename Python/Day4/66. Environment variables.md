# Environment Variables in Python

## 1. Overview
**Environment variables** are dynamic, OS-level `KEY=VALUE` string pairs stored outside an application's source code and passed into a running process by the operating system.

* **Separation of Configuration from Code:** Allows the same codebase to run across different environments (development, testing, staging, production) without modifying source files.
* **Security:** Keeps sensitive credentials—such as database passwords, API keys, and JWT secrets—out of version control (Git).
* **Process Scope:** A process inherits a copy of its parent process's environment variables upon launch. Changes made inside a Python script affect **only that Python process and any child processes it spawns**—they never modify the parent terminal or system-wide settings permanently.

---

## 2. Reading Environment Variables (`os.environ` vs. `os.getenv()`)
Python's built-in **`os`** module provides two primary ways to read environment variables:

### 1. `os.environ` (Dictionary-Like Mapping)
`os.environ` is a mapping object representing the current process environment. Indexing it with square brackets (`os.environ["KEY"]`) raises a **`KeyError`** if the variable is not set—making it ideal for **mandatory** configuration values where the app should fail immediately if missing.

```python
import os

# 1. Mandatory lookup: raises KeyError if 'DATABASE_URL' is missing
db_url = os.environ["DATABASE_URL"]

# 2. Safe lookup using .get(): returns None (or fallback) if missing
log_level = os.environ.get("LOG_LEVEL", "INFO")

# 3. Checking existence before access
if "API_KEY" in os.environ:
    print("API_KEY is configured.")
```

### 2. `os.getenv()` (Convenience Function)
`os.getenv(key, default=None)` is a wrapper around `os.environ.get()`. It never raises a `KeyError`, returning `None` (or the specified `default`) when the variable does not exist:

```python
import os

# Returns None if 'CACHE_HOST' is not set
cache_host = os.getenv("CACHE_HOST")

# Returns 'localhost' if 'APP_HOST' is not set
app_host = os.getenv("APP_HOST", "localhost")
print(f"Binding server to {app_host}")
```

### Comparison: `os.environ["KEY"]` vs. `os.getenv("KEY")`

| Feature | `os.environ["KEY"]` | `os.getenv("KEY", default=None)` |
| :--- | :--- | :--- |
| **Behavior When Missing** | Raises `KeyError` | Returns `default` (`None` if omitted) |
| **Best Used For** | Required secrets/configs (fail-fast startup) | Optional settings with sensible defaults |
| **Supports Assignment/Deletion** | Yes (`os.environ["K"] = "V"`, `del os.environ["K"]`) | No (read-only lookup function) |

## 3. Setting and Unsetting Environment Variables

### 1. Modifying Variables Inside Python (Runtime Scope)
Because `os.environ` is a mutable mapping, you can add, update, or remove variables during runtime. Both keys and values **must be `str` objects** (passing an `int` or `None` raises `TypeError`).

```python
import os
import subprocess

# Set or update an environment variable for the current process
os.environ["APP_ENV"] = "staging"
os.environ["MAX_WORKERS"] = str(4)  # Must convert integers to str

# Child processes inherit updated environment variables
subprocess.run(["python", "-c", "import os; print(os.getenv('APP_ENV'))"])

# Remove a variable safely (returns None if key does not exist)
os.environ.pop("TEMP_TOKEN", None)

# Remove a variable strictly (raises KeyError if key does not exist)
del os.environ["APP_ENV"]
```

### 2. Passing Variables from the Command Line / Shell
In practice, environment variables are usually injected by the shell, Docker container, or CI/CD pipeline before Python starts:

* **Linux / macOS (Bash / Zsh):**
  ```bash
  # Export for the entire terminal session
  export API_KEY="secret_token_123"
  python app.py

  # Inline for a single command execution only
  APP_ENV=production PORT=8080 python app.py
  ```
* **Windows (PowerShell):**
  ```powershell
  $env:API_KEY = "secret_token_123"
  python app.py
  ```
* **Windows (Command Prompt / CMD):**
  ```cmd
  set API_KEY=secret_token_123
  python app.py
  ```

## 4. Type Conversion and Boolean Parsing
Environment variables are **always stored as strings (`str`)**, even when assigned numeric or boolean-looking values such as `PORT=8000` or `DEBUG=False`.

### The Boolean Parsing Trap
In Python, calling `bool("False")` or `bool("0")` evaluates to **`True`** because any non-empty string is truthy. Always compare normalized lowercase strings explicitly:

```python
import os

def get_bool_env(key: str, default: bool = False) -> bool:
    raw = os.getenv(key)
    if raw is None:
        return default
    return raw.strip().lower() in ("1", "true", "yes", "on")

# Casting numeric and list environment variables
port = int(os.getenv("PORT", "8000"))
timeout = float(os.getenv("REQUEST_TIMEOUT", "5.5"))
debug_mode = get_bool_env("DEBUG", default=False)

# Parsing comma-separated lists (e.g., ALLOWED_HOSTS="localhost,127.0.0.1,example.com")
raw_hosts = os.getenv("ALLOWED_HOSTS", "")
allowed_hosts = [h.strip() for h in raw_hosts.split(",") if h.strip()]
```

## 5. Local Development with `.env` Files (`python-dotenv`)
Setting dozens of variables manually in the terminal during local development is tedious. Developers commonly store local variables in a **`.env`** file at the project root and load them using the third-party **`python-dotenv`** package (`pip install python-dotenv`).

### 1. Example `.env` File
```env
# Application settings
APP_ENV=development
DEBUG=true
PORT=8000

# Secrets (never commit this file to Git)
DATABASE_URL=postgresql://admin:pass123@localhost:5432/fde_db
API_KEY="sk-live-987654321"
```

### 2. Loading `.env` in Python
Call `load_dotenv()` at the very entry point of your application before reading `os.environ` or `os.getenv()`:

```python
import os
from dotenv import load_dotenv

# Reads .env and populates os.environ
# By default (override=False), existing OS environment variables take precedence
load_dotenv()

db_url = os.environ["DATABASE_URL"]
port = int(os.getenv("PORT", "8000"))
print(f"Connected to {db_url} on port {port}")
```

### 3. Version Control Hygiene (`.gitignore` and `.env.example`)
* Add `.env` to your **`.gitignore`** file so real credentials are never pushed to GitHub.
* Commit a **`.env.example`** template file containing placeholder values so teammates know which variables are required:
  ```env
  APP_ENV=development
  DEBUG=true
  PORT=8000
  DATABASE_URL=postgresql://user:password@localhost:5432/dbname
  API_KEY=your_api_key_here
  ```

## 6. Security and Production Best Practices

1. **Fail Fast on Startup:** Validate all mandatory environment variables immediately when the application boots (for example, inside a dedicated `config.py` module) rather than letting a missing key crash a background job hours later.
2. **Never Hardcode Fallback Secrets:** Use defaults only for non-sensitive settings (`PORT`, `LOG_LEVEL`, `TIMEOUT`). Never write `os.getenv("SECRET_KEY", "hardcoded_prod_secret")`.
3. **Never Log Entire `os.environ` Dumps:** Printing `dict(os.environ)` to logs exposes API keys, cloud credentials, and session tokens in plain text.
4. **Case Sensitivity:** Environment variable names are **case-sensitive** on Linux and macOS (`API_KEY != api_key`), whereas Windows treats them as **case-insensitive**. Always use `UPPER_SNAKE_CASE` consistently.

```python
# config.py — Centralized, fail-fast configuration pattern
import os
from dotenv import load_dotenv

load_dotenv()

class Config:
    DATABASE_URL: str = os.environ["DATABASE_URL"]  # Mandatory: fails immediately if unset
    API_KEY: str = os.environ["API_KEY"]            # Mandatory: fails immediately if unset
    PORT: int = int(os.getenv("PORT", "8000"))      # Optional with safe default
    DEBUG: bool = os.getenv("DEBUG", "false").lower() in ("1", "true", "yes")
```

## 7. Quick Reference

| Construct / Command | Purpose | Key Notes |
| :--- | :--- | :--- |
| `os.environ["KEY"]` | Reads a required environment variable | Returns `str`; raises `KeyError` if missing |
| `os.environ.get("KEY", default)` | Reads an optional environment variable | Returns `str` or `default` (`None` if omitted) |
| `os.getenv("KEY", default)` | Convenience wrapper for `os.environ.get()` | Safe read-only lookup; never raises `KeyError` |
| `os.environ["KEY"] = "val"` | Sets or updates a variable for current/child processes | Both key and value must be `str` |
| `os.environ.pop("KEY", None)` | Deletes a variable without raising `KeyError` | Affects only current process and child processes |
| `dotenv.load_dotenv()` | Loads `KEY=VALUE` pairs from `.env` into `os.environ` | Does not overwrite existing OS variables unless `override=True` |
