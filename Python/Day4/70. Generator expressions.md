# Generator Expressions

## 1. Overview
Introduced in Python 2.4 (PEP 289), a **generator expression** is a compact, inline syntax for creating a **generator object** without writing a full `def` generator function with `yield`.

* **Lazy Evaluation:** Computes and yields one item at a time on demand rather than building and storing an entire collection in memory up front.
* **Iterator Protocol Built In:** Evaluating a generator expression immediately returns a `generator` instance that implements both `__iter__()` and `__next__()`.
* **Constant Memory Footprint ($O(1)$):** Holds only the current iteration state in RAM regardless of whether the underlying data stream contains ten elements or ten billion.

```python
# List comprehension: builds the entire list in memory immediately
squares_list = [x * x for x in range(5)]

# Generator expression: returns a lazy generator object
squares_gen = (x * x for x in range(5))

print(squares_list)        # [0, 1, 4, 9, 16]
print(squares_gen)         # <generator object <genexpr> at 0x...>
print(next(squares_gen))   # 0
print(list(squares_gen))   # [1, 4, 9, 16] (consumes remaining items)
```

## 2. Syntax and Anatomy

### Basic Forms
```python
# 1. Basic mapping
gen = (expression for item in iterable)

# 2. Filtering with 'if'
filtered_gen = (expression for item in iterable if condition)

# 3. Conditional expression (ternary) inside the output expression
labeled_gen = ("even" if x % 2 == 0 else "odd" for x in range(5))

# 4. Nested 'for' clauses (evaluated left-to-right, matching nested loops)
matrix = [[1, 2], [3, 4], [5, 6]]
flattened_gen = (num for row in matrix for num in row)
print(list(flattened_gen))  # [1, 2, 3, 4, 5, 6]
```

### Parentheses Omission Rule
When a generator expression is passed as the **sole argument** to a function call, Python allows you to omit the extra pair of parentheses around the generator expression:

```python
numbers = [1, 2, 3, 4, 5]

# Valid: single argument -> outer parentheses of the generator expression can be omitted
total = sum(x * x for x in numbers)
print(total)  # 55

# Required: multiple arguments -> generator expression MUST be wrapped in parentheses
total_with_offset = sum((x * x for x in numbers), start=100)
print(total_with_offset)  # 155
```

## 3. Generator Expressions vs. List Comprehensions

| Feature | Generator Expression `(expr for x in seq)` | List Comprehension `[expr for x in seq]` |
| :--- | :--- | :--- |
| **Delimiters** | Parentheses `(...)` | Square brackets `[...]` |
| **Return Type** | `generator` (an iterator) | `list` (an iterable sequence) |
| **Evaluation Strategy** | Lazy (computes next value only on `next()`) | Eager (computes every value immediately) |
| **Memory Usage** | $O(1)$ constant (~200 bytes) | $O(n)$ proportional to output length |
| **Time to First Item** | Instantaneous (no upfront loop execution) | Must finish processing all $n$ elements first |
| **Short-Circuiting** | Supported (`any()`, `all()`, `next()` stop early) | Not supported (evaluates entire list first) |
| **Reusability** | Single-pass (exhausted after one full traversal) | Reusable across unlimited loops |
| **Sequence Operations** | Does **not** support `len()`, indexing, or slicing | Supports `len()`, `lst[i]`, slicing, `reversed()` |

### Memory and Short-Circuiting Benchmark
```python
import sys

n = 1_000_000
list_comp = [i * 2 for i in range(n)]
gen_expr = (i * 2 for i in range(n))

print("List comprehension size :", sys.getsizeof(list_comp), "bytes")  # ~8,448,728 bytes
print("Generator expression size:", sys.getsizeof(gen_expr), "bytes")   # ~200 bytes

# Short-circuiting advantage: stops immediately at the first match (i = 500)
has_large_square = any(i * i > 200_000 for i in range(1_000_000_000))
print("Found match:", has_large_square)  # True (executes in microseconds)
```

## 4. Practical Use Cases

### 1. Aggregations and Reduction Functions
Reduction built-ins (`sum()`, `min()`, `max()`, `any()`, `all()`) consume iterators one element at a time, making generator expressions the idiomatic choice:

```python
scores = [84, 91, 76, 95, 88]

average = sum(s for s in scores) / len(scores)
all_passed = all(s >= 75 for s in scores)
any_distinction = any(s >= 90 for s in scores)

print(f"Average: {average:.1f} | All Passed: {all_passed} | Distinction: {any_distinction}")
```

### 2. String Joining (`str.join()`)
```python
tags = ["python", "fde", "generators", "clean-code"]
slug = "-".join(tag.strip().lower() for tag in tags)
print(slug)  # 'python-fde-generators-clean-code'
```

### 3. Safe First-Match Lookup with `next()`
Pairing `next(..., default)` with a generator expression finds the first matching item and halts immediately without scanning the remainder of the sequence:

```python
records = [
    {"id": 101, "status": "ACTIVE"},
    {"id": 102, "status": "FAILED"},
    {"id": 103, "status": "FAILED"},
]

first_failure = next((r for r in records if r["status"] == "FAILED"), None)
print(first_failure)  # {'id': 102, 'status': 'FAILED'}
```

### 4. Streaming File Processing Pipelines
Generator expressions can be chained together to transform large files line by line with minimal RAM usage:

```python
from pathlib import Path

log_path = Path("application.log")

with log_path.open(mode="r", encoding="utf-8") as f:
    stripped_lines = (line.strip() for line in f)
    non_empty = (line for line in stripped_lines if line)
    error_lines = (line for line in non_empty if "ERROR" in line)

    for err in error_lines:
        print(err)
```

## 5. Evaluation Timing and Scoping Rules
Understanding **when** Python evaluates each part of a generator expression prevents subtle runtime bugs:

1. **Outermost Iterable is Evaluated Eagerly:** When the generator expression is created, Python immediately calls `iter()` on the outermost iterable expression. If that object is not iterable, `TypeError` is raised right away.
2. **Output Expression, Conditions, and Inner Iterables are Evaluated Lazily:** They are evaluated step-by-step only as `next()` pulls items from the generator.
3. **Isolated Loop Variable Scope:** Like comprehensions, the loop variable inside `(x for x in seq)` has its own local scope and does not overwrite an outer variable with the same name.
4. **Late Binding of External Variables:** Non-loop variables referenced inside the output expression or `if` clause are looked up when each item is yielded—not when the generator expression was defined.

```python
# 1. Outermost iterable is checked at creation time
# bad_gen = (x for x in 12345)  # Immediately raises TypeError: 'int' object is not iterable

# 2. Late binding of external variables
multiplier = 2
nums = [1, 2, 3]
scaled = (n * multiplier for n in nums)

multiplier = 10  # Mutated BEFORE iteration begins
print(list(scaled))  # [10, 20, 30] (uses multiplier = 10, not 2)
```

## 6. Common Pitfalls and Edge Cases

1. **Single-Pass Exhaustion:**
   A generator expression can only be iterated over once. Passing it to `sum()` and then `max()` leaves the second call with an empty iterator (`ValueError: max() arg is an empty sequence`):
   ```python
   gen = (x for x in [10, 20, 30])
   print(sum(gen))   # 60
   print(list(gen))  # [] (already exhausted)
   ```
2. **Printing a Generator Expression Directly:**
   Calling `print(x for x in range(3))` outputs `<generator object <genexpr> at 0x...>`, not the elements. Unpack with `*`, pass to `list()`, or iterate with a `for` loop to inspect values.
3. **Closing File Streams Before Consuming a Generator:**
   If a generator expression reads from an open file (`(line for line in f)`), you must consume the generator **inside** the `with open(...)` block; iterating after the block exits raises `ValueError: I/O operation on closed file`.
4. **Using a List Comprehension When Multiple Passes Are Needed:**
   If you need `len()`, random indexing (`data[0]`), sorting, or multiple traversals over the results, use a list comprehension `[...]` instead of converting a generator expression into a list manually (`list(x for x in seq)` is slower and less readable than `[x for x in seq]`).

## 7. Quick Reference

| Pattern / Construct | Syntax | Behavior / Notes |
| :--- | :--- | :--- |
| Basic generator expression | `(expr for x in iterable)` | Creates a lazy `generator` iterator |
| Filtered generator expression | `(expr for x in iterable if cond)` | Yields `expr` only for items where `cond` is truthy |
| Sole-argument shorthand | `sum(x * x for x in nums)` | Extra parentheses omitted when generator is the only argument |
| Multi-argument call | `sum((x for x in nums), start=0)` | Inner parentheses required when passing additional arguments |
| Short-circuit search | `next((x for x in seq if cond), None)` | Stops at first match and returns `None` if no item matches |
| Materialize all items | `list(gen)` or `tuple(gen)` | Consumes remaining items into a sequence; exhausts `gen` |
