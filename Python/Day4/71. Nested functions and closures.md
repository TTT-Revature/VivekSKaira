# Nested Functions and Closures

## 1. Overview
In Python, functions are **first-class objects**: they can be defined inside other functions, assigned to variables, passed as arguments, and returned as values.

* **Nested (Inner) Function:** A function defined inside the body of another (outer) function. It is visible only within the scope of its enclosing function unless explicitly returned or passed out.
* **Closure:** A nested function object that captures and remembers variables from its enclosing lexical scope—even after the outer function has finished executing and its local stack frame has been destroyed.
* **Primary Uses:** Encapsulating helper logic, creating configurable function factories, maintaining lightweight state without global variables or classes, and building Python decorators.

---

## 2. Nested (Inner) Functions
Defining a helper function inside an outer function keeps implementation details private and avoids cluttering the module's global namespace.

### Encapsulating Validation and Helper Logic
A common pattern is validating arguments once in the outer function before delegating work to an inner recursive or iterative helper:

```python
def factorial(n: int) -> int:
    """Computes n! after validating input once in the outer scope."""
    if not isinstance(n, int) or n < 0:
        raise ValueError("Input must be a non-negative integer.")

    def _compute(k: int) -> int:
        if k <= 1:
            return 1
        return k * _compute(k - 1)

    return _compute(n)

print(factorial(5))  # 120
# _compute(5)        # NameError: name '_compute' is not defined
```

## 3. Lexical Scoping and the LEGB Rule
Python resolves variable names using **lexical (static) scoping**—meaning scope is determined by where a function is *written* in the source code, not where it is *called*. When code inside a nested function references a variable name, Python searches four scopes in order (**LEGB**):

1. **L — Local:** Names assigned inside the current (inner) function.
2. **E — Enclosing:** Names in the local scopes of any enclosing functions, from inner to outer.
3. **G — Global:** Names defined at the top level of the current module.
4. **B — Built-in:** Names preassigned in Python's `builtins` module (`len`, `sum`, `int`, etc.).

```python
x = "global"

def outer() -> None:
    x = "enclosing"

    def inner() -> None:
        x = "local"
        print("Inside inner:", x)  # Resolves in Local (L)

    inner()
    print("Inside outer:", x)      # Resolves in outer's Local (E for inner)

outer()
print("At module level:", x)       # Resolves in Global (G)
```

## 4. What is a Closure?
A **closure** occurs when a nested function binds to variables from an enclosing function's scope and outlives that enclosing function's execution.

### Three Conditions for a Closure
1. **A nested function** must be defined inside an enclosing function.
2. **A free variable** from the enclosing function's scope must be referenced inside the nested function.
3. **The enclosing function must return** (or otherwise expose) the nested function object.

### Example: Function Factory
```python
from collections.abc import Callable

def make_multiplier(factor: int) -> Callable[[int], int]:
    """Returns a specialized function that multiplies inputs by 'factor'."""
    def multiply(value: int) -> int:
        return value * factor  # 'factor' is captured from the enclosing scope

    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

# make_multiplier() has already finished executing, yet each closure retains its own 'factor'
print(double(10))  # 20
print(triple(10))  # 30
```

## 5. Inspecting Closure Internals (`__closure__` and `cell` Objects)
When Python compiles a function that references enclosing variables, it stores those variables in special **`cell`** objects rather than destroying them when the outer function returns.

* **`func.__code__.co_freevars`:** Tuple of strings naming the enclosing variables captured by the closure.
* **`func.__closure__`:** Tuple of `cell` objects holding the captured values (or `None` if the function is not a closure). Access each value via **`cell.cell_contents`**.

```python
def power_factory(exponent: int):
    label = f"power_{exponent}"

    def raise_to(base: float) -> float:
        return base ** exponent

    return raise_to

square = power_factory(2)
print("Free variable names :", square.__code__.co_freevars)        # ('exponent',)
print("Closure cells       :", square.__closure__)                # (<cell at 0x...: int object>,)
print("Captured value      :", square.__closure__[0].cell_contents) # 2

# Notice 'label' was NOT referenced inside raise_to(), so Python did not capture it
```

## 6. Modifying Enclosing State with `nonlocal`
By default, reading an enclosing variable inside a nested function works automatically, but **rebinding (assigning to) it** creates a brand-new local variable inside the inner function—causing an `UnboundLocalError` if you also read it (such as `count += 1`).

Declaring **`nonlocal variable_name`** tells Python that assignments should update the variable in the nearest enclosing function scope.

### Example: Stateful Counter Closure
```python
from collections.abc import Callable

def make_counter(start: int = 0, step: int = 1) -> Callable[[], int]:
    """Creates a stateful counter closure without using a class or global variable."""
    count = start

    def increment() -> int:
        nonlocal count
        count += step
        return count

    return increment

counter_a = make_counter(start=10, step=5)
counter_b = make_counter()

print(counter_a())  # 15
print(counter_a())  # 20
print(counter_b())  # 1 (independent closure state)
```

### `nonlocal` vs. `global`

| Feature | `nonlocal` | `global` |
| :--- | :--- | :--- |
| **Target Scope** | Nearest enclosing function scope (excludes global scope) | Module-level global scope |
| **Variable Must Already Exist?** | Yes — raises `SyntaxError` if no enclosing binding exists | No — creates the global variable on assignment if absent |
| **Use Outside Nested Functions** | Invalid (`SyntaxError: nonlocal declaration not allowed at module level`) | Valid inside any function |
| **State Isolation** | Isolated per closure instance | Shared across the entire module |

## 7. Closures vs. Classes
Both closures and classes can bundle behavior with state. Choose the construct that matches the complexity of your design:

| Criterion | Closure | Class (with `__call__` or Methods) |
| :--- | :--- | :--- |
| **Best Used For** | Single behavior with 1–2 state variables (factories, decorators, callbacks) | Multiple related methods, complex state transitions, inheritance |
| **Boilerplate** | Minimal (concise function syntax) | Higher (`class`, `__init__`, `self` references) |
| **State Inspection / Mutation** | Encapsulated (hidden inside `__closure__` cells) | Explicit attributes (`obj.count`, easily inspected or reset) |
| **Extensibility** | Harder to extend without returning dicts/tuples of functions | Easily extended via additional methods or subclassing |

```python
# Equivalent callable class for comparison with make_multiplier()
class Multiplier:
    def __init__(self, factor: int) -> None:
        self.factor = factor

    def __call__(self, value: int) -> int:
        return value * self.factor

times_four = Multiplier(4)
print(times_four(10))  # 40
```

## 8. Common Pitfalls and Edge Cases

### 1. Late Binding in Loops (The Loop Closure Trap)
Closures look up free variables **when the inner function is called**, not when it is defined. Creating closures inside a `for` loop causes every closure to share the same loop variable and see its final value:

```python
# PITFALL: All functions capture the same variable 'i', which ends at 2
broken_funcs = []
for i in range(3):
    broken_funcs.append(lambda x: x + i)

print([fn(10) for fn in broken_funcs])  # [12, 12, 12] (instead of [10, 11, 12])

# FIX 1: Capture the current value via a default parameter (evaluated at definition time)
fixed_default = []
for i in range(3):
    fixed_default.append(lambda x, offset=i: x + offset)

print([fn(10) for fn in fixed_default])  # [10, 11, 12]

# FIX 2: Use a dedicated factory function to create a separate enclosing scope per iteration
def make_adder(offset: int):
    return lambda x: x + offset

fixed_factory = [make_adder(i) for i in range(3)]
print([fn(10) for fn in fixed_factory])  # [10, 11, 12]
```

### 2. `UnboundLocalError` When Mutating Enclosing Immutable Variables
```python
def broken_tracker():
    total = 0

    def add(amount: int) -> int:
        # total += amount  # Raises UnboundLocalError without 'nonlocal total'
        nonlocal total
        total += amount
        return total

    return add
```

### 3. Mutating In-Place Does Not Require `nonlocal`
If an enclosing variable holds a **mutable** object (such as a `list` or `dict`), calling mutating methods like `.append()` does not rebind the variable name, so `nonlocal` is not required:

```python
def make_history_logger():
    history: list[str] = []

    def log(event: str) -> list[str]:
        history.append(event)  # Mutates the existing list in place; no 'nonlocal' needed
        return list(history)

    return log

record = make_history_logger()
print(record("LOGIN"))   # ['LOGIN']
print(record("UPLOAD"))  # ['LOGIN', 'UPLOAD']
```

## 9. Quick Reference

| Concept / Keyword | Syntax / Attribute | Description |
| :--- | :--- | :--- |
| Nested function | `def outer(): def inner(): ...` | Function defined inside another function's local scope |
| Closure | Inner function returned by outer function | Retains access to enclosing free variables after outer function exits |
| `nonlocal` | `nonlocal var_name` | Allows rebinding an immutable variable in an enclosing function scope |
| `fn.__closure__` | `tuple[CellType, ...] \| None` | Stores `cell` objects holding captured enclosing variables |
| `fn.__code__.co_freevars` | `tuple[str, ...]` | Lists the names of free variables captured by the closure |
| Loop capture fix | `lambda x, val=i: ...` or factory function | Binds each iteration's value eagerly instead of late-binding the loop variable |
