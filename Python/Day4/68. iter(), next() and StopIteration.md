# `iter()`, `next()`, and `StopIteration`

## 1. Overview
At the core of Python's iteration mechanism are two built-in functions—**`iter()`** and **`next()`**—and one built-in exception—**`StopIteration`**. Together, they execute Python's **Iterator Protocol** manually or behind the scenes in every `for` loop, comprehension, and unpacking operation.

* **`iter()`:** Obtains an **iterator** from an iterable object or wraps a zero-argument callable with a stop condition (sentinel).
* **`next()`:** Advances an **iterator** by one step and returns its next element (or a fallback default value when exhausted).
* **`StopIteration`:** A built-in exception raised by `__next__()` to signal that an iterator has no more items to produce.

---

## 2. The `iter()` Built-In Function
Python's `iter()` function has **two distinct call signatures** depending on whether one or two arguments are passed.

### 1. Single-Argument Form: `iter(object)`
Requests an iterator from an iterable `object`:
1. Calls `object.__iter__()` if defined and verifies that it returns an iterator.
2. If `__iter__()` is absent, falls back to `object.__getitem__()` starting at integer index `0`, `1`, `2`, ... until `IndexError` occurs.
3. Raises **`TypeError: '...' object is not iterable`** if neither protocol is supported.

```python
languages = ["Python", "SQL", "Java"]
it = iter(languages)

print(type(it))  # <class 'list_iterator'>

# Passing an integer (non-iterable) raises TypeError
# iter(42)       # TypeError: 'int' object is not iterable
```

### 2. Two-Argument Sentinel Form: `iter(callable, sentinel)`
Creates a **callable iterator** that repeatedly invokes `callable()` (with zero arguments) on each step until the returned value equals `sentinel` (`value == sentinel`), at which point it raises `StopIteration` without yielding the sentinel.

```python
import io
from functools import partial

# Example: Reading a text stream in fixed 8-character chunks until EOF ("")
stream = io.StringIO("Python_FDE_Training_2026")
read_chunk = partial(stream.read, 8)

for chunk in iter(read_chunk, ""):
    print(chunk)
# Output:
# Python_F
# DE_Train
# ing_2026
```
*(Common real-world uses include reading fixed-size byte blocks from binary files via `iter(partial(f.read, 4096), b"")` or polling user input until a termination keyword like `"EXIT"`.)*

## 3. The `next()` Built-In Function
The `next()` function retrieves the next item from an **iterator** by invoking its `__next__()` method.

### 1. Single-Argument Form: `next(iterator)`
Returns the next element and moves the iterator's internal cursor forward. When no elements remain, it raises **`StopIteration`**. Passing a plain iterable (such as a `list`) instead of an iterator raises **`TypeError`**.

```python
scores = iter([88, 92, 95])

print(next(scores))  # 88
print(next(scores))  # 92
print(next(scores))  # 95
# print(next(scores))  # Raises StopIteration
```

### 2. Two-Argument Default Form: `next(iterator, default)`
Suppresses `StopIteration` when the iterator is exhausted and returns `default` instead:

```python
scores = iter([88, 92])

print(next(scores, -1))  # 88
print(next(scores, -1))  # 92
print(next(scores, -1))  # -1 (exhausted; no exception raised)
```

### Practical Idiom: Finding the First Match Safely
Combining `next(..., default)` with a generator expression locates the first matching item in a collection and stops immediately (short-circuiting) without scanning remaining elements:

```python
trainees = [
    {"id": 101, "name": "Vivek", "track": "FDE"},
    {"id": 102, "name": "Rashi", "track": "Data Science"},
    {"id": 103, "name": "Lakshya", "track": "FDE"},
]

first_fde = next((t for t in trainees if t["track"] == "FDE"), None)
first_cloud = next((t for t in trainees if t["track"] == "Cloud"), None)

print(first_fde)    # {'id': 101, 'name': 'Vivek', 'track': 'FDE'}
print(first_cloud)  # None
```

## 4. The `StopIteration` Exception
**`StopIteration`** inherits directly from `Exception` and represents **normal control flow termination**, not a runtime failure.

### How Built-In Constructs Handle `StopIteration`
Python automatically catches and handles `StopIteration` in all iteration-consuming constructs:
* **`for` loops:** Terminate the loop cleanly when `StopIteration` is raised.
* **Collection constructors (`list()`, `tuple()`, `set()`, `dict()`):** Collect yielded items until `StopIteration` stops consumption.
* **Reduction functions (`sum()`, `min()`, `max()`, `any()`, `all()`):** Consume the iterator until `StopIteration`.
* **Sequence unpacking (`a, b = iterator`):** Raises `ValueError: not enough values to unpack` if `StopIteration` occurs before all target variables are assigned.

```python
# Demonstrating manual step-by-step traversal with try/except StopIteration
it = iter(("A", "B"))

while True:
    try:
        item = next(it)
        print("Fetched:", item)
    except StopIteration:
        print("Iterator exhausted cleanly.")
        break
```

### `StopIteration.value` in Generators
When a generator function executes a `return expr` statement, Python raises `StopIteration(expr)` internally, storing `expr` in the exception's **`.value`** attribute:

```python
def batch_worker():
    yield "Task 1"
    yield "Task 2"
    return "All tasks completed"

gen = batch_worker()
print(next(gen))  # 'Task 1'
print(next(gen))  # 'Task 2'

try:
    next(gen)
except StopIteration as exc:
    print("Return payload:", exc.value)  # 'All tasks completed'
```

## 5. Common Pitfalls and Edge Cases

1. **Calling `next()` Directly on a Non-Iterator Iterable:**
   Containers like `list`, `str`, and `dict` are *iterables*, not *iterators*. Always call `iter()` first before passing them to `next()`:
   ```python
   text = "ABC"
   # next(text)        # TypeError: 'str' object is not an iterator
   print(next(iter(text)))  # 'A'
   ```
2. **Raising `StopIteration` Inside a Generator (PEP 479):**
   Since Python 3.7, if an unhandled `StopIteration` escapes inside a generator function (for example, from an unguarded `next()` call on an inner iterator), Python converts it into a **`RuntimeError: generator raised StopIteration`** rather than silently ending the generator early. Always use **`return`** to terminate a generator or provide a default value to `next(inner_it, default)`.
   ```python
   def safe_first_items(iterables):
       for seq in iterables:
           it = iter(seq)
           first = next(it, None)  # Safe: avoids uncaught StopIteration inside generator
           if first is not None:
               yield first

   print(list(safe_first_items([[10, 20], [], [30, 40]])))  # [10, 30]
   ```
3. **Permanent Exhaustion:**
   Once an iterator raises `StopIteration`, it remains exhausted forever. Subsequent calls to `next()` will immediately raise `StopIteration` again.

## 6. Quick Reference

| Function / Exception | Signature | Behavior | Exceptions Raised |
| :--- | :--- | :--- | :--- |
| `iter(obj)` | `iter(iterable) -> iterator` | Calls `obj.__iter__()` (or `__getitem__`) to return an iterator | `TypeError` if `obj` is not iterable |
| `iter(func, sentinel)` | `iter(callable, sentinel) -> iterator` | Calls `func()` repeatedly until return value equals `sentinel` | `TypeError` if `func` is not callable |
| `next(it)` | `next(iterator) -> item` | Calls `it.__next__()` to fetch the next element | `StopIteration` at end; `TypeError` if not an iterator |
| `next(it, default)` | `next(iterator, default) -> item` | Calls `it.__next__()`; returns `default` when exhausted | `TypeError` if `it` is not an iterator |
| `StopIteration` | `StopIteration(value=None)` | Signals end of iteration; `.value` holds generator return value | Converted to `RuntimeError` if leaked from a generator |
