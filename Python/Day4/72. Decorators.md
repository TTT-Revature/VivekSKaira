# Decorators in Python

## 1. Overview
A **decorator** is a design pattern and language feature in Python that allows you to wrap another function, method, or class to **extend or modify its behavior without altering its source code**.

* **Built on First-Class Functions and Closures:** Because Python functions can be passed as arguments and returned from other functions, a decorator is simply a callable that accepts a target callable and returns a replacement callable.
* **Syntactic Sugar (`@`):** Placing `@my_decorator` immediately above a `def` or `class` statement is shorthand for reassigning the name to the return value of `my_decorator(...)`:
  ```python
  @my_decorator
  def greet():
      print("Hello")

  # Exact equivalent without '@' syntax:
  def greet():
      print("Hello")
  greet = my_decorator(greet)
  ```
* **Common Use Cases:** Logging, execution timing, authentication/authorization checks, input validation, caching/memoization, and retry logic.

---

## 2. Basic Function Decorators
To decorate functions with arbitrary signatures and return values, the inner `wrapper` function must accept `*args` and `**kwargs`, forward them to the original function, and return its result.

### Example: Execution Timer Decorator
```python
import time
from collections.abc import Callable

def timer(func: Callable) -> Callable:
    """Measures and prints the execution time of the decorated function."""
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"[TIMER] {func.__name__} executed in {elapsed:.4f}s")
        return result

    return wrapper

@timer
def compute_sum(n: int) -> int:
    return sum(range(n))

total = compute_sum(1_000_000)
print("Total:", total)
# Output:
# [TIMER] compute_sum executed in 0.0198s
# Total: 499999500000
```

## 3. Preserving Function Metadata (`@functools.wraps`)
When a decorator replaces `func` with `wrapper`, the decorated function loses its original metadata (`__name__`, `__doc__`, `__annotations__`, and `__module__`), reporting `"wrapper"` instead.

Applying **`@functools.wraps(func)`** to the inner `wrapper` copies the original function's metadata onto `wrapper` and sets `wrapper.__wrapped__ = func` so introspection tools, debuggers, and `help()` continue to work accurately.

```python
from functools import wraps
from collections.abc import Callable

def log_calls(func: Callable) -> Callable:
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__} with args={args}, kwargs={kwargs}")
        return func(*args, **kwargs)

    return wrapper

@log_calls
def add(a: int, b: int) -> int:
    """Returns the sum of two integers."""
    return a + b

print(add(3, 5))          # Calling add with args=(3, 5), kwargs={} -> 8
print(add.__name__)       # 'add' (would be 'wrapper' without @wraps)
print(add.__doc__)        # 'Returns the sum of two integers.'
print(add.__wrapped__)    # <function add at 0x...> (original unwrapped function)
```

## 4. Decorators with Arguments (Decorator Factories)
A standard decorator accepts only the target function (`def decorator(func):`). To pass configuration arguments to a decorator (such as `@repeat(times=3)`), write a **decorator factory**—an outer function that accepts the configuration parameters and returns the actual decorator.

### Three-Layer Nesting Pattern
```python
from functools import wraps
from collections.abc import Callable

def repeat(times: int) -> Callable:
    """Decorator factory that runs the decorated function 'times' times."""
    if times < 1:
        raise ValueError("times must be at least 1")

    def decorator(func: Callable) -> Callable:
        @wraps(func)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result

        return wrapper

    return decorator

@repeat(times=3)
def send_ping(host: str) -> str:
    print(f"Pinging {host}...")
    return "OK"

status = send_ping("api.internal")
print("Final status:", status)
```
*(Execution breakdown: `repeat(times=3)` is called first and returns `decorator`; Python then applies `@decorator` to `send_ping`, returning `wrapper`.)*

## 5. Stacking Multiple Decorators
You can apply multiple decorators to a single function. Understanding the difference between **definition-time wrapping** and **call-time execution** is essential:

* **Application Order (Definition Time):** Applied **bottom-up** (closest to `def` runs first):
  ```python
  @decorator_a
  @decorator_b
  def target():
      pass
  # Equivalent to: target = decorator_a(decorator_b(target))
  ```
* **Execution Order (Call Time):** Runs **top-down** (outermost wrapper executes first, delegates inward, and finishes last).

```python
from functools import wraps

def bold(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return f"<b>{func(*args, **kwargs)}</b>"
    return wrapper

def italic(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return f"<i>{func(*args, **kwargs)}</i>"
    return wrapper

@bold
@italic
def format_text(msg: str) -> str:
    return msg

# italic wraps format_text first -> bold wraps the result of italic
print(format_text("Python"))  # '<b><i>Python</i></b>'
```

## 6. Class-Based Decorators and Decorating Classes

### 1. Using a Class as a Stateful Decorator (`__call__`)
Any class implementing **`__init__`** (to capture the target function) and **`__call__`** (to intercept calls) can be used as a decorator—useful when tracking metrics or state across calls:

```python
from functools import update_wrapper
from collections.abc import Callable

class CallCounter:
    """Class-based decorator that counts how many times a function is invoked."""

    def __init__(self, func: Callable) -> None:
        update_wrapper(self, func)  # Equivalent of @wraps for class-based decorators
        self.func = func
        self.count = 0

    def __call__(self, *args, **kwargs):
        self.count += 1
        print(f"[{self.func.__name__}] Call #{self.count}")
        return self.func(*args, **kwargs)

@CallCounter
def fetch_data() -> str:
    return "payload"

fetch_data()
fetch_data()
print("Total invocations:", fetch_data.count)  # Total invocations: 2
```

### 2. Decorating a Class
Decorators can also accept a `class` object, attach new methods or attributes, register the class, and return it:

```python
def add_repr(cls):
    """Class decorator that injects a default __repr__ displaying instance attributes."""
    def __repr__(self) -> str:
        attrs = ", ".join(f"{k}={v!r}" for k, v in self.__dict__.items())
        return f"{cls.__name__}({attrs})"

    cls.__repr__ = __repr__
    return cls

@add_repr
class Trainee:
    def __init__(self, name: str, track: str) -> None:
        self.name = name
        self.track = track

t = Trainee("Vivek", "FDE")
print(t)  # Trainee(name='Vivek', track='FDE')
```

## 7. Common Built-In and Standard Library Decorators

| Decorator | Module | Purpose |
| :--- | :--- | :--- |
| `@property` | Built-in | Exposes a method as a read-only attribute (with optional `@x.setter` and `@x.deleter`) |
| `@staticmethod` | Built-in | Defines a method inside a class that receives neither `self` nor `cls` |
| `@classmethod` | Built-in | Defines a method that receives the class `cls` as its first argument |
| `@functools.wraps(fn)` | `functools` | Copies `__name__`, `__doc__`, and annotations from `fn` onto `wrapper` |
| `@functools.lru_cache` | `functools` | Memoizes function return values in an LRU cache to avoid redundant computation |
| `@functools.cache` | `functools` | Unbounded lightweight memoization cache (Python 3.9+) |
| `@dataclasses.dataclass` | `dataclasses` | Auto-generates `__init__`, `__repr__`, and `__eq__` for data-holding classes |
| `@contextlib.contextmanager` | `contextlib` | Converts a generator function with `yield` into a `with`-statement context manager |

## 8. Common Pitfalls and Edge Cases

1. **Forgetting `return` Inside `wrapper`:**
   If `wrapper` calls `func(*args, **kwargs)` without returning its result, the decorated function silently returns `None`:
   ```python
   def broken_decorator(func):
       def wrapper(*args, **kwargs):
           func(*args, **kwargs)  # Missing 'return' -> caller always receives None!
       return wrapper
   ```
2. **Omitting `@functools.wraps`:**
   Without `@wraps(func)`, every decorated function reports `__name__ == "wrapper"`, breaking logging, unit test discovery, and API frameworks (such as Flask or FastAPI) that inspect function names and type hints.
3. **Confusing `@decorator` vs. `@decorator()`:**
   * Use `@decorator` (no parentheses) when the decorator expects `func` directly.
   * Use `@decorator()` (with parentheses) only when `decorator` is a factory function returning a decorator. Mixing them up raises `TypeError` (`missing 1 required positional argument` or `'function' object is not callable`).
4. **Hardcoding Positional Arguments Instead of `*args, **kwargs`:**
   Writing `def wrapper(x):` restricts the decorator to single-argument functions. Always use `def wrapper(*args, **kwargs):` for general-purpose decorators.

## 9. Quick Reference

| Pattern | Structure | Equivalent Expansion |
| :--- | :--- | :--- |
| Basic decorator | `@dec` above `def fn():` | `fn = dec(fn)` |
| Decorator with arguments | `@dec(arg)` above `def fn():` | `fn = dec(arg)(fn)` |
| Stacked decorators | `@dec1` over `@dec2` over `def fn():` | `fn = dec1(dec2(fn))` |
| Metadata preservation | `@functools.wraps(func)` on `wrapper` | Copies `__name__`, `__doc__`, `__annotations__`, sets `__wrapped__` |
| Class-based decorator | Class with `__init__(self, func)` and `__call__` | `fn = MyDecorator(fn)` |
