# Reading Tracebacks and Debugging

## 1. Overview
When an unhandled exception occurs in Python, the interpreter halts execution and prints a **traceback** (also called a stack trace)—a structured report of the active function calls on the call stack at the exact moment the error happened.

* **Traceback:** Shows *what* error occurred, *where* it failed, and the *sequence of function calls* that led to that line.
* **Debugging:** The systematic process of reproducing a defect, isolating its root cause using tracebacks, logging, or interactive debuggers (`pdb` / IDE debuggers), and verifying the fix.

---

## 2. Anatomy of a Python Traceback
Python prints tracebacks with the **oldest call (entry point) at the top** and the **most recent call (where the error actually occurred) at the bottom**.

### Example Multi-Frame Traceback
```python
def calculate_average(scores: list[int]) -> float:
    return sum(scores) / len(scores)

def generate_report(trainee: dict) -> str:
    avg = calculate_average(trainee["scores"])
    return f"{trainee['name']}: {avg:.2f}"

def main() -> None:
    record = {"name": "Vivek", "scores": []}
    print(generate_report(record))

if __name__ == "__main__":
    main()
```

```text
Traceback (most recent call last):
  File "/projects/fde_notes/report.py", line 13, in <module>
    main()
    ~~~~^^
  File "/projects/fde_notes/report.py", line 10, in main
    print(generate_report(record))
          ~~~~~~~~~~~~~~~^^^^^^^^
  File "/projects/fde_notes/report.py", line 5, in generate_report
    avg = calculate_average(trainee["scores"])
          ~~~~~~~~~~~~~~~~~^^^^^^^^^^^^^^^^^^^
  File "/projects/fde_notes/report.py", line 2, in calculate_average
    return sum(scores) / len(scores)
           ~~~~~~~~~~~~^~~~~~~~~~~~~
ZeroDivisionError: division by zero
```

### How to Read It Step by Step (Bottom-Up Strategy)
1. **Start at the Very Bottom (Exception Type & Message):**
   `ZeroDivisionError: division by zero` identifies *what* went wrong (`ZeroDivisionError`) and *why* (`division by zero`).
2. **Read the Frame Immediately Above the Error:**
   `File ".../report.py", line 2, in calculate_average` shows the exact file, line number, and function where the exception was raised.
3. **Inspect Fine-Grained Error Indicators (`~` and `^`):**
   Introduced in Python 3.11, caret markers (`^^^^^^^^^^^^`) pinpoint the exact sub-expression that failed on that line—here highlighting `sum(scores) / len(scores)` rather than another expression on the same line.
4. **Walk Upward Through the Call Stack:**
   Move upward frame by frame (`calculate_average` <- `generate_report` <- `main` <- `<module>`) until you reach the line in **your own code** that passed invalid data (line 9 passed `"scores": []`, an empty list).

## 3. Chained Exception Tracebacks
When one exception occurs while handling or translating another exception, Python prints multiple tracebacks connected by one of two messages:

| Connecting Message | Attribute | Meaning |
| :--- | :--- | :--- |
| `During handling of the above exception, another exception occurred:` | `exc.__context__` | A new unhandled error occurred *inside* an `except` or `finally` block while handling the first error |
| `The above exception was the direct cause of the following exception:` | `exc.__cause__` | Code explicitly raised a new exception from the original one using `raise NewError(...) from err` |

*(Tip: Always fix the **first (upper)** exception first when seeing `During handling of the above exception...`, because the second error is usually a side effect of broken error-handling code.)*

## 4. Interactive Debugging with `breakpoint()` and `pdb`
Python includes a built-in interactive debugger (**`pdb`**) and a built-in **`breakpoint()`** function (PEP 553) that pauses program execution at any chosen line and opens an interactive prompt to inspect variables and step through code.

### Using `breakpoint()`
```python
def compute_discounted_total(prices: list[float], discount: float) -> float:
    subtotal = sum(prices)
    breakpoint()  # Execution pauses here and opens the (Pdb) interactive prompt
    total = subtotal * (1 - discount)
    return round(total, 2)

print(compute_discounted_total([100.0, 250.0, 50.0], 0.15))
```

### Essential `pdb` Interactive Commands

| Command | Short | Description |
| :--- | :--- | :--- |
| `list` / `longlist` | `l` / `ll` | Displays source code around the current line (`ll` shows the entire current function) |
| `next` | `n` | Executes the current line and steps **over** function calls to the next line in the current function |
| `step` | `s` | Steps **into** a function called on the current line |
| `return` | `r` | Continues execution until the current function returns |
| `continue` | `c` | Resumes normal execution until the next breakpoint or program end |
| `print expr` | `p expr` | Evaluates and prints the value of a Python expression or variable |
| `pp expr` | `pp expr` | Pretty-prints complex data structures (`dict`, nested `list`) |
| `where` | `w` | Prints the current call stack (traceback) showing active frames |
| `up` / `down` | `u` / `d` | Moves one frame up (to caller) or down (to callee) in the call stack |
| `break line` | `b line` | Sets a new breakpoint at `line` (or `file.py:line`) |
| `quit` | `q` | Aborts the debugger and terminates the program immediately |

### Running Scripts Under `pdb` from the Command Line
* **Run from start under debugger:** `python -m pdb script.py`
* **Post-mortem debugging (enters `pdb` automatically on crash):** `python -m pdb -c continue script.py`
* **Disable all `breakpoint()` calls temporarily without editing code:**
  ```bash
  PYTHONBREAKPOINT=0 python script.py
  ```

## 5. Practical Debugging Techniques

### 1. Self-Documenting f-Strings (`f"{expr=}"`) and `repr()`
Plain `print(x)` hides trailing spaces, invisible newline characters, and type differences (`"42"` vs. `42`). Use **`f"{var=}"`** (Python 3.8+) or **`repr()`** during quick diagnostics:

```python
user_id = "101 "
expected_id = 101

# Plain print hides the trailing space and string type:
print(user_id, expected_id)        # 101  101

# Self-documenting f-string uses repr() automatically:
print(f"{user_id=}, {expected_id=}")  # user_id='101 ', expected_id=101
```

### 2. Capturing Tracebacks Programmatically (`traceback` Module)
When catching broad exceptions in background workers or API handlers, use the standard **`traceback`** module (or `logger.exception()`) to record the full stack trace as a string without crashing the service:

```python
import traceback

def safe_execute(func, *args):
    try:
        return func(*args)
    except Exception:
        error_trace = traceback.format_exc()
        print("Captured full traceback:\n", error_trace)
        return None

safe_execute(lambda x: 10 / x, 0)
```

### 3. Systematic Defect Isolation
1. **Reproduce Consistently:** Identify the exact input, environment variables, and state that trigger the error.
2. **Narrow the Scope (Binary Search):** Place `breakpoint()` or log checkpoints halfway through a failing pipeline to determine whether data is already corrupted before that point or fails afterward.
3. **Create a Minimal Reproducible Example (MRE):** Strip away unrelated modules, network calls, and data until only the smallest self-contained snippet that reproduces the bug remains.
4. **Verify Assumptions with `assert`:** Add temporary `assert` checks on data types, shapes, and non-empty preconditions at function boundaries.

## 6. Diagnosing Common Built-In Exceptions

| Exception | Typical Root Cause | First Thing to Check |
| :--- | :--- | :--- |
| `AttributeError` | Calling a method/attribute on `None` (`'NoneType' object has no attribute...`) or wrong object type | Check if a prior function returned `None` implicitly or a lookup failed |
| `TypeError` | Passing wrong argument types, wrong argument count, or calling a non-callable object (`'list' object is not callable`) | Check if a variable shadowed a built-in name (e.g., `list = [1, 2]`) or check `type(obj)` |
| `KeyError` | Accessing `d[key]` when `key` is absent from the dictionary | Print `d.keys()` with `repr()` to check spelling, case, or leading/trailing whitespace |
| `IndexError` | Indexing past the end of a sequence (`lst[i]`) or calling `.pop()` on an empty list | Print `len(seq)` and the index value before access |
| `ValueError` | Right data type, invalid value (e.g., `int("abc")`, unpacking mismatch `a, b = [1, 2, 3]`) | Inspect raw input string or sequence length right before conversion/unpacking |
| `UnboundLocalError` | Assigning to a variable inside a function after reading it, without `global` or `nonlocal` | Search the function body for any `var =` or `var +=` assignment |
| `ModuleNotFoundError` | Missing package, wrong virtual environment, or running script from wrong working directory | Check `which python` / active `venv` and inspect `sys.path` |
| `RecursionError` | Recursive function missing a base case or base case is never reached | Print recursive parameters on entry and verify termination condition |

## 7. Quick Reference

| Tool / Construct | Usage | Purpose |
| :--- | :--- | :--- |
| Traceback reading order | Read bottom-up (`Exception` -> top frame) | Identifies failure type first, then traces callers upward |
| `breakpoint()` | Built-in function | Pauses execution and launches `pdb` (or configured debugger) |
| `PYTHONBREAKPOINT=0` | Environment variable | Disables all `breakpoint()` calls at runtime without code changes |
| `python -m pdb script.py` | CLI command | Launches script directly inside the interactive `pdb` debugger |
| `f"{var=}"` | Self-documenting f-string | Prints variable name alongside its `repr()` value and type clues |
| `traceback.format_exc()` | Standard library function | Returns the active exception's full formatted traceback as a `str` |
