# Iterable vs. Iterator

## 1. Overview
In Python, iteration is governed by the **Iterator Protocol**, which separates **collections that can be looped over** from **stateful objects that track traversal progress**:

* **Iterable:** Any object capable of returning its elements one at a time (e.g., `list`, `tuple`, `str`, `dict`, `set`, `range`). An iterable implements `__iter__()` and produces a fresh iterator whenever `iter()` is called on it.
* **Iterator:** A stateful object that represents a stream of data and remembers its current position during traversal. An iterator implements both `__iter__()` and `__next__()`, yielding one item per `next()` call until it raises `StopIteration`.

> **Core Rule:** Every **iterator** is also an **iterable** (because it implements `__iter__()` returning `self`), but not every **iterable** is an **iterator** (for example, a `list` is an iterable, not an iterator).

---

## 2. What is an Iterable?
An **iterable** is any object you can pass to Python's built-in `iter()` function or loop over using a `for` loop.

* **Required Protocol:** Must implement **`__iter__()`** (which returns an iterator object) or the legacy sequence protocol **`__getitem__()`** with zero-based integer indices starting at `0`.
* **Stateless & Reusable:** An iterable does not track a "current position." You can iterate over the same `list` or `str` multiple times because each `for` loop requests a brand-new iterator.

```python
numbers = [10, 20, 30]  # 'list' is an iterable

# Calling iter() creates independent iterator instances
it1 = iter(numbers)
it2 = iter(numbers)

print(next(it1))  # 10
print(next(it1))  # 20
print(next(it2))  # 10 (it2 starts independently from the beginning)

# Calling next() directly on a plain iterable raises TypeError
# next(numbers)   # TypeError: 'list' object is not an iterator
```

---

## 3. What is an Iterator?
An **iterator** is the object that actually performs the step-by-step traversal and keeps track of which element comes next.

* **Required Protocol (Iterator Protocol):**
  1. **`__iter__(self)`:** Returns `self` so an iterator can be used directly in a `for` loop or passed to functions expecting an iterable.
  2. **`__next__(self)`:** Returns the next item in the sequence. Once no items remain, it raises **`StopIteration`**.
* **Single-Pass (Exhaustible):** Once an iterator reaches the end and raises `StopIteration`, it is **exhausted**. Calling `next()` again continues to raise `StopIteration`, and looping over it again yields zero items.

```python
numbers = [10, 20, 30]
it = iter(numbers)  # 'list_iterator' is an iterator

# An iterator's __iter__() returns itself
print(iter(it) is it)  # True
print(iter(numbers) is numbers)  # False

print(next(it))  # 10
print(next(it))  # 20
print(next(it))  # 30
# print(next(it))  # Raises StopIteration

# Supplying a default value to next() prevents StopIteration
print(next(it, "END"))  # 'END'
```

### Common Built-In Iterators
Several standard Python objects and built-in functions return **iterators** directly rather than materializing lists in memory:
* File objects returned by `open()`
* Generator objects (from generator functions using `yield` or generator expressions `(x for x in ...)`)
* Built-in wrappers: `enumerate()`, `zip()`, `map()`, `filter()`, `reversed()`

---

## 4. Side-by-Side Comparison

| Feature | Iterable | Iterator |
| :--- | :--- | :--- |
| **Definition** | Object that can produce an iterator | Stateful object that yields elements one by one |
| **Required Methods** | `__iter__()` (or `__getitem__()`) | Both `__iter__()` and `__next__()` |
| **`iter(obj)` Behavior** | Returns a new iterator object (`iter(obj) is not obj`) | Returns itself (`iter(obj) is obj`) |
| **`next(obj)` Behavior** | Raises `TypeError: '...' object is not an iterator` | Returns next item or raises `StopIteration` |
| **State Tracking** | Stateless (no internal cursor) | Stateful (tracks current traversal position) |
| **Reusability** | Reusable across multiple loops | Single-pass; cannot be reset once exhausted |
| **Memory Usage** | Usually holds all elements in memory (except `range`) | Lazy evaluation; computes/fetches one item at a time |
| **Examples** | `list`, `tuple`, `str`, `dict`, `set`, `range` | `list_iterator`, generators, `zip()`, `map()`, open files |

---

## 5. How `for` Loops Work Under the Hood
Python does not use index counters for `for` loops. Instead, every `for` loop translates an **iterable** into an **iterator** and repeatedly calls `next()` until `StopIteration` is caught internally:

```python
# Standard Python 'for' loop
skills = ["Python", "SQL", "Git"]
for skill in skills:
    print(skill)

# Exact internal execution flow using iter() and next()
iterator = iter(skills)
while True:
    try:
        skill = next(iterator)
        print(skill)
    except StopIteration:
        break
```

## 6. Creating Custom Iterators

### 1. Single-Pass Custom Iterator Class
To build a custom iterator, implement `__iter__()` returning `self` and `__next__()` raising `StopIteration` when complete:

```python
class Countdown:
    """Custom iterator that counts down from start to 1."""

    def __init__(self, start: int) -> None:
        self.current = start

    def __iter__(self) -> "Countdown":
        return self

    def __next__(self) -> int:
        if self.current <= 0:
            raise StopIteration
        value = self.current
        self.current -= 1
        return value

timer = Countdown(3)
for num in timer:
    print(num)  # Prints: 3, 2, 1

# Second loop produces nothing because 'timer' is now exhausted
print(list(timer))  # []
```

### 2. Reusable Custom Iterable (Separating Iterable from Iterator)
If you want a custom collection to support **multiple independent loops**, return a new iterator instance from `__iter__()` instead of returning `self`:

```python
class ReusableCountdown:
    """Reusable iterable that creates a fresh Countdown iterator per loop."""

    def __init__(self, start: int) -> None:
        self.start = start

    def __iter__(self) -> Countdown:
        return Countdown(self.start)

counter = ReusableCountdown(3)
print(list(counter))  # [3, 2, 1]
print(list(counter))  # [3, 2, 1] (works again because a fresh iterator was created)
```

## 7. Type Checking (`collections.abc`) and Common Pitfalls

### 1. Checking With `collections.abc`
Use abstract base classes from `collections.abc` to verify whether an object is an `Iterable` or an `Iterator`:

```python
from collections.abc import Iterable, Iterator

nums = [1, 2, 3]
nums_iter = iter(nums)

print(isinstance(nums, Iterable))       # True
print(isinstance(nums, Iterator))       # False

print(isinstance(nums_iter, Iterable))  # True
print(isinstance(nums_iter, Iterator))  # True
```

### 2. Pitfall: Accidental Iterator Exhaustion
Because functions like `zip()`, `map()`, and `filter()` return **iterators**, consuming them once (e.g., via `list()`, `len()`, or a `for` loop) empties them permanently:

```python
names = ["Vivek", "Rashi"]
scores = [95, 92]

paired = zip(names, scores)  # 'paired' is an iterator

print("First pass :", list(paired))  # [('Vivek', 95), ('Rashi', 92)]
print("Second pass:", list(paired))  # [] (exhausted!)
```

## 8. Quick Reference

| Construct / Class | Role | Key Behavior |
| :--- | :--- | :--- |
| `__iter__(self)` | Iterable & Iterator method | Returns an iterator object (`self` on iterators) |
| `__next__(self)` | Iterator method | Returns the next item or raises `StopIteration` |
| `iter(iterable)` | Built-in function | Calls `iterable.__iter__()` to obtain an iterator |
| `next(iterator[, default])` | Built-in function | Calls `iterator.__next__()`; returns `default` instead of raising at EOF |
| `StopIteration` | Built-in exception | Signals that an iterator has no more items to produce |
| `collections.abc.Iterable` | Abstract Base Class | Checks if an object supports iteration (`isinstance(x, Iterable)`) |
| `collections.abc.Iterator` | Abstract Base Class | Checks if an object is an iterator (`isinstance(x, Iterator)`) |
