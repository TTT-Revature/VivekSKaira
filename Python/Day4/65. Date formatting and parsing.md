# Date Formatting and Parsing

## 1. Overview
Converting between structured Python date/time objects (`date`, `time`, `datetime`) and string representations (`str`) is essential for logging, API payloads, database exports, and user interfaces.

* **Formatting (Serialization):** Converting a `date`, `time`, or `datetime` object **into a `str`** using `.isoformat()`, `.strftime()`, or Python f-string format specifiers.
* **Parsing (Deserialization):** Converting a text `str` **into a `date`, `time`, or `datetime` object** using `.fromisoformat()` or `datetime.strptime()`.

---

## 2. ISO 8601 Formatting and Parsing (`.isoformat()` & `.fromisoformat()`)
**ISO 8601** (`YYYY-MM-DDTHH:MM:SS`) is the international standard for representing dates and times. It eliminates regional ambiguity (such as `04/05/2026` meaning April 5 in the US vs. May 4 in India/UK) and sorts chronologically when compared as plain strings.

### 1. Formatting with `.isoformat()`
Available on `date`, `time`, and `datetime` objects. On `datetime`, you can customize the separator (`sep`) and precision (`timespec`):

```python
from datetime import date, time, datetime, timezone

d = date(2026, 11, 22)
t = time(23, 5, 42, 123456)
dt = datetime(2026, 11, 22, 23, 5, 42, 123456, tzinfo=timezone.utc)

print(d.isoformat())                                # '2026-11-22'
print(t.isoformat(timespec="seconds"))              # '23:05:42'
print(dt.isoformat())                               # '2026-11-22T23:05:42.123456+00:00'
print(dt.isoformat(sep=" ", timespec="minutes"))    # '2026-11-22 23:05+00:00'
```
*(Valid `timespec` values: `'auto'`, `'hours'`, `'minutes'`, `'seconds'`, `'milliseconds'`, `'microseconds'`.)*

### 2. Parsing with `.fromisoformat()`
Available on `date`, `time`, and `datetime`. Since Python 3.11, `.fromisoformat()` supports nearly all valid ISO 8601 formats, including space separators, compact dates (`YYYYMMDD`), and the `'Z'` UTC designator:

```python
from datetime import date, time, datetime

d = date.fromisoformat("2026-11-22")
t = time.fromisoformat("23:05:42")
dt_utc = datetime.fromisoformat("2026-11-22T23:05:42Z")
dt_offset = datetime.fromisoformat("2026-11-22 23:05:42+05:30")

print(d)          # 2026-11-22
print(t)          # 23:05:42
print(dt_utc)     # 2026-11-22 23:05:42+00:00
print(dt_offset)  # 2026-11-22 23:05:42+05:30
```

## 3. Custom Formatting (`.strftime()` and f-strings)
When you need human-readable dates, custom report headers, or filenames, use **`.strftime(format)`** ("string format time") or inline f-string formatting.

### Using `.strftime()`
Available on `date`, `time`, and `datetime` objects:

```python
from datetime import datetime

dt = datetime(2026, 11, 22, 23, 0, 15)

# Human-readable report display
print(dt.strftime("%B %d, %Y"))             # 'November 22, 2026'
print(dt.strftime("%a, %d %b %Y %I:%M %p")) # 'Sun, 22 Nov 2026 11:00 PM'

# Safe timestamp for log files or backup filenames (no colons or spaces)
filename = dt.strftime("backup_%Y%m%d_%H%M%S.sql")
print(filename)                             # 'backup_20261122_230015.sql'
```

### Shorthand Formatting Inside f-Strings
Python `date`, `time`, and `datetime` objects implement `__format__()`, allowing you to place `strftime` directives directly after a colon `:` inside an f-string:

```python
from datetime import datetime

now = datetime(2026, 11, 22, 23, 0)
print(f"Generated on {now:%Y-%m-%d at %H:%M}")
# Output: Generated on 2026-11-22 at 23:00
```

## 4. Custom Parsing (`datetime.strptime()`)
**`datetime.strptime(date_string, format)`** ("string parse time") parses a custom-formatted string into a `datetime` object by matching the input string character-for-character against a format template.

### Extracting `datetime`, `date`, or `time`
Because `strptime()` exists only on the `datetime` class (not on `date` or `time`), call `.date()` or `.time()` on the result when you only need one component:

```python
from datetime import datetime

# 1. Parsing a full timestamp
raw_log = "22-Nov-2026 23:00:45 +0530"
parsed_dt = datetime.strptime(raw_log, "%d-%b-%Y %H:%M:%S %z")
print(parsed_dt)          # 2026-11-22 23:00:45+05:30
print(parsed_dt.tzinfo)   # datetime.timezone(datetime.timedelta(seconds=19800))

# 2. Parsing a date-only string -> extract .date()
parsed_date = datetime.strptime("22/11/2026", "%d/%m/%Y").date()
print(parsed_date, type(parsed_date))  # 2026-11-22 <class 'datetime.date'>

# 3. Parsing a time-only string -> extract .time()
parsed_time = datetime.strptime("09:30 PM", "%I:%M %p").time()
print(parsed_time, type(parsed_time))  # 21:30:00 <class 'datetime.time'>
```

### Handling Multiple Possible Formats Safely
`strptime()` raises a **`ValueError`** if the string does not match the format template or represents an impossible calendar date (e.g., `"2026-02-30"`). To parse external inputs that may arrive in several formats, iterate through candidate templates:

```python
from datetime import datetime

def parse_flexible_date(text: str) -> datetime:
    formats = (
        "%Y-%m-%d",
        "%d/%m/%Y",
        "%d-%b-%Y",
        "%Y-%m-%d %H:%M:%S",
    )
    for fmt in formats:
        try:
            return datetime.strptime(text.strip(), fmt)
        except ValueError:
            continue
    raise ValueError(f"Unrecognized date format: {text!r}")

print(parse_flexible_date("22/11/2026"))   # 2026-11-22 00:00:00
print(parse_flexible_date("22-Nov-2026"))  # 2026-11-22 00:00:00
```

## 5. Complete Format Directives Reference

### Date Directives

| Directive | Meaning | Example |
| :--- | :--- | :--- |
| `%Y` | 4-digit year with century | `2026` |
| `%y` | 2-digit year without century (`00`–`99`) | `26` |
| `%m` | Month as zero-padded decimal (`01`–`12`) | `11` |
| `%B` | Full month name (locale-dependent) | `November` |
| `%b` | Abbreviated month name (locale-dependent) | `Nov` |
| `%d` | Day of the month as zero-padded decimal (`01`–`31`) | `22` |
| `%j` | Day of the year as zero-padded decimal (`001`–`366`) | `326` |
| `%A` | Full weekday name (locale-dependent) | `Sunday` |
| `%a` | Abbreviated weekday name (locale-dependent) | `Sun` |
| `%w` | Weekday as decimal (`0` = Sunday ... `6` = Saturday) | `0` |
| `%u` | ISO weekday as decimal (`1` = Monday ... `7` = Sunday) | `7` |
| `%U` / `%W` | Week number of the year (`00`–`53`, Sunday / Monday first) | `47` / `46` |
| `%V` | ISO 8601 week number (`01`–`53`) | `47` |

### Time, Timezone, and Special Directives

| Directive | Meaning | Example |
| :--- | :--- | :--- |
| `%H` | Hour on 24-hour clock (`00`–`23`) | `23` |
| `%I` | Hour on 12-hour clock (`01`–`12`) | `11` |
| `%p` | Locale AM or PM equivalent | `PM` |
| `%M` | Minute as zero-padded decimal (`00`–`59`) | `05` |
| `%S` | Second as zero-padded decimal (`00`–`59`) | `42` |
| `%f` | Microsecond as 6-digit zero-padded decimal (`000000`–`999999`) | `123456` |
| `%z` | UTC offset as `+HHMM` or `-HHMM` (empty if naive) | `+0530` |
| `%Z` | Timezone name (empty if naive) | `IST` |
| `%%` | Literal `%` character | `%` |

## 6. Common Pitfalls and Edge Cases

1. **Missing Year Defaults to `1900` (Leap Year Bug):**
   When parsing a string without a year (such as `"29 Feb"`), `datetime.strptime()` defaults the year to **`1900`**. Because `1900` was **not** a leap year, parsing `"29 Feb"` with `"%d %b"` raises `ValueError: day is out of range for month`. Always prepend or supply a valid leap year (e.g., `f"2024 {raw_str}"`) before calling `strptime()`.
2. **12-Hour Clock (`%I`) Without `%p`:**
   Using `%I` without `%p` in `strptime()` assumes AM (e.g., `"09:00"` becomes `09:00`, never `21:00`). Always pair `%I` with `%p`, or use `%H` for 24-hour times.
3. **Platform-Specific Zero-Padding Removal:**
   Standard `%d` and `%H` always zero-pad single digits (`05`). Removing zero-padding uses non-standard C library flags (`%-d` on Linux/macOS vs. `%#d` on Windows) that are not cross-platform and do not work in `strptime()`. For portable formatting without leading zeros, access integer attributes directly:
   ```python
   from datetime import date

   d = date(2026, 3, 5)
   print(f"{d.day} {d:%B %Y}")  # '5 March 2026' (works on all OS platforms)
   ```
4. **Locale Sensitivity:**
   Directives like `%B`, `%b`, `%A`, `%a`, and `%p` depend on the system's active `locale` setting. In multi-region backend services, store and transmit timestamps in numeric ISO 8601 format (`%Y-%m-%d` or `.isoformat()`).

## 7. Quick Reference

| Method / Syntax | Direction | Supported Classes | Best Used For |
| :--- | :--- | :--- | :--- |
| `obj.isoformat(...)` | Format (`obj -> str`) | `date`, `time`, `datetime` | APIs, JSON payloads, databases, sortable logs |
| `cls.fromisoformat(s)` | Parse (`str -> obj`) | `date`, `time`, `datetime` | Fast parsing of standard ISO 8601 strings |
| `obj.strftime(fmt)` | Format (`obj -> str`) | `date`, `time`, `datetime` | Custom display strings, reports, filenames |
| `f"{obj:%Y-%m-%d}"` | Format (`obj -> str`) | `date`, `time`, `datetime` | Concise inline formatting inside f-strings |
| `datetime.strptime(s, fmt)` | Parse (`str -> datetime`) | `datetime` only | Parsing legacy or custom non-ISO date/time strings |
