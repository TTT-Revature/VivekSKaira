# Creating and Importing Modules

## 1. Overview
In Python, a **module** is any file ending with the `.py` extension that contains Python code—such as functions, classes, variables, and runnable statements.

* **Code Organization:** Splits large applications into smaller, logical, and maintainable files.
* **Reusability:** Allows functions and constants written once in a module to be imported and reused across multiple scripts.
* **Namespace Isolation:** Each module has its own independent symbol table (namespace), preventing variable or function name collisions between different files.

---

## 2. Creating a Custom Module
To create a module, save valid Python definitions inside a `.py` file. Use `snake_case` for module filenames (per PEP 8) and avoid naming files after built-in standard library modules (such as `math.py`, `random.py`, or `re.py`).

### Example Module: `metrics_utils.py`
```python
"""Utility functions and constants for trainee score evaluation."""

PASSING_THRESHOLD = 75

def calculate_average(scores: list[float]) -> float:
    """Return the arithmetic mean of a list of scores."""
    if not scores:
        return 0.0
    return round(sum(scores) / len(scores), 2)

def get_status(score: float) -> str:
    """Return 'Pass' if score meets threshold, otherwise 'Retake'."""
    return "Pass" if score >= PASSING_THRESHOLD else "Retake"
```

## 3. Importing Modules
Once `metrics_utils.py` is created, another Python script (for example, `main.py` in the same directory) can import and use its contents in several ways.

### 1. Standard Module Import (`import module`)
Loads the entire module object into the current namespace. You access its contents using dot notation (`module.item`), which keeps namespaces clean and makes it obvious where each function came from:

```python
import metrics_utils

scores = [82, 91, 88]
avg = metrics_utils.calculate_average(scores)

print(f"Threshold: {metrics_utils.PASSING_THRESHOLD}")  # Threshold: 75
print(f"Average: {avg}")                                # Average: 87.0
print(f"Status: {metrics_utils.get_status(avg)}")       # Status: Pass
```

### 2. Importing with an Alias (`import module as alias`)
Assigns a shorter local alias to a module name—widely used for standard and third-party libraries (e.g., `import numpy as np`, `import pandas as pd`):

```python
import metrics_utils as mu

print(mu.get_status(68))  # Retake
```

### 3. Selective Import (`from module import item1, item2`)
Imports specific functions, classes, or constants directly into the current script's namespace so they can be called without the module prefix:

```python
from metrics_utils import calculate_average, PASSING_THRESHOLD

avg = calculate_average([90, 95, 85])
print(f"Average: {avg} (Pass Mark: {PASSING_THRESHOLD})")
# Output: Average: 90.0 (Pass Mark: 75)
```

### 4. Selective Import with an Alias (`from module import item as alias`)
Renames a specific imported object locally to shorten long names or prevent collisions with existing identifiers in your script:

```python
from metrics_utils import calculate_average as calc_avg

print(calc_avg([70, 80, 90]))  # 80.0
```

### 5. Wildcard Import (`from module import *`)
Imports all public names (names not starting with an underscore `_`) from a module directly into the current namespace:

```python
from metrics_utils import *

print(get_status(85))  # Pass
```
*(Best Practice: Avoid `from module import *` in production code. It pollutes the local namespace, risks silently overwriting existing variables or functions, and obscures where names originate.)*

## 4. Dual-Purpose Modules: `if __name__ == "__main__":`
Every Python module has a built-in `__name__` attribute whose value depends on how the file is executed:

* **Run directly (`python metrics_utils.py`):** `__name__` is set to `"__main__"`.
* **Imported (`import metrics_utils`):** `__name__` is set to the module's filename (`"metrics_utils"`).

When Python imports a module, it executes all top-level statements in that file from top to bottom. Wrapping test or driver code inside `if __name__ == "__main__":` ensures that code runs **only** when the file is executed directly—not when imported by another script:

```python
# Inside metrics_utils.py
PASSING_THRESHOLD = 75

def get_status(score: float) -> str:
    return "Pass" if score >= PASSING_THRESHOLD else "Retake"

# Guard block: skipped during 'import metrics_utils'
if __name__ == "__main__":
    print("Running module self-tests...")
    assert get_status(80) == "Pass"
    assert get_status(60) == "Retake"
    print("All tests passed!")
```

## 5. Module Search Path (`sys.path`)
When you execute `import my_module`, Python searches for `my_module.py` in a strict sequence of directories stored in `sys.path`:

1. **Input Script Directory:** The folder containing the script being executed (or the current working directory in interactive REPL mode).
2. **`PYTHONPATH` Environment Variable:** Any additional directories listed in the OS `PYTHONPATH` variable.
3. **Standard Library Directories:** Built-in modules installed with Python (such as `os`, `sys`, `re`, `json`, `math`).
4. **`site-packages` Directory:** Third-party packages installed via `pip`.

```python
import sys

# Inspect the ordered list of directories Python searches for modules
for path in sys.path:
    print(path)
```
*(If Python cannot find the module in any `sys.path` location, it raises `ModuleNotFoundError: No module named '...'`.)*

---

## 6. Module Caching and Reloading
To optimize performance, Python executes a module's code **only once** per interpreter session—the first time it is imported—and caches the loaded module object in the `sys.modules` dictionary. Subsequent `import` statements reuse the cached object without re-running the file.

During interactive debugging (e.g., in the REPL or Jupyter), if you edit a module file on disk and want to force Python to re-execute it without restarting the session, use `importlib.reload()`:

```python
import importlib
import metrics_utils

# After modifying metrics_utils.py on disk:
importlib.reload(metrics_utils)
```

## 7. Quick Reference

| Import Syntax | Example | Access Syntax | Recommended Usage |
| :--- | :--- | :--- | :--- |
| `import module` | `import math` | `math.sqrt(16)` | Default choice; keeps namespaces clean and explicit |
| `import module as alias` | `import datetime as dt` | `dt.date.today()` | Shortens long module names or follows standard conventions |
| `from module import item` | `from math import sqrt` | `sqrt(16)` | Convenient when using only 1–3 specific items frequently |
| `from module import item as alias` | `from math import factorial as fact` | `fact(5)` | Resolves name conflicts or shortens verbose function names |
| `from module import *` | `from math import *` | `sqrt(16)` | Avoid; causes namespace pollution and hides name origins |
| `if __name__ == "__main__":` | Guard block at file bottom | Runs only on direct execution | Prevents test/script code from running when imported |
