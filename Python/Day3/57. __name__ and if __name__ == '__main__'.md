# `__name__` and `if __name__ == "__main__"`

## 1. Overview
In Python, **`__name__`** is a built-in special ("dunder") variable that the interpreter automatically assigns to every module when it is loaded. Its value tells you **how the Python file is currently being used**:

* **Executed directly as a script:** Python sets `__name__` to `"__main__"`.
* **Imported as a module by another file:** Python sets `__name__` to the module's name (its filename without the `.py` extension, or its dotted package path).

The idiom **`if __name__ == "__main__":`** acts as an execution guard, allowing a single `.py` file to serve both as a **reusable importable module** and as a **standalone runnable script**.

---

## 2. How Python Assigns `__name__`

When the Python interpreter loads a file, it executes all top-level statements in that file from top to bottom. Before running the first line, Python initializes `__name__` based on the entry point:

| Execution Method | Command | Value of `__name__` Inside `math_tools.py` |
| :--- | :--- | :--- |
| **Direct Script Execution** | `python math_tools.py` | `"__main__"` |
| **Module Flag Execution** | `python -m math_tools` | `"__main__"` |
| **Top-Level Import** | `import math_tools` | `"math_tools"` |
| **Package Import** | `from utils import math_tools` | `"utils.math_tools"` |

---

## 3. Problem Without the Guard vs. Solution With the Guard

### Without `if __name__ == "__main__":` (Unintended Side Effects)
If executable driver or test code sits at the top level of a module, importing that module triggers all of those statements immediately:

```python
# File: math_tools.py (WITHOUT guard)
def add(a: int, b: int) -> int:
    return a + b

# Top-level statements always execute on import
print("Testing add(2, 3):", add(2, 3))
```

```python
# File: main_app.py
import math_tools  # Immediately prints: Testing add(2, 3): 5

print(math_tools.add(10, 20))  # 30
```

### With `if __name__ == "__main__":` (Clean Separation)
Placing the driver code inside the `if __name__ == "__main__":` block ensures it runs **only** when `math_tools.py` is invoked directly:

```python
# File: math_tools.py (WITH guard)
def add(a: int, b: int) -> int:
    return a + b

def multiply(a: int, b: int) -> int:
    return a * b

if __name__ == "__main__":
    # Runs ONLY when executing `python math_tools.py`
    print(f"Module __name__ is: {__name__}")
    assert add(2, 3) == 5
    assert multiply(4, 5) == 20
    print("Self-tests passed successfully.")
```

```python
# File: main_app.py
import math_tools  # Imports cleanly with zero unwanted output

# Inside main_app.py, math_tools.__name__ is "math_tools", while __name__ is "__main__"
print(math_tools.__name__)     # 'math_tools'
print(math_tools.add(10, 20))  # 30
```

## 4. Best Practice: Encapsulating Entry-Point Logic in `main()`
Because `if` blocks in Python do not create a new variable scope, any variables defined directly inside `if __name__ == "__main__":` become **global variables** for that module.

To keep variables properly scoped and make the entry point callable or testable from other scripts, wrap script execution inside a `main()` function:

```python
import sys

def process_data(items: list[str]) -> list[str]:
    return [item.strip().upper() for item in items]

def main() -> None:
    """Entry point when executed from the command line."""
    raw_items = sys.argv[1:] or ["python", "sql", "git"]
    cleaned = process_data(raw_items)
    print("Processed:", cleaned)

if __name__ == "__main__":
    main()
```

---

## 5. Key Use Cases

1. **Dual-Purpose Modules (Library + CLI Tool):** Expose reusable functions and classes for other modules to import while providing a command-line interface when run directly.
2. **Inline Smoke Tests and Debugging:** Include quick `assert` checks or sample runs at the bottom of a utility module without affecting production callers.
3. **Multiprocessing Safety (`multiprocessing` module):** On Windows and macOS, Python's `multiprocessing` spawns new child processes by re-importing the main script. Without `if __name__ == "__main__":`, each child process would recursively spawn new processes, causing a `RuntimeError` or infinite loop:
   ```python
   from multiprocessing import Process

   def worker() -> None:
       print("Worker running")

   if __name__ == "__main__":
       p = Process(target=worker)
       p.start()
       p.join()
   ```

## 6. Quick Reference

| Concept / Syntax | Behavior | Purpose |
| :--- | :--- | :--- |
| `__name__` | Built-in `str` attribute on every module | Identifies whether the file is the main entry point or an imported module |
| `__name__ == "__main__"` | Evaluates to `True` only when run directly | Guards script-only logic from running during `import` |
| `module.__name__` | Evaluates to `"module"` (or `"pkg.module"`) | Identifies the imported module's qualified name |
| `def main() -> None:` | Standard entry-point function called inside the guard | Prevents entry-point variables from leaking into global module scope |
