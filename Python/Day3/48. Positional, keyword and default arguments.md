# Positional, Keyword, and Default Arguments

## 1. Overview
When calling a function in Python, arguments are mapped to the function's parameters using three primary mechanisms:

* **Positional Arguments:** Matched strictly by their left-to-right order in the function call.
* **Keyword Arguments:** Matched explicitly by parameter name (`key=value`), regardless of position.
* **Default Arguments:** Parameters given a fallback value in the function definition (`def`), making them optional during a function call.

---

## 2. Positional Arguments
Positional arguments are the most standard way to pass data into a function. Python assigns each argument to the parameter at the corresponding index.

* **Order Matters:** Swapping the positions of two arguments assigns them to different parameters.
* **Exact Count Required:** Supplying fewer or more positional arguments than required parameters raises a `TypeError`.

```python
def format_session(module, day_number, duration_hrs):
    print(f"Day {day_number}: {module} ({duration_hrs} hrs)")

# Matched by position: module="Functions", day_number=4, duration_hrs=2.5
format_session("Functions", 4, 2.5)
# Output: Day 4: Functions (2.5 hrs)

# Wrong order produces unintended results
format_session(4, "Functions", 2.5)
# Output: Day Functions: 4 (2.5 hrs)

# Missing an argument raises TypeError
# format_session("Functions", 4)
# TypeError: format_session() missing 1 required positional argument: 'duration_hrs'
```

---

## 3. Keyword Arguments
Keyword arguments specify the target parameter name explicitly using `parameter_name=value` syntax during the function call.

* **Order Independence:** Keyword arguments can appear in any order.
* **Improved Readability:** Makes function calls self-documenting, especially when passing boolean flags or multiple numeric values.

```python
def create_deployment(service, environment, replicas, auto_scale):
    print(f"{service} [{environment}] -> replicas={replicas}, auto_scale={auto_scale}")

# Arguments passed in arbitrary order using parameter names
create_deployment(
    auto_scale=True,
    replicas=3,
    service="api-gateway",
    environment="production"
)
# Output: api-gateway [production] -> replicas=3, auto_scale=True
```

### Rules for Mixing Positional and Keyword Arguments
You can combine positional and keyword arguments in the same call, provided you follow two rules:

1. **Positional Before Keyword:** All positional arguments must come **before** any keyword arguments (`SyntaxError` otherwise).
2. **No Duplicate Assignments:** You cannot pass a value positionally and then assign the same parameter again by keyword (`TypeError` otherwise).

```python
def connect(host, port, protocol):
    print(f"{protocol}://{host}:{port}")

# Valid: positional argument first, followed by keyword arguments
connect("127.0.0.1", protocol="https", port=8443)
# Output: [https://127.0.0.1:8443](https://127.0.0.1:8443)

# Invalid 1: positional argument after keyword argument
# connect(host="127.0.0.1", 8443, "https")
# SyntaxError: positional argument follows keyword argument

# Invalid 2: 'host' receives two values (one positional, one keyword)
# connect("127.0.0.1", host="localhost", port=8080, protocol="http")
# TypeError: connect() got multiple values for argument 'host'
```

## 4. Default Arguments
Default arguments are defined by assigning a default value to a parameter in the `def` signature (`param=default_value`). If the caller omits that argument, Python automatically uses the default.

### Parameter Ordering Rule in `def`
In a function definition, **non-default (required) parameters must always precede default (optional) parameters**. Placing a non-default parameter after a default parameter raises a `SyntaxError`.

```python
# Valid: required parameter 'score' comes before default parameters
def evaluate_test(score, pass_mark=75, max_score=100):
    status = "Pass" if score >= pass_mark else "Retake"
    print(f"Score: {score}/{max_score} | Status: {status}")

evaluate_test(84)                        # Uses both defaults (pass_mark=75, max_score=100)
evaluate_test(72, 70)                    # Overrides pass_mark positionally
evaluate_test(42, max_score=50, pass_mark=35)  # Overrides both using keywords

# Invalid definition: non-default parameter after default parameter
# def invalid_func(a=10, b):
#     pass
# SyntaxError: non-default argument follows default argument
```

### Critical Pitfall: Mutable Default Arguments
Python evaluates default parameter expressions **only once** when the `def` statement executes—not every time the function is called. If you use a mutable object (such as a `list` or `dict`) as a default value, the same object is shared and mutated across every call that omits that argument.

```python
# INCORRECT: 'completed' list is created once and persists across calls
def record_topic_bad(topic, completed=[]):
    completed.append(topic)
    return completed

print(record_topic_bad("Lists"))   # ['Lists']
print(record_topic_bad("Tuples"))  # ['Lists', 'Tuples'] (unexpected state leak!)

# CORRECT: Use None as the sentinel default and initialize a new list inside
def record_topic_good(topic, completed=None):
    if completed is None:
        completed = []
    completed.append(topic)
    return completed

print(record_topic_good("Lists"))   # ['Lists']
print(record_topic_good("Tuples"))  # ['Tuples']
```

## 5. Combining Positional, Keyword, and Default Arguments

```python
def generate_report(trainee_name, track, batch="FDE-2026", include_remarks=False):
    header = f"Trainee: {trainee_name} | Track: {track} | Batch: {batch}"
    if include_remarks:
        return f"{header} | Remarks: Ready for evaluation"
    return header

# 1. Only required positional arguments
print(generate_report("Vivek", "Python"))

# 2. Positional arguments + selective keyword override (skipping 'batch')
print(generate_report("Priya", "Data Engineering", include_remarks=True))

# 3. All arguments passed via keywords
print(generate_report(track="Cloud", trainee_name="Amit", batch="FDE-02"))
```

## 6. Quick Reference

| Argument Type | Where Specified | Order Constraint | Error on Misuse |
| :--- | :--- | :--- | :--- |
| **Positional** | Function call: `f(a, b)` | Must match parameter order; must appear before keyword arguments | `TypeError` (wrong count) or `SyntaxError` (after keyword) |
| **Keyword** | Function call: `f(y=2, x=1)` | Any order among keyword arguments, but must follow positional arguments | `TypeError` (unknown or duplicate parameter name) |
| **Default** | Function definition: `def f(x, y=5):` | Must be placed after all non-default parameters in `def` | `SyntaxError` (non-default parameter follows default) |
