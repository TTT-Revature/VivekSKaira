# Return Values and Multiple Returns

## 1. Overview
The **`return`** statement terminates the execution of a function and passes a result back to the caller.

* **Data Output:** Allows functions to compute values and hand them over to other parts of a program for further processing.
* **Immediate Exit:** As soon as Python executes a `return` statement, the function exits immediately—even if there are remaining lines or active loops inside the function.
* **Any Object Type:** A function can return any Python object (`int`, `float`, `str`, `bool`, `list`, `dict`, `tuple`, `None`, or even another `function`).

---

## 2. Returning a Single Value
A `return` statement can evaluate any valid Python expression (a literal, variable, arithmetic operation, or another function call) and send the resulting object back to the caller.

```python
def calculate_final_score(base_score: int, bonus: int) -> int:
    total = min(base_score + bonus, 100)
    return total

# Store the returned value in a variable
final = calculate_final_score(88, 7)
print(final)  # 95

# Use the returned value directly inside another expression
print(f"Percentage: {calculate_final_score(75, 10)}%")  # Percentage: 85%
```

---

## 3. Implicit `None` Return
In Python, every function returns a value—even if you do not write a `return` statement.

* **No `return` statement:** When execution reaches the end of the function body, Python implicitly returns `None`.
* **Bare `return`:** Writing `return` with no expression exits the function early and also returns `None`.

```python
# 1. Function with no return statement (void/procedure-style function)
def print_banner(title: str) -> None:
    print(f"=== {title} ===")

result = print_banner("Python Functions")
print(result)         # None
print(type(result))   # <class 'NoneType'>

# 2. Bare return used to exit early without a value
def process_items(items: list) -> None:
    if not items:
        return  # Exits early, implicitly returning None
    print(f"Processing {len(items)} items...")
```

## 4. Returning Multiple Values
Python functions do not literally return separate values; instead, separating expressions with commas after `return` **packs them into a single `tuple`**.

### Tuple Packing and Unpacking
```python
def analyze_scores(scores: list[int]) -> tuple[int, int, float]:
    lowest = min(scores)
    highest = max(scores)
    average = round(sum(scores) / len(scores), 2)
    return lowest, highest, average  # Packed automatically into a tuple

marks = [78, 92, 85, 64, 96]

# 1. Receive as a single tuple
summary = analyze_scores(marks)
print(summary)        # (64, 96, 83.0)
print(type(summary))  # <class 'tuple'>

# 2. Unpack directly into individual variables
low, high, avg = analyze_scores(marks)
print(f"Low: {low}, High: {high}, Avg: {avg}")
# Output: Low: 64, High: 96, Avg: 83.0
```

### Partial Unpacking (`_` and `*`)
* **Ignoring values with `_`:** Use an underscore `_` as a throwaway variable for returned items you do not need.
* **Extended unpacking with `*`:** Capture multiple returned items into a `list`.

```python
def get_user_record():
    return "FDE-101", "Vivek", "Python", "SQL", "Git"

# Ignore the first element, capture the name, and group remaining skills into a list
_, name, *skills = get_user_record()
print(name)    # 'Vivek'
print(skills)  # ['Python', 'SQL', 'Git']
```

### Returning Dictionaries or Lists for Larger Payloads
When a function needs to return more than 3–4 values, returning a **`dict`** (or a `dataclass` / `NamedTuple`) makes the output self-documenting and prevents callers from mixing up variable order:

```python
def get_batch_metrics(scores: list[int]) -> dict[str, int | float]:
    return {
        "count": len(scores),
        "min": min(scores),
        "max": max(scores),
        "average": round(sum(scores) / len(scores), 2)
    }

metrics = get_batch_metrics([80, 90, 85])
print(metrics["average"])  # 85.0
```

## 5. Early Return Pattern (Guard Clauses)
Using multiple `return` statements allows you to handle invalid inputs or edge cases immediately at the top of a function, avoiding deeply nested `if-else` blocks.

```python
# Without early return (nested and harder to scan)
def divide_nested(a: float, b: float) -> float | str:
    if b != 0:
        return a / b
    else:
        return "Error: Division by zero"

# With early return / guard clause (flat and readable)
def divide_clean(a: float, b: float) -> float | str:
    if b == 0:
        return "Error: Division by zero"  # Guard clause exits immediately
    return a / b
```

### Unreachable Code After `return`
Any code placed after an unconditionally executed `return` inside the same block will never execute:

```python
def demo_unreachable():
    return "Done"
    print("This line will never run")  # Unreachable code
```

## 6. Returning Functions (Higher-Order Functions)
Because functions are first-class objects in Python, a function can construct and return another function:

```python
def make_multiplier(factor: int):
    def multiply(number: int) -> int:
        return number * factor
    return multiply  # Returns the inner function object without calling it

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))  # 20
print(triple(10))  # 30
```

---

## 7. Quick Reference

| Return Pattern | Syntax Example | Returned Object Type | Key Behavior |
| :--- | :--- | :--- | :--- |
| **Single Value** | `return total` | Type of `total` | Exits function and sends one object back |
| **No Return / Bare `return`** | `return` or omitted | `NoneType` (`None`) | Implicitly returns `None` upon exit |
| **Multiple Values** | `return a, b, c` | `tuple` | Packs comma-separated values into a tuple |
| **Keyed Multiple Values** | `return {"k1": a, "k2": b}` | `dict` | Self-documenting output for 4+ fields |
| **Guard Clause** | `if invalid: return None` | Any | Exits early on edge cases to flatten logic |
| **Function Return** | `return inner_func` | `function` | Returns a callable function object (closure) |
