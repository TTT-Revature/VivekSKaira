# Parameters and Arguments

## 1. Overview
In Python functions, **parameters** and **arguments** define how data is passed into a function:

* **Parameter:** A variable listed inside the parentheses of a function **definition** (`def`). It acts as a placeholder for incoming data.
* **Argument:** The actual value or expression passed inside the parentheses during a function **call**.

```python
# 'module' and 'hours' are PARAMETERS
def log_study(module, hours):
    print(f"Module: {module} | Duration: {hours} hrs")

# "Python Functions" and 2.5 are ARGUMENTS
log_study("Python Functions", 2.5)
```

---

## 2. Positional Arguments
Positional arguments are matched to parameters strictly by their **left-to-right order**. The number and position of arguments must match the function's parameter list.

```python
def create_profile(name, track, batch_id):
    print(f"{name} -> {track} (Batch {batch_id})")

create_profile("Vivek", "FDE", 101)
# Output: Vivek -> FDE (Batch 101)

# Passing arguments in the wrong order changes the meaning
create_profile(101, "Vivek", "FDE")
# Output: 101 -> Vivek (Batch FDE)
```

---

## 3. Keyword Arguments
Keyword arguments are passed using `parameter_name=value` syntax, matching values by **parameter name** rather than position.

* **Order Independence:** Keyword arguments can be supplied in any order.
* **Ordering Rule:** Positional arguments must always appear **before** keyword arguments in a function call; placing a positional argument after a keyword argument raises a `SyntaxError`.

```python
def deploy_service(service_name, environment, port):
    print(f"Deploying {service_name} to {environment} on port {port}")

# 1. Pure keyword arguments (any order)
deploy_service(port=8080, service_name="auth-api", environment="prod")

# 2. Mixing positional and keyword arguments (positional first)
deploy_service("auth-api", port=8080, environment="staging")

# 3. Invalid: positional argument after keyword argument
# deploy_service(service_name="auth-api", "prod", 8080)  # SyntaxError
```

---

## 4. Default Parameters
You can assign a **default value** to a parameter in the `def` signature. If the caller omits that argument, Python uses the default value.

* **Ordering Rule:** Parameters with default values must always come **after** parameters without default values (`SyntaxError` otherwise).

```python
def calculate_grade(score, passing_mark=75):
    return "Pass" if score >= passing_mark else "Retake"

print(calculate_grade(88))      # 'Pass'   (uses default passing_mark=75)
print(calculate_grade(72, 70))  # 'Pass'   (overrides default with 70)
```

### The Mutable Default Argument Pitfall
Default parameter values are evaluated **only once** when the `def` statement is executed—not each time the function is called. Never use a mutable object (like `[]` or `{}`) directly as a default value, or it will be shared across all calls.

```python
# BAD: The same list object is reused across every call
def add_skill_bad(skill, skills=[]):
    skills.append(skill)
    return skills

print(add_skill_bad("Python"))  # ['Python']
print(add_skill_bad("SQL"))     # ['Python', 'SQL'] (unintended state retention!)

# GOOD: Use None as the default and create a fresh list inside the function
def add_skill_good(skill, skills=None):
    if skills is None:
        skills = []
    skills.append(skill)
    return skills

print(add_skill_good("Python"))  # ['Python']
print(add_skill_good("SQL"))     # ['SQL']
```

## 5. Variable-Length Arguments (`*args` and `**kwargs`)
When a function needs to accept an arbitrary number of arguments, Python provides `*args` and `**kwargs` (the names `args` and `kwargs` are standard conventions; the `*` and `**` operators do the actual work).

### 1. Arbitrary Positional Arguments (`*args`)
Collects any extra positional arguments into a **`tuple`**:
```python
def calculate_average(*scores):
    if not scores:
        return 0.0
    return sum(scores) / len(scores)

print(calculate_average(85, 90, 95))      # 90.0
print(calculate_average(70, 80, 90, 100)) # 85.0
```

### 2. Arbitrary Keyword Arguments (`**kwargs`)
Collects any extra keyword arguments into a **`dict`**:
```python
def build_config(app_name, **options):
    print(f"App: {app_name}")
    for key, value in options.items():
        print(f"  {key} = {value}")

build_config("DriveWise", debug=True, retries=3, timeout=30)
# Output:
# App: DriveWise
#   debug = True
#   retries = 3
#   timeout = 30
```

## 6. Positional-Only (`/`) and Keyword-Only (`*`) Parameters
Python allows API authors to strictly enforce how callers pass arguments using `/` and `*` markers in the function signature (introduced in Python 3.8):

* **Before `/` (Positional-Only):** Must be passed by position; passing by keyword raises a `TypeError`.
* **Between `/` and `*` (Positional-or-Keyword):** Can be passed either positionally or by keyword.
* **After `*` or `*args` (Keyword-Only):** Must be passed explicitly by keyword; passing positionally raises a `TypeError`.

```python
def configure_server(host, port, /, protocol="https", *, timeout=10, verify_ssl=True):
    print(f"{protocol}://{host}:{port} (timeout={timeout}, ssl={verify_ssl})")

# Valid calls:
configure_server("localhost", 8000, timeout=30)
configure_server("localhost", 8000, "http", verify_ssl=False)

# Invalid calls:
# configure_server(host="localhost", port=8000)         # TypeError: host & port are positional-only
# configure_server("localhost", 8000, "https", 30)      # TypeError: timeout is keyword-only
```

---

## 7. Standard Parameter Ordering Rule
When combining multiple parameter types in a single function definition, Python requires them in this exact order:

```python
def full_example(pos_only, /, standard, default_param=10, *args, kw_only, **kwargs):
    pass
```

1. Positional-only parameters (followed by `/`)
2. Standard positional-or-keyword parameters (non-default first, then default)
3. `*args` (or bare `*` if there are keyword-only parameters without `*args`)
4. Keyword-only parameters
5. `**kwargs`

## 8. Unpacking Arguments During Function Calls (`*` and `**`)
You can unpack collections directly into function arguments when calling a function:

* **`*iterable`:** Unpacks elements of a `list`, `tuple`, or `set` as **positional arguments**.
* **`**dict`:** Unpacks `key: value` pairs of a dictionary as **keyword arguments** (keys must match parameter names).

```python
def register_trainee(name, age, track):
    print(f"Registered: {name}, Age {age}, Track: {track}")

# 1. Unpacking a list/tuple with *
data_list = ["Vivek", 23, "FDE"]
register_trainee(*data_list)

# 2. Unpacking a dictionary with **
data_dict = {"name": "Priya", "age": 22, "track": "Data Science"}
register_trainee(**data_dict)
```

---

## 9. Quick Reference

| Syntax | Role | Collected Type / Behavior |
| :--- | :--- | :--- |
| `def f(a, b):` | Standard parameters | Accepts positional or keyword arguments |
| `def f(a, b=10):` | Default parameter | Uses `10` if `b` is omitted; must follow non-defaults |
| `def f(*args):` | Arbitrary positional parameters | Packs extra positional arguments into a `tuple` |
| `def f(**kwargs):` | Arbitrary keyword parameters | Packs extra keyword arguments into a `dict` |
| `def f(a, /, b):` | Positional-only marker (`/`) | Parameters before `/` cannot be passed by keyword |
| `def f(a, *, b):` | Keyword-only marker (`*`) | Parameters after `*` must be passed by keyword |
| `f(*iterable)` | Call-site iterable unpacking | Expands items into separate positional arguments |
| `f(**mapping)` | Call-site dictionary unpacking | Expands `key: value` pairs into keyword arguments |
