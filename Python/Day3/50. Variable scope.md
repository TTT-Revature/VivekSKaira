# Variable Scope

## 1. Overview
**Variable scope** defines the region of a Python program where a variable name is recognized and can be accessed. Python manages variable names using **namespaces**—mappings from variable names to objects in memory.

* **Lifetime:** A variable exists in memory only while its namespace is active (e.g., a local variable is created when a function is called and destroyed when the function exits).
* **Isolation:** Scope prevents variables inside one function from accidentally colliding with or overwriting variables in another function.

---

## 2. The LEGB Rule (Scope Resolution Order)
Whenever you reference a variable name, Python searches for it across four scopes in the exact order **L -> E -> G -> B**, stopping at the first match:

1. **L — Local:** Names assigned inside the current function (including parameters).
2. **E — Enclosing:** Names in the local scope of any enclosing (outer) functions, from inner to outer.
3. **G — Global:** Names defined at the top level of the current module (`.py` file) or declared with `global`.
4. **B — Built-in:** Predefined names loaded automatically by Python (`len`, `print`, `int`, `range`, `Exception`, etc.).

*(If a name is not found in any of the four scopes, Python raises a `NameError`.)*

### LEGB Resolution Example
```python
x = "Global x"  # Global scope (G)

def outer_function():
    x = "Enclosing x"  # Enclosing scope (E)

    def inner_function():
        x = "Local x"  # Local scope (L)
        print(x)       # Resolves to 'Local x'
        print(len(x))  # 'len' resolves in Built-in scope (B) -> 7

    inner_function()
    print(x)  # Resolves to 'Enclosing x'

outer_function()
print(x)      # Resolves to 'Global x'
```

## 3. Local vs. Global Scope

### Local Variables
Variables created inside a function belong exclusively to that function's local scope and cannot be accessed outside it:
```python
def calculate_total():
    tax_rate = 0.18  # Local variable
    return 100 * (1 + tax_rate)

print(calculate_total())  # 118.0
# print(tax_rate)         # Raises NameError: name 'tax_rate' is not defined
```

### Global Variables and the `UnboundLocalError` Pitfall
Functions can **read** global variables freely. However, if you **assign** (`=`, `+=`, etc.) to a variable anywhere inside a function without declaring it `global`, Python treats that variable as **local** throughout the entire function body:

```python
counter = 10  # Global variable

def read_counter():
    print(counter)  # Valid: reads global 'counter' -> 10

def broken_increment():
    # Python sees 'counter += 1' and marks 'counter' as a local variable,
    # causing the read before assignment to fail:
    counter += 1    # Raises UnboundLocalError: cannot access local variable 'counter'
```

## 4. Modifying Outer Scopes (`global` and `nonlocal`)

### 1. The `global` Keyword
Use `global` inside a function when you need to **rebind or modify** a module-level global variable:

```python
active_users = 0

def register_login():
    global active_users
    active_users += 1

register_login()
register_login()
print(active_users)  # 2
```
*(Best Practice: Avoid overusing `global` for state mutation—passing arguments into functions and returning new values makes code easier to test and debug.)*

### 2. The `nonlocal` Keyword
Use `nonlocal` inside a **nested function** when you need to modify a variable belonging to an **enclosing function's scope** (commonly used in closures):

* `nonlocal` searches enclosing function scopes only; it cannot bind to module-level global variables (`SyntaxError` otherwise).

```python
def create_counter():
    count = 0  # Enclosing variable

    def increment():
        nonlocal count
        count += 1
        return count

    return increment

counter_fn = create_counter()
print(counter_fn())  # 1
print(counter_fn())  # 2
```

## 5. Block Scope vs. Function Scope
Unlike languages such as C, C++, or Java, Python **does not create a new variable scope** for control-flow blocks (`if`, `for`, `while`, `with`, or `try-except`). Variables defined inside these blocks remain accessible in the surrounding function or module scope:

```python
if True:
    status = "Active"

for i in range(3):
    last_index = i

print(status)      # 'Active' (accessible outside the if block)
print(last_index)  # 2        (accessible outside the for loop)
```

*(Note: Functions, classes, and comprehensions (`[x for x in ...]`) **do** create their own local scope, so comprehension loop variables do not leak into the outer scope.)*

## 6. Inspecting Namespaces (`locals()` and `globals()`)
Python provides two built-in functions to inspect active variable bindings as dictionaries:

* **`globals()`:** Returns a dictionary representing the current module's global symbol table.
* **`locals()`:** Returns a dictionary representing the current local symbol table.

```python
module_name = "Python Scope"

def inspect_scopes(param_a):
    local_var = 42
    print("Local variables:", locals())
    print("Global 'module_name' exists:", "module_name" in globals())

inspect_scopes("test")
# Output:
# Local variables: {'param_a': 'test', 'local_var': 42}
# Global 'module_name' exists: True
```

## 7. Quick Reference

| Scope / Keyword | Lookup Priority | Where Defined | Modification Rule |
| :--- | :--- | :--- | :--- |
| **Local (`L`)** | 1st (First) | Inside the current function (`def` / `lambda`) | Default scope for any assignment inside a function |
| **Enclosing (`E`)** | 2nd | Inside outer/parent functions of a nested function | Read-only from inner function unless declared `nonlocal` |
| **Global (`G`)** | 3rd | Top level of a `.py` file / module | Read-only inside functions unless declared `global` |
| **Built-in (`B`)** | 4th (Last) | Python's `builtins` module (`len`, `sum`, `str`, etc.) | Avoid assigning to built-in names so they are not shadowed |
| **`global x`** | — | Inside a function | Binds `x` to the module-level global variable for reassignment |
| **`nonlocal x`** | — | Inside a nested function | Binds `x` to the nearest enclosing function variable |
