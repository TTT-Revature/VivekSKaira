# `unittest` Basics in Python

## 1. Overview
**`unittest`** is Python's built-in unit testing framework included in the standard library (inspired by Java's JUnit and the xUnit family). It provides a structured, object-oriented way to write, organize, and run automated tests without installing any third-party packages.

* **Core Building Blocks of `unittest`:**
  * **Test Case (`unittest.TestCase`):** The fundamental unit of testing; a class grouping related test methods and assertion helpers.
  * **Test Fixture:** Setup and cleanup logic (`setUp`, `tearDown`) that prepares a clean environment before a test runs and cleans up afterward.
  * **Test Suite (`unittest.TestSuite`):** A collection of test cases or nested suites executed together.
  * **Test Runner (`unittest.TextTestRunner`):** Orchestrates test execution and formats pass, fail, and error results in the console.

## 2. Writing Your First `unittest` Test Case
To create tests with `unittest`, follow four structural rules:
1. Import the **`unittest`** module.
2. Define a class inheriting from **`unittest.TestCase`**.
3. Name every test method with the **`test_`** prefix so the test runner automatically discovers and executes it.
4. Verify outcomes using **`self.assert*`** methods rather than Python's bare `assert` statement.

### Example: Module Under Test and Unit Test File

```python
# File: src/math_ops.py
def divide(numerator: float, denominator: float) -> float:
    """Return numerator divided by denominator; raise ValueError on zero division."""
    if denominator == 0:
        raise ValueError("Denominator cannot be zero")
    return numerator / denominator


def is_even(number: int) -> bool:
    """Return True if number is divisible by 2."""
    return number % 2 == 0
```

```python
# File: tests/test_math_ops.py
import unittest
from src.math_ops import divide, is_even


class TestMathOps(unittest.TestCase):
    def test_divide_positive_numbers(self) -> None:
        result = divide(10.0, 2.0)
        self.assertEqual(result, 5.0)

    def test_divide_negative_numerator(self) -> None:
        self.assertEqual(divide(-9.0, 3.0), -3.0)

    def test_is_even_returns_true_for_even_integers(self) -> None:
        self.assertTrue(is_even(4))
        self.assertTrue(is_even(0))

    def test_is_even_returns_false_for_odd_integers(self) -> None:
        self.assertFalse(is_even(7))


if __name__ == "__main__":
    unittest.main()
```

## 3. Standard Assertion Methods
`TestCase` provides rich assertion methods that produce clear failure diffs and remain active even if Python runs with optimization flags (`python -O`, which strips bare `assert` statements).

### Core Value, Identity, and Membership Assertions

| Method | Checks That |
| :--- | :--- |
| `self.assertEqual(a, b)` | `a == b` (uses type-aware diffing for lists, dicts, sets, and strings) |
| `self.assertNotEqual(a, b)` | `a != b` |
| `self.assertTrue(x)` | `bool(x) is True` |
| `self.assertFalse(x)` | `bool(x) is False` |
| `self.assertIs(a, b)` | `a is b` (exact same object identity in memory) |
| `self.assertIsNot(a, b)` | `a is not b` |
| `self.assertIsNone(x)` | `x is None` |
| `self.assertIsNotNone(x)` | `x is not None` |
| `self.assertIn(member, container)` | `member in container` |
| `self.assertNotIn(member, container)` | `member not in container` |
| `self.assertIsInstance(obj, cls)` | `isinstance(obj, cls)` |
| `self.assertNotIsInstance(obj, cls)` | `not isinstance(obj, cls)` |

### Floating-Point and Collection Assertions

| Method | Purpose | Example |
| :--- | :--- | :--- |
| `self.assertAlmostEqual(a, b, places=7)` | Asserts `round(a - b, places) == 0` for floating-point math | `self.assertAlmostEqual(0.1 + 0.2, 0.3, places=7)` |
| `self.assertGreater(a, b)` / `assertLess(a, b)` | Asserts `a > b` or `a < b` (also `assertGreaterEqual`, `assertLessEqual`) | `self.assertGreater(score, 0)` |
| `self.assertCountEqual(seq1, seq2)` | Asserts both sequences contain the same elements in **any order** | `self.assertCountEqual([1, 2, 2], [2, 1, 2])` |
| `self.assertDictEqual(d1, d2)` | Compares two dictionaries and highlights exact key/value mismatches | `self.assertDictEqual(actual, expected)` |

## 4. Testing Exceptions (`assertRaises` and `assertRaisesRegex`)
To verify that invalid inputs trigger the expected exception, use **`self.assertRaises()`** as a `with` context manager:

```python
import unittest
from src.math_ops import divide


class TestDivideExceptions(unittest.TestCase):
    def test_divide_by_zero_raises_value_error(self) -> None:
        # Passes if ValueError is raised inside the with-block; fails otherwise
        with self.assertRaises(ValueError) as context:
            divide(10.0, 0.0)

        # Inspect the captured exception message
        self.assertEqual(str(context.exception), "Denominator cannot be zero")

    def test_divide_by_zero_matches_error_pattern(self) -> None:
        # Combines exception type verification with regex message matching
        with self.assertRaisesRegex(ValueError, r"cannot be zero"):
            divide(5.0, 0.0)
```

## 5. Test Fixtures: Setup and Teardown Lifecycle
When multiple tests in a class need identical objects, temporary files, or fresh state, `unittest` provides lifecycle hooks so setup code is not duplicated across every test method:

| Fixture Hook | Scope & Execution Frequency | Common Use Case |
| :--- | :--- | :--- |
| `setUp(self)` | Runs **before each** `test_*` method | Creating fresh instances, temporary folders, or clean state per test |
| `tearDown(self)` | Runs **after each** `test_*` method (even if the test fails) | Closing files, resetting state, cleaning per-test resources |
| `setUpClass(cls)` (`@classmethod`) | Runs **once before all** tests in the class | Loading read-only configuration or expensive immutable fixtures |
| `tearDownClass(cls)` (`@classmethod`) | Runs **once after all** tests in the class | Releasing class-level shared resources |
| `setUpModule()` / `tearDownModule()` | Module-level functions run **once per module** | Module-wide initialization and teardown |

### Fixture Example with `setUp`, `tearDown`, and `addCleanup`
```python
from pathlib import Path
import tempfile
import unittest


class TestFileStorage(unittest.TestCase):
    def setUp(self) -> None:
        # Runs fresh before every single test_* method
        self.temp_dir = tempfile.TemporaryDirectory()
        self.workspace = Path(self.temp_dir.name)
        # addCleanup guarantees cleanup runs even if setUp fails partway through
        self.addCleanup(self.temp_dir.cleanup)

    def test_write_and_read_notes_file(self) -> None:
        note_file = self.workspace / "notes.txt"
        note_file.write_text("Revature FDE Training", encoding="utf-8")

        self.assertTrue(note_file.exists())
        self.assertEqual(note_file.read_text(encoding="utf-8"), "Revature FDE Training")

    def test_workspace_starts_empty_for_next_test(self) -> None:
        # Proves test independence: notes.txt from the previous test does not exist here
        self.assertEqual(list(self.workspace.iterdir()), [])
```

## 6. Subtests, Skipping, and Expected Failures

### 1. Iterating Over Test Cases with `self.subTest()`
In a standard `for` loop inside a test method, the first failed assertion aborts the entire method immediately. Wrapping each iteration in **`with self.subTest(...)`** executes all cases and reports every failing input individually:

```python
class TestEvenNumbers(unittest.TestCase):
    def test_multiple_integers(self) -> None:
        cases = [
            (2, True),
            (3, False),
            (0, True),
            (-4, True),
        ]
        for value, expected in cases:
            with self.subTest(value=value):
                self.assertEqual(value % 2 == 0, expected)
```

### 2. Skipping Tests and Marking Expected Failures
```python
import sys
import unittest


class TestPlatformFeatures(unittest.TestCase):
    @unittest.skip("Feature scheduled for next sprint")
    def test_unimplemented_export(self) -> None:
        pass

    @unittest.skipIf(sys.platform == "win32", "POSIX permissions not applicable on Windows")
    def test_posix_file_mode(self) -> None:
        self.assertTrue(True)

    @unittest.skipUnless(sys.version_info >= (3, 11), "Requires Python 3.11 or newer")
    def test_python_311_feature(self) -> None:
        self.assertTrue(True)

    @unittest.expectedFailure
    def test_known_rounding_bug(self) -> None:
        # Fails as expected without breaking the build; alerts if it unexpectedly passes
        self.assertEqual(1 / 3, 0.33)
```

## 7. Running Tests from the Command Line (Test Discovery)
Run `unittest` from your project root using `python -m unittest`:

```bash
# 1. Automatically discover and run all test_*.py files under tests/
python -m unittest discover -s tests -p "test_*.py"

# 2. Run in verbose mode (-v) to print each test method name and status
python -m unittest discover -s tests -v

# 3. Run a specific test module, class, or single test method
python -m unittest tests.test_math_ops
python -m unittest tests.test_math_ops.TestMathOps
python -m unittest tests.test_math_ops.TestMathOps.test_divide_positive_numbers

# 4. Filter tests matching a substring (-k) and stop on the first failure (-f)
python -m unittest discover -s tests -k "divide" -f
```

### Reading Test Output Codes
* **`.` (dot):** Test passed.
* **`F` (Failure):** An assertion (`self.assert*`) failed (`AssertionError`).
* **`E` (Error):** An unexpected unhandled exception occurred during test execution.
* **`s` (Skipped):** Test was skipped via `@unittest.skip*`.
* **`x` (Expected Failure):** Test decorated with `@unittest.expectedFailure` failed as expected.

## 8. Common Pitfalls and Best Practices

1. **Omitting the `test_` Prefix on Test Methods:**
   Helper methods inside a `TestCase` (such as `def check_output(self):`) are intentionally ignored by `unittest`. Every test method you want executed must start with **`test_`**.
2. **Calling a Function Directly Inside `assertRaises()` Instead of Using `with`:**
   Writing `self.assertRaises(ValueError, divide(10, 0))` calls `divide(10, 0)` *before* `assertRaises` is ever entered, crashing the test with an unhandled `ValueError`. Always use the **`with self.assertRaises(ValueError):`** context manager form.
3. **Forgetting `__init__.py` Inside the `tests/` Directory:**
   `unittest discover` requires test directories to be importable Python packages. Always include an empty **`tests/__init__.py`** file so `python -m unittest discover` finds nested test modules reliably.
4. **Relying on Test Execution Order:**
   `unittest` runs test methods sorted alphabetically by method name. Never design `test_step_2` to depend on state mutated by `test_step_1`; isolate every test using `setUp()`.

## 9. Quick Reference

| Construct / Command | Purpose |
| :--- | :--- |
| `class TestFeature(unittest.TestCase):` | Defines a test case class grouping related unit tests |
| `def test_behavior(self):` | Test method automatically discovered and run by `unittest` |
| `self.assertEqual(a, b)` / `assertTrue(x)` | Standard value and boolean assertions with detailed failure diffs |
| `self.assertAlmostEqual(a, b, places=7)` | Compares floating-point numbers within decimal tolerance |
| `with self.assertRaises(ExcType):` | Verifies that a block of code raises `ExcType` |
| `setUp(self)` / `tearDown(self)` | Per-test setup and cleanup fixture methods |
| `with self.subTest(param=val):` | Runs parameterized loop iterations independently without early abort |
| `@unittest.skip("reason")` | Unconditionally skips a test method or class |
| `python -m unittest discover -s tests -v` | Discovers and runs all `test_*.py` modules under `tests/` verbosely |
