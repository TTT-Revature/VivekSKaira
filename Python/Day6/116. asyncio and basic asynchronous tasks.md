# `asyncio` and Basic Asynchronous Tasks in Python

## 1. Overview
**`asyncio`** is Python's standard library framework for writing concurrent single-threaded applications using coroutines, multiplexed I/O access over sockets and other resources, and cooperative task scheduling.

* **The Event Loop (`asyncio` Core Engine):**
  An `asyncio` program runs on a single thread controlled by an **event loop**. The event loop maintains a queue of ready tasks and monitors OS I/O readiness (using `epoll` on Linux, `kqueue` on macOS, or `IOCP` on Windows). Whenever a running task reaches an `await` expression on an unfinished I/O operation, it suspends and hands control back to the loop, which immediately switches to another ready task.
* **Why Asynchronous Tasks Matter:**
  A raw coroutine object does not run concurrently on its own—awaiting it directly runs it sequentially. Wrapping coroutines in **`asyncio.Task`** objects registers them with the event loop so multiple I/O operations progress concurrently on the same thread.

---

## 2. Core `asyncio` Primitives: Coroutines, Tasks, and Futures
Any object that can be used in an **`await`** expression is an **Awaitable**. `asyncio` defines three primary awaitable types:

| Awaitable Type | How It Is Created | Role in `asyncio` |
| :--- | :--- | :--- |
| **Coroutine** | Calling an `async def` function | Encapsulates suspendable code; does **not** start executing until awaited or wrapped in a `Task` |
| **Task (`asyncio.Task`)** | `asyncio.create_task(coro)` or `tg.create_task(coro)` | Subclass of `Future` that wraps a coroutine and schedules it to run concurrently on the event loop |
| **Future (`asyncio.Future`)** | `loop.create_future()` (mostly low-level/library code) | Low-level placeholder representing an eventual result or exception set asynchronously by callback-based code |

### Coroutine vs. `Task` Execution Behavior
```python
import asyncio
import time


async def worker(label: str, delay: float) -> str:
    await asyncio.sleep(delay)
    return f"{label} done"


async def compare_sequential_vs_tasks() -> None:
    # 1. Awaiting coroutines directly runs them SEQUENTIALLY (~0.60s total)
    start_seq = time.perf_counter()
    res_a = await worker("A", 0.3)
    res_b = await worker("B", 0.3)
    print(f"Sequential ({time.perf_counter() - start_seq:.2f}s): {res_a}, {res_b}")

    # 2. Wrapping coroutines in Tasks schedules them CONCURRENTLY (~0.30s total)
    start_conc = time.perf_counter()
    task_a = asyncio.create_task(worker("A", 0.3), name="Worker-A")
    task_b = asyncio.create_task(worker("B", 0.3), name="Worker-B")
    print(f"Concurrent ({time.perf_counter() - start_conc:.2f}s): {await task_a}, {await task_b}")


if __name__ == "__main__":
    asyncio.run(compare_sequential_vs_tasks())
```

## 3. Running Programs and Creating Basic Tasks

### 1. Bootstrapping with `asyncio.run()`
**`asyncio.run(main(), *, debug=None)`** is the standard top-level entry point for an `asyncio` application:
1. Creates a new event loop and sets it as the running loop for the current thread.
2. Executes the `main()` coroutine until it returns or raises an exception.
3. Cancels any remaining background tasks, shuts down async generators and the default thread pool executor, and closes the event loop.

*(Call `asyncio.run()` only once at the top level of your program; never call it inside an already-running event loop.)*

### 2. Scheduling Tasks with `asyncio.create_task()`
**`asyncio.create_task(coro, *, name=None, context=None)`** wraps a coroutine into a `Task` and schedules it on the running event loop:
* The task begins running as soon as the current coroutine yields control at its next `await` point.
* Passing **`name="..."`** attaches a human-readable identifier retrievable via `task.get_name()` for logging and debugging.

```python
import asyncio


async def send_notification(recipient: str, delay: float) -> str:
    current = asyncio.current_task()
    task_name = current.get_name() if current else "unknown"
    print(f"[{task_name}] Sending notification to {recipient}...")
    await asyncio.sleep(delay)
    return f"Delivered to {recipient}"


async def main() -> None:
    t1 = asyncio.create_task(send_notification("vivek@example.com", 0.2), name="EmailTask")
    t2 = asyncio.create_task(send_notification("+91-9000000000", 0.1), name="SmsTask")

    # Yield control briefly or await tasks directly
    result_1 = await t1
    result_2 = await t2
    print(result_1, "|", result_2)


if __name__ == "__main__":
    asyncio.run(main())
```

## 4. Coordinating Multiple Asynchronous Tasks

### 1. Structured Concurrency with `asyncio.TaskGroup` (Preferred, Python 3.11+)
**`asyncio.TaskGroup`** guarantees that all child tasks complete before execution leaves the `async with` block, and automatically cancels sibling tasks if any child raises an unhandled exception:

```python
import asyncio


async def fetch_endpoint(name: str, latency: float) -> dict[str, object]:
    await asyncio.sleep(latency)
    return {"endpoint": name, "status": 200}


async def main() -> None:
    async with asyncio.TaskGroup() as tg:
        users_task = tg.create_task(fetch_endpoint("/users", 0.25), name="FetchUsers")
        orders_task = tg.create_task(fetch_endpoint("/orders", 0.15), name="FetchOrders")

    # Both tasks are guaranteed finished here
    print(users_task.result())
    print(orders_task.result())


if __name__ == "__main__":
    asyncio.run(main())
```

### 2. `asyncio.gather()`
**`asyncio.gather(*aws, return_exceptions=False)`** accepts coroutines or tasks, schedules any bare coroutines automatically, and returns results in **input order**:

```python
import asyncio


async def compute_square(n: int) -> int:
    await asyncio.sleep(0.1)
    return n * n


async def main() -> None:
    results = await asyncio.gather(
        compute_square(2),
        compute_square(4),
        compute_square(6),
    )
    print(results)  # [4, 16, 36]


if __name__ == "__main__":
    asyncio.run(main())
```

### 3. `asyncio.wait()` for Fine-Grained Completion Control
**`asyncio.wait(aws, *, timeout=None, return_when=ALL_COMPLETED)`** accepts a collection of `Task` objects and returns two sets: **`(done, pending)`**. It supports three completion modes:
* **`asyncio.ALL_COMPLETED` (default):** Waits until every task finishes or is cancelled.
* **`asyncio.FIRST_COMPLETED`:** Returns as soon as **any single task** finishes (useful for racing redundant mirrors or polling pipelines).
* **`asyncio.FIRST_EXCEPTION`:** Returns immediately if any task raises an exception (or when all finish if none fail).

```python
import asyncio


async def query_mirror(mirror_name: str, latency: float) -> str:
    await asyncio.sleep(latency)
    return f"Response from {mirror_name}"


async def main() -> None:
    tasks = {
        asyncio.create_task(query_mirror("mirror-1", 0.5), name="M1"),
        asyncio.create_task(query_mirror("mirror-2", 0.1), name="M2"),
        asyncio.create_task(query_mirror("mirror-3", 0.4), name="M3"),
    }

    # Stop waiting as soon as the fastest mirror responds
    done, pending = await asyncio.wait(tasks, return_when=asyncio.FIRST_COMPLETED)

    fastest = done.pop()
    print("Fastest result:", fastest.result())

    # Cancel remaining slower tasks cleanly
    for task in pending:
        task.cancel()
    await asyncio.gather(*pending, return_exceptions=True)


if __name__ == "__main__":
    asyncio.run(main())
```

## 5. Task Lifecycle, Inspection, and Callbacks
An `asyncio.Task` progresses from **Pending** -> **Running** -> **Done** (either *Finished with result*, *Finished with exception*, or *Cancelled*).

### Inspecting Running Tasks and Attaching Callbacks
```python
import asyncio


async def background_job(job_id: int) -> str:
    await asyncio.sleep(0.15)
    return f"job-{job_id}-complete"


def on_task_finished(task: asyncio.Task[str]) -> None:
    """Synchronous callback invoked automatically when the task transitions to done."""
    if task.cancelled():
        print(f"[Callback] {task.get_name()} was cancelled.")
    elif (exc := task.exception()) is not None:
        print(f"[Callback] {task.get_name()} failed with {exc!r}")
    else:
        print(f"[Callback] {task.get_name()} succeeded: {task.result()}")


async def main() -> None:
    task = asyncio.create_task(background_job(42), name="ReportJob")
    task.add_done_callback(on_task_finished)

    # Inspect all tasks currently registered on the running loop
    active_names = [t.get_name() for t in asyncio.all_tasks()]
    print("Active tasks on loop:", active_names)
    print("Done before await?   :", task.done())

    await task
    print("Done after await?    :", task.done())


if __name__ == "__main__":
    asyncio.run(main())
```

## 6. Timeouts and Shielding Critical Tasks

### 1. Enforcing Deadlines (`asyncio.timeout`)
Wrap awaitable operations in **`async with asyncio.timeout(delay):`** to automatically cancel the enclosed operations and raise **`TimeoutError`** if they exceed `delay` seconds:

```python
import asyncio


async def external_api_call() -> str:
    await asyncio.sleep(1.5)
    return "payload"


async def main() -> None:
    try:
        async with asyncio.timeout(0.25):
            response = await external_api_call()
            print(response)
    except TimeoutError:
        print("Request exceeded 0.25s budget and was cancelled.")


if __name__ == "__main__":
    asyncio.run(main())
```

### 2. Protecting Critical Operations from Cancellation (`asyncio.shield`)
Wrapping a task or coroutine in **`await asyncio.shield(aw)`** prevents an outer cancellation (such as a request timeout) from cancelling an inner critical operation (such as committing a payment record):

```python
import asyncio


async def commit_transaction() -> str:
    await asyncio.sleep(0.3)
    return "Transaction committed"


async def main() -> None:
    commit_task = asyncio.create_task(commit_transaction())
    try:
        async with asyncio.timeout(0.1):
            # Outer timeout fires at 0.1s, but commit_task keeps running in the background
            await asyncio.shield(commit_task)
    except TimeoutError:
        print("Caller timed out waiting, awaiting shielded commit completion...")
        final_status = await commit_task
        print("Shielded task status:", final_status)


if __name__ == "__main__":
    asyncio.run(main())
```

## 7. Common Pitfalls and Best Practices

1. **Dropping Strong References to Background `create_task()` Objects:**
   The `asyncio` event loop holds only **weak references** to active tasks. Calling `asyncio.create_task(sync_cache())` without saving the returned `Task` allows Python's garbage collector to destroy the task mid-execution. Store background tasks in a `set` and discard them upon completion (`background_tasks.add(t); t.add_done_callback(background_tasks.discard)`), or manage them inside an `asyncio.TaskGroup`.
2. **Awaiting Tasks Immediately on Creation Inside a Loop:**
   Writing `for url in urls: result = await asyncio.create_task(fetch(url))` creates and awaits one task at a time, eliminating all concurrency. Create all tasks first (or use `TaskGroup` / `gather`) before awaiting their results.
3. **Never Retrieving an Exception from a Failed Background Task:**
   If a `Task` created via `asyncio.create_task()` raises an exception and is never awaited (and `.exception()` is never inspected), `asyncio` logs `Task exception was never retrieved` when the task is garbage-collected. Always `await` tasks, use `TaskGroup`, or inspect `task.exception()` in a done callback.
4. **Blocking the Event Loop with Synchronous Code:**
   Calling `time.sleep()`, synchronous socket/file I/O, or CPU-heavy loops inside `async def` blocks the single event loop thread so **no other task can run**. Offload blocking I/O with `await asyncio.to_thread(fn, *args)` and heavy CPU work with `loop.run_in_executor(ProcessPoolExecutor(), fn, *args)`.
5. **Passing Bare Coroutines to `asyncio.wait()`:**
   Since Python 3.11, passing raw coroutine objects directly to `asyncio.wait([coro1(), coro2()])` raises **`TypeError: Passing coroutines is forbidden, use tasks explicitly`**. Always wrap them with `asyncio.create_task(...)` before calling `asyncio.wait()`.

## 8. Quick Reference

| Function / Method | Purpose |
| :--- | :--- |
| `asyncio.run(coro)` | Creates an event loop, runs `coro` to completion, and closes the loop |
| `asyncio.create_task(coro, *, name=None)` | Schedules `coro` concurrently on the running event loop and returns a `Task` |
| `async with asyncio.TaskGroup() as tg:` | Structured concurrency container that awaits all child tasks and cancels siblings on failure |
| `asyncio.gather(*aws, return_exceptions=False)` | Runs multiple awaitables concurrently and returns results in input order |
| `asyncio.wait(tasks, return_when=...)` | Waits on a set of `Task` objects and returns `(done, pending)` sets |
| `asyncio.as_completed(aws)` | Yields futures in order of completion as each task finishes |
| `async with asyncio.timeout(seconds):` | Cancels enclosed operations and raises `TimeoutError` if deadline expires |
| `asyncio.shield(aw)` | Protects an inner task/coroutine from being cancelled by an outer cancellation |
| `task.done()` / `task.cancelled()` | Checks whether a task has finished or was cancelled |
| `task.result()` / `task.exception()` | Retrieves the return value or raised exception of a completed task |
| `task.cancel()` / `task.add_done_callback(fn)` | Requests task cancellation or registers a callback to run on completion |
| `asyncio.current_task()` / `asyncio.all_tasks()` | Returns the currently running `Task` or a set of all active tasks on the loop |
