# Multiprocessing in Python

## 1. Overview
**Multiprocessing** achieves true hardware parallelism by running multiple independent OS processes simultaneously across multiple CPU cores.

* **Isolated Memory and Interpreter per Process:**
  Unlike threads—which share a single Python interpreter and memory space—each process spawned by Python's **`multiprocessing`** module has its own **dedicated Python interpreter, memory heap, and Global Interpreter Lock (GIL)**.
* **Why Multiprocessing Matters:**
  * **True CPU Parallelism:** Bypasses the GIL completely, allowing pure-Python CPU-bound code (numerical computation, data parsing, cryptography, image processing) to utilize 100% of multiple physical CPU cores.
  * **Fault Isolation:** A memory leak or segmentation fault in a worker process does not corrupt the memory space of the parent process.
* **Primary Standard Library Interfaces:**
  * **`multiprocessing`:** Low-level API for spawning individual `Process` instances, IPC queues/pipes, shared memory, and synchronization primitives.
  * **`concurrent.futures.ProcessPoolExecutor`:** High-level worker pool API for distributing tasks across CPU cores and collecting results via `Future` objects.

## 2. Creating and Managing Processes (`multiprocessing.Process`)
The **`Process`** class mirrors the API of `threading.Thread` (`start()`, `join()`, `is_alive()`), but launches an independent OS process.

```python
import multiprocessing as mp
import os
import time


def compute_factorial_digits(number: int) -> None:
    """CPU-bound worker task running inside a separate OS process."""
    worker_name = mp.current_process().name
    pid = os.getpid()
    parent_pid = os.getppid()

    result = 1
    for i in range(2, number + 1):
        result *= i

    digit_count = len(str(result))
    print(f"[{worker_name} | PID={pid}, PPID={parent_pid}] {number}! has {digit_count} digits")


if __name__ == "__main__":
    print(f"Main Process PID: {os.getpid()} | Available CPU cores: {os.cpu_count()}")
    start = time.perf_counter()

    processes = [
        mp.Process(target=compute_factorial_digits, args=(40_000,), name=f"Worker-{idx}")
        for idx in range(1, 5)
    ]

    for proc in processes:
        proc.start()

    for proc in processes:
        proc.join()
        print(f"{proc.name} exited with code: {proc.exitcode}")

    elapsed = time.perf_counter() - start
    print(f"Total parallel runtime: {elapsed:.2f}s")
```

### Key `Process` Attributes and Methods

| Attribute / Method | Purpose |
| :--- | :--- |
| `proc.start()` | Spawns the child OS process and executes `run()` / `target` asynchronously |
| `proc.join(timeout=None)` | Blocks the caller until the child process terminates or `timeout` seconds elapse |
| `proc.is_alive()` | Returns `True` while the child process is still running |
| `proc.pid` | Operating system Process ID (`None` before `start()` is called) |
| `proc.exitcode` | Exit status after termination (`0` = normal exit, `> 0` = error, `< 0` = killed by signal) |
| `proc.terminate()` / `proc.kill()` | Forcefully stops a child process (`SIGTERM` / `SIGKILL`); avoid unless hung, as `finally` blocks do not run |
| `os.cpu_count()` | Returns the number of logical CPUs available on the system |

## 3. Process Start Methods (`spawn`, `fork`, `forkserver`)
Depending on the operating system, Python supports three ways to initialize a new worker process:

| Start Method | How It Works | Platform Support & Defaults | Trade-Offs |
| :--- | :--- | :--- | :--- |
| **`spawn`** | Starts a brand-new Python interpreter from scratch and imports the target module, passing only required arguments via `pickle` | **Windows & macOS default**; available on Linux | **Safest** (no inherited locks/threads), but slowest startup time; requires `if __name__ == "__main__":` |
| **`fork`** | Calls OS `fork()` to clone the parent process memory immediately (copy-on-write) | Available on POSIX/Linux (not Windows) | Fastest startup, **unsafe if parent has active threads or open sockets/locks** |
| **`forkserver`** | Starts a clean single-threaded server process early on; future workers fork from that clean server | **Linux/POSIX default (Python 3.14+)**; available on Unix | Combines fast process creation with thread safety |

### Selecting a Start Method Explicitly
Use **`mp.get_context("spawn")`** (preferred over global `mp.set_start_method()`) so libraries and modules do not conflict over global process settings:

```python
import multiprocessing as mp


def worker(x: int) -> int:
    return x * x


if __name__ == "__main__":
    ctx = mp.get_context("spawn")
    with ctx.Pool(processes=2) as pool:
        print(pool.map(worker, [10, 20, 30]))
```

## 4. High-Level Parallelism with `ProcessPoolExecutor`
**`concurrent.futures.ProcessPoolExecutor`** manages a fixed pool of worker processes, handles serialization automatically, and propagates worker exceptions back to the main process via `Future` objects.

```python
from concurrent.futures import ProcessPoolExecutor, as_completed
import os
import time


def is_prime(n: int) -> tuple[int, bool]:
    """CPU-intensive primality test."""
    if n < 2:
        return n, False
    for divisor in range(2, int(n**0.5) + 1):
        if n % divisor == 0:
            return n, False
    return n, True


if __name__ == "__main__":
    candidates = [10_000_019, 10_000_079, 10_000_103, 10_000_121, 10_000_139, 10_000_141]
    max_workers = os.cpu_count() or 4

    start = time.perf_counter()
    with ProcessPoolExecutor(max_workers=max_workers) as executor:
        # 1. Using map() with chunksize to batch IPC overhead on large iterables
        ordered_results = list(executor.map(is_prime, candidates, chunksize=2))
        print("Ordered results:", ordered_results)

        # 2. Using submit() + as_completed() to handle tasks as they finish
        futures = [executor.submit(is_prime, num) for num in candidates]
        for future in as_completed(futures):
            num, prime_flag = future.result()  # Re-raises any exception thrown in worker
            if prime_flag:
                print(f"Prime found: {num}")

    print(f"Completed in {time.perf_counter() - start:.3f}s")
```

## 5. Inter-Process Communication (IPC) and Shared State
Because separate processes have isolated address spaces, mutating a global variable or list inside a worker process **does not affect the parent process**. Python provides explicit IPC mechanisms to exchange data safely:

### 1. `multiprocessing.Queue` (Producer-Consumer Message Passing)
Serializes (`pickle`) objects over an underlying OS pipe with built-in locking, safe for multiple producers and multiple consumers:

```python
import multiprocessing as mp


def square_worker(input_q: mp.Queue, output_q: mp.Queue) -> None:
    while True:
        item = input_q.get()
        if item is None:  # Sentinel value to stop worker
            break
        output_q.put((item, item * item))


if __name__ == "__main__":
    tasks: mp.Queue[int | None] = mp.Queue()
    results: mp.Queue[tuple[int, int]] = mp.Queue()

    workers = [mp.Process(target=square_worker, args=(tasks, results)) for _ in range(2)]
    for w in workers:
        w.start()

    numbers = [2, 4, 6, 8]
    for num in numbers:
        tasks.put(num)
    for _ in workers:
        tasks.put(None)  # One stop sentinel per worker

    collected = [results.get() for _ in numbers]
    for w in workers:
        w.join()

    print("Collected results:", sorted(collected))
```

### 2. `multiprocessing.Pipe` (Two-Way Point-to-Point Channel)
`parent_conn, child_conn = mp.Pipe()` returns a pair of `Connection` objects (`send()` / `recv()`) for fast two-way communication between **exactly two processes** (not safe for multiple concurrent readers/writers on the same end without external locking).

### 3. Synchronized Shared Memory (`Value` and `Array`)
`mp.Value(typecode, val)` and `mp.Array(typecode, sequence)` allocate C-type primitives (`'i'` for signed int, `'d'` for double) in shared OS memory wrapped with an internal lock:

```python
import multiprocessing as mp


def increment_shared(shared_counter: mp.Value, steps: int) -> None:
    for _ in range(steps):
        with shared_counter.get_lock():
            shared_counter.value += 1


if __name__ == "__main__":
    counter = mp.Value("i", 0)
    procs = [mp.Process(target=increment_shared, args=(counter, 5_000)) for _ in range(4)]

    for p in procs:
        p.start()
    for p in procs:
        p.join()

    print(f"Shared counter total: {counter.value}")  # Guaranteed: 20000
```

### 4. Zero-Copy Shared Memory (`multiprocessing.shared_memory`) and `Manager`
* **`multiprocessing.shared_memory.SharedMemory`:** Allocates raw named byte buffers accessible directly across processes without pickling—ideal for large **NumPy arrays** or image buffers.
* **`multiprocessing.Manager()`:** Runs a background server process hosting proxy Python objects (`manager.dict()`, `manager.list()`). Convenient for sharing arbitrary Python containers, though slower than `Queue` or `SharedMemory` because every access travels over IPC sockets.

## 6. `multiprocessing` vs. `threading`

| Feature | `multiprocessing` | `threading` |
| :--- | :--- | :--- |
| **Memory Space** | Isolated memory per process | Shared memory across all threads in one process |
| **CPython GIL Impact** | **Bypassed** (each process has its own interpreter & GIL) | **Subject to GIL** (only one thread executes Python bytecode at a time) |
| **Best Workload** | **CPU-bound** tasks (math, parsing, media, ML preprocessing) | **I/O-bound** tasks (network requests, database queries, disk I/O) |
| **Startup & RAM Overhead** | High (spawns full OS process and interpreter per worker) | Low (lightweight thread stack within existing process) |
| **Data Sharing** | Explicit IPC (`Queue`, `Pipe`, `Value`, `SharedMemory`, `pickle`) | Direct object references (protected by `Lock` or `queue.Queue`) |
| **Crash Isolation** | High (worker crash does not terminate parent process) | Low (unhandled fatal C crash terminates entire process) |

## 7. Common Pitfalls and Best Practices

1. **Omitting the `if __name__ == "__main__":` Guard:**
   On platforms using `spawn` (Windows and macOS), child processes re-import the main Python script to locate the target function. Without `if __name__ == "__main__":` wrapping process creation, every child process spawns new children infinitely until Python raises `RuntimeError: An attempt has been made to start a new process before the current process has finished its bootstrapping phase`.
2. **Passing Unpicklable Targets or Arguments:**
   Because `spawn` and `Queue` serialize objects with `pickle`, target functions must be **top-level named functions** in an importable module—`lambda` expressions, nested inner functions, open file handles, database connections, and `threading.Lock` objects will fail with `PicklingError` or `TypeError`.
3. **Deadlocking on `proc.join()` Before Draining a `multiprocessing.Queue`:**
   `Queue` buffers items in an OS pipe with a fixed size. If a child process puts large items into a `Queue` and the parent calls `proc.join()` *before* reading from the queue, the child blocks waiting for pipe space while the parent blocks waiting for the child to exit—causing an immediate **deadlock**. Always drain the queue (`queue.get()`) *before* calling `proc.join()`.
4. **Using `ProcessPoolExecutor` for Tiny Tasks Without `chunksize`:**
   Sending 100,000 tiny function calls one by one over IPC pipes spends more time pickling and scheduling than computing. Pass **`chunksize=...`** (e.g., `executor.map(fn, items, chunksize=500)`) so each worker receives a batch of items per IPC round-trip.
5. **Spawning More Workers Than Physical CPU Cores for CPU-Bound Work:**
   Creating 32 worker processes on an 8-core machine triggers heavy OS context switching and multiplies RAM usage by 32x without increasing throughput. Default to `os.cpu_count()` (or fewer if each worker uses large amounts of RAM).

## 8. Quick Reference

| Construct / Class | Module | Primary Purpose |
| :--- | :--- | :--- |
| `Process(target=..., args=...)` | `multiprocessing` | Creates and controls a single child OS process (`start()`, `join()`, `pid`) |
| `ProcessPoolExecutor(max_workers)` | `concurrent.futures` | Manages a reusable pool of worker processes with `map()` and `submit()` |
| `get_context("spawn" / "forkserver")` | `multiprocessing` | Explicitly selects process start mechanism without mutating global state |
| `Queue(maxsize=0)` | `multiprocessing` | Process-safe FIFO queue for producer-consumer message passing |
| `Pipe()` | `multiprocessing` | Fast two-way point-to-point channel between two processes |
| `Value(type, val)` / `Array(type, seq)` | `multiprocessing` | Synchronized C-type primitives and arrays in shared OS memory |
| `SharedMemory(create=True, size=...)` | `multiprocessing.shared_memory` | Zero-copy raw byte buffer shared across processes (for NumPy/binary data) |
| `Manager()` | `multiprocessing` | Server process providing proxy shared `dict` and `list` objects |
