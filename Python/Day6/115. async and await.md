# Asynchronous Programming with `async` and `await` in Python

## 1. Overview
**Asynchronous programming** in Python uses the native **`async`** and **`await`** keywords (introduced in PEP 492) alongside the standard library **`asyncio`** module to write single-threaded concurrent code using **coroutines**.

* **How It Works (Cooperative Multitasking):**
  Instead of relying on the operating system to preemptively switch between heavy OS threads, coroutines voluntarily **pause (`await`)** whenever they wait on slow I/O (network sockets, HTTP requests, database queries) and yield control back to a central **event loop**, which immediately runs another ready coroutine.
* **Why `async` / `await` Matters:**
  * **High Scalability for I/O:** A single thread running an `asyncio` event loop can manage tens of thousands of concurrent network connections with minimal memory overhead (a few kilobytes per coroutine vs. megabytes per OS thread).
  * **Explicit Suspension Points:** Context switches happen **only** at `await`, `async with`, and `async for` boundaries, making concurrency flow explicit and reducing subtle thread-interleaving bugs.

## 2. Core Building Blocks: Event Loop, Coroutines, and Tasks

### 1. Coroutine Functions (`async def`) and `await`
* Defining a function with **`async def`** creates a **coroutine function**.
* Calling a coroutine function does **not** execute its body immediately—it returns a **coroutine object** that must be scheduled on an event loop.
* The **`await`** keyword suspends the enclosing coroutine until the target **awaitable** (another coroutine, an `asyncio.Task`, or an `asyncio.Future`) completes and returns its result. (`await` can only be used inside an `async def` function.)

### 2. Entry Point (`asyncio.run()`) and `asyncio.Task`
* **`asyncio.run(coro)`:** Creates a fresh event loop, executes the top-level coroutine until completion, closes asynchronous generators, and shuts down the loop.
* **`asyncio.create_task(coro)`:** Wraps a coroutine in a **`Task`** and schedules it to run concurrently on the running event loop immediately.

```python
import asyncio
import time


async def fetch_user_profile(user_id: int, delay: float) -> dict[str, object]:
    """Simulate an asynchronous network call."""
    await asyncio.sleep(delay)  # Yields control back to the event loop
    return {"user_id": user_id, "status": "active"}


async def main() -> None:
    start = time.perf_counter()

    # Schedule two tasks concurrently on the event loop
    task_1 = asyncio.create_task(fetch_user_profile(101, 0.5))
    task_2 = asyncio.create_task(fetch_user_profile(102, 0.5))

    # Await both scheduled tasks
    user_1 = await task_1
    user_2 = await task_2

    elapsed = time.perf_counter() - start
    print(user_1, user_2)
    print(f"Completed in {elapsed:.2f}s (instead of 1.00s sequentially)")


if __name__ == "__main__":
    asyncio.run(main())
```

## 3. Running Multiple Coroutines Concurrently

### 1. Structured Concurrency with `asyncio.TaskGroup` (Python 3.11+, Recommended)
**`asyncio.TaskGroup`** provides structured concurrency using an `async with` block:
* Every task created via **`tg.create_task(...)`** is automatically awaited when exiting the `async with` block.
* If **any** task raises an unhandled exception, `TaskGroup` automatically **cancels all remaining sibling tasks**, waits for them to clean up, and raises an **`ExceptionGroup`**.

```python
import asyncio


async def fetch_service_metric(service: str, delay: float) -> tuple[str, int]:
    await asyncio.sleep(delay)
    return service, 200


async def collect_all_metrics() -> list[tuple[str, int]]:
    async with asyncio.TaskGroup() as tg:
        tasks = [
            tg.create_task(fetch_service_metric("auth", 0.3)),
            tg.create_task(fetch_service_metric("orders", 0.2)),
            tg.create_task(fetch_service_metric("billing", 0.4)),
        ]

    # All tasks are guaranteed finished at this point
    return [task.result() for task in tasks]


if __name__ == "__main__":
    print(asyncio.run(collect_all_metrics()))
```

### 2. `asyncio.gather()`
**`asyncio.gather(*aws, return_exceptions=False)`** schedules multiple awaitables concurrently and returns a list of results in the **exact order** passed in:
* With `return_exceptions=False` (default), the first exception immediately propagates to the caller (without automatically cancelling sibling tasks).
* With `return_exceptions=True`, exceptions are returned as objects inside the result list instead of raising.

```python
import asyncio


async def risky_call(item_id: int) -> str:
    await asyncio.sleep(0.1)
    if item_id == 2:
        raise ValueError("Item 2 unavailable")
    return f"ok-{item_id}"


async def main() -> None:
    results = await asyncio.gather(
        risky_call(1),
        risky_call(2),
        risky_call(3),
        return_exceptions=True,
    )
    print(results)  # ['ok-1', ValueError('Item 2 unavailable'), 'ok-3']


if __name__ == "__main__":
    asyncio.run(main())
```

### 3. Processing Results in Completion Order (`asyncio.as_completed`)
Use **`asyncio.as_completed(aws)`** when you want to process each result as soon as it finishes rather than waiting for the slowest task:

```python
import asyncio


async def job(name: str, duration: float) -> str:
    await asyncio.sleep(duration)
    return f"{name} ({duration}s)"


async def main() -> None:
    coroutines = [job("slow", 0.4), job("fast", 0.1), job("medium", 0.2)]
    for completed_future in asyncio.as_completed(coroutines):
        result = await completed_future
        print("Finished:", result)


if __name__ == "__main__":
    asyncio.run(main())
```

## 4. Timeouts, Cancellation, and Concurrency Limits

### 1. Enforcing Timeouts (`asyncio.timeout` and `asyncio.wait_for`)
* **`asyncio.timeout(seconds)` (Python 3.11+):** Context manager that cancels the enclosed block and raises **`TimeoutError`** if execution exceeds `seconds`.
* **`asyncio.wait_for(aw, timeout)`:** Wraps a single awaitable with a timeout and cancels it on expiry.

```python
import asyncio


async def slow_query() -> str:
    await asyncio.sleep(2.0)
    return "query_result"


async def main() -> None:
    try:
        async with asyncio.timeout(0.3):
            data = await slow_query()
            print(data)
    except TimeoutError:
        print("Query timed out after 0.3s and was cancelled cleanly.")


if __name__ == "__main__":
    asyncio.run(main())
```

### 2. Task Cancellation (`task.cancel()` and `CancelledError`)
Calling **`task.cancel()`** injects **`asyncio.CancelledError`** into the suspended coroutine at its next `await` point. Catch `CancelledError` only if you need to release resources, and **always re-raise it**:

```python
import asyncio


async def background_poller() -> None:
    try:
        while True:
            print("Polling queue...")
            await asyncio.sleep(0.2)
    except asyncio.CancelledError:
        print("Cleaning up poller resources before exit...")
        raise  # Always re-raise CancelledError so cancellation completes properly


async def main() -> None:
    poller = asyncio.create_task(background_poller())
    await asyncio.sleep(0.5)
    poller.cancel()
    try:
        await poller
    except asyncio.CancelledError:
        print("Poller task confirmed cancelled.")


if __name__ == "__main__":
    asyncio.run(main())
```

### 3. Bounding Concurrency with `asyncio.Semaphore`
When launching thousands of async HTTP requests, cap simultaneous in-flight operations using **`asyncio.Semaphore`** so you do not overwhelm downstream servers or exhaust OS file descriptors:

```python
import asyncio

rate_limiter = asyncio.Semaphore(3)  # At most 3 concurrent requests


async def fetch_page(page_num: int) -> str:
    async with rate_limiter:
        await asyncio.sleep(0.2)
        return f"Page {page_num} fetched"


async def main() -> None:
    async with asyncio.TaskGroup() as tg:
        tasks = [tg.create_task(fetch_page(i)) for i in range(1, 10)]
    print(f"Fetched {len(tasks)} pages with max concurrency 3.")


if __name__ == "__main__":
    asyncio.run(main())
```

## 5. Asynchronous Context Managers and Iterators

### 1. `async with` (Asynchronous Context Managers)
Used for resources whose setup (`__aenter__`) or teardown (`__aexit__`) performs asynchronous I/O—such as `aiohttp.ClientSession`, `httpx.AsyncClient`, async database transactions, or `asyncio.Lock`.

```python
import asyncio


class AsyncDatabaseSession:
    async def __aenter__(self) -> "AsyncDatabaseSession":
        await asyncio.sleep(0.05)  # Async connection handshake
        return self

    async def execute(self, sql: str) -> str:
        await asyncio.sleep(0.05)
        return f"Result for [{sql}]"

    async def __aexit__(self, exc_type: object, exc: object, tb: object) -> None:
        await asyncio.sleep(0.05)  # Async connection close


async def main() -> None:
    async with AsyncDatabaseSession() as session:
        output = await session.execute("SELECT * FROM trainees")
        print(output)


if __name__ == "__main__":
    asyncio.run(main())
```

### 2. `async for` and Asynchronous Generators
An **`async def`** function containing **`yield`** defines an **asynchronous generator**, consumed with **`async for`** to stream paginated API responses or live event streams lazily:

```python
import asyncio
from collections.abc import AsyncIterator


async def stream_pages(total_pages: int) -> AsyncIterator[str]:
    for page in range(1, total_pages + 1):
        await asyncio.sleep(0.1)  # Fetch next page asynchronously
        yield f"chunk_{page}"


async def main() -> None:
    async for chunk in stream_pages(3):
        print("Received:", chunk)


if __name__ == "__main__":
    asyncio.run(main())
```

## 6. Offloading Blocking Functions (`asyncio.to_thread`)
If you must call a synchronous blocking function (such as legacy file I/O, `requests.get`, or `sqlite3`) inside an `async` application, offload it to a worker thread using **`await asyncio.to_thread(...)`** so the event loop remains responsive:

```python
import asyncio
import time


def legacy_blocking_io(file_name: str) -> str:
    """Synchronous blocking function that cannot use await."""
    time.sleep(0.4)
    return f"Loaded {file_name}"


async def main() -> None:
    # Runs legacy_blocking_io in a separate thread without blocking the event loop
    result = await asyncio.to_thread(legacy_blocking_io, "archive.csv")
    print(result)


if __name__ == "__main__":
    asyncio.run(main())
```

## 7. `async` / `await` (`asyncio`) vs. `threading`

| Feature | `async` / `await` (`asyncio`) | `threading` |
| :--- | :--- | :--- |
| **Scheduling Model** | Cooperative (coroutines yield explicitly at `await`) | Preemptive (OS scheduler interrupts threads at any time) |
| **Execution Unit** | Lightweight coroutines on a single thread | OS-managed threads sharing process memory |
| **Memory Overhead** | Very low (~few KB per coroutine; scales to 10,000s of tasks) | Higher (~1–8 MB stack per OS thread) |
| **Race Condition Surface** | Lower (no switching between `await` points; still use `asyncio.Lock` across `await`) | Higher (any multi-bytecode operation can be preempted; requires `threading.Lock`) |
| **Library Compatibility** | Requires `async`-compatible libraries (`httpx`, `aiohttp`, `asyncpg`) | Works directly with standard synchronous libraries |

## 8. Common Pitfalls and Best Practices

1. **Forgetting to `await` a Coroutine:**
   Calling `fetch_user_profile(101, 0.5)` without `await` or `asyncio.create_task()` returns an unexecuted coroutine object and triggers `RuntimeWarning: coroutine 'fetch_user_profile' was never awaited`.
2. **Awaiting Tasks Sequentially Inside a Loop:**
   Writing `results = [await fetch(url) for url in urls]` executes each request one after another sequentially. Create all tasks first via **`asyncio.TaskGroup`** or pass all coroutines to **`asyncio.gather()`** so they run concurrently.
3. **Calling Blocking Synchronous Functions Inside `async def`:**
   Calling `time.sleep(2)`, `requests.get(url)`, or heavy CPU loops directly inside a coroutine freezes the **entire event loop** so no other coroutine can execute. Use `await asyncio.sleep()`, async HTTP clients, `await asyncio.to_thread()`, or `loop.run_in_executor()`.
4. **Swallowing `asyncio.CancelledError`:**
   Catching `except Exception:` does not catch `CancelledError` (which inherits from `BaseException` since Python 3.8), but catching `except BaseException:` or `except asyncio.CancelledError:` without re-raising breaks `asyncio.timeout()` and `TaskGroup` cancellation. Always re-raise `CancelledError` after cleanup.
5. **Dropping References to Background `create_task()` Objects:**
   The event loop keeps only **weak references** to running tasks. If you call `asyncio.create_task(bg_job())` without storing the returned `Task` in a variable or `set` (or managing it inside a `TaskGroup`), Python's garbage collector can destroy the task mid-execution.

## 9. Quick Reference

| Keyword / Function | Purpose |
| :--- | :--- |
| `async def fn():` | Declares an asynchronous coroutine function |
| `await expr` | Suspends current coroutine until `expr` (coroutine, `Task`, or `Future`) completes |
| `asyncio.run(main())` | Entry point that creates an event loop, runs `main()`, and closes the loop |
| `asyncio.create_task(coro)` | Schedules `coro` to run concurrently as a `Task` on the event loop |
| `async with asyncio.TaskGroup() as tg:` | Structured concurrency container that awaits all tasks and cancels siblings on error |
| `asyncio.gather(*aws)` | Runs multiple awaitables concurrently and collects results in input order |
| `async with asyncio.timeout(sec):` | Cancels enclosed block and raises `TimeoutError` if deadline is exceeded |
| `asyncio.Semaphore(n)` | Limits the number of coroutines accessing a resource concurrently to `n` |
| `async with obj:` / `async for x in gen:` | Asynchronous context manager and asynchronous stream iteration |
| `await asyncio.to_thread(fn, *args)` | Offloads a blocking synchronous function to a background worker thread |
