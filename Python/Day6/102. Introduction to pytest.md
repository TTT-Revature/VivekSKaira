# Introduction to `pytest`

## 1. Overview
**`pytest`** is the industry-standard third-party testing framework for Python. While Python's built-in `unittest` module requires subclassing `TestCase` and learning dozens of `self.assert*` methods, `pytest` lets you write tests as **plain Python functions** using Python's native **`assert`** keyword.

* **Why `pytest` Is Widely Adopted:**
  * **Minimal Boilerplate:** Write standalone `def test_*()` functions—no mandatory classes or inheritance.
  * **Rich Failure Diagnostics (Assertion Rewriting):** Automatically inspects failing `assert` expressions and prints detailed diffs of intermediate values, lists, dictionaries, and strings.
  * **Modular Fixtures (`@pytest.fixture`):** Replaces rigid `setUp`/`tearDown` hierarchies with reusable, composable dependency injection.
  * **Built-In Parameterization (`@pytest.mark.parametrize`):** Runs a single test function across dozens of input/output combinations with separate pass/fail reporting per case.
  * **Backward Compatibility:** Discovers and runs existing `unittest.TestCase` test suites out of the box without modification.

## 2. Installation and Project Configuration
`pytest` is a third-party package installed from PyPI into your project's active virtual environment (`.venv`):

```bash
# Install pytest inside your active virtual environment
python -m pip install pytest

# Verify installation
pytest --version
```

### Standard Layout and `pyproject.toml` Setup
Configure `pytest` options centrally in **`pyproject.toml`** so every contributor and CI pipeline runs with consistent settings:

```text
project_root/
├── pyproject.toml
├── src/
│   └── pricing/
│       ├── __init__.py
│       └── calculator.py
└── tests/
    ├── conftest.py
    └── test_calculator.py
```

```toml
# File: pyproject.toml
[tool.pytest.ini_options]
testpaths = ["tests"]
pythonpath = ["src"]
addopts = "-ra -q"
markers = [
    "slow: marks tests that take longer to execute",
    "integration: marks tests interacting with external services or files",
]
```

## 3. Test Discovery Rules and Writing Your First Tests
When you run `pytest` from the repository root, it automatically searches for and collects tests matching strict naming conventions:

* **Test Files:** Named **`test_*.py`** or **`*_test.py`**.
* **Test Functions:** Functions prefixed with **`test_`** outside classes.
* **Test Classes:** Classes prefixed with **`Test`** (must **not** define an `__init__` method) containing **`test_`** methods.

### Example: Production Module and `pytest` Suite

```python
# File: src/pricing/calculator.py
def apply_tax(amount: float, tax_rate: float) -> float:
    """Return total amount including tax_rate (expressed as a decimal, e.g., 0.18)."""
    if amount < 0:
        raise ValueError("Amount cannot be negative")
    if not 0.0 <= tax_rate <= 1.0:
        raise ValueError("Tax rate must be between 0.0 and 1.0")
    return round(amount * (1 + tax_rate), 2)
```

```python
# File: tests/test_calculator.py
import pytest
from pricing.calculator import apply_tax


def test_apply_tax_standard_rate() -> None:
    assert apply_tax(100.0, 0.18) == 118.0


def test_apply_tax_zero_rate() -> None:
    assert apply_tax(250.0, 0.0) == 250.0


def test_apply_tax_negative_amount_raises_value_error() -> None:
    with pytest.raises(ValueError, match=r"Amount cannot be negative"):
        apply_tax(-10.0, 0.18)
```

## 4. Native `assert` Rewriting and Special Comparisons
When `pytest` imports test modules, it rewrites the Abstract Syntax Tree (AST) of `assert` statements so failures display exact left-hand and right-hand values rather than a bare `AssertionError`:

```python
def test_user_payload_structure() -> None:
    actual = {"id": 101, "role": "trainee", "active": False}
    expected = {"id": 101, "role": "trainee", "active": True}
    assert actual == expected
    # On failure, pytest highlights the exact differing key: 'active': False != True
```

### Floating-Point Tolerance (`pytest.approx`)
Use **`pytest.approx()`** to compare floating-point numbers or sequences of floats within a safe relative/absolute tolerance:

```python
import pytest


def test_floating_point_sum() -> None:
    assert (0.1 + 0.2) == pytest.approx(0.3)
    assert [0.1 + 0.2, 0.2 + 0.4] == pytest.approx([0.3, 0.6])
```

## 5. Fixtures (`@pytest.fixture`) and `conftest.py`
**Fixtures** are functions decorated with **`@pytest.fixture`** that prepare test data, objects, or temporary resources and inject them into any test that lists the fixture name as a parameter.

### 1. Basic Fixture and Teardown with `yield`
Code before `yield` runs during **setup**; code after `yield` runs during **teardown** (guaranteed to execute even if the test fails):

```python
import pytest


@pytest.fixture
def sample_cart() -> list[dict[str, object]]:
    # Setup: create fresh cart data for each test
    cart = [
        {"item": "Keyboard", "price": 1500.0},
        {"item": "Mouse", "price": 700.0},
    ]
    yield cart
    # Teardown: cleanup logic runs after the test completes
    cart.clear()


def test_cart_item_count(sample_cart: list[dict[str, object]]) -> None:
    assert len(sample_cart) == 2


def test_cart_total_price(sample_cart: list[dict[str, object]]) -> None:
    total = sum(entry["price"] for entry in sample_cart)
    assert total == 2200.0
```

### 2. Fixture Scopes
Control how often a fixture is created and torn down using the **`scope`** parameter:

| Scope | Lifecycle | Typical Use Case |
| :--- | :--- | :--- |
| `scope="function"` *(default)* | Created and destroyed **per test function** | Mutable lists, dictionaries, fresh service instances |
| `scope="class"` | Shared across all test methods in a `Test*` class | Class-level read-only setup |
| `scope="module"` | Created **once per test file** | Loading a read-only reference dataset |
| `scope="session"` | Created **once for the entire `pytest` run** | Database containers, compiled schemas, HTTP test clients |

### 3. Sharing Fixtures via `conftest.py`
Any fixture placed inside **`tests/conftest.py`** is automatically available to all test files in that directory and its subdirectories **without needing an `import` statement**.

### 4. Useful Built-In Fixtures
`pytest` ships with ready-to-use fixtures out of the box:
* **`tmp_path`:** Provides a unique `pathlib.Path` temporary directory per test (cleaned up automatically).
* **`monkeypatch`:** Safely modifies environment variables (`monkeypatch.setenv(...)`), attributes, or dictionaries for the duration of a single test and restores them afterward.
* **`capsys`:** Captures `stdout` and `stderr` output written via `print()` so tests can assert on console messages (`captured = capsys.readouterr()`).

```python
from pathlib import Path


def test_saving_report_to_temp_dir(tmp_path: Path) -> None:
    output_file = tmp_path / "summary.txt"
    output_file.write_text("All checks passed", encoding="utf-8")

    assert output_file.exists()
    assert output_file.read_text(encoding="utf-8") == "All checks passed"
```

## 6. Parameterized Testing (`@pytest.mark.parametrize`)
Instead of writing duplicate test functions for different inputs, **`@pytest.mark.parametrize`** runs the same test logic across multiple test cases and reports each case independently:

```python
import pytest
from pricing.calculator import apply_tax


@pytest.mark.parametrize(
    "amount, tax_rate, expected_total",
    [
        (100.0, 0.05, 105.0),
        (100.0, 0.18, 118.0),
        (0.0, 0.18, 0.0),
        (49.99, 0.10, 54.99),
    ],
)
def test_apply_tax_multiple_cases(amount: float, tax_rate: float, expected_total: float) -> None:
    assert apply_tax(amount, tax_rate) == expected_total
```

## 7. Markers (`@pytest.mark.*`)
Markers attach metadata to test functions to control execution or group tests by category:

```python
import sys
import pytest


@pytest.mark.skip(reason="Pending payment gateway sandbox credentials")
def test_live_payment_webhook() -> None:
    pass


@pytest.mark.skipif(sys.platform == "win32", reason="POSIX shell script test")
def test_unix_deployment_script() -> None:
    assert True


@pytest.mark.xfail(reason="Known upstream rounding discrepancy #42")
def test_legacy_rounding() -> None:
    assert round(2.675, 2) == 2.68


@pytest.mark.slow
def test_full_dataset_aggregation() -> None:
    assert sum(range(1_000_000)) == 499_999_500_000
```

## 8. Essential Command-Line Flags

| Command | Effect |
| :--- | :--- |
| `pytest` | Discovers and executes all tests under configured `testpaths` |
| `pytest -v` | Verbose output printing each test's full node ID and status |
| `pytest -s` | Disables output capturing so `print()` statements appear live in the terminal |
| `pytest tests/test_calculator.py` | Runs tests inside a single specific file |
| `pytest tests/test_calculator.py::test_apply_tax_zero_rate` | Runs one specific test function by node ID |
| `pytest -k "tax and not zero"` | Runs tests whose names match a boolean keyword expression |
| `pytest -m "not slow"` | Skips tests marked with `@pytest.mark.slow` |
| `pytest -x` / `pytest --maxfail=2` | Stops test execution immediately on the 1st (or 2nd) failure |
| `pytest --lf` | Re-runs only the tests that failed during the previous run (`--last-failed`) |
| `pytest --fixtures` | Lists all available built-in and custom fixtures in the project |

## 9. `pytest` vs. `unittest`

| Feature | `pytest` | `unittest` (Standard Library) |
| :--- | :--- | :--- |
| **Installation** | Third-party (`pip install pytest`) | Built into Python standard library |
| **Test Structure** | Plain `def test_*()` functions (or `Test*` classes) | Requires subclassing `unittest.TestCase` |
| **Assertions** | Native `assert` keyword with automatic AST diffing | 30+ methods (`self.assertEqual`, `self.assertIn`, etc.) |
| **Setup & Teardown** | Modular `@pytest.fixture` functions with `yield` and scopes | Class/module methods (`setUp`, `tearDown`, `setUpClass`) |
| **Parameterization** | Built-in `@pytest.mark.parametrize` decorator | Manual `for` loops with `with self.subTest():` |
| **Plugin Ecosystem** | Extensive (`pytest-cov`, `pytest-mock`, `pytest-asyncio`) | Minimal; mostly custom test runners |

## 10. Common Pitfalls and Best Practices

1. **Adding `__init__` to a `Test*` Class:**
   If a class named `TestOrderService` defines `def __init__(self):`, `pytest` skips the entire class with `PytestCollectionWarning: cannot collect test class 'TestOrderService' because it has a __init__ constructor`. Use `@pytest.fixture` instead of `__init__`.
2. **Mutating Fixtures with Broad Scopes (`module` or `session`):**
   If a `scope="session"` fixture returns a mutable `list` or `dict` and one test mutates it, every subsequent test receives corrupted state. Keep `session`/`module` fixtures immutable or read-only, and use default `scope="function"` for mutable objects.
3. **Forgetting to Register Custom Markers in `pyproject.toml`:**
   Using `@pytest.mark.integration` without listing `integration` under `[tool.pytest.ini_options] markers` triggers `PytestUnknownMarkWarning` (and fails builds if `--strict-markers` is enabled). Always register custom markers in `pyproject.toml`.
4. **Module Import Errors (`ModuleNotFoundError`) When Running `pytest`:**
   When using a `src/` layout, running `pytest` without `pythonpath = ["src"]` in `pyproject.toml` or an editable install (`pip install -e .`) prevents `pytest` from locating your package inside `src/`.
5. **Omitting `test_` Prefix on Helper Functions vs. Test Functions:**
   Helper functions inside `tests/` should **not** start with `test_` (otherwise `pytest` tries to execute them as tests), while every actual test function **must** start with `test_`.

## 11. Quick Reference

| Construct / CLI Flag | Purpose |
| :--- | :--- |
| `def test_behavior(): assert x == y` | Standard `pytest` unit test using native `assert` |
| `with pytest.raises(ExcType, match=r"..."):` | Verifies expected exception type and regex message pattern |
| `pytest.approx(val, rel=1e-6)` | Compares floating-point numbers within tolerance |
| `@pytest.fixture(scope="function")` | Defines reusable setup/teardown dependency injected via parameter name |
| `tests/conftest.py` | Central file sharing fixtures automatically across test modules |
| `tmp_path` / `monkeypatch` / `capsys` | Built-in fixtures for temp directories, env/attr patching, and stdout capture |
| `@pytest.mark.parametrize("a,b", [...])` | Runs one test across multiple input/expected tuples |
| `@pytest.mark.skip` / `@pytest.mark.xfail` | Skips a test or marks an expected failure |
| `pytest -v -k "expr" -m "not slow"` | Runs verbose tests filtered by name keyword and marker expression |
