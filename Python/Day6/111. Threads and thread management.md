# Threads and Thread Management in Python

## 1. Overview
A **thread** (thread of execution) is the smallest sequence of programmed instructions managed independently by the operating system scheduler within a **process**.

* **Shared Memory Model:**
  All threads inside the same Python process share the **same virtual address space** (global variables, heap objects, open file descriptors), while each thread maintains its own **call stack**, instruction pointer, and local variables.
* **Lightweight Creation & Fast Context Switching:**
  Creating a thread and sharing data between threads requires far less memory and overhead than spawning separate OS processes.
* **Core Python Modules:**
  * **`threading`:** Low-level API for creating, naming, inspecting, and synchronizing individual `Thread` objects.
  * **`queue`:** Thread-safe FIFO/LIFO/priority queues (`queue.Queue`) for coordinating producer-consumer pipelines.
  * **`concurrent.futures.ThreadPoolExecutor`:** High-level worker pool for managing reusable threads, bounding concurrency, and retrieving return values or exceptions via `Future` objects.
* **GIL Consideration:**
  In standard CPython builds, the Global Interpreter Lock (GIL) allows only one thread to execute Python bytecode at a time, releasing the lock during blocking I/O (network sockets, disk reads/writes, `time.sleep()`). Consequently, threads excel at **I/O-bound concurrency** and keeping user interfaces responsive.

## 2. Creating and Managing `threading.Thread`
The `threading` module provides two primary ways to define thread execution: passing a `target` callable (preferred) or subclassing `threading.Thread`.

### 1. Passing a `target` Callable (Recommended)
```python
import threading
import time


def fetch_order(order_id: int, delay: float = 0.5) -> None:
    """Simulate a blocking I/O task running inside a worker thread."""
    worker_name = threading.current_thread().name
    print(f"[{worker_name}] Fetching order {order_id}...")
    time.sleep(delay)
    print(f"[{worker_name}] Completed order {order_id}")


# Create Thread instances (does NOT start execution yet)
t1 = threading.Thread(target=fetch_order, args=(101,), kwargs={"delay": 0.4}, name="Worker-1")
t2 = threading.Thread(target=fetch_order, args=(102,), kwargs={"delay": 0.2}, name="Worker-2")

# Start concurrent execution
t1.start()
t2.start()

print(f"Active threads while running: {threading.active_count()}")

# Block the main thread until both worker threads finish
t1.join()
t2.join()

print(f"t1 alive after join: {t1.is_alive()}")
print("All orders processed.")
```

### 2. Subclassing `threading.Thread`
Subclass `Thread` only when you need to encapsulate thread-specific state alongside custom lifecycle logic. Always call **`super().__init__()`** in `__init__` and override **`run()`** (never override `start()`):

```python
import threading
import time


class HeartbeatMonitor(threading.Thread):
    def __init__(self, service_name: str, interval: float) -> None:
        super().__init__(name=f"Monitor-{service_name}")
        self.service_name = service_name
        self.interval = interval
        self.checks_completed = 0

    def run(self) -> None:
        for _ in range(3):
            time.sleep(self.interval)
            self.checks_completed += 1
            print(f"[{self.name}] Check #{self.checks_completed} OK")


monitor = HeartbeatMonitor("AuthService", interval=0.2)
monitor.start()
monitor.join()
print(f"Total checks recorded: {monitor.checks_completed}")
```

### Key Thread Lifecycle Methods and Functions

| Method / Function | Purpose |
| :--- | :--- |
| `thread.start()` | Allocates an OS thread and invokes `thread.run()` asynchronously (can only be called **once** per `Thread` instance) |
| `thread.join(timeout=None)` | Blocks the calling thread until `thread` terminates or `timeout` seconds elapse |
| `thread.is_alive()` | Returns `True` from the moment `start()` runs until `run()` completes |
| `threading.current_thread()` | Returns the `Thread` object corresponding to the caller's thread of control |
| `threading.main_thread()` | Returns the primary `Thread` object from which the Python interpreter started |
| `threading.active_count()` | Returns the number of currently alive `Thread` objects |
| `threading.enumerate()` | Returns a `list` of all currently alive `Thread` objects |

## 3. Daemon vs. Non-Daemon Threads
Python classifies every thread as either **non-daemon** (default) or **daemon** (`daemon=True`):

* **Non-Daemon Threads (`daemon=False`):**
  The Python interpreter **waits** for all non-daemon threads to finish executing before shutting down the process.
* **Daemon Threads (`daemon=True`):**
  Background service threads (such as metrics collectors or cache cleaners). Once **all non-daemon threads exit**, the interpreter **terminates immediately**, abruptly stopping any remaining daemon threads without running their `finally` blocks or flushing open buffers.

```python
import threading
import time


def background_metrics_flusher() -> None:
    while True:
        print("[Daemon] Flushing metrics...")
        time.sleep(0.3)


# Mark as daemon so it does not prevent program exit when main work finishes
metrics_thread = threading.Thread(
    target=background_metrics_flusher,
    name="MetricsFlusher",
    daemon=True,
)
metrics_thread.start()

time.sleep(0.7)
print("Main thread finished; process will now exit immediately.")
```

*(Rule of Thumb: Never use `daemon=True` for threads that write files, commit database transactions, or release external locks, because abrupt termination can leave data corrupted or incomplete.)*

## 4. Thread Synchronization Primitives
Because threads share memory and the OS preemptively switches between them between bytecode instructions, compound operations (like `balance += amount`) are **not atomic** and can cause **race conditions**.

### 1. `threading.Lock` (Mutual Exclusion)
A **`Lock`** has two states: *locked* and *unlocked*. Only one thread can hold the lock at a time; other threads attempting to acquire it block until it is released. Always use a **`with lock:`** context manager so the lock is released even if an exception occurs:

```python
import threading


class BankAccount:
    def __init__(self, initial_balance: int) -> None:
        self.balance = initial_balance
        self._lock = threading.Lock()

    def deposit(self, amount: int) -> None:
        with self._lock:
            # Critical section: guaranteed exclusive access by one thread at a time
            current = self.balance
            self.balance = current + amount


account = BankAccount(0)
threads = [
    threading.Thread(target=lambda: [account.deposit(1) for _ in range(10_000)])
    for _ in range(5)
]

for t in threads:
    t.start()
for t in threads:
    t.join()

print(f"Final balance (expected 50000): {account.balance}")
```

### 2. `threading.RLock` (Reentrant Lock)
A standard `Lock` deadlocks if the **same thread** tries to acquire it twice before releasing it (e.g., when a locked method calls another locked method on the same object). **`RLock`** tracks the owning thread and recursion depth, allowing the owning thread to acquire it multiple times and requiring an equal number of releases.

### 3. `threading.Semaphore` and `BoundedSemaphore`
A **`Semaphore(value)`** maintains an internal counter limiting how many threads can access a shared resource simultaneously (such as a pool of 3 database connections or rate-limited API calls). `BoundedSemaphore` raises `ValueError` if `.release()` is called more times than `.acquire()`.

```python
import threading
import time

api_rate_limiter = threading.Semaphore(2)  # Allow at most 2 concurrent API calls


def call_external_api(request_id: int) -> None:
    with api_rate_limiter:
        print(f"Request {request_id} acquired slot")
        time.sleep(0.3)
        print(f"Request {request_id} releasing slot")


workers = [threading.Thread(target=call_external_api, args=(i,)) for i in range(5)]
for w in workers:
    w.start()
for w in workers:
    w.join()
```

### 4. `threading.Event` (Cross-Thread Signaling)
An **`Event`** wraps a boolean flag (`False` initially) used to coordinate start/stop signals across threads:
* `event.set()`: Sets the flag to `True` and wakes up all threads waiting on it.
* `event.clear()`: Resets the flag to `False`.
* `event.wait(timeout=None)`: Blocks until the flag becomes `True` (or `timeout` expires).

```python
import threading
import time

stop_event = threading.Event()


def worker_loop() -> None:
    while not stop_event.is_set():
        print("Worker polling...")
        # Wait up to 0.2s, but wake immediately if stop_event.set() is called
        stop_event.wait(timeout=0.2)
    print("Worker received shutdown signal and exited cleanly.")


worker = threading.Thread(target=worker_loop)
worker.start()

time.sleep(0.5)
stop_event.set()  # Signal cooperative shutdown
worker.join()
```

### 5. `threading.Condition` and `threading.Barrier`
* **`Condition(lock=None)`:** Combines a lock with `wait()` / `notify()` / `notify_all()` methods so consumer threads can sleep until a specific state condition becomes true.
* **`Barrier(parties)`:** Blocks a fixed number of threads (`parties`) at a synchronization point until all of them reach the barrier, then releases them together.

## 5. Thread-Safe Queues and Thread-Local Storage

### 1. Producer-Consumer Pipelines with `queue.Queue`
Instead of manually locking shared lists, pass tasks between threads using **`queue.Queue`**, which handles all internal locking and condition signaling automatically:

```python
from queue import Queue
import threading
import time

task_queue: Queue[str | None] = Queue(maxsize=10)


def producer(items: list[str]) -> None:
    for item in items:
        task_queue.put(item)
    # Sentinel value signals worker to stop
    task_queue.put(None)


def consumer() -> None:
    while True:
        item = task_queue.get()
        try:
            if item is None:
                break
            time.sleep(0.1)
            print(f"Processed: {item}")
        finally:
            task_queue.task_done()


prod = threading.Thread(target=producer, args=(["doc_1", "doc_2", "doc_3"],))
cons = threading.Thread(target=consumer)

prod.start()
cons.start()

prod.join()
task_queue.join()  # Wait until every queued item has called task_done()
cons.join()
```

### 2. Per-Thread State with `threading.local()`
**`threading.local()`** creates an object whose attributes are stored separately for every thread—ideal for thread-specific context such as request IDs or non-thread-safe database sessions:

```python
import threading

request_context = threading.local()


def handle_request(request_id: str) -> None:
    request_context.id = request_id
    print(f"[{threading.current_thread().name}] Handling {request_context.id}")


t1 = threading.Thread(target=handle_request, args=("REQ-001",), name="T1")
t2 = threading.Thread(target=handle_request, args=("REQ-002",), name="T2")
t1.start()
t2.start()
t1.join()
t2.join()
```

## 6. High-Level Thread Management with `ThreadPoolExecutor`
Manually creating, starting, and joining individual `Thread` objects becomes cumbersome when collecting return values, propagating exceptions, or capping concurrency. **`concurrent.futures.ThreadPoolExecutor`** manages a reusable pool of worker threads:

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import time


def check_url(url: str) -> tuple[str, int]:
    """Simulate an HTTP health check returning (url, status_code)."""
    if "broken" in url:
        raise ConnectionError(f"Failed to reach {url}")
    time.sleep(0.2)
    return url, 200


urls = [
    "[https://api.example.com/auth](https://api.example.com/auth)",
    "[https://api.example.com/broken](https://api.example.com/broken)",
    "[https://api.example.com/orders](https://api.example.com/orders)",
]

with ThreadPoolExecutor(max_workers=3, thread_name_prefix="HealthCheck") as executor:
    # Submit tasks and map each Future back to its input URL
    future_to_url = {executor.submit(check_url, url): url for url in urls}

    # Process results as soon as each thread finishes (completion order)
    for future in as_completed(future_to_url):
        url = future_to_url[future]
        try:
            _, status = future.result()
            print(f"OK   : {url} -> {status}")
        except ConnectionError as exc:
            print(f"FAIL : {url} -> {exc}")
```

*(Note: Use `executor.map(func, iterable)` when you want results returned in the **exact order of the input iterable**, and `as_completed(futures)` when you want to process results as soon as each individual task completes.)*

## 7. Common Pitfalls and Best Practices

1. **Calling `thread.run()` Instead of `thread.start()`:**
   Calling `t.run()` executes the method **synchronously in the current thread** instead of launching a new OS thread. Always call `t.start()`.
2. **Deadlocks from Inconsistent Lock Acquisition Order:**
   If Thread A acquires `lock_1` then waits for `lock_2`, while Thread B acquires `lock_2` then waits for `lock_1`, both threads freeze permanently. Always acquire multiple locks in a **strict global order** across all code paths, or use a single coarse lock / `timeout` parameter (`lock.acquire(timeout=5.0)`).
3. **Silent Exceptions Inside Raw `threading.Thread`:**
   An unhandled exception inside a `threading.Thread` prints a traceback to `stderr` (and invokes `threading.excepthook`), **without crashing or notifying the main thread**. Prefer `ThreadPoolExecutor`, which captures exceptions inside the `Future` and re-raises them when `future.result()` is called.
4. **Assuming Python Bytecode Operations Are Thread-Safe Without Locks:**
   Even with the GIL enabled, operations like `counter += 1`, `items.append(x)` followed by `len(items)` checks, or read-modify-write dictionary updates span multiple bytecode instructions and require a `Lock` or `Queue`.
5. **Spawning Unbounded Threads for Large Workloads:**
   Launching thousands of raw `Thread` instances consumes significant stack memory (~1–8 MB per OS thread) and degrades throughput via context-switching overhead. Always cap concurrency using `ThreadPoolExecutor(max_workers=...)` or a `Semaphore`.

## 8. Quick Reference

| Primitive / Class | Module | Primary Purpose |
| :--- | :--- | :--- |
| `Thread(target=..., daemon=False)` | `threading` | Creates and manages an individual OS thread (`start()`, `join()`, `is_alive()`) |
| `Lock()` | `threading` | Basic mutual exclusion lock; use via `with lock:` |
| `RLock()` | `threading` | Reentrant lock that the same thread can acquire multiple times safely |
| `Semaphore(n)` | `threading` | Caps concurrent access to a resource pool at `n` threads |
| `Event()` | `threading` | Thread-safe boolean flag (`set()`, `clear()`, `wait()`) for start/stop signals |
| `local()` | `threading` | Stores isolated attributes per thread without cross-thread leakage |
| `Queue(maxsize=0)` | `queue` | Thread-safe FIFO queue for producer-consumer task passing (`put()`, `get()`, `join()`) |
| `ThreadPoolExecutor(max_workers)` | `concurrent.futures` | Manages a bounded pool of reusable worker threads with `Future` return/error handling |
